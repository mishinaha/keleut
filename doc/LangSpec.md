# Keleut 言語仕様

## 1. 適用範囲

本書は、現在の Keleut の構文、型規則、評価規則および標準環境を定める。
標準環境を読み込んだプログラムを対象とし、利用できない構文や実行機能は各節に制限として記す。
型検査に成功することと、外部関数や穴を含むプログラムが実行を完了することは別の条件である。

**型**：値が属する集合と、その値に許される操作を表すもの。
**エフェクト**：出力や可変状態へのアクセスなど、式の評価に伴う作用。
**行**：ラベルとその型を並べたもの。
レコード、構造的ヴァリアント、エフェクトの型に用いる。
**行変数**：行の未指定部分を表す変数。
行変数を持つ行を「開いた行」、持たない行を「閉じた行」と呼ぶ。

## 2. 字句

### 2.1. ソース形式

ソースは UTF-8 とする。
改行は LF とし、文字列外の空白、タブ、CR は区切りとして扱う。
CRLF も改行として使える。
BOM（U+FEFF）は文字列とコメントの外では位置を問わず字句エラーになる。

ファイルの先頭には `#!` で始まる行を置ける。
その行はプログラムの意味に影響しない。
先頭以外の `#!` は認めない。

`//` から行末までは行コメント、`/*` と `*/` の間はブロックコメントである。
ブロックコメントは入れ子にできる。
改行を含むブロックコメントは、文を区切るかどうかの判定では改行として扱う。

### 2.2. 識別子

識別子には ASCII の英字、数字、アンダースコアを使う。
先頭に数字は置けない。
大文字と小文字を区別する。

| 用途 | 先頭文字 | 例 |
| --- | --- | --- |
| 値、関数、レコードのラベル | 英小文字または `_` | `value`、`with_file`、`_item` |
| 型、コンストラクタ、モジュール、エフェクト、型クラス | 英大文字 | `List`、`Cons`、`Console` |
| エフェクトの操作 | 英小文字 | `write`、`yield_` |
| 型パラメータ | 英字または `_` | `A`、`E`、`h` |
| `run` のリージョン変数 | 英小文字または `_` | `h`、`heap` |

単独の `_` は識別子ではなく、パターンのワイルドカードまたは型構成子の引数の穴に用いる。
構造的ヴァリアントのラベルは `#Even` のように `#` と大文字始まりの名前を組み合わせる。

次の語を予約する。
レコードのラベルなど、識別子を要求する位置にも使えない。

```text
and case class derive effect extends extern false fn handle if
instance let match module newtype perform pub rec resume run
true type val with
```

`return`、`cancel`、`structural`、`Type`、`EffectRow` は文脈に応じて意味を持つ名前である。
ただし、エフェクトの操作名に `return` と `cancel` は使えない。

### 2.3. 文の区切り

宣言と式文はセミコロンまたは改行で区切る。
トップレベルとブロックでは、直前のトークンが文を終えられ、直後のトークンが文を始められるときに改行が区切りとなる。
空行と余分なセミコロンは許す。

識別子、リテラル、閉じ括弧、`???` は文の終端になれる。
二項演算子、`.`、`\`、`match`、`handle`、`and`、`extends`、`|`、`case` の前の改行は継続とする。
行頭の `(` は前の行の関数呼び出しの続きとは扱わず、新しい文を始める。
負数で新しい文を始める場合は、前の文との間にセミコロンを置く。

丸括弧、角括弧、レコード、レコード型、エフェクト行の内部では、改行を文の区切りにしない。
ただし、その内部に書いたブロックではブロックの区切り規則を使う。
`case` のパターンとガードの途中も改行できる。

カンマで区切るリストには末尾カンマを置ける。
`...rest` と `extends R` の後ろには置けない。

## 3. 型

### 3.1. 型の形

基本型は `Boolean`、`Int32`、`Int64`、`Float64`、`String` である。
`Unit` は空レコード型 `{}` の別名であり、値は `{}` または `()` と書く。
`Never` はコンストラクタを持たず、通常の値を構築できない型である。

| 型の形 | 意味 |
| --- | --- |
| `List[Int32]` | 型構成子への型引数の適用 |
| `(A, B) => C @ E` | 引数が 2 個、返り値が `C`、エフェクト行が `E` の関数 |
| `{x: A, y: B}` | 閉じたレコード型 |
| `{x: A extends R}` | 行変数 `R` を持つレコード型 |
| `(A, B)` | 2 要素タプル型 |
| `#Ok(A) \| #Err(String)` | 構造的ヴァリアント型 |

関数の引数の個数は型の一部である。
2 引数関数、タプルを 1 個受け取る関数、関数を返す 1 引数関数はそれぞれ異なる型を持つ。

```text
(A, B) => C
((A, B)) => C
(A) => (B) => C
```

型位置の `(A)` と `(A,)` はともに 1 要素タプル型である。
式位置の `(e)` のような、単なるグループ化にはならない。
矢印型の引数を囲む括弧は引数リストを表す。
`@` は直近の矢印に付く。
関数束縛の返り値に矢印型を書く場合も、その矢印の `@` と束縛自身の `@` を区別する。

### 3.2. 型パラメータ

関数や型の名前の後ろに `[A, B]` のような型パラメータリストを書ける。
関数の使用時には型引数を推論する。
値の呼び出しに明示的な型引数を渡す構文はない。

型パラメータの注釈は、その型を具体型に限定する指定ではない。
宣言したすべての型に対して本体が成立する必要がある。
たとえば `[A](x: A): A` の本体を整数値だけに限定することはできない。

**カインド**：型や型構成子がどの種類の引数を取り、どの種類の結果を返すかの区分。
値の型には `Type`、行には行のカインドを使う。
エフェクト行の別名には `EffectRow` と注記する。
レコードやヴァリアントの行変数も、値の型とは区別する。

`F[_]` は型引数を 1 個取る型パラメータ、`F[_, _]` は 2 個取る型パラメータを表す。
この形の各引数と結果のカインドは `Type` である。
型パラメータへ任意のカインドを直接注記する構文はない。

裸の型パラメータのカインドは型注釈や型宣言内の使用位置から決まる。
型宣言のパラメータについては、同じ宣言群内の型の本体での使用も考慮するが、値の本体からは決めない。
使用位置から決まらない場合は `Type` とする。
同じパラメータを値の型と行の両方には使えない。

型引数は、対応するパラメータのカインドに従って解釈する。
次の `Callback[{}]` の `{}` は空のエフェクト行、`Box[{}]` の `{}` は空レコード型である。

```keleut
newtype Callback[E] = Callback(() => Unit @ E)
newtype Box[A] = Box(A)

let callback: Callback[{}] = Callback(fn() => ())
let box: Box[{}] = Box(())
```

### 3.3. 型エイリアス

`type` は型に透過的な別名を付ける。
別名を展開した型と元の型を区別しない。
型引数の個数は宣言に一致させる。
型エイリアスの再帰や部分適用は認めない。

```keleut
type Point = {x: Float64, y: Float64}
type Pair[A, B] = (A, B)
type Output: EffectRow = {Print, Console}
```

エイリアスのカインド注釈を省略すると `Type` になる。
`EffectRow` の別名は、`@` の後ろ、エフェクト行の要素、`EffectRow` の別名の右辺、行を取る型引数位置で使える。
関数の引数型、返り値型、レコードのフィールド型など、値の型を要求する位置には使えない。

### 3.4. 型の一致

型の一致には、型構成子、引数の個数、各引数の型、関数のエフェクト行が一致することを要求する。
数値型間の暗黙変換や、レコードの余分なフィールドを捨てる部分型付けはない。
余分なフィールドを受け取る関数は行変数を使う。

行では、異なるラベルの並び順を型の違いとしない。
同じラベルが複数ある場合は、そのラベル同士の順序と個数を保存する。
たとえば `{x: Int32, y: String}` と `{y: String, x: Int32}` は同じ型だが、`{x: Int32, x: String}` と `{x: String, x: Int32}` は異なる型である。

## 4. リテラル

### 4.1. 真偽値

`true` と `false` は `Boolean` の値である。
他の型の値を真偽値として暗黙に解釈する規則はない。

### 4.2. 数値

整数には 10 進表記と、`0x`、`0o`、`0b` で始まる表記を使える。
数字列には区切りの `_` を挿入できる。
浮動小数リテラルには小数点または `e`、`E` に続く 10 進の指数を書く。
指数には `+` または `-` を付けられるが、指数内には `_` を置けない。

```keleut
let decimal = 1_000
let hexadecimal = 0xff
let octal = 0o17
let binary = 0b1010
let wide = 42i64
let fraction = 1.5
let exponent = 1.5e-3
let trailing_dot = 1.
let negative = -1
```

`.5` は認めない。
`1.`、`1.e5`、`1.f64` は浮動小数として扱う。
`1.foo` は数値へのフィールド選択にはならない。
負号は数値リテラルに付けられるが、変数や一般の式への単項マイナスはない。
一般の値の符号反転には減算または数値プリミティブを使う。

数値型と対応する接尾辞は次のとおりである。

| 型 | 表現 | 接尾辞 |
| --- | --- | --- |
| `Int32` | 32 ビット符号付き整数 | `i32` |
| `Int64` | 64 ビット符号付き整数 | `i64` |
| `Float64` | IEEE 754 の 64 ビット浮動小数 | `f64` |

接尾辞のない整数は文脈により `Int32` または `Int64` になる。
型が決まらないまま束縛を一般化する場合は `Int32` にする。
浮動小数リテラルは `Float64` にする。
数値リテラルの型を未確定のまま多相化しない。
整数の字面に `f64` を付けることはできるが、小数点や指数を持つ字面に整数接尾辞は付けられない。

`Integral` と `Fractional` は数値リテラルのための予約された条件である。
利用者が型クラスとして宣言したり、制約やインスタンスを書いたりすることはできない。
数値型には `Int8`、`Int16`、符号なし整数型、`Float32` は含まれない。

10 進整数リテラルが型の符号付き範囲を超えると、評価時にエラーになる。
2 進、8 進、16 進整数は型のビット幅全体を使え、最上位ビットを符号として解釈する。
たとえば `0xffffffffi32` の値は `-1` である。

### 4.3. 数値演算

整数の加減乗算と符号反転の桁あふれは、型のビット幅で折り返す。
整数除算はゼロ方向に切り捨てる。
型の最小値を `-1` で除した結果も、その型の最小値へ折り返す。
整数のゼロ除算とゼロによる剰余は実行時エラーになる。
剰余演算子はなく、剰余にはプリミティブを使う。

浮動小数演算は NaN と正負の無限大を含む値を生成できる。
浮動小数のゼロ除算もこれらの値を生成し、整数のゼロ除算とは扱いが異なる。
NaN を含む `==`、`<`、`<=`、`>`、`>=` は `false`、`!=` は `true` になる。
`0.0` と `-0.0` は等しい。
NaN と無限大を直接表すリテラルはない。

明示的な数値変換には次の関数を使う。

| 関数 | 変換 |
| --- | --- |
| `__i32_to_i64` | `Int32` から `Int64` |
| `__i32_to_f64` | `Int32` から `Float64` |
| `__i64_to_i32` | `Int64` から `Int32`。下位 32 ビットを残す |
| `__i64_to_f64` | `Int64` から `Float64`。必要なら丸める |
| `__f64_to_i32` | `Float64` から `Int32` |
| `__f64_to_i64` | `Float64` から `Int64` |

浮動小数から整数への変換はゼロ方向へ切り捨てる。
NaN、無限大、切り捨てた結果が変換先の範囲外になる値は実行時エラーにする。

### 4.4. 文字列

文字列は二重引用符で囲む。
生の改行を含められる。
文字列内の CR は値の一部として残る。

認めるエスケープは `\n`、`\t`、`\r`、`\a`、`\b`、`\f`、`\v`、`\\`、`\"`、`\'`、`\uXXXX`、`\UXXXXXXXX` である。
Unicode の指定はそれぞれ 4 桁、8 桁の 16 進数とする。
サロゲートと U+10FFFF を超える値は字句エラーになる。

`String` はバイト列として比較、連結、切り出しを行う。
長さと部分文字列の位置は Unicode の文字数ではなくバイト数で数える。
部分文字列の切り出しは UTF-8 の文字境界を要求しない。
文字単位の `Char` 型はない。

## 5. 式

### 5.1. 評価順序

式は必要な引数を評価してから関数を呼び出す。
呼び出し先を先に評価し、引数を左から右へ評価する。
二項演算子の左右、タプルの要素、コンストラクタの引数、レコードのフィールドも左から右へ評価する。
コンストラクタの名前付き引数も、宣言内のフィールド順ではなく呼び出しに書いた順に評価する。

レコード拡張では、追加するフィールドを先に、`extends` の右の式を最後に評価する。
レコード更新では基底を先に評価し、更新値を記述順に評価する。
`match` は対象の式を 1 回評価してから節を調べる。

`&&` と `||` は短絡評価する。
左辺だけで結果が決まる場合は右辺を評価しない。
ただし、型検査は左右の両方に行う。

### 5.2. 演算子

優先順位を強い順に示す。

| 優先順位 | 構文 | 結合規則 |
| --- | --- | --- |
| 1 | 呼び出し、`.`、`\` | 左結合 |
| 2 | `!`、負の数値リテラル | 前置 |
| 3 | `*`、`/` | 左結合 |
| 4 | `+`、`-` | 左結合 |
| 5 | `==`、`!=`、`<`、`<=`、`>`、`>=` | 連鎖不可 |
| 6 | `&&` | 左結合 |
| 7 | `\|\|` | 左結合 |
| 8 | 後置の `match`、`handle` | 左から適用 |
| 9 | `fn(...) => ...` | 本体を右に取る |

`a < b < c` は書けない。
`match` や `handle` の結果をさらに算術演算に使う場合は括弧で囲む。
利用者が演算子の字面や優先順位を追加することはできない。

### 5.3. 関数

無名関数は `fn(x, y) => e` と書く。
引数を持たない関数は `fn() => e` とする。
引数にはパターンと型注釈を書ける。
関数は定義された位置の束縛を参照する。

関数呼び出しは `f(a, b)` と書く。
引数を空白だけで並べる呼び出し、暗黙のカリー化、部分適用はない。
通常の関数の引数は位置で対応させ、`f(x = 1)` のような名前付き引数は使えない。

### 5.4. ブロック

ブロックは波括弧で囲んだ文の列である。
内部には `let`、`let rec`、式文、`with` を書ける。
型、モジュール、エフェクト、型クラスの宣言は置けない。

最後の文が式ならその値をブロックの値とし、最後が束縛なら `Unit` を返す。
途中の式の値は捨てる。
末尾のセミコロンは最後の式の値を捨てる指定にはならない。

式位置の `{` は、直後の形によってレコードとブロックを区別する。

| `{` に続く形 | 解釈 |
| --- | --- |
| `}` | 空レコード |
| 識別子の後ろに `=`、`,`、`with`、`extends` | レコード |
| `extends` | レコード |
| フィールド名の後ろに `:` | レコード型の形 |
| それ以外 | ブロック |

`{x}` は変数 `x` を返すブロックである。
1 フィールドのレコードには `{x = x}` または `{x,}` を使う。
型、エフェクト行、宣言本体、パターンの波括弧にはそれぞれの文脈の規則を適用する。

### 5.5. 穴

`???` は任意の型を取り得る式である。
型検査は周囲が要求する型を与えるが、評価がその式に到達すると実行時エラーになる。
関数本体に書いた穴は、その関数を呼び出すまでは評価しない。

## 6. 束縛

### 6.1. 値と関数の定義

値の束縛は `let p = e`、関数の定義は `let f(x, y) = e` と書く。
`let` は文であり、`in` は使わない。
値の束縛には値の型、関数には引数型、返り値型、エフェクト行を注釈できる。

```keleut
let answer: Int32 = 42
let identity[A](x: A): A = x
let add_pair(p: (Int32, Int32)): Int32 = p._0 + p._1
```

局所束縛の有効範囲は、その束縛より後ろの同じブロック内である。
同じ名前を再び束縛すると、新しい束縛がそれ以降で有効になる。
再束縛は、以前の束縛を捕捉した関数の意味を変更しない。
変数への代入構文はない。

### 6.2. 一般化

**一般化**：束縛の型に残った型変数を、使用ごとに別の型へ具体化できるようにすること。
関数定義と、構文上の値を単一の名前へ束縛する `let` に適用する。
リテラル、識別子、無名関数、穴、値だけからなるレコードやコンストラクタ適用、構造的ヴァリアントは構文上の値に含む。
値のレコードからフィールドを除く式も含む。

関数呼び出しやフィールド選択の結果は、純粋な計算であっても構文上の値には含めない。
このような束縛の型変数は、使用ごとに独立して具体化できない。
分解パターンで束縛した各変数も一般化しない。

型クラス制約がある型変数は、束縛の型から特定できる必要がある。
結果の型にも引数の型にも現れず、具体型も決まらない制約は曖昧性エラーになる。
数値リテラルの条件は既定化で型が決まるため、この曖昧性検査の例外とする。

### 6.3. 再帰

再帰関数には `let rec`、相互再帰には `and` を使う。
各束縛は単一の名前と関数を定義する必要がある。
値束縛の形では右辺を `fn(...) => ...` とする。
再帰的なデータ値の束縛や、多相再帰は認めない。

```keleut
let rec even(n: Int32): Boolean = n == 0 || odd(n - 1)
and odd(n: Int32): Boolean = n != 0 && even(n - 1)
```

同じ再帰群の複数の関数に、具体的な非空のエフェクト行を注釈し、先行する関数から後続の関数を呼ぶ形は受理しない。
この制限は、互いを呼び合う場合だけでなく、一方向の前方呼び出しにも適用する。
各関数が独立に導入した行変数同士も、同じ綴りだけでは同じ変数にならない。
この場合は各関数のエフェクト行を推論させる。

### 6.4. 宣言順序

型の宣言群では型名を前方参照できる。
再帰データは `newtype` を介して定義する。

トップレベルの値は、型検査で利用できる完全な署名を持つ場合に前方参照できる。
関数束縛では各引数と返り値を注釈し、最外のエフェクト行を明示する。
`pub` の最外の `@` の省略は、後述する純粋性の規則に従う。
入れ子の矢印で省略した `@` は空行として確定する。

実行時の初期化は宣言順に行う。
前方参照を含む関数は、参照先の初期化後に呼び出す必要がある。
インスタンスのメソッドも、インスタンス宣言を実行する前には呼び出せない。

### 6.5. `with`

`with p = f(a)` は、その後ろの文を無名関数にして呼び出しの最後の引数へ渡す。
残りの文の範囲は、現在のブロックまたはトップレベルの末尾までである。
右辺には関数呼び出しを書く。

```text
with x = f(a)
残りの文

f(a, fn(x) => { 残りの文 })
```

束縛パターンが単独の `_` なら、渡す無名関数は引数を持たない。
これは 1 個の引数を受け取って捨てる指定ではない。
残りの文がなければ無名関数の返り値は `Unit` になる。

実際の値を受け取る例を示す。

```keleut
let with_value[A, B, E](x: A, body: (A) => B @ E): B @ E = body(x)
let doubled(): Int32 = {
  with x = with_value(21)
  x * 2
}
```

## 7. レコード

### 7.1. 構築と選択

レコードはフィールド名と値の組である。
型名を宣言せずに構築できる。
`{x, y}` は `{x = x, y = y}` の略記である。
フィールドの選択は `p.x` と書く。

```keleut
let point = {x = 1.0, y = 2.0}
let x = point.x
let sum_xy[R](p: {x: Float64, y: Float64 extends R}): Float64 =
  p.x + p.y
```

`{x: Float64, y: Float64}` は、指定したフィールドだけを持つ型である。
`extends R` を付けた型は、指定外のフィールドを行変数 `R` として受け取る。
`{extends R}` は行 `R` 全体を持つレコード型を表す。

### 7.2. 拡張と制限

`{x = v extends p}` は `p` にフィールドを重ねた新しいレコードを返す。
同じ名前のフィールドが存在しても上書きしない。
選択は同名フィールドのうち最も外側の値を返す。

`p \ x` は最も外側の `x` だけを除いた新しいレコードを返す。
内側に同名フィールドがあれば、そのフィールドが選択可能になる。
選択と制限には、対象のラベルが存在することを型で要求する。

```keleut
let p = {x = 1 extends {x = "inner", y = true}}
let outer: Int32 = p.x
let inner: String = (p \ x).x
```

異なるラベルの順序は型の一致に影響しないが、式を評価する順序には影響する。
重複ラベルは記述順を保存し、先頭のフィールドを外側とする。

### 7.3. 更新

`{p with x = v}` は既存の最も外側の `x` を置き換えた新しいレコードを返す。
元のレコードは変更しない。
更新後のフィールドは元と異なる型でもよい。
フィールドが存在しなければ型エラーになる。

基底の `p` は単一の小文字側の識別子とする。
`{p.origin with ...}` や `{f(x) with ...}` は書けない。
複数フィールドの更新は左から順に行う。

## 8. タプル

タプルは `_item` という同じラベルを重ねたレコードである。
位置と重複ラベルの順序が対応する。

| 構文 | 等価なレコード |
| --- | --- |
| `(a, b)` | `{_item = a, _item = b}` |
| `(a,)` | `{_item = a}` |
| `()` | `{}` |
| `(A, B)` | `{_item: A, _item: B}` |

`t._0` は最初の要素、`t._1` は次の要素を選択する。
`t._N` は `_item` を `N` 個除いてから `_item` を選択する操作と同じである。
添字は非負の 10 進整数を識別子の一部として書き、`t.0` は認めない。

閉じたタプル型は要素数の一致を要求する。
先頭要素だけを要求する型には `{_item: A extends R}` を使う。
`_item` は通常のラベルでもあるため、この型は他の名前のフィールドを含むレコードも受け取る。

型や診断の表示では、`_item` だけを持つ閉じた行をタプル表記にする。
1 要素の場合もカンマを残す。
空行の型は `{}`、値は `()` と表示する。
開いた行はタプル表記にせず、`_item` を表示する。

## 9. 構造的ヴァリアント

**構造的ヴァリアント**：名前付きのケースのいずれかを値とする構造的な型。
ラベルは特定の型宣言に所属せず、宣言なしで `#Even` のように使える。

型のケースは `|` で結合する。
最後に行変数を置くと、記載したケース以外も受け取れる。
途中に置く型エイリアスは閉じたヴァリアント型でなければならない。

```keleut
type Result[A] = #Ok(A) | #Err(String)

let describe[R](v: #Even | #Odd | R): String = v match {
  case #Even => "even"
  case #Odd => "odd"
  case _ => "other"
}
```

各ラベルの積載値は 1 個である。
引数を省略したラベルは `Unit` を積載する。
`#Pair(a, b)` は `#Pair((a, b))` と同じで、型とパターンでも同じ規則を使う。
ラベル付き引数は認めない。

構築したヴァリアントの型は開いた行を持ち、文脈の型注釈によって閉じることができる。
再帰型や利用者定義の型クラスインスタンスが必要な場合は、名目的な型を使う。

## 10. 名目的な型

### 10.1. 宣言

**名目的な型**：宣言の名前によって他の型と区別する型。
`newtype` で宣言し、右辺にコンストラクタを `|` で並べる。
右辺は型エイリアスの型式とは異なる。

```keleut
newtype Tree[A] = Leaf(A) | Branch(left: Tree[A], right: Tree[A])
newtype UserId(Int32)
newtype Empty
```

`newtype UserId(Int32)` は、型名と同じ名前のコンストラクタを 1 個持つ宣言の略記である。
右辺を省略した型はコンストラクタを持たない。
`newtype Hidden = ???` は表現が与えられていない型であり、構築やコンストラクタによる分解はできない。

コンストラクタのフィールドは順序を持ち、名前を付けても省略してもよい。
名前付きフィールドと無名フィールドを混在させられる。
コンストラクタ名はプログラム全体で一意とする。
別のモジュールに同名コンストラクタを宣言して使い分けることはできない。

### 10.2. 構築

コンストラクタの適用では、全フィールドをちょうど 1 回ずつ指定する。
名前付き引数は対応するフィールドへ、位置引数は未指定の先頭フィールドへ順に対応させる。
両者を混在させてもよいが、同じフィールドを重複指定してはならない。
評価順は引数の記述順である。

引数を持たないコンストラクタは名前だけで値になる。
引数が必要なコンストラクタを名前だけで関数値として取り出すことはできない。
必要なら `fn(x) => Some(x)` のように関数で包む。

## 11. パターン照合

### 11.1. パターン

パターンは関数の引数、`let` の分解、`match` の節、ハンドラの引数に用いる。
1 個のパターンや 1 組の引数内で、同じ変数名を重複して束縛してはならない。

| 形 | 意味 |
| --- | --- |
| `_` | 値を受け取り、束縛しない |
| `x` | 値を変数 `x` に束縛する |
| `true`、`42`、`"text"` | リテラルとの一致を調べる |
| `Some(x)` | 名目的なコンストラクタを分解する |
| `#Ok(x)` | 構造的ヴァリアントを分解する |
| `{x, y = p}` | フィールド `x` と `y` を取り出す |
| `{x, ...rest}` | 指定外のフィールドを `rest` に束縛する |
| `(x, y)` | 要素数が一致するタプルを分解する |
| `(x, ...rest)` | タプルの先頭と残りのレコードを分ける |

レコードパターンは指定していないフィールドを許す。
空のレコードパターン `{}` も余分なフィールドを許すため、空レコードだけへの一致判定にはならない。
タプルパターンは `...rest` を持たない限り閉じており、`()` は空タプルを要求する。
`(p)` はパターンのグループ化、`(p,)` は 1 要素タプルである。

コンストラクタパターンを名前付きフィールドだけで書く場合は、一部のフィールドを省略できる。
たとえば `Cons(tail = t)` は先頭要素を束縛しない。
位置パターンを含める場合は全フィールドを指定する。

`let` の最外の束縛パターンには、変数、`_`、名目的なコンストラクタ、レコード、タプルを使える。
リテラルや `#Case` を直接その位置に置く形はない。
引数の型注釈や束縛全体の型注釈は書けるが、`case p: T => ...` という節パターンの型注釈はない。
`p | q` という選択パターンもない。

### 11.2. `match`

`match` は対象式の後ろに書く。
上から順にパターンを調べ、パターンが一致し、ガードも成立する最初の節の本体を評価する。
ガードは `Boolean` を返す式でなければならない。

```keleut
let classify(n: Int32): String = n match {
  case 0 => "zero"
  case x if x < 0 => "negative"
  case _ => "positive"
}
```

全節の本体は同じ型を持つ必要がある。
ガード付きの節は、他の場合を覆う保証には数えない。
どの節にも一致しなければ実行時エラーになる。
`if` はガードにだけ用い、単独の条件式の構文はない。
条件分岐は `Boolean` に対する `match` でも表せる。

対象が構造的ヴァリアントの場合、ガードのない節に残り全体を受け取るパターンがなければ、照合する行を閉じる。
これにより、型注釈のない関数の引数を、節に挙げたケースの閉じた和として推論できる。
残りを `_` や変数で受け取る節があれば、未確定の尾部を開いたままにする。
明示した行変数を勝手に空行へ限定することはできない。

処理系は網羅漏れと到達不能な節を検査し、通常は警告する。
`let` や関数引数の、失敗する可能性があるパターンも検査対象になる。
警告があっても実行を許す場合、束縛時の照合失敗は実行時エラーになる。
コンストラクタを持たない型に対しては、節を持たない `match {}` が網羅的である。

## 12. 型クラス

### 12.1. 宣言と制約

**型クラス**：型に要求する操作の署名をまとめたもの。
型クラスはパラメータを 1 個持つ。
そのカインドは `Type`、または `F[_]` のように `Type` を取り `Type` を返す形に限る。

各メソッドは矢印型を持つ。
少なくとも 1 個の引数の型の先頭に、クラスパラメータそのもの、またはそのパラメータの型適用が現れなければならない。
返り値だけにクラスパラメータが現れるメソッドは宣言できない。
異なる型クラスで同じメソッド名を宣言することもできない。

```keleut
type class Render[A] {
  val render: (A) => String
}

newtype Label(String)
type instance Render[Label] {
  let render(x) = x match { case Label(s) => s }
}

let render_twice[A: Render](x: A): String = render(x) + render(x)
```

型パラメータの制約は `[A: Add + Mul]` のように `+` で並べる。
メソッドは `render(x)` または `Render.render(x)` と呼べる。
型エイリアスのパラメータに付けた制約は、そのエイリアスを使う際に要求する。
名目的な型のパラメータの制約は、値の構築時にも要求する。
行変数には型クラス制約を付けられない。
スーパークラス、複数パラメータの型クラス、一般的なランク 2 多相はない。
`Ord` の制約から `Eq` の制約を導く規則もない。

### 12.2. インスタンス

インスタンスは `type instance C[T] { ... }` と書く。
本体には、クラスの全メソッドを `let` または `let rec` で定義する。
クラスにない補助メソッドは追加できないため、補助関数はメソッド内の局所束縛などで定義する。
各メソッドの型はクラス宣言の署名を満たす必要がある。

インスタンスの対象は型構成子とする。
レコード、タプル、構造的ヴァリアントへ利用者が直接インスタンスを宣言することはできない。
型エイリアスに対して新しいインスタンスを与えることもできない。

前提を持つインスタンスでは、`instance` の直後に型パラメータを書く。
`[A: Eq]` の `A` は、対象型の `_` に左から対応する。

```keleut
type instance[A: Eq] Eq[List[_]] {
  let rec eq(xs, ys) = (xs, ys) match {
    case (Nil, Nil) => true
    case (Cons(x, xt), Cons(y, yt)) => x == y && eq(xt, yt)
    case _ => false
  }
}
```

対象型に書く `_` の数は、型構成子の引数の総数と一致させる。
束縛する型パラメータの数は `_` の数を超えてはならない。
束縛されなかった右側の `_` は未適用のまま残り、インスタンスの対象はその分の型引数を取る。
残った型構成子のカインドはクラスパラメータと一致する必要がある。

インスタンスの型パラメータは、メソッドの型注釈から参照できる。
メソッド自身に同名の型パラメータがある場合は内側を優先する。
前提はインスタンスを適用できるかどうかの条件であり、別のインスタンスを値として渡して選び直す手段はない。

クラスと型構成子の組に対するインスタンスは一意とする。
インスタンスは大域的に可視であり、`pub` は付けられない。
標準の組み込みインスタンスを確認のために再宣言できる場合も、その動作を置き換えることはできない。
標準環境の `Show[List[_]]` と `Show[Option[_]]` は再宣言できない。

### 12.3. 高階型パラメータ

型構成子をパラメータとするクラスでは `F[_]` のように引数の数を書く。
メソッド自身には値の型とエフェクト行のパラメータを追加できる。

```keleut
type class Functor[F[_]] {
  val map[A, B, E]: (F[A], (A) => B @ E) => F[B] @ E
}

type instance Functor[List[_]] {
  let rec map[A, B, E](xs: List[A], f: (A) => B @ E): List[B] @ E =
    xs match {
      case Nil => Nil
      case Cons(x, tail) => Cons(f(x), map(tail, f))
    }
}
```

`Functor[List[_]]` の `_` は束縛せず、`List` を 1 引数の型構成子として渡している。
エフェクト行を引数に取る型構成子は、この `F[_]` の要求には一致しない。
標準環境に `Functor`、`map`、`Monad` などの宣言は含まれず、必要なクラスとインスタンスをプログラムで定義する。

### 12.4. 演算子クラス

| 演算子 | 操作 | 標準でインスタンスを持つ型 |
| --- | --- | --- |
| `+` | `Add.add` | `Int32`、`Int64`、`Float64`、`String` |
| `-` | `Sub.sub` | `Int32`、`Int64`、`Float64` |
| `*` | `Mul.mul` | `Int32`、`Int64`、`Float64` |
| `/` | `Div.div` | `Int32`、`Int64`、`Float64` |
| `==` | `Eq.eq` | `Int32`、`Int64`、`Float64`、`String`、`Boolean` |
| `!=` | `Eq.eq` の否定 | `Eq` と同じ |
| `<`、`<=`、`>`、`>=` | `Ord.lt`、`Ord.le`、`Ord.gt`、`Ord.ge` | `Int32`、`Int64`、`Float64`、`String` |

算術メソッドの型は `(A, A) => A`、比較メソッドの型は `(A, A) => Boolean` である。
`String` の `+` は連結、順序比較はバイト列の辞書順とする。
`&&`、`||`、`!` は `Boolean` 専用であり、型クラスのメソッドではない。

### 12.5. 構造的な等値比較

`Eq` は閉じたレコード、タプル、構造的ヴァリアントに構造的な等値比較を与える。
すべてのフィールドや積載値が `Eq` を満たす必要がある。
レコードでは対応するラベルの値を比較し、重複ラベルは同じラベル内の順序で対応させる。
ヴァリアントではラベルと積載値を比較する。

行変数を残す型にこの導出は適用しない。
関数の等値比較も定義しない。
名目的な型の比較は、利用者がその型のインスタンスを定義する。
構造内に名目的な型がある場合は、その型の `Eq` を使う。

`derive structural` は、この組み込みの導出を示す指定である。
新しい利用者定義クラスに独自の構造的導出を付けることはできない。

## 13. エフェクト

### 13.1. 宣言と行

エフェクトは、操作名と操作の型を宣言する。
操作の型には矢印型を書く。
利用者のエフェクト宣言に型パラメータは付けられない。
同じエフェクト内の操作名は重複できないが、別のエフェクトで同じ操作名を使うことはできる。

```keleut
effect Ask = { ask: () => String }
effect Log = { log: (String) => Unit }
type Request: EffectRow = {Ask, Log}
```

関数型の `@` の右側にエフェクト行を書く。

| 記法 | 意味 |
| --- | --- |
| `@ {}` | 空行 |
| `@ Print` | `@ {Print}` の略記 |
| `@ {Print, Console}` | 2 個のラベルを持つ行 |
| `@ E` | 行変数または行の別名 |
| `@ {Print extends E}` | `Print` と行変数 `E` からなる行 |
| `@ Heap[h]` | リージョン `h` の可変状態を扱う行 |

エフェクト行の別名を行の要素として書くと、その内容を展開する。
開いた別名も使えるが、展開後に独立した尾部の行変数を複数並べることはできない。
異なるラベルの順序は型の一致には影響せず、同じラベルの重複は保存する。

### 13.2. 注釈の位置

関数の行と呼び出し側の行は一致させる。
行にラベルを追加して暗黙に適合させるサブエフェクティングはない。
そのため、明示的な `@ {}` の関数は、空でない行の文脈からそのまま呼び出せない。

**最外の矢印**：関数束縛ではその関数自身の矢印、値束縛では型注釈の先頭に直接書いた矢印。
型エイリアスを展開した結果の矢印は、この最外の矢印には含めない。

最外の矢印に書く注釈は、次の規則で扱う。

| 注釈 | 本体の条件 | 使用時の行 |
| --- | --- | --- |
| `@ {}` | 純粋 | 空行のまま |
| `@ Print` など、閉じた非空行 | 書いたラベル以外のエフェクトを起こさない | 尾部を開き、他のエフェクトと同じ文脈で呼べる |
| `@ E`、`@ {Print extends E}` | 注釈の行に従う | 明示した行変数を使う |

最外の `@` を省略した場合は宣言によって異なる。

| 宣言 | 省略の意味 |
| --- | --- |
| `pub` のない `let` | 本体から推論する。一般化できる純粋な関数は行多相になる |
| `pub let` | 本体にエフェクトを要求する処理を許さず、使用時の型は行多相とする |
| 型クラスのメソッド | 各インスタンスの実装を純粋とし、使用時の型は行多相とする |
| `extern` | 使用時の型を行多相とする |

`pub` のない一般化可能な束縛では、本体が空行の関数を呼んだために行が空と決まった場合も、省略した最外の行を一般化する。
一方、最外の `@` を省略した `pub let` の本体からは、明示的な空行に固定された関数をそのまま呼ぶ形を受理しない。
高階関数で呼び出し先の行を通す場合は、行変数を明示する。

以上は関数の呼び出し時の行の規則である。
`pub let n: Int32 = e` のような関数型でない値の初期化式は、その位置のエフェクト行で評価する。
`pub` だけを理由に初期化式を純粋には制限しない。

最外以外の矢印では、書かれた行をそのまま使い、暗黙に尾部を開かない。
`@` の省略は `@ {}` と同じである。
この規則は関数の引数や返り値内の矢印、レコードやタプルの要素、コンストラクタのフィールド、型エイリアス内の矢印に適用する。

```keleut
let apply[A, B, E](f: (A) => B @ E, x: A): B @ E = f(x)
let pure_increment(x: Int32): Int32 = x + 1
let result = apply(pure_increment, 41)
```

エフェクトの操作署名の先頭の矢印に `@` を書いても、その注釈は `perform` の行を制約しない。
操作の引数の中に現れる矢印には、入れ子の矢印の規則を適用する。

### 13.3. `perform`

操作は `perform op(args)` と呼び出す。
実引数は操作の署名に一致する必要がある。
曖昧な操作名は `perform Print.print(message)` のようにエフェクト名で修飾できる。

非修飾の操作名は次の順で解決する。

1. その操作を宣言するエフェクトが 1 個なら、そのエフェクトを選ぶ。
2. 複数ある場合は、その位置のエフェクト行に現れる候補のうち最も左のものを選ぶ。
3. 行に候補がなければ、修飾を要求する型エラーにする。

行を注釈している場合、この「左」は注釈に書いた順序である。
実行時のハンドラの入れ子順だけでは決めない。
操作を解決した後は、そのエフェクトを現在の行で扱えることも要求する。

### 13.4. `handle`

**ハンドラ**：エフェクトの操作を受け取り、その後の計算を再開するか終了するかを定める式。
`body handle { ... }` と書き、1 個のエフェクトを対象にする。
本体の行から対象ラベルを 1 個除いた行が、ハンドラの外側の行になる。
各操作節、`return` 節、`cancel` 節はその外側の行で評価する。

```keleut
effect Ask = { ask: () => String }

let greeting(): String =
  ("hello, " + perform Ask.ask()) handle {
    case Ask.ask() => resume("Keleut")
    case return(value) => value
  }
```

対象エフェクトは操作節から決める。
修飾された操作節があれば、その修飾先を対象とし、非修飾の操作節も同じエフェクトの操作として読む。
異なるエフェクトへの修飾を混在させてはならない。

すべて非修飾の場合は、書かれた全操作を持ち、かつ宣言した全操作がこのハンドラに現れるエフェクトを候補とする。
候補が複数あれば修飾を要求する。
操作節を持たないハンドラは認めない。

全操作に対して少なくとも 1 個、ガードがなく、引数を取りこぼさない節が必要である。
変数、`_`、それらだけからなるレコードやタプルのパターンは、この条件を満たす。
リテラルやコンストラクタによる絞り込みだけでは条件を満たさない。
同じ操作に複数の節を書けるが、どれにも一致しない操作を外側のハンドラへ自動で転送する規則はない。

`case return(p) => e` は、本体の正常終了値を `p` に束縛する。
省略時は値をそのまま返す。
操作節の返り値と `return` 節の返り値は、ハンドラ式全体の型に一致する必要がある。
`return` 節は 1 個までで、ガードや名前の修飾は認めない。

同じエフェクトのハンドラを重ねた場合、操作は最も内側のハンドラに届く。
エフェクト名で修飾しても、同じエフェクトの外側のハンドラを指定することはできない。
操作節自身から同じエフェクトを起こした場合は、その節の外側にあるハンドラが受け取る。

### 13.5. `resume`

`resume(v)` は中断した操作へ値 `v` を返し、その操作以降の計算を再開する。
`v` の型は操作の返り値型に一致させる。
操作が `Unit` を返す場合は `resume()` と書ける。
引数は高々 1 個で、名前付き引数は認めない。

再開した計算でも同じハンドラが有効であり、同じ操作を再び処理する。
`resume` 自身の返り値はハンドラ式全体の型を持つ。
したがって、再開した結果を使って操作節の返り値を組み立てられる。

`resume` は操作節内の専用構文であり、関数値ではない。
変数への束縛、返り値としての持ち出し、無名関数への閉じ込めはできない。
ガード、`return` 節、`cancel` 節でも使えない。
同じ継続の再開は高々 1 回とし、2 回目の再開は実行時エラーになる。

### 13.6. 巻き戻し

操作節が `resume` を呼ばずに返ると、中断した残りの計算を破棄し、その節の値をハンドラの結果にする。
破棄する計算内のハンドラは、内側から外側へ巻き戻す。
専用の例外構文や `defer` 構文はなく、この動作と後始末の節を組み合わせる。

`case cancel => e` は、ハンドラが外側から巻き戻されるときの後始末を定める。
本体の実行時エラーによる巻き戻しでも実行する。
正常終了時の後始末は `return` 節に書く。
操作を処理したハンドラ自身が継続を破棄して終了する場合、そのハンドラ自身の `cancel` 節は実行しない。

`cancel` 節は 1 個までで、型は `Unit` とする。
省略時は何もしない。
ガード、名前の修飾、理由を受け取る引数は認めない。

`cancel` 節は自身のハンドラの外側で動作する。
同じエフェクトを起こした場合も、自身の操作節には戻らない。
後始末中の実行時エラーや、継続の破棄による再度の脱出は抑制し、診断として記録する。
これによって残りの後始末を続ける。

### 13.7. 標準のエフェクト

| 名前 | 操作または用途 | 利用者による `handle` |
| --- | --- | --- |
| `Console` | `write: (String) => Unit` | 不可 |
| `Print` | `print: (String) => Unit` | 可 |
| `Async` | `yield_: () => Unit`、`sleep: (Int64) => Unit` | 不可 |
| `Fs` | ファイル操作。操作宣言はない | 不可 |
| `Heap[h]` | リージョンの可変状態。操作宣言はない | `run` で処理 |
| `Blocking` | 外部関数のブロッキング。操作宣言はない | `pinned` で除去可能 |

トップレベルの評価で残せるエフェクトは `Console`、`Async`、`Fs`、`Blocking` である。
`Print` や利用者定義エフェクトはハンドラで処理する必要がある。
`Heap[h]` の `h` は `run` の外へ持ち出せないため、トップレベルには残せない。

`Async.yield_()` と `Async.sleep(...)` は現在、どちらも直ちに `Unit` を返す。
待機、タスクの切り替え、キャンセルの配送は提供しない。
`scope`、`spawn`、チャネル、期限付き実行も標準環境の機能には含まれない。

## 14. リージョン

### 14.1. `run`

**リージョン**：可変状態を利用できる範囲を型で区別するための局所的な領域。
`run h { ... }` は、新しいリージョン変数 `h` を導入して本体を評価し、その `Heap[h]` を外側のエフェクト行から除く。
別々の `run` が導入するリージョン変数は、同じ綴りでも異なるものとする。
`h` のカインドは `Type` であり、エフェクト行そのものとしては使えない。

結果の型に `h` を残すことはできない。
`Ref[h, A]` や `MutableArray[h, A]` を直接返すだけでなく、レコード、ヴァリアント、関数の型を介して残す形も拒否する。
外側の可変状態へ保存するなど、`h` を外側の型へ混入させることもできない。

```keleut
let sum(xs: Array[Int32]): Int32 = run h {
  let acc = Ref.new(0)
  Array.each(xs, fn(x) => Ref.set(acc, Ref.get(acc) + x))
  Ref.get(acc)
}
```

この関数は内部で可変状態を使うが、外側に `Heap` を要求しない。
`run` が除くのは自分の `Heap[h]` だけであり、出力などの他のエフェクトは残る。
別のリージョンの状態を新しい `run` で操作し、そのエフェクトを消すことはできない。

### 14.2. 参照

`Ref[h, A]` はリージョン `h` に属し、型 `A` の値を保持する可変参照である。
次の署名の `[h, A]` は型パラメータを表す説明用の記法である。
この節の各署名の最外の行は、束縛の注釈と同じ規則で読む。

```text
Ref.new : [h, A] (A) => Ref[h, A] @ Heap[h]
Ref.get : [h, A] (Ref[h, A]) => A @ Heap[h]
Ref.set : [h, A] (Ref[h, A], A) => Unit @ Heap[h]
```

`new` は新しい参照を作り、`get` は現在の値を返し、`set` は保持する値を置き換える。
保持する値の型は更新によって変えられない。

### 14.3. 配列

`Array[A]` は不変配列、`MutableArray[h, A]` はリージョン `h` に属する可変配列である。
いずれも添字は `Int32` とし、`0` から長さ未満までを有効とする。
範囲外の添字は実行時エラーになる。

```text
Array.length        : [A] (Array[A]) => Int32
Array.get           : [A] (Array[A], Int32) => A
Array.each          : [A, E] (Array[A], (A) => Unit @ E) => Unit @ E
MutableArray.new    : [h, A] (Int32, A) => MutableArray[h, A] @ Heap[h]
MutableArray.length : [h, A] (MutableArray[h, A]) => Int32 @ Heap[h]
MutableArray.get    : [h, A] (MutableArray[h, A], Int32) => A @ Heap[h]
MutableArray.set    : [h, A] (MutableArray[h, A], Int32, A) => Unit @ Heap[h]
MutableArray.freeze : [h, A] (MutableArray[h, A]) => Array[A] @ Heap[h]
```

`MutableArray.new(n, value)` は長さ `n` の配列を作り、全要素を同じ初期値にする。
初期値自体が可変参照などの場合、その値を各要素が共有する。
負の長さは実行時エラーになる。
配列の長さを変更する操作はない。
`Array.each` は添字の小さい順に各要素へ関数を適用する。

`freeze` が返した配列は、その後に元の配列へ要素を書き込んでも変わらない。
この保証は配列の要素を格納する 1 段だけに適用する。
要素自身が可変参照や可変配列なら、それらの同一性は保存する。
要素の型に `h` が残る配列は、`freeze` 後もリージョンの外へ返せない。

不変配列の `length` と `get` は `Heap` を要求しない。
可変配列は読み取りや長さの取得にも `Heap[h]` を要求する。
配列リテラルと `Array.new` はなく、不変配列の構築には可変配列の `freeze` を使う。

## 15. モジュール

### 15.1. 名前と可視性

モジュールは宣言を名前の下にまとめる。
モジュール内の値と型は、外部から `M.name`、`M.Type` のような修飾名で参照する。
内部では同じモジュールの名前を修飾せずに参照できる。
`import` 構文はない。

```keleut
module Counter {
  pub newtype Counter(Int32)
  pub let initial(): Counter = Counter(0)
  let hidden_value: Int32 = 1
}

type Count = Counter
let count: Count = Counter.initial()
```

モジュール外から参照できる宣言には `pub` を付ける。
`newtype` の型名とコンストラクタは同じ可視性を持つ。
公開コンストラクタは大域的に一意な名前を持ち、モジュール外でも非修飾名で使える。
モジュールと同名の公開型は、`Counter.Counter` の代わりに `Counter` と参照できる。
これをコンパニオン型とする。

複数のソースファイルは 1 個のプログラムを構成する。
ファイル境界は名前の可視性を隔てない。
可視性の境界はモジュールであり、トップレベルの非公開宣言を別ファイルから隠す規則はない。
`pub module` の有無だけで、内部宣言の個別の可視性は変わらない。

型エイリアスの本体は宣言したモジュールの名前で解釈する。
非公開型を指す公開エイリアスは、その型を別名経由で公開するが、非公開のコンストラクタを公開する指定にはならない。

### 15.2. 公開署名

`pub let` と `pub extern` には、各引数と返り値の型注釈が必要である。
値束縛なら束縛全体の型を注釈する。
注釈内の入れ子の矢印には `@` を明示する。
この要求は `pub newtype` のフィールドに書く矢印にも適用する。

最外の矢印だけは `@` を省略でき、エフェクトの節で定めた純粋性と行多相の規則に従う。
ただし、`pub let rec f: (...) => T = fn(...) => ...` の値束縛形では、先頭の矢印にも `@` を明示する。
`pub let rec f(...): T = ...` の関数束縛形では、最外の `@` を省略できる。

### 15.3. 宣言の制限

モジュール内に書けるのは `type`、`newtype`、単一の名前を束縛する `let` と `let rec`、`type instance`、`extern` である。
入れ子のモジュール、エフェクト宣言、型クラス宣言、式文、分解パターンによる `let` は利用できない。

モジュール内の値名と利用者が定義したトップレベルの値名を同じ綴りにはできない。
コンパニオン型も既存のトップレベルの型名を置き換えられない。
`Ref.get` や `Eq.eq` など、標準の操作やクラスメソッドと同じ修飾名をモジュール宣言で作ることはできない。
モジュール名自体を予約するわけではなく、`Array` の下に標準環境にない別の名前を追加することはできる。

## 16. 標準環境

### 16.1. データ型

標準環境には次の型を含む。

```text
type Unit = {}
newtype Option[A] = None | Some(A)
newtype List[A] = Nil | Cons(head: A, tail: List[A])
newtype Never
```

`Option` と `List` は名目的な型である。
そのほか、基本型と `Ref`、`Array`、`MutableArray`、演算子クラス、標準エフェクトを提供する。

基本型の名前を別の型として宣言し直すことはできない。
標準環境の型、エフェクト、クラスを同じ構造で確認のために再宣言する形は、1 プログラムにつき各名前で 1 回まで許す。
型パラメータ、フィールド、ラベル、操作、メソッドの型が一致する必要がある。
型、エフェクト、クラスについて、利用者同士の重複宣言は認めない。
型エイリアス、`newtype`、エフェクトは名前を共有できず、異なる宣言種別への置き換えも認めない。

### 16.2. 文字列化

`Show[A]` は `show: (A) => String` を持つ。
`show(x)` と `Show.show(x)` は同じ操作を指定する。

| 型 | 文字列化 |
| --- | --- |
| `Int32`、`Int64` | 符号付き 10 進数。型接尾辞は付けない |
| `Boolean` | `true` または `false` |
| `String` | 内容をそのまま返す。引用符は付けない |
| `Float64` | 以下に定める数値表記 |
| `List[A]` | 要素が `Show` を持つとき、`[1, 2]`、空なら `[]` |
| `Option[A]` | 要素が `Show` を持つとき、`Some(1)` または `None` |

有限の `Float64` は、読み戻すと同じ値になる表記を使う。
絶対値が `1e16` 未満の整数値には小数点表記を使う。
それ以外は、有効数字の桁数 `p` を 1 桁から 17 桁まで増やし、丸めた 10 進表記を読み戻して同じ値になる最初の `p` を使う。
丸めた値の 10 進の指数が `-4` 未満または `p` 以上なら指数表記、それ以外なら小数点表記を使い、不要な末尾のゼロを除く。
小数点も指数もない表記には `.0` を加え、指数の `+` と先行するゼロは除く。
たとえば `100000.0`、`0.0001`、`1e-5`、`1e16` となる。

非有限値は `nan`、`inf`、`-inf` と表示する。
これらの綴りはソース上のリテラルではない。
NaN の符号は表示しない。

### 16.3. 出力

```text
echo        : (String) => Unit @ Console
echoln      : (String) => Unit @ Console
println     : (String) => Unit @ Print
with_stdout : [A, E] (() => A @ {Print, Console extends E})
              => A @ {Console extends E}
```

`echo` は文字列を標準出力へ書く。
`echoln` は文字列の後ろに LF を付けて書く。
`println` は LF を付けた文字列で `Print.print` を起こすため、単独では標準出力へ接続しない。
`with_stdout` は本体の `Print` を処理して `Console` に接続する。

```keleut
with_stdout(fn() => println("hello"))
```

### 16.4. プリミティブ

数値プリミティブの名前と署名は、次の規則で定まる。
`T` は対応する数値型を表す説明用の記号である。

| 名前の形 | 対象 | 署名 |
| --- | --- | --- |
| `__int32_add`、`__int64_add`、`__float64_add` など | `add`、`sub`、`mul`、`div` | `(T, T) => T` |
| `__int32_rem`、`__int64_rem` | 整数の剰余 | `(T, T) => T` |
| `__int32_neg`、`__int64_neg`、`__float64_neg` | 符号反転 | `(T) => T` |
| 同じ接頭辞に `eq`、`lt`、`le`、`gt`、`ge` | 数値比較 | `(T, T) => Boolean` |
| `__show_int32` | 整数の文字列化 | `(Int32) => String` |

文字列には次のプリミティブを提供する。

```text
__string_concat : (String, String) => String
__string_eq     : (String, String) => Boolean
__string_lt     : (String, String) => Boolean
__string_le     : (String, String) => Boolean
__string_gt     : (String, String) => Boolean
__string_ge     : (String, String) => Boolean
__string_length : (String) => Int32
__string_sub    : (String, Int32, Int32) => String
__panic         : [A] (String) => A
```

`__string_sub(s, pos, len)` は位置 `pos` から `len` バイトを返す。
負の位置や長さ、文字列の範囲を超える指定は実行時エラーになる。
`__panic` はメッセージを伴う実行時エラーを起こし、正常には値を返さない。

### 16.5. ファイル操作

現在のファイル操作の対象は、プログラムの 1 回の実行内で共有する仮想ファイルである。
ホストのファイルシステムにある同名のファイルを読み書きする機能ではなく、実行をまたぐ永続化も行わない。

```text
__open  : (String) => Int32 @ Fs
__read  : (Int32) => String @ Fs
__write : (Int32, String) => Unit @ Fs
__close : (Int32) => Unit @ Fs
```

`__open(path)` はパスを指す新しいハンドルを返す。
同じパスのハンドルは同じ内容を参照する。
`__read` は内容全体を返し、書き込みのないパスは空文字列とする。
読み取り位置は進めない。
`__write` は末尾へ文字列を追加する。
`__close` はハンドルを無効にし、繰り返し閉じてもエラーにしない。
無効なハンドルによる読み書きは実行時エラーになる。

4 操作とも `Fs` を要求するため、純粋な関数の文脈では呼べない。
`File` エフェクトや `with_file` は標準環境には含まれず、必要な操作と後始末を利用者がハンドラとして定義する。

### 16.6. 純粋な計算の組み合わせ

```text
par_map : [A, B] (Array[A], (A) => B @ {}) => Array[B]
par     : [A, B] (() => A @ {}, () => B @ {}) => (A, B)
```

`par_map` は各要素へ関数を適用し、元と同じ要素順の不変配列を返す。
`par` は 2 個の関数の結果を、引数に対応する順のタプルとして返す。
どちらもコールバックのエフェクト行は空でなければならない。
コールバック内の `run` で局所的に可変状態を使うことはできる。

現在の評価順は、`par_map` が添字順、`par` が第 1 関数、第 2 関数の順である。
同時実行は保証しない。

## 17. 外部関数

外部関数は `extern "C" let ...` または `extern "prim" let ...` で宣言する。
宣言に本体は書かない。
この 2 種類以外のリンケージ名は認めない。

```keleut
extern "C" let sqrt(x: Float64): Float64
let root = sqrt(9.0)
```

`"C"` で呼び出せる名前は `sin`、`cos`、`sqrt`、`exp`、`log` であり、型はいずれも `(Float64) => Float64` とする。
その名前に異なる引数型や返り値型を宣言することはできない。
エフェクト注釈は別に指定できる。

その他の外部関数名も署名の宣言はできるが、呼び出すと実行時エラーになる。
任意の C ライブラリをロードする機能はない。
モジュール内の外部関数も、外部名には関数の非修飾名を使う。
標準環境のプリミティブ名は、モジュール内からも `extern` で再宣言できない。

ブロックし得る関数には `@ Blocking` を付ける。
`Blocking` は呼び出し側の行へ伝わり、トップレベルに残せる。
`pinned` は、本体の行から `Blocking` を除いて結果を返す。

```text
pinned : [A, E] (() => A @ {Blocking extends E}) => A @ E
```

`pinned` は本体を 1 回呼び出す。
外部呼び出しの中断、キャンセル配送、追加のタスク実行は提供しない。
