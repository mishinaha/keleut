### 3.2 言語設計の要点

- 静的型付けの ML 系言語で、レコード、タプル、構造的ヴァリアント、エフェクトをすべて Scoped Labels 方式の行多相で扱う。
  タプルは `_item` ラベルを重ねたレコードの糖衣で、`Unit` は空レコードと同一物である。
- 名目的な型は `newtype` で宣言する。
  再帰型は `newtype` を通すほかなく、型エイリアスは非再帰に限る。
- 型クラスは 1 パラメータのみで、高階カインドを許す。
  多パラメータ型クラスとランク 2 多相は意図的に排除し、エフェクトと行多相で代用する。
  コヒーレンスを堅持し、インスタンスは大域可視で、隠したり選び直したりできない。
  利用者がインスタンスを書けるのは名目的な型（`newtype` と組み込み型）だけで、構造的な型には組み込みの `derive structural` だけがインスタンスを与える。
  演算子は利用者が定義できず、組み込み演算子が標準ライブラリの型クラスを呼ぶ。
- 関数は多値を取って単値を返し、arity は型の一部である。
  カリー化と部分適用は言語機能として持たない。
- 代数的エフェクトとハンドラを持つ。
  `resume` は節の外に持ち出せず（second-class）、高々 1 回しか呼べない（アフィン）。
  専用の例外機構は持たず、`resume` を呼ばずに節を抜けると処理系が中断されたフラグメントを自動で巻き戻す（後入れ先出し）。
  `defer` も持たず、後始末はハンドラの `cancel` 節に書く。
- `run h { … }` は rigid なリージョン変数 `h` を導入して `Heap[h]` エフェクトを消し、`h` が結果型に漏れていないことを脱出検査で確かめる（Koka の `st<h>` と同じ）。
  ランク 2 多相を一般機能として持たないので構文として提供する。
- 並列性は純粋な計算に限る。
  並行性は §11 のエフェクト（`Async`、`Nursery`、`Deadline`、`Background`）で表し、利用者はスケジューラを書けない。
  トップレベルに残せるランタイム提供のエフェクトとして仕様が例に挙げるのは `Console` と `Async` で、列挙は閉じていない。
  Go の `context.Context` に相当する型は導入しない。
- `module` と `pub` で可視性を分ける。
  `pub` には引数と返り値の型注釈を完全に書くことを要求し、エフェクト行だけは省略できる。
  省略したエフェクト行は推論せず `@ {}`（純粋）と読む。
- `???` は未実装のホールで、`sample.kel` 自身がパーサコンビネータ（§9）、並行機能（§11）、FFI（§12）、モジュール（§13）の例の本体をこれで埋めている。

将来の拡張に対する禁止事項も本文に書いてある。
`{` の読み分けが「代入演算子が存在しないこと」に依存するため、`r.f = v` のような代入を足すとレコードとブロックの区別が壊れる。

### 4.2 動く範囲

`diktor` の処理は字句解析、構文解析、精緻化（型推論）、評価の 4 フェーズで、`driver.ml` が束ねる。

- 字句解析と構文解析は、sedlex による 3 層の字句解析（生トークン、`{` の 3 分割再分類、自動セミコロン挿入）と、Menhir による LR(1) 構文解析からなる。
  `--strict` で conflict 0 を保ち、`sample.kel` 全文 2,526 トークンをパースする。
- 型推論は、HM 推論、Scoped Labels の行単一化、エフェクト行、`run` の剛定数と脱出検査、注釈の skolem 化、1 パラメータ型クラスと高階カインドの単一化、曖昧性検査、Maranget の網羅性検査、数値リテラルの予約述語と既定化を持つ。
  型エラーには `ファイル:行:桁` の位置が付く。
- 評価は型付き木を辿る評価器で、Keleut のエフェクトを OCaml 5 の `Effect.Deep` に写す。
  `cancel` 節の LIFO 巻き戻し、アフィンな `resume`、末尾 `resume` の最適化を含む。
  型クラスは実行時の値タグで動的にディスパッチし、解決キャッシュを持つ。
- CLI は `--type-check`、`--dump-tokens`、`--dump-ast`、`--no-prelude`、`--prelude PATH`、`--strict-exhaustive` の 6 オプションを持つ。
  モードを選ぶオプションを並べたときは最後の指定が有効になり、`--prelude` と `--no-prelude` を両方書いたときは `--no-prelude` が有効になる。
  `--help` はなく、ハイフンで始まる未知の引数は使い方の誤りになる。
  出力先は `--type-check` では型行も警告も誤りも標準出力、実行モードでは標準出力をプログラムの出力専用にし診断を標準エラーに出す（D54）。
  終了コードは 0（正常）、1（型エラー。`--strict-exhaustive` のときは残った警告も 1）、2（字句と構文のエラー）、3（実行時エラー）、4（未実装）、64（使い方の誤りと、入力ファイルを開けないこと）、74（出力の書き出し失敗）の 7 種類。

プレリュード `lib/prelude.kel` は処理系本体で唯一の Keleut ソースで、次を提供する。

- `Unit`、`Option`、`List` の 3 つの型。
- `Console`、`Print`、`Async` の 3 つの `effect`。
- 52 本の `extern "prim"` 署名。
- `echo` / `echoln` / `println` / `with_stdout` の 4 つの関数。

演算子クラス（`Add` など）、予約述語、`Ref` / `Array` / `Heap` / `Blocking`、`par` / `par_map` / `pinned` は OCaml 側（`decls.ml`）の組み込み表にある。
置き場所の基準は「宣言構文で書けるか」ではなく「OCaml 側の表と二重管理にならないか」である（`lib/prelude.kel` §15.1、`lib/decls.ml` §6.11、§6.11b、§6.12）。

- `Ref` と `Array` は実装が OCaml 側の値と不可分で、二重管理になる。
- `par` と `par_map` は型は書けても値が Keleut で書けない。
- 演算子クラスは実装がプリミティブにしかない。
- 予約述語は名前を予約するために表に載せている。

### 4.3 実体を持たない機能

次の機能は動くが、中身が実体を持たない。
本文はファイル I/O と `extern "C"` を「張りぼて」と呼び、`Async` と `par` / `par_map` についてもそれぞれ実体がないことを明記している。

- ファイル I/O（`__open` など 4 本）はメモリ上のダミーで、実ファイルに触れない。
- `Async` は型だけで、`yield_` と `sleep` は実行時に何もしない。
- `par` / `par_map` は逐次実装で、コールバックの行が `@ {}` に閉じていることを根拠に並列実行と観測同値としている。
  ただし「型が純粋を守る」前提には課題 V14 と V15 の破れがあり（§6.1 の 10 と 11）、保証はその 2 つを除いた範囲に留まる。
- `extern "C"` は `sin` / `cos` / `sqrt` / `exp` / `log` の 5 名だけを型契約つきで実装し、未知名は宣言を受理して呼ぶと実行時エラーにする。

### 4.4 未実装として拒否する構文

次は未実装として終了コード 4 で拒否する。

- 数値型は `Int32` / `Int64` / `Float64` の 3 つだけで、`1u8` のような接尾辞や `Int8` は受け付けない。
- `module` の入れ子、`module` 内の `effect` / `type class` / 式文、エフェクト行のモジュール修飾ラベル（`@ {M.Db}`）、引数付きの `cancel(reason)` 節は受け付けない。

### 4.5 ソースの体裁

`lib/*.ml`、`lib/parser.mly`、`lib/prelude.kel`、`bin/main.ml` は `MiniLang.scala` と同じ「文芸的プログラミング」で書かれ、列 0 の `(* … *)` ブロック（`prelude.kel` は `//` 行）が日本語の本文、その間にコードが挟まる。
第 1 章 `syntax.ml` から第 16 章 `driver.ml` までの章立てと読む順序は `diktor/README.md` にある。
`awk -f tools/weave.awk lib/unify.ml > unify.md` のように 1 章ずつ Markdown 記事に変換できる。

この体裁には守るべき規約がある（`diktor/doc/log/260829-3-literate.md`。ここではビルドを壊すものと表記の決まりだけを抜く）。
コメント内の `"`、対にならない `(*` と `*)`、`{|`、`prelude.kel` 内の `|prelude}` の並びの 4 つはビルドを壊す。
`prelude.kel` は `lib/dune` の規則で `{prelude|…|prelude}` として OCaml に埋め込まれるため、最後の 1 つは埋め込み文字列を途中で閉じる。
`ocamlformat` と `dune fmt` は列 0 のブロックを再インデントして規約と weave を壊すので掛けない。
`.ocamlformat` が残っているため機械的な歯止めはなく、規約は文書だけが担保している。
`prelude.kel` を除く各ソースには 2 行の Copyright と SPDX ヘッダがあり、規約は各ファイルにこの形式を求めている。
節参照は「§N.M」、計画は「計画 §N.M」、仕様は「sample.kel §N」、お手本は「MiniLang §N」と書き、データ構築子は「コンストラクタ」、型は「型構成子」と呼ぶ。
節番号を詰めないことは `260829-4-plan.md` §16 の原則である。
