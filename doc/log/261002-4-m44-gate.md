### 条件 3

改訂後の LangSpec §13.2 の要点は次の 3 つである(文面は M45 で書く)。

- 最外の矢印に書いた閉じた行は、`@ {}` を含めて、本体をその閉じた行のもとで検査し、使うときは尾部を開く。
  `@ {}` の関数は、どの行の文脈からも呼べる。
- 閉じた行のもとで検査する本体から呼ぶ関数は、その呼び出しで決まる行が本体の閉じた行と一致すればよい(閉じた行の関数でもよい)。
- `pub` で最外の `@` を省略したら `@ {}` と同じにする。
  `pub` のない `let` で `@` を省略した一般化できる関数は、推論した最外の行が閉じていれば尾部を開く(S1+ の拡張)。

| ブロック | 受理が導ける理由 |
|---|---|
| sumclosed、noSub、val1 | `@ {}` の関数を、空でない閉じた行の本体から呼ぶ。`@ {}` は使うときに尾部を開く |
| eachclosed | `@ {}` の関数を、`run` の中で `Heap[h]` を持つ行のコールバックに渡す。同じ理由 |
| nested3 | 本体の閉じた行 `{A}` と、引数の関数の閉じた行 `{A}` が一致する |
| valclosed、valclosedfn | 初期化式または呼ぶ関数(エイリアスで閉じた `{Console}`)の行が、注釈の閉じた行 `{Console}` と一致する |
| recandboth、recandbothfn、recandfwd、recandfwdfn | 群の束縛の閉じた行がどれも `{Console}` で、呼ぶ向きによらず一致する |
| pub15 | `pub` の省略の本体は閉じた空の行で検査する。`helper` の一般化されない行は、その呼び出しで空に決まる |
| vrleak4 | 一般化されない `h` の行が、`g` の注釈の閉じた行 `{Console}` に決まる。`g` は `{Console}` の文脈から呼ばれる |
| clsalias3ok((b')) | `@` を省略した一般化できる `use` の推論した行 `{Print}` は閉じているので、尾部を開く |

### p01 の決定

統括者は、クラスメソッドの `@ {}` も開くと決めた。
p01(`val cm: (A) => A @ {}` のメソッドを、値でない式 `idf(fn(x: Int32) => x)` で実装する形)は拒否になる。

理由は 2 つある。

- S1 の 2 点目(`@ {}` はどの行からでも呼べる)を、クラスメソッドにも同じく当てはめる(q07、q08 は `@ {}` のメソッドを `@ Console` の本体から呼べる)。
- p01 の形は、閉じた空でない行のメソッドでは変更前から拒否されている(p02)。
  `@ {}` も同じ規則に入るだけである。
  η 展開した `let cm(x) = idf(x)` は通る(q23)。

他の選択肢は、クラスメソッドの `@ {}` だけを開かないことである。
その場合 p01 は受理のまま残るが、`@ {}` のメソッドは空でない行の文脈から呼べず、2 点目がメソッドにだけ当てはまらない。

`classes.t` の inam は p01 と同じ形で、拒否の理由が「曖昧な制約」から「型クラスのメソッドの実装は純粋でなければなりません … スコープ付きの型 ς1 がスコープの外に漏れています」に変わる((a))。
