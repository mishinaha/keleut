### 13.2. 注釈の位置

関数型のエフェクト行は、書いたとおりに読む。
閉じた行は、その関数が起こしうるエフェクトの全体を表す。
行変数で終わる行は、その行変数の分だけ、ほかのエフェクトを許す。
2 つの行を一致させる規則は §3.4 のとおりであり、行にラベルを足して暗黙に合わせる一般の規則（サブエフェクティング）はない。
例外は、次に定める使用時の開きだけである。

**使用時の開き**：閉じた行を持つ関数を、呼び出すとき、または関数型を要求する位置に置くとき、その行のラベルが要求する側の行に含まれていればよいとする規則。
処理系は、閉じた行の尾部を新しい行変数として開いてから、要求する側の行と一致させる。
行変数で終わる行は開かず、要求する側の行とそのまま一致させる。
関数型を要求する位置は、仮引数の型が関数型である実引数（実引数が無名関数で、仮引数の型の返り値が関数型なら、その本体の値も含む）、返り値の型注釈が関数型である関数束縛の本体、型注釈が関数型である値束縛の初期化式である。
閉じた行で検査した本体が起こすエフェクトはその行に含まれるので、尾部を開いても、型に書かれていないエフェクトが起きることはない。

**最外の矢印**：関数束縛ではその関数自身の矢印、値束縛では型注釈の先頭に直接書いた矢印、型クラスのメソッドと外部関数では宣言した型の先頭の矢印。
型エイリアスを展開して現れる矢印は、最外の矢印に含めない。

最外の矢印の行は、本体を検査する文脈の行になる。
閉じた行を書いた束縛の本体が、その行にないエフェクトを起こすと、型検査に通らない。
最外の `@` を省略したときの意味は、宣言の種類で決まる。

| 宣言 | `@` の省略の意味 |
| --- | --- |
| `pub` のない `let` | 本体から推論する |
| `pub let` | `@ {}` |
| 型クラスのメソッド | `@ {}`。各インスタンスの実装は純粋でなければならない |
| `extern "C"` | `@ Blocking` |
| `extern "prim"` | 新しい行変数。使うたびに別の行へ具体化する |

最外以外の矢印では、`@` を省略すると `@ {}` と同じ意味になる。
この規則は、関数の引数や返り値の中の矢印、レコードやタプルの要素、コンストラクタのフィールド、型エイリアスの中の矢印に適用する。
受け取った関数の行を自分の行へ通したいときは、次の `apply` のように行変数を明示する。

```keleut
let apply[A, B, E](f: (A) => B @ E, x: A): B @ E = f(x)
let pure_increment(x: Int32): Int32 = x + 1
let result = apply(pure_increment, 41)
```

使用時の開きには、2 つの制限がある。
1 つ目に、関数型を要求しない位置に置いた関数の行は開かない。
コンストラクタの引数、レコードのフィールド、タプルの要素、`match` の各節の値、`perform` と `resume` の引数がこれにあたる。
そのような位置で行の違う関数と同じ型にするには、`fn() => f()` のように無名関数で包む。
2 つ目に、使用の時点で関数の行がまだ決まっていないときは、開かずに一致させる。
そのため、注釈のない引数の関数を呼んでから閉じた行の関数と同じ型にする形と、一般化しない束縛を行の違う 2 つの文脈から呼ぶ形は、文の順序によって受理されるかどうかが変わる。

`pub let n: Int32 = e` のように関数型でない値の初期化式は、その宣言の位置のエフェクト行で評価する。
`pub` が付いていることだけを理由に、初期化式を純粋に制限することはない。

エフェクトの操作の型では、先頭の矢印に `@` を書いても、`perform` の行はその注釈に制約されない。
操作の引数の中に現れる矢印には、最外以外の矢印の規則を適用する。
