### 下書きの誤り

1. 修飾名の形が変わらないという主張は半分だけ正しい。
波括弧の要素は修飾名も `find_alias` で引く(:1213-1216 のコメントと :1218)。
そのため試作は、波括弧の中の修飾名の文面も変える。

```
$ cat q1.kel
module M {
  type T = Int32
}
let f(): Int32 @ {M.T} = 1
HEAD: ! q1.kel:4:18: 型エラー: 型 M.T は module M の外からは参照できません(pub を付けてください)
試作: ! q1.kel:4:18: 型エラー: エフェクト行に Type エイリアス M.T は置けません(: EffectRow を付けてください)
```

引数つきの `@ {M.T[Int32], Console}`(q4)も同じく変わる。
一方で `@ M.T`(a14)と `@ M.T[Int32]`(q5)は可視性の誤りのままである。
HEAD では `@ M.T` と `@ {M.T}` が同じ可視性の誤りだったが、試作の後は文面が分かれる。
下書きの「a1、a3、a12、b1 だけが変わる」は担当の例の範囲では正しいが、変わる形の集合の記述としては足りない。
P[V56-2] の根拠「経路は `find_alias` の外にある」も、`@ M.T` だけに当てはまる。

2. cram の前書き「module の外からエフェクト位置に書くと、pub の有無によらず、Type エイリアスとして拒否する。pub でなくても可視性の誤りにはならない」は言い過ぎである。
反例が 2 つある。
修飾して `@ P.P` と書くと(a7)、試作の後も可視性の誤りになる。
別ファイルから import した module の非 pub の Type エイリアスのコンパニオンは(`ex/imp2/a.kel`、`b.kel`)、HEAD と試作のどちらも「未知のエフェクト: P」になる。
前書きは「同じファイルの中で、module 名だけで書くと」に限るべきである。

3. b1 を改善の例に数えるのは誤解を招く。
b1 の `E` は利用者の型パラメータで、正しい診断は V57 の「行変数 E は extends の位置にのみ書けます」である。
試作の案内に従って module E のエイリアスに `: EffectRow` を付け(c1、可視性の誤り)、pub を付けると(c2)、HEAD でも試作でも受理され、`{E, Console}` の `E` は型パラメータではなく module のエイリアス `{Print}` を指す。

```
$ cat c2.kel
module E {
  pub type E: EffectRow = {Print}
}
let f[E](x: Int32): Int32 @ {E, Console} = x
HEAD と試作: f : (Int32) => Int32 @ {Print, Console}
```

同じ宣言で `@ E` と書くと型パラメータを指す(c6 の `f : (Int32) => Int32`)。
この非対称は HEAD からあり、本項の退行ではないが、b1 の「どの段の案内も実行できる」は、利用者の意図とは別の意味で受理される終点に導く。
V57 と突き合わせる観測として記録すべきである。
