## 裏取りした主張

`lib/lexer.ml` の `Lex_error` の文面は 8 種で、すべて英語である(324、326、372、381、399、406、416、492、552、553 行)。
lexer.ml のほかに `Lex_error` を投げる箇所は無い(`grep -rn Lex_error lib bin`)。
driver.ml の行(770、771、774、1151〜1153、1163)、§ 番号(lexer §2.5〜§2.7、driver §16.6b、§16.8)、台帳の行(261010-2-m53.md:713)は写しと一致する。
英語の文面を照合する箇所は driver.ml 770 行の 1 か所だけである。
`unexpected end of unicode escape`、`unterminated block comment`、`stray '#!'` はどの cram にも現れない。
LangSpec の 1621 行(終了状態 2)と 1782 行(診断の文面は評価の結果に含めない)は下書きのとおりである。

## 誤り

LangSpec に §0 は無い。
26 行と 29 行は §2.1(ソース形式)、295 行は §4.4(文字列)である。
下書きの「§0(26、29 行)と §2(295 行)」は「§2.1(26、29 行)と §4.4(295 行)」に直す。

V121 との重なりの記述が誤りである。
V121 の差分も lib/lexer.ml を変える。
冒頭の記事の 54〜58 行の段落を書き換え、552〜553 行の直後に `read_raw_token` の包みを足し、そこで `Lex_error ("不正な UTF-8 バイト列です", ...)` を投げる。
V123 の差分を当てた写しに V121.patch を --dry-run で当てると、lexer.ml の hunk 1(51 行)が失敗し、hunk 3 は fuzz 2 で当たる。
「行が隣り合うだけで衝突しない」は成り立たない。
また V121 の後では lexer.ml の文面は 9 種になる(9 種目は日本語)。

driver.ml 769 行(`try_parse` の `パースエラー`)は V115、V118、X-F5b の 3 つが書き換える。
V123 を当てた写しに 3 つの差分をそれぞれ当てると、どれも driver.ml の try_parse の hunk が失敗する(V115 は 766 行、V118 は 771 行、X-F5b は 774 行の hunk)。
下書きは V118 を可能性として挙げるだけで、V115 の driver.ml と X-F5b に触れていない。

件数の言い方：要約の「tokens.t の 14 ブロック」は、課題の数え方ではコマンド 14、ブロック 5(err、bom、bom2、c0〜wj、surr〜badesc)である。
下書き (5) の「期待値が変わる既存のブロック(17 行)」も、コマンド 17、ブロック 7(tokens.t 5、run_exit.t 1、errloc.t 1)と書く。
