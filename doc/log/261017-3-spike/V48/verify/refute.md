## 退行の探索

境界の形を 13 本書いた(`verify/ex/`、出力は `x.head.txt` と `x.proto.txt`、差分は `x.diff`)。
エイリアス、module の中と修飾、pub、import、型パラメータ、ガード、入れ子のハンドラ、構造的ヴァリアント、リテラルを含むタプル、操作節、インスタンスのメソッド、`--prelude` の差し替え、REPL である。
変わったのは、値の無い型を受ける行が 1 つのエントリの警告が消える場合だけだった。
値のある型(`Opt2[E]` の `Sm(x)`、`M.A` の `MkA(n)`、`Option[Never]` のガード付きの節、`#A(Never) | #B`、`Option[Absurd]`、`--prelude` で差し替えた `Option`)の警告はすべて残った(実測)。
警告の消えたエントリは、どれも受ける型に値が無いので、実行時の照合失敗を見逃す形ではない(ソースから導いた性質)。

一方、型検査の時間の退行が 1 つある。
`inhabited` は探索の結果を覚えないので、コンストラクタの引数が値の無い型に行き着く形で、データ型の段数に対して指数の時間がかかる(ソースから導いた性質、実測で確認)。

```
newtype Empt
newtype T0 = A0(T1) | B0(T1)
...
newtype T25 = A25(Empt) | B25(Empt)
let f(t: T0): Int32 = t match { case u => 1 }
echo("ok")
```

段数 n に対する所要時間(秒、HEAD / 試作)は、16 段で 0.00 / 0.02、20 段で 0.00 / 0.38、24 段で 0.00 / 6.59、26 段で 0.00 / 28.57 である(実測)。
どちらも `ok` を出して終了状態 0 で、出力は同じである。
2 段ごとにおよそ 4 倍になる。
HEAD の `useful` は、変数のパターンで `default_matrix` に降りるので、この形で型を開かない。
