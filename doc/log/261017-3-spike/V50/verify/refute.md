## 5. 仕様の文面の案

(4) の 1 文目「修飾せずに書いた型パラメータの名前は、`@` の直後でも行の要素でも型パラメータを指し、同じ名前のエフェクトやエフェクト行の別名を指さない」は、引数つきの形で実測と食い違う。
型パラメータ `Heap` と `@ Heap[h]`、`@ {Heap[h]}` は、HEAD でも試作でもエフェクト `Heap` を指す(a15。`f : (Int32) => Int32 @ {Heap[h]}`)。
型パラメータ `Print` と `@ Print[Int32]`、`@ {Print[Int32]}` も、両方でエフェクト `Print` を指して受理される(b05、b09。引数の個数を照合しない点は本項の外)。
1 文目を「引数なしで書いた」に限り、引数つきの名前は同名のエフェクトがあればそれを指すことを書くか、少なくとも「エフェクトを指さない」を引数なしに限る必要がある。

§18 との関係:
- §18.1(束縛名の付け替え)の条件 2 と 3 は捕獲を除くので、試作でも矛盾しない。
  試作では、エイリアス `W` を行の要素に書いた式の有効範囲で型パラメータを `W` に付け替えることが、条件 2 に触れる形になる(HEAD では触れない)。
- §18.4(型エイリアスへの置換)は、置き換えたエイリアスの名前が型パラメータに覆われる場合を除外していない。
  型の位置では HEAD から同じ事情があり、試作で行の要素も同じになるだけなので矛盾ではないが、新しい段落と合わせて読むと除外が暗黙である。
- §15.5 の終了状態は、拒否が型エラー(終了コード 1)なので変わらない。REPL では拒否しても終了コード 0 のまま(r15)。
- 付録 A の文法は変わらない。

§15.1:1479-1482 は、エフェクト行を書く位置で module の EffectRow エイリアスが標準環境のエフェクトとトップレベルの別名より優先すると書く。
新しい段落はその上に型パラメータを置くことになるので、§15.1 からの参照か、段落の中で §15.1 の別名も覆うことを書くと読み合わせやすい(矛盾ではない)。

## 6. 判断事項の推奨案

P[V50-1] の推奨は支持する。
ただし代案の一覧に、エイリアスを `@ W` と `@ {W}` の両方で先に引く案(略記の規則は満たし、波括弧の中の受理は保つが、`@ W` の解決が変わり、型の位置の内側優先とエフェクト名の扱い(a07、a08)とは逆になる)が無い。
推奨の根拠 3「エフェクト名では HEAD でも両方の形で型パラメータが先に当たる」は、引数なしの形に限られる。引数つきではエフェクト名が型パラメータより先に当たる(a15)。

P[V50-2] の推奨(案内を添えない)は結論としては受け入れられるが、根拠の「V57 が外したい依存が戻る」は誤りである。
V57 は `find_row_alias` の条件を自分で足した項目で、その依存を外す意図は V57 の final.md に書かれていない(`items/V57/final.md:48`、`:110`)。依存を外すのは本項の試作である。
また、本項は受理していたプログラムを拒否に変えるので、移行の手がかりとしての案内の価値は、型の位置(振る舞いが変わらない)より高い。
r09、r13 のようにカインドが `Type` の型パラメータにも「行変数 W」と出るが、これは別名の無い形でも HEAD から同じである(b11 `let f[W](x: W): W @ {W} = x` は HEAD で 1:21 同じ文面)ので、本項の判断の根拠にはならない。
