## 5. 注記の文面の誤り

注記は「A のスコープの外で作られた、型の決まっていない変数」と述べるが、A のスコープの中で作られた変数が外側の変数の型と共有されてレベルが下がり、そこに A が入る形がある。

```
let idf[A](x: A): A = x
let bad = fn(y) => {
  let f[A](x: A): A = {
    let r = idf(fn(q) => q)
    let _ = y(r)
    r(x)
  }
  f
}
```

試作の出力(`ex/r19_shared.kel`):

```
! r19_shared.kel:6:7: 型エラー: スコープ付きの型 ς1 がスコープの外に漏れています(ς1 は型パラメータ A です。A のスコープの外で作られた、型の決まっていない変数(注釈の無い引数や、一般化されない束縛の型など)に A を入れようとしています)
```

A が入る変数は `q` の型で、`f` の本体の中で作られ、`y(r)` で `y` の型と共有された。
「A のスコープの外で作られた」は事実に合わない。
これは台帳の要約が名指しを求めた原因(外側の単相の型変数との共有)そのものである。
下書き (3) の「スコープの外で作られた、は両方を含む」は誤りで、`unify.ml` に足す記事の「その変数が型パラメータのスコープの外で作られ」も同じく誤りである。
`ex/r20_shared_list.kel`(`let xs = idf(Nil)` を `y` に渡してから `Cons(x, xs)`)も同じ形である。

文面は、作られた場所ではなく共有で述べる案がよい。
例: 「ς1 は型パラメータ A です。A のスコープの外の型とつながった、型の決まっていない変数(注釈の無い引数の型や、一般化されない束縛の型など)に A を入れようとしています」。
cram に r19 の形を 1 ブロック足すとよい。
