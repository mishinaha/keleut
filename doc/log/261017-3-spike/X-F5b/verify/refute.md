## 4. 誤判定(新しく見つけた形)

D[X-F5b-2] の (ii) は、詰まったトークンが予約語や `true` でも数値を名指す。

```
let a = 1.2.match { case _ => 1 }
HEAD: f1.kel:1:13: パースエラー(付近のトークンを確認してください)
試作: f1.kel:1:9: パースエラー: 数値リテラル 1.2 の直後に . が続いています(数値リテラルの綴りを確認してください)
```

`1.0.if`、`1.2.true`、`1.2.with` も同じである(`verify/ex/f.out`、`verify/ex/g.out`)。
浮動小数の後ろの `.` はフィールド選択として文法に合う(`1.2.foo` と `1.2._0` は構文を通り型エラーになる)。
したがって (ii) で詰まるのは、`.` の後ろが数値か予約語のときだけで、数値の綴り間違いは前者だけである。
(ii) を詰まったトークンが `NUMBER` の場合に限れば、`1.2.3`、`1.5e3.2`、`1.2.3.4`、`1..3` の判定は変わらず、予約語の形だけが従来の文面に戻る。

(i) の予約語の形(`1else`、`1in`、`1.then`、`(1else)`)は下書きの 6 節が認めたリスクの範囲である。
ただし 6 節は `1..3`(results.edge.txt で `1. の直後に .`)にも (ii) の予約語の形にも触れていない。
