仕様の「構文エラー」は menhir の段の拒否も含む。

#### (3) 判断と確定

D[V115-1]: menhir の `Parser'.Error` の診断を `構文エラー: 付近のトークンを確認してください` にする。
`parse_unit_with` と `try_parse` の 2 か所を同じ文面にする。

判断事項 P[V115-1]: 文面の形をどうするか。

- 推奨案: `構文エラー: 付近のトークンを確認してください`(ほかの構文エラーと同じ `構文エラー: <本文>` の形)。
- 代案 A: `構文エラー(付近のトークンを確認してください)`(括弧の形を残し、語だけ替える)。
- 代案 B: 語をすべて「パースエラー」にそろえ、§15.5 の側を「パースエラー」に改める。
- 推奨の根拠: 処理系の構文エラーの診断はすべて `<位置>: 構文エラー: ` で始まるようになり、利用者と cram が 1 つの接頭辞で見分けられる。
  V60 と V88 は一般の構文エラーに個別の案内を足す項目で、その案内も同じ `構文エラー: <本文>` の形に入る。
  代案 B は仕様の語(字句エラー、構文エラー、型エラー、実行時エラー)の並びを崩す。
  さらに LangSpec 397 行は menhir の段で拒否する `(g(a)) { ... }` を構文エラーと呼んでおり、仕様の語はすでに menhir の段の拒否を含む。
  代案 B はこの文面とも合わない。

推奨案で確定する。
