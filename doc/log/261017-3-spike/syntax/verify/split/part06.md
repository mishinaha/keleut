- **D[V88-1](方法)**:A を採る。パーサを `--table` で生成し、`lib/driver.ml` に増分 API の駆動 `parse_program` を置く。`parse_unit_with` と `try_parse` はこれを呼ぶ。詰まったとき、その直前の状態(`InputNeeded` の checkpoint)が手元に残るので、次の条件をすべて満たせば `Syntax_error_at (予約語の位置, 文面)` を投げ、満たさなければ `Parser'.Error` を投げる。
  1. 詰まったトークンが予約語である(`true` と `false` を含む)。
  2. それを同じ綴りの `LOWER_IDENTIFIER` に置き換えると、次の実際のトークンまで読み進められる(`acceptable`)。または、直前が `{blk` で次が `=` か `,` である。
  3. 同じ位置に `(` を置くと、その直後に同じ予約語を置ける形ではない(`true`、`false` には適用しない)。
- **D[V88-2](予約語の表の置き場)**:予約語の判定は `lib/lexer.ml` の新しい §2.13 `reserved_word` が、`show_token` で綴りに戻して `keyword_or_ident` に引き直す形で行う。表を写さないので、予約語を増やしても判定は自動で追随する。
- **D[V88-3](字句解析器の状態)**:条件 2 で次のトークンを読むので、字句解析器の `prev`、`last_sp`、`last_ep` を読む前の値に戻す。汎用の文面の位置と、対話的な実行が続きの行を待つ判定(`prev = Some EOF`)を変えないためである。同じ分野の V118 が足す `before_ep` と `before_cont`、X-F5b が足す `recent` も、`read` が更新するので同じく戻す。分野の合成で、戻さない変種を測った。`let x =` ⏎ `let y = 2` は V118 の位置(1:8 と、括弧の中に 2:1)を失って 2:1 に戻り、`let a = (1else)` は X-F5b の数値の文面を失って汎用の文面に戻った(`doc/log/261017-3-spike/syntax/ex/results.norestore.txt`)。

条件 2 の次のトークンまで見る部分は、予約語を予約語として書いたが位置が違う入力を除くためである。
1 トークンだけで判定した最初の試作では、`late.kel`(宣言の後ろの `from`)、`wth.kel`、`operand.kel`(`1 + if ...`)、`test/repl.t` の 74 行(対話的な実行の入力の 8 行目)の `and` も予約語の文面になった(本文の検討の記録。差分は残していない)。
