#### (4) 仕様側の改訂案

§16 の冒頭(1642 行の `## 16. 標準環境` と 1644 行の `### 16.1. データ型` の間)に足す。

```markdown
本書が本文、`text` のブロック、表で示す標準環境の署名（§12.4、§14.2、§14.3、§16、§17 のメソッド、関数、操作、プリミティブの型）は、次のように読む。

- 署名の先頭の `[h, A]` のような角括弧は、型パラメータを示す説明用の記法であり、型式の構文ではない。型パラメータは使うたびに具体化する。
- 最外の矢印で `@` を省略した署名は、`@ {}` と書いた署名と同じである。`pub let` の注釈と型クラスのメソッドで最外の `@` を省略したとき（§13.2）と同じ読み方である。
- `extern "prim"` で宣言するプリミティブ（§16.4）の署名で最外の `@` を省略したときは、§13.2 の `extern "prim"` の規則に従い、使うたびに新しい行変数になる。
- 最外以外の矢印で省略した `@` は `@ {}` である（§13.2）。

閉じた行を持つ標準環境の関数と型クラスのメソッドは、利用者が宣言した関数と同じく使用時の開き（§13.2）を受ける。
演算子（§12.4）の使用は、対応するメソッドの呼び出しとして開く。
処理系が表示する型（§13.1）では、`@` を省いた矢印の行は行変数を表すので、署名の書き方とは読みが違う。
```

ほかの節には次の 1 文ずつを足す、または置き換える。

#### (6) リスク

- 受理が広がる(演算子): 演算子を本体に持つ無名関数を束縛した一般化しない値が、行の違う文脈から呼べるようになる(bopweak)。仕様どおりの変化である。
- 表示が変わる: 一般化しない束縛の行が閉じ直しで `{}` になる形は、`--type-check` と REPL の応答に ` @ {}` が付く。
