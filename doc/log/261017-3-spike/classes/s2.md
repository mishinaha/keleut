#### (2) 現状(根拠つき)

台帳の要約は「初期化式がエフェクトを起こすと、診断が ς1 の漏れや曖昧性エラーになる」だが、実測では原因はエフェクトではなかった。
例は `doc/log/261017-3-spike/V110/` の `ex/`、`ex2/`、`verify/ex/` にあり、HEAD と最終の試作の全出力は `doc/log/261017-3-spike/V110/results.final.txt` にある。

inam はこの項目の形ではなくなった(実測)。
`test/classes.t` の 105〜115 行の inam は、HEAD で 4:1 の「曖昧な制約: Show を満たす型が決まりません」になる。
初期化式の `show(read_("z"))` の `Show` の制約は実際に決まらないので、この診断は原因を指している。
inam は変えない。

1 つ目の問題は、組み込みのクラスと `@ E` のメソッドで、値でない初期化式の値束縛がエフェクトの有無によらず拒否されることである(実測)。
`ex/b4.kel`(`idf(fn(x) => "foo")`)、`ex/b5.kel`(`{ let n = 1i32; fn(x) => "foo" }`)、`ex/e8.kel`(`{ echoln("init"); fn(x) => "foo" }`)、`ex/c7.kel`(利用者のクラスの `val sz[E]: (A) => Int32 @ E`)は、HEAD でどれも「型クラスのメソッドの実装は純粋でなければなりません … 本体がエフェクトを起こしています。元の報告: スコープ付きの型 ς1 がスコープの外に漏れています」になる。
`verify/ex/r8.kel`(組み込みの `Show` で効果多相の `memo` を初期化式で呼ぶ形)と `r9.kel`(`@ E` のメソッドで同じ形)も同じである。
b4、b5、c7 は何もエフェクトを起こしていない。
原因は次のとおりである(ソースから導いた性質)。
値でない初期化式は一般化しないので、返す無名関数の最外の行は水準 0 の行変数のまま `check_instance_bodies` の `subsume`(`lib/elab.ml` §11.38、4514〜4569 行)に届く。
宣言の行は、組み込みのクラス(HEAD では `lib/decls.ml` §6.12 の `arrow1` / `arrow2` の行変数)と `@ E` と書いたメソッドでは水準 1 の剛定数で、4559 行の `Unify.unify ie se` が `lib/unify.ml` 173 行の脱出検査で落ちる。
利用者のクラスで `@` を省略したメソッドの行は `TRowEmpty`(§11.33)なので落ちない(`ex/u1.kel`、`ex/u2.kel` は HEAD で受理)。
LangSpec §13.2(1151 行)によれば `Show.show` の行も `@ {}` で、b4、b5 は仕様では受理する形である。

2 つ目の問題は、インスタンスの本体の束縛の行に制約が無いことである(ソースと実測)。
`check_instance_bodies`(4488 行)は本体を `elab_binding env 0 (new_row_var 0)`(4576 行。`let rec` は 4581 行)で推論し、その行をどこにも照らさない。
トップレベルは閉じた行 `eff0`(4744 行、4970 行)で推論する。
`ex/u4.kel`(利用者のクラスで初期化式が `perform ask()`)は HEAD で型検査を通り、実行で「未処理のエフェクト操作: Ask.ask」、終了状態 3 になる。
`verify/ex/r4.kel`(`perform print`)も同じく終了状態 3 である。
`ex/u3.kel`(初期化式が `Ref.new(0i32)`)は受理して実行する。
同じ式をトップレベルに書くと拒否される(`ex/t3.kel` は 2:9、`ex/t2.kel` は 5:19)。
LangSpec §15.4(1577 行)はインスタンスの初期化式をトップレベルの初期化に含め、1583 行で評価の規則を §13.7 に委ね、§13.7(1340 行)は行に残せるエフェクトを `Console` と `Blocking` に限る。
u4 はこの規定と食い違う。

3 つ目の問題は、使うたびに評価する初期化式がエフェクトを起こせることである(実測)。
`lib/interp.ml` §14.12 の 1368 行は、前提を持つインスタンスと制約を持つメソッドの実装を、使うたびに初期化式から作る。
`ex2/q7.kel`(`type instance[A: Sz] Sz[Box[_]] { let sz = { echoln("init"); fn(b: Box[A]) => … } }` を `@ {}` と注釈した関数から呼ぶ)は、HEAD で受理し、純粋と注釈した関数の呼び出しの中で `init` を出す。
`ex2/q6.kel` は使うたびに `init` を出し、`ex2/q8.kel`(`Ref.new`)も受理する。
LangSpec §6.4(653〜654 行)は、これらの初期化式を「構文上の値なので、停止し、エフェクトを起こさない」と書くが、HEAD は値でない初期化式を受理する(`ex2/q9.kel` の `idf(…)`、`ex2/q13.kel` の停止しない呼び出し)。
前提つきのインスタンスで `{ let q = 1 / z; fn(b) => "box" }` を受理し、メソッドを使った時点でゼロ除算になる形もある(`doc/log/261017-3-spike/V97/verify/ex/r20_premdiv_user.kel`。HEAD も試作も `a`、`b` の後に実行時エラー、終了状態 3)。
組み込みのクラスの同じ形(`ex2/q1.kel`)は、HEAD では 1 つ目の漏れで偶然に拒否される。
1 つ目だけを直すと q1 は受理され、`init` を 2 回出す(中間の試作で実測)。

#### (3) 判断と確定

直し方は次の 3 つで、どれも `lib/elab.ml` の `check_instance_bodies` の中に収まる。

1. `subsume` で、引数と返り値を合わせた後の実装の最外の行が束縛されていない行変数なら、`TRowEmpty` に決めてから既存の扱いに入る(D[V110-2])。
   空の行は行の最小元で、既存の「実装の行が空なら宣言の行と単一化せずに受理する」に合流する。
2. 本体は HEAD のとおり新しい行変数 ρ の下で推論し、`subsume` の後で ρ のラベルを許す行と照らす(D[V110-1])。
   許す行の外のラベルがあれば、その名前を挙げて拒否する。
   照らした後、ρ の尾部を空の行で閉じる。
   順序は 1 が先である。
   効果多相の関数を初期化式で呼ぶと、その行変数は ρ と返す関数の行に共有され、1 で空の行に決まってから 2 に届く。
3. 許す行は、宣言の実行で 1 回だけ評価する初期化式では `eff0`(トップレベルの行。対話的な実行では `Print` を含む)、前提を持つインスタンスと制約を持つメソッド(`Tree.DMethod` の `mk` が空でない)では空の行にする(D[V110-3])。

判断事項 P[V110-1]: インスタンスの値束縛の初期化式が起こしてよいエフェクトをどう決めるか。
V97 の P[V97-2](初期化式の行)は同じ問いなので、この判断事項に統合する。

- 推奨案: 1 回だけ評価する初期化式はトップレベルの評価と同じ行、使うたびに評価する初期化式は空の行にする(V110 の案)。
- 代案 A: どの初期化式も純粋に限る(空の行)。V97 の試作の D[V97-4] で、V97 の最終稿の推奨だった。
- 代案 B: HEAD のまま制約しない。
- 代案 C: 初期化式を構文上の値に限る。§6.4 の 654 行の現行の文面に実装を合わせる形である。
- 推奨の根拠: 1 回だけ評価する初期化式は §15.4 でトップレベルの初期化と同じ順に評価されるので、トップレベルと同じ行にそろえる。
  使うたびに評価する初期化式は使う側の行の下で走るので、エフェクトを許すと q7 のように純粋と注釈した関数の中でエフェクトが起きる。
  推奨案はこれを空の行で拒否する。
  V97 の最終稿が代案 A を推した理由は「トップレベルの行にすると、前提つきのインスタンスで初期化式の `echoln` が使うたびに起きる」だったが、推奨案は使うたびに評価する初期化式を空の行に限るので、この反論は当たらない。
  代案 A は HEAD が受理して正しく動く u1、u2、`ex/c2.kel`、`ex/c5.kel`(`echoln("init")`)と、V97 の反証者の r1_weakinit(先の使用で行が `Console` に決まった一般化しない束縛を初期化式で呼ぶ形)を拒否に変える。
  代案 B は u4 と q7 を型検査で拒否できない。
  代案 C は HEAD が利用者のクラスで受理する `{ let base = 2 + 3; fn(x) => x + base }`(`doc/log/261017-3-spike/V97/verify/ex/r7_premise.kel`)や r20 を拒否に変えるので、受理の変化がほかの案より大きい。
- 合成の差分は推奨案で作った。
  代案 A を採るときは、`check_init_row` の許す行を前提の有無によらず `TRowEmpty` にする 1 行の変更で済み、`test/instance_init.t` の instinitcon と REPL のブロックの期待値が拒否に変わる。

判断事項 P[V110-2]: 1 つ目の漏れを `subsume` の局所の扱いで直すか、組み込みのスキーマを閉じて直すか。

- 推奨案: 両方を行う。`subsume` で束縛されていない実装の行を空の行に決める変更をこの項目で入れ、組み込みのスキーマは N.1 で閉じる。
- 代案: 組み込みのクラスのメソッドのスキーマを閉じる(N.1)だけにする。
- 推奨の根拠: 代案では c7、r9(利用者の `@ E` のメソッド)が直らない。
  N.1 を入れた後も、`subsume` の変更が要るのは `@ E` のメソッドの形である(合成で c7 は `1` を出す。実測)。

判断事項 P[V110-3]: 初期化式の行の検査をどこで行うか。

- 推奨案: 2 のとおり、推論の後で照らす(位置はメソッドの束縛、例えば u4 は 5:7)。
- 代案 D: 本体を `eff0` の下で推論する(下書きの案。位置は `perform`、u4 は 5:38)。
- 推奨の根拠: 代案 D は効果多相の関数を初期化式で呼ぶ形を、HEAD の受理から拒否に変える(反証者の実測。r2、r6、r10、r11、r12、r16、対話的な実行)。
  呼び出しの行変数が `eff0` と単一化され、返す関数の行が `{Console, Blocking}` に固まるためである。
  推奨案の代償は位置で、`perform` でなく束縛を指す。
  文面がエフェクトの名前とメソッドの名前を挙げるので、原因には届く。

D[V110-1]: インスタンスの本体の束縛は新しい行変数 ρ の下で推論し、`subsume` の後で ρ のラベルを許す行と照らす。許す行の外のラベルがあれば、エフェクトの名前とメソッドの名前を挙げる型エラーにする。照らした後で ρ の尾部を空の行で閉じる。

D[V110-2]: `subsume` で、引数と返り値を合わせた後の実装の最外の行が束縛されていない行変数なら、`TRowEmpty` に決める。

D[V110-3]: 許す行は、1 回だけ評価する初期化式では `eff0`、前提を持つインスタンスと制約を持つメソッドの初期化式では空の行とする。

#### (4) 仕様側の改訂案

LangSpec §12.2 の 958 行「各メソッドの型は、クラス宣言の署名を満たさなければならない。」の後の段落の並び(V136、V132 の段落の後)に、次の段落を足す。
§12.2 の 958 行の後に入るほかの段落との並びと全文は N.z に書く。

```
値束縛で書いたメソッドの初期化式が起こしてよいエフェクトは、宣言の実行で 1 回だけ評価するものではトップレベルの評価と同じであり（§13.7、§15.4）、メソッドを使うたびに評価するもの（§6.4）では無い。
署名の行と照らすのは初期化式の値の関数の行で、初期化式が起こすエフェクトは含まない。
初期化式が起こしてよいエフェクトの外のエフェクトを起こすインスタンスは、型検査で拒否する。
初期化式は構文上の値に限らないので、ゼロ除算などの実行時エラーを起こすことや、停止しないことがある。評価の時点は §6.4 で定める。
```

4 文目は V97 の試作の段階の案から採った(inidiv と inipremdiv の実測)。

§6.4 の 654 行「これらの初期化式は構文上の値なので、停止し、エフェクトを起こさない。」を、次の 2 文に置き換える。

```
制約付きで一般化した値束縛と式文は構文上の値なので、停止し、エフェクトを起こさない。
インスタンスのメソッドの初期化式は構文上の値でなくてもよいが、エフェクトを起こせない（§12.2）。
```

655 行を次に替える(V97 と V110 の案を 1 つにした)。

```
評価の時点の違いが現れるのは、初期化式が穴（`???`）やゼロ除算などで実行時エラーを起こすときや停止しないときに、それが起きるかどうかと、その時点だけである。
```
