#### LangSpec の同じ行を触る項目の調整

§12.2 の 958 行「各メソッドの型は、クラス宣言の署名を満たさなければならない。」の後には、V136、V132、V110 の 3 つの段落を、この順に空行で区切って足す。
仮引数の型の決まり方(V136)、実装が起こせるエフェクトと失敗するメソッド(V132)、値束縛の初期化式(V110)の順で、後の段落が前の段落の規則を前提にする。
V97 の試作の段階の §12.2 の案は、V110 の段落の 4 文目に統合した。
足す全文は次のとおりである。

````markdown
メソッドの仮引数のうち、型注釈のない変数と `_` の型は、クラス宣言の署名の対応する引数の型に決まる。
ただし、署名の引数の型のうちメソッド自身の型パラメータの位置は、本体から推論してから署名と照らし合わせる。
値束縛で書いたメソッドの初期化式が無名関数で、その仮引数がすべて型注釈のない変数か `_` であるときも同じである。
仮引数の数が署名と違うメソッドと、それ以外の仮引数の型は、本体から推論してから署名と照らし合わせる。
返り値の型と最外の行は、署名から決めない。
したがって、本体の数値リテラルの型（§4.2）と網羅性と冗長性の検査（§11.2）は、仮引数に署名の型を注釈した関数と同じ型に基づく。
たとえば署名の引数が `Never` のとき、`match {}` は網羅的であり、`case _` の節には一致する値がないという警告が出る。

インスタンスの実装が起こせるエフェクトは、クラスの宣言のメソッドの最外の行にあるものに限る（§13.2。値束縛で書いたメソッドの初期化式が起こすエフェクトは、この節の後の段落で定める）。
最外の `@` を省略したメソッドの実装は純粋でなければならないので、再開しない操作（§13.1）で失敗することもできない。
標準環境のクラス（`Eq` や `Show` など）のメソッドも最外の行が `@ {}` なので（§16 の冒頭）、そのメソッドの実装はエフェクトを起こせない。
宣言の行が `@ E` のように行変数だけのときは、実装はどの `E` でも通らなければならないので、自分の本体で `Fail` のような特定のエフェクトを起こせない。
引数の関数から届く `E` のエフェクトを通すことはできる（§12.3 の `Functor` の例）。
インスタンスごとに別のエフェクトを足す手段はない。
失敗するメソッドは、次のように宣言の行に失敗のエフェクトを書く。

```keleut
effect Fail = { throw: (String) => Never }

type class Parse[A] {
  val parse: (String) => A @ Fail
}

type instance Parse[Int32] {
  let parse(s) = if s == "0" then 0 else perform throw("not a digit: " + s)
}

let parse_or[A: Parse](s: String, d: A): A = parse(s) handle { case throw(_) => d }
```

失敗しないインスタンスは、同じ宣言の下で純粋な実装として書ける。
呼ぶ側のほかのエフェクトも通すには、`val parse[E]: (String) => A @ {Fail extends E}` のように宣言の行を行変数で開く。
最外の行が純粋なメソッドで失敗を扱うには、`Option[A]` のような値で返すか、`val mk: (A) => (() => Int32 @ Fail)` のように返り値の関数の行に失敗のエフェクトを書くか、実装の中のハンドラで捕まえる。

値束縛で書いたメソッドの初期化式が起こしてよいエフェクトは、宣言の実行で 1 回だけ評価するものではトップレベルの評価と同じであり（§13.7、§15.4）、メソッドを使うたびに評価するもの（§6.4）では無い。
署名の行と照らすのは初期化式の値の関数の行で、初期化式が起こすエフェクトは含まない。
初期化式が起こしてよいエフェクトの外のエフェクトを起こすインスタンスは、型検査で拒否する。
初期化式は構文上の値に限らないので、ゼロ除算などの実行時エラーを起こすことや、停止しないことがある。評価の時点は §6.4 で定める。
````
