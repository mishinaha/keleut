## 推奨案への意見

推奨案(所属を先に)の採用に反対はしない。
ただし推奨の根拠の 1 つ「所属違反のほうが直す場所が読める」には反例がある。
操作名の書き誤り(`case File.wirte(s)`、`ex/r9_typo.kel`)では、HEAD は「File の write が漏れています」と正しい名前を示し、試作は「操作 wirte はエフェクト File に属しません」と書いた名前だけを示す(実測、`typo.out`)。
どちらの順でも、片方の情報が隠れる。
代案 B を退ける根拠「ほかの型エラーが 1 件ずつ報告される作りと揃わない」も正確ではない。
B は 1 件の診断の文面に補足を添える形にでき(例: 所属違反の文面の後に、対象で漏れている操作を括弧で添える)、報告の件数は 1 件のままである。
B を退けるなら、根拠は文面の新設と cram の文面の増加に置くのがよい。
