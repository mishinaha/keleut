## 見つけた問題

1. 剛定数の名前が文の中で食い違う(d1)。
   エラーの型と出どころの型を別々の show で表示するので、名前の振り直しが 2 回起きる。
   newtype P2[A, B] に [A: Eq, B: Eq] Eq の前提を付け、let f[A: Eq, B](x: P2[A, B], y: P2[A, B]): Boolean = x == y とすると、試作は
   「型パラメータ ς1 は Eq のインスタンスではありません。P2[ς1, ς2] が Eq であるための前提として要求されました。[A: Eq] のように制約を書いてください」
   と出す。
   前半の ς1 は B で、後半の ς1 は A である。
   HEAD は前半だけなので食い違いが無い。
   show.ml の show_all を 1 回で呼ぶ表示(show2 と同じ作り)にする必要がある。

2. 出どころが付くかどうかが let の一般化で変わる(d6、d8)。
   let k = fn(x) => Cons(x, Nil) == Nil の後で k(o) とすると、x の変数は一般化されて表の鍵が切れ、試作でも文が付かない。
   同じ比較を fn の中で直接 x と Opaque に結ぶ形(d2)では付く。
   下書きの (7) の「未定変数を経る形で出どころが付き」はこの限定を書いていない。

3. 位置の式と出どころが別の式になる例が、p18 より強い形である(d2)。
   fn(x) => { let a = Cons(x, Nil) == Nil; x == o } では、診断の位置は 5:5 の x == o(Opaque の直接の比較)で、文は List[Opaque] の前提だと言う。
   (6) のリスクは p18(位置の式も List[List[Opaque]] の比較)だけを挙げている。

4. 出どころの型に、束縛していない未定変数が _A の形で残る(d3)。
   (6) の「内部の形」に pr19 と ς1 しか挙げていない。
