## 誤った添え書き(実測)

pre と本体の単一化で落ちたときの「f の本体が、型パラメータを持つ g を参照しています」は、前にある束縛が g を参照しただけで付く。
その参照が g の型パラメータを決めたかどうかを見ていない。
g 自身の多相再帰が原因の形で、原因でない f を名指しする。

ex/self2.kel:

    let rec f(n: Int32): Int32 = { let k = g; n }
    and g[B](y: B): Int32 = g(1i32)
    echoln(show(f(1i32)))

HEAD: `! self2.kel:2:5: 型エラー: スコープ付きの型が一致しません: Int32 と ς1` [1]
試作: 同じ報告の後ろに `(再帰群の中で、前にある束縛から後ろにある束縛への参照は単相です。f の本体が、型パラメータを持つ g を参照しています。前にある束縛の本体が後ろの束縛の型パラメータを何かの型に決める形は、型検査に通りません。§6.3)` [1]

g だけの群(ex/self1.kel)も、2 つを逆順にした群(ex/self3.kel)も、HEAD と試作の両方で同じく `Int32 と ς1` で落ちる。
f の参照は原因でなく、逆順にしても通らない。
REPL でも同じ添え書きが出る(ex/repl.in の 5 行目)。

## 仕様との関係

LangSpec は診断の文面を規定しないので、§15.5 の終了状態(1 のまま)、§18、付録 A と矛盾しない。
添える文面の末尾の §6.3 は、2 つの型パラメータの形を書いている。
具体的な型を渡す形(conc2、genbad)を書くのは §18.2 の括弧の中(1824 行)で、§6.3 は「後ろの束縛の型パラメータは具体化されない」とだけ書く。
具体的な型の形に添えるなら、§6.3 と §18.2 の両方を挙げるほうが文面と仕様が対応する。
