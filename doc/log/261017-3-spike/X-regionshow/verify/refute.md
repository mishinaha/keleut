## 3. 退行の探索

`verify/ex/` に 15 本ほどを書いて両方で走らせた。
受理と拒否、終了コード、実行の出力が変わる形は見つからなかった。
変わったのは、リージョンの位置に現れる変数の表示名だけである。

- エイリアス経由(`type R[k] = Ref[k, Int32]`、`type HE[E]: EffectRow = {Heap[E]}`): `h` になる。
- module の中の pub 束縛と、それを外で束縛し直した値(`p5.kel`): `M.g` も `h` も `h` になる。
- 制約つきのリージョン変数(`p6.kel`): `[A: Show] (Ref[A, Int32], A) => String` が `[h: Show] (Ref[h, Int32], h) => String` になる。§9.7 の前置も新しい名前に揃う。
- REPL(`repl.in`): 弱い変数は `_h` になり、値の表示は変わらない。
- `--prelude` に空のファイルを渡した形(`q12.kel`): `h` になる。
- ガードつきの match の中の `Ref.new`(`q13.kel`): 診断の文面と位置は変わらない。
- 剛定数が絡む診断(`q7.kel`、`q8.kel`、`q9.kel`): `ς1`、`ς2` のまま変わらない。
- 実行(`q6.kel`): 出力 `2`、終了コード 0 で同じ。

下書きのリスク節に無い形(実測):
利用者の newtype がリージョンを包む形では、同じ型パラメータが署名ごとに違う名前で出る。

```
newtype Box[k] = Box(Ref[k, Int32])
let unbox[k](b: Box[k]): Ref[k, Int32] = b match { case Box(r) => r }
let size[k](b: Box[k]): Int32 = 0
```

試作では `unbox : (Box[h]) => Ref[h, Int32]`、`size : (Box[A]) => Int32` と出る(HEAD はどちらも `A`)。
リージョンかどうかを 1 回の印字に現れる位置で決めるので、`Ref` や `Heap` が同じ印字に現れないとリージョンの名前にならない。
受理は変わらないが、リスク節に書き、P[X-regionshow-3] の比較に入れる。

## 4. 仕様との照合

§18 の冒頭(LangSpec:1782)は「処理系が表示する型、診断、警告の文面は、評価の結果に含めない」と定めるので、表示名の変更は保存する性質と矛盾しない。
§18.5 の対話的な実行の表示は、型だけから決まる名付けなので、挟まった入力に左右されない。
§15.5 の終了状態と付録 A の文法には触れない。
仕様の文面を変えないという判断は妥当である。
ただし、下書き 4 節の「LangSpec は型変数の表示名(`A`、`_A`、`ς1`、`R1`)を定めておらず」は、LangSpec:1120 が `@ {Print extends R1}` を例として書いているので、「例として `R1` を示すだけで、名付けの規則は定めていない」と書くほうが正確である。

## 5. 判断事項について

P[X-regionshow-1] と P[X-regionshow-3] の推奨には異論が無い。
P[X-regionshow-3] の比較には、3 節の `Box[A]` と `Box[h]` の不揃いを、表示だけで直す案の欠点として加える。
カインドで選ぶ案(V21)なら、`size` も `Box[h]` と出る(推測。V21 の設計次第である)。

P[X-regionshow-2] の推奨の根拠の 1 つは誤りである。
「`R1` と同じく番号で何個目かが読める」とあるが、`pick` の添字は通し番号ではない。
`h` が 1 個目、`h1` が 2 個目なので、`h1` の 1 は個数と 1 ずれる(`two : (Ref[h, Int32], Ref[h1, Int32])`、試作の実測)。
`R1` は 1 個目の行変数である。
推奨案そのもの(仕様の綴り `h` と一致)は保てるので、根拠からこの文を外す。
見落とされた代案として、`h1, h2…` と 1 から番号を振る案がある(`R1`、`ς1` と揃うが、1 個だけのときに仕様の `h` と一致しない)。

## 6. ほかの項目との重なり

- X-effsuffix: 同じ `show.ml` を触る。期待値の重なりは `@ {Heap[h]}` の行だけでなく、`@` の無い `kinds.t:845` の `g : (Ref[A, Int32]) => Int32` と、`@ {}` の `visibility.t:498` も、空行と行変数の区別を変えると動きうる。

- X-premise、X-perform: 診断の文面に型を埋めるので、そこにリージョン変数が出れば `h` になる。期待値の順序に注意する。
