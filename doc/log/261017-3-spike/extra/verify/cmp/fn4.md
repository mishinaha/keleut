#### (3) 判断と確定

判断事項 P[V49-1]: 台帳の形が消えたことを受けて、V49 をどう扱うか。
- 推奨案: 同じ文言と同じ欠陥が残る形(型パラメータの剛定数の脱出)に対象を測り直し、直す。
- 代案: 台帳の形は HEAD で再現しないので「直さない(解消済み)」として閉じ、残る形を新しい台帳に載せる。
- 推奨の根拠: 台帳の要約の欠陥は「原因(外側の単相の型変数との共有)を名指ししない」ことで、残る形は同じ原因で同じ文言を出す。直す費用は S で、既存の期待値は 1 行しか動かない(試作で実測)。

判断事項 P[V49-2]: どの剛定数に原因を添えるか。
- 推奨案: `make_rigids` が作る剛定数だけに添える。これは束縛と再帰群と前方参照の署名の型パラメータに加えて、インスタンスの頭、型エイリアスの引数、extern の型パラメータを含む(7 か所の呼び出しのすべて)。`run` のヒープとインスタンス検査の skolem の報告は変えない。
- 代案: `run` のヒープにも「ς1 は run h のリージョンです」を添える。
- 推奨の根拠: リージョンの文面は V122、X-D74、X-regionshow が触り、`test/region.t`、`typecheck_m6.t`、`repl.t`、`verify_fixes.t` の vr など 6 か所以上の期待値が動く。`run` の脱出は §14.1 が定める規則そのもので、利用者はどの `run` かを位置から読める。

判断事項 P[V49-3]: 報告の形。
- 推奨案: 元の文言をそのまま残し、括弧で事実を後ろに添える(`ς1` の表示は変えない)。
- 代案: `ς1` の代わりに `A` を表示する(V122 の代案 1 と同じ、表記の変更)。
- 推奨の根拠: 元の文言の部分文字列「スコープ付きの型」と「がスコープの外に漏れています」は、`row_failure`(`lib/elab.ml` 276 行)と V44 の `escape_failure` が見る。前に置く文を変えなければ、それらの判定は変わらない。表記の変更は V122 が規模 L として退けた。

D[V49-1]: `make_rigids` は、作った剛定数の識別子と型パラメータの名前を `Unify.rigid_tparams` に登録する。
D[V49-2]: `occurs_adjust` の脱出の報告は、剛定数が登録されていれば、次の文面を後ろに添える(実測の文面):

```
スコープ付きの型 ς1 がスコープの外に漏れています(ς1 は型パラメータ A です。A のスコープの外の型と共有された、型の決まっていない変数(注釈の無い引数の型や、一般化されない束縛の型など)に A を入れようとしています)
```

注記は、変数が作られた場所ではなく、外側の型との共有を述べる。
剛定数より浅いレベルの変数は、型パラメータのスコープの外で作られたか、スコープの中で作られて外側の変数と単一化され、レベルが下がった変数である(ソースを読んで導いた性質。§8.3 のレベル調整)。
どちらも外側の型と共有されている。
後者の形は実測で確かめた(`verify/ex/r19_shared.kel`。`f[A]` の中の `fn(q) => q` の `q` の型が `y(r)` で `y` の引数の型と共有され、`r(x)` で落ちる)。
「など」を付けるのは、再帰群の中の参照(V111 の nestouter)やインスタンスの頭の型パラメータでも同じ報告になるからである。
