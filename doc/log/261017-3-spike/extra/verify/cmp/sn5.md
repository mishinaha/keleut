#### (2) 現状(根拠つき)

規範は `doc/sample.kel:515` の「各操作には、ガードがなく、どんな引数にも一致する節が 1 つ以上要る(一致しなかった操作を外側のハンドラへ回す規則はない)」である。

文言は 2615-2617 行で組み立てる。
「(ガードや絞り込みパターンだけの節は v0 では後送りできません)」は、後送り(外側のハンドラへ回すこと)が将来の版で入るように読める。
規範は後送りの規則を持たないので、言い回しが合わない(台帳の本体)。

```
! guard.kel:2:9: 型エラー: 操作 ask の節が取りこぼします(ガードや絞り込みパターンだけの節は v0 では後送りできません)。変数パターンでガードの無い case ask(...) を最後に置いてください
```

実測から、言い回しのほかに 2 点を読み取れる。
主文の「取りこぼします」は §13.4 の語ではない。
案内の「変数パターンでガードの無い case ask(...)」は、引数の無い操作(`zero.kel`)では変数パターンを書く場所が無く、案内のとおりには書けない。

#### (3) 判断と確定

判断事項 P[V53-1]: 主文を何で書くか。
推奨案: §13.4 の 1237 行の語で「操作 ask には、ガードがなく、どんな引数にも一致する節がありません」とする。
代案: 「操作 ask の節が取りこぼします」を残し、括弧の中だけを変える。
推奨の根拠: 欠けている条件を仕様と同じ語で名指しすると、利用者が §13.4 の該当の文を引ける。
「取りこぼす」は仕様にも規範にも無い語である。

判断事項 P[V53-2]: 括弧の中の理由をどうするか。
推奨案: 「(どの節にも一致しなかった操作を外側のハンドラへ回す規則はありません)」とする。
語は `doc/sample.kel:515` の「一致しなかった操作を外側のハンドラへ回す規則はない」と §13.4 の 1243 行の「どの節にも一致しなかった操作を外側のハンドラへ自動で回す規則はない」から取る(1243 行の「自動で」は落とす)。
代案 1: 括弧ごと消す。
代案 2: 「(どの節にも一致しなかった操作は外側のハンドラへ回りません)」と振る舞いで書く。
推奨の根拠: 一致しない操作が外側のハンドラへ回る言語(OCaml 5 の effect handler では、処理しない effect は外側へ回る)を知る利用者は、部分的な節だけのハンドラを書きうる(推測)。理由を残すと、なぜ拒否されたかがわかる。
規範と仕様の文と同じ語にすると、将来の版で入るという読みが生じない。
代案 2 は、型検査で拒否したプログラムの実行時の振る舞いを述べることになり、意味がずれる。

判断事項 P[V53-3]: 直し方の案内をどうするか。
推奨案: 操作の引数の個数に合わせて `_` を並べ、「ガードの無い case ask(_) を最後に置いてください」とする(引数が無ければ `case ask()`、2 引数なら `case pair(_, _)`)。
代案: 「変数パターンでガードの無い case ask(...) を最後に置いてください」を残す。
推奨の根拠: 案内した節は §13.4 の 1239 行の「`_`」の形で、そのまま書けば条件を満たす(`two_fixed.kel` で受理を実測)。
引数の無い操作でも書ける形になる。

実装の選び方として、引数の個数をどこから読むかに 2 案がある。
案 a(採る): その操作の最初の節の引数の数から読む。
案 b: 宣言した操作のスキーマ(`target_info.Decls.ef_ops`)から読む。
総和性の検査の前に引数の個数の検査があるので、出力は同じになる(ソースを読んで導いた性質)。
案 b は検査の順への依存と `[] -> 0` の分岐が要らないが、スキーマを具体化して `TArrow` と `TRecord` を分解するコードを `op_clauses` の組み立てと別にもう 1 回書くことになる。
案 a は節の組がすでに手元にあり、差分が小さい。
振る舞いは同じなので、差分の小さい案 a を採り、依存は行コメントに書く。
修飾した節を持つハンドラでも、修飾していない `case ask(_)` は同じエフェクトの操作として読まれる(§13.4 の 1229 行。`qual_fixed.kel` で受理を実測)。

D[V53-1]: 総和性の診断の文面を次に確定する(`<op>` は操作名、`<args>` は引数の個数だけの `_` を `, ` でつないだもの)。

```
操作 <op> には、ガードがなく、どんな引数にも一致する節がありません(どの節にも一致しなかった操作を外側のハンドラへ回す規則はありません)。ガードの無い case <op>(<args>) を最後に置いてください
```

拒否の条件、位置、終了コードは変えない。
引数の個数は、その操作の最初の節の引数の数から読む。
総和性の検査の前に、網羅の検査(どの操作にも節があること。HEAD の `lib/elab.ml:2558-2562`)と引数の個数の検査(`:2584-2587`)を通っているので、節は 1 つ以上あり、個数は宣言と一致する(ソースを読んで導いた性質。2 引数の操作に 1 引数の節を書くと個数の検査で止まることを反証者が `verify/ex/r7_arity.kel` で実測)。
