## 4. 退行

D[V110-1](本体の束縛を `eff0` の下で推論する)で、HEAD が受理し正しく実行するプログラムを試作が拒否する形が見つかった。
形は、効果多相の関数を初期化式で呼び、その返す関数の行がその関数の行変数 `E` を持つものである。
呼び出しの `E` が周囲の行 `eff0` と単一化されて `{Console, Blocking}` に固まり、返る関数の行も同じになる。
その行は空でないので、`subsume` の純粋性の検査で落ちる。
HEAD では周囲の行が新しい行変数なので、`subsume` がそれを空の行に決めて受理していた(ソースから導いた性質。下の代案の試作で裏づけた)。

r6.kel(verify/ex/r6.kel):

```
type class Sz[A] { val sz: (A) => Int32 }
newtype Foo = Foo
let memo[E](f: (Foo) => Int32 @ E): (Foo) => Int32 @ E = { let v = f(Foo); fn(x) => v }
type instance Sz[Foo] {
  let sz = memo(fn(x) => 7i32)
}
echoln(show(sz(Foo)))
```

HEAD は `7` を出して終了状態 0 である。
試作は「r6.kel:5:7: 型エラー: 型クラスのメソッドの実装は純粋でなければなりません(…)。インスタンスメソッド sz の本体がエフェクトを起こしています。元の報告: ラベル Console がありません(行は閉じています)」で終了状態 1 である。
この文面は何もエフェクトを起こしていない実装を「エフェクトを起こしています」と言うので、V110 の問題(原因を名指ししない)を別の形で作り直す。

同じ類の形として次も試作で拒否に変わった(どれも HEAD は受理して正しく出力する)。

- r2.kel: `mkf[E](k: () => Unit @ E): (Foo) => Int32 @ E = { k(); fn(x) => 1i32 }` を `let sz = mkf(fn() => ())` で使う。HEAD は `1`。
- r10.kel: r6 の束縛に注釈 `(Foo) => Int32` を書く。HEAD は `7`。
- r12.kel: 初期化式の中の局所束縛 `let m = memo(fn(x) => 3i32)` を、返す無名関数の中で呼ぶ。HEAD は `3`。
- r11.kel: r6 のクラスとインスタンスを imp/lib.kel に置いて import する。HEAD は `9`、試作は imp/lib.kel:5:7 で同じ拒否。
- r16.kel: インスタンスを `module M { … }` の中に置く。HEAD は `5`、試作は 6:9 で同じ拒否。
- 対話的な実行(verify/ex/repl1.txt の 6〜8 行): r12 と同じ形で、HEAD は `3`、試作は `<stdin>:7:29` で同じ拒否と、続く入力の「Bar は Sz のインスタンスではありません」。

組み込みの `Show` の同じ形(r8.kel)と `@ E` のメソッド(r9.kel)は HEAD でも拒否(ς1 の漏れ)で、試作でも拒否のまま(元の報告が「行 ς1 は注釈で固定された行変数なので、ラベル Console を足せません」に変わる)である。
つまり試作は、この形の組み込みのクラスを直さず、利用者のクラスの受理を狭める。

下書き (3) の「推奨案で拒否に変わる HEAD の受理は、トップレベルでも拒否する形(u3 の Heap、u4 の未処理の操作)だけである」は誤りである。
r6 の初期化式をトップレベルの値束縛 `let g = memo(fn(x) => 7i32)` に書くと、トップレベルでは受理する。

## 6. 仕様の文面

下書きの §12.2 の 3 文目「署名の行と照らすのは初期化式の値の関数の行で、初期化式が起こすエフェクトは含まない」は、試作の振る舞いと合わない。
r6 は初期化式の値の関数が何も起こさないのに、初期化式の周囲の行が値の関数の行へ流れ込んで拒否される。
代案の形ならこの文と合う。
§15.4(1577 行と 1583 行の「各ファイルのトップレベルの評価の規則は §13.7 で定める」)は、インスタンスの初期化式をすでにトップレベルの初期化に含めている。
下書きの「LangSpec には、インスタンスの初期化式が起こしてよいエフェクトを直接書いた文が無い」は字義どおりには正しいが、§13.7 に足す 1 文は §15.4 の帰結を繰り返すものである。
§15.5 の終了状態との矛盾は無い(u4 は終了状態 3 から 1 に移り、表の「型検査での拒否」に合う)。
§18.2 は値束縛で書いたメソッドを持つインスタンスを初期化で評価する宣言として扱っており、追加文と矛盾しない。

## 7. 判断事項

P[V110-1] の推奨案(トップレベルと同じ行に限る)の方針には異論が無い。
異論は実装の手段で、「`check_instance_bodies` に `eff0` を渡す」は 4 節の退行を生む。
代案 C として「本体を新しい行変数の下で推論し、`subsume` の後でその行が `eff0` に収まることを確かめる」を挙げ、これを推奨とするのがよい。
P[V110-2] の推奨案(`subsume` で決まっていない行を空の行に決める)には異論が無い。
代案 C はこの扱いが先に働くことに依存するので、2 つの順序(`subsume` の後に収まりを確かめる)を設計に書く必要がある。
