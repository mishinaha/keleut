#### (3) 判断と確定

判断事項 P[V24-1]: 操作ごとの診断をどこに向けるか。

- 推奨案: 操作の型の位置(`at_node te`)。構文木を変えずに済み、行で操作を特定できる。予約名と英小文字の検査は、名前の右の型を指すことになる。
- 代案 A: 構文木の操作に名前の位置を持たせ(`ef_ops` を位置つきにする)、名前の検査は名前を指す。`syntax.ml`、`parser.mly`、`dump.ml`、`elab.ml` に波及し、`--dump-ast` の出力が変わりうる。
- 代案 B: 名前の検査だけは宣言の先頭のまま残す。
- 推奨の根拠: 台帳の求めは「どの操作かを位置から読める」ことで、1 操作 1 行の書き方なら型の位置で足りる。代案 A は費用が 4 ファイルに広がるわりに、桁の差が数文字である。

判断事項 P[V24-2]: pub newtype のフィールドで、フィールドの型の先頭を指すか、`@` の無い矢印そのものを指すか。

- 推奨案: フィールドの型の先頭(`at_node f.T.fd_ty`)。直下のカインド検査と同じ位置になる。
- 代案: `fully_effected` を「最初の `@` の無い矢印のノードを返す」関数に変え、その矢印を指す。`check_pub_annots` も同じ関数を使うので、`pub let` の位置とそろえるなら同時に変えることになる。
- 推奨の根拠: 台帳の求めはフィールドの特定であり、文言が「注釈の中の矢印」と言うので、フィールドが分かれば矢印は読める。

判断事項 P[V24-3]: type class のメソッドの 3 つの診断(クラスパラメータが現れない、矢印でない型、重複)を本項目で直すか。

- 推奨案: 本項目に含め、`at_node v.T.cv_ty` でメソッドの型を指す。重複は 2 度目の宣言の型を指す。
- 代案: 直さずに台帳に別に記録する。
- 推奨の根拠: 重複の記事(`:4014`)が操作の重複と同じ拒否だと書いており、操作だけを直すと位置の扱いが食い違う。直し方は操作と同じ形で、費用は約 15 行と既存の 2 ブロックの期待値である(試作で実測)。

判断事項 P[V24-4]: `pub let` / `extern` の完全注釈検査(`check_pub_annots`、`:383-399`)を同時に直すか。

- 推奨案: 直さない。台帳の候補 V[V24-1] として別に記録する。実測では `ex/pl1.kel`(3 行目の引数 `g` の注釈)が `1:9`(束縛の名前)を指す。
- 代案: 引数の `PAnnot` のノードと返り値の注釈で包む。`test/pub.t` などの既存ゴールデンの位置がさらに動く(本試作では数えていない)。
- 推奨の根拠: 束縛では名前の位置が引数の直前にあり、宣言の先頭よりは近い。メソッドと違って、操作と同じだと書いた記事も無い。

確定した設計:

- D[V24-1]: `pub newtype` の完全注釈の診断は、そのフィールドの型の位置を指す。
- D[V24-2]: effect の操作ごとの 4 つの診断(予約名、英小文字、矢印でない型、重複)は、その操作の型の位置を指す。重複は 2 度目の宣言の型を指す。effect の型パラメータの診断は宣言全体の誤りなので、宣言の先頭のままにする。
- D[V24-3]: type class のメソッドごとの 3 つの診断(クラスパラメータが現れない、矢印でない型、重複)は、そのメソッドの型の位置を指す。重複は 2 度目の宣言の型を指す。
- D[V24-4]: 検査の順序と文言は変えない。重複の検査は、HEAD と同じく全操作、全メソッドの型を読んだ後に置く。

台帳 V[V24-1](候補): `pub let` / `extern` の完全注釈検査(`check_pub_annots`)の診断は、注釈の欠けた引数や返り値ではなく束縛の名前を指す(`ex/pl1.kel` で `1:9`)。
