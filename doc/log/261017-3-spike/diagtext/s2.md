実装(ソースを読んで導いた性質):

#### (3) 判断と確定

D[V102-1]:
言い換えを添える条件に、宣言したフィールドの型(`fi_ty`。型パラメータを置き換える前のスキーマ)が閉じた行を書いた位置を含むことを足す。
閉じた行を書いた位置は、最外の行が閉じた矢印と、型の型引数に書いた閉じた行(`TRowEmpty`、または `TRowEmpty` で終わる `TRowExtend`。`Cb[{}]` の `{}`)の 2 つである。
フィールドの最外に限らず、型引数、レコード、矢印の引数と返り値の中も数える。
エイリアスは宣言の時点で展開されているので、エイリアスを経た矢印も数える。
型パラメータ(Generic の変数)の位置と、行が行変数で終わる矢印は数えない。

判断事項 P[V102-1]: 言い換えを添えないときに何を出すか。
推奨案: 単一化の報告だけを出す(`pa2.kel` と同じ)。
代案 1: 制限の 1 つ目の案内(「名前の参照でない式の関数は閉じた行のまま届きます。無名関数で包むか名前に束縛してください。§13.2」)を添える。
代案 2: 「(コンストラクタ Cons の引数です)」のように位置だけを添える。
推奨の根拠: 型パラメータに閉じた行が流れ込む原因は制限の 1 つ目に限らない(`nestedname.kel` は名前の注釈の入れ子の矢印が原因で、包んでも束縛しても直らない)。
代案 1 は `nestedname.kel` で再び的外れになる。
型変数の仮引数を持つ関数の呼び出しはすでに報告だけを出すので、推奨案はそれとそろう。
代案 2 は位置がすでにコンストラクタを指しているので、足す情報が少ない。
推奨案で確定する。

判断事項 P[V102-2]: 閉じた行の有無を、宣言の構文(`fd_ty`)で見るか、作ったスキーマ(`fi_ty`)で見るか、何を数えるか。
推奨案: スキーマで、最外の行が閉じた矢印と、型引数に書いた閉じた行を数える。
代案 1: スキーマで、閉じた矢印だけを数える(下書きの案)。
代案 2: 構文の矢印をすべて数える。
推奨の根拠: 代案 1 は `rowarg.kel` で HEAD の的確な案内を消す(行の型パラメータを取る型に `{}` を書いたのが原因で、案内の「行を通すなら行変数を型パラメータに取ってください」が当たる)。
代案 2 はエイリアスで書いたフィールド(`alias.kel`)で案内を消し、行変数で終わる矢印だけのフィールド(`tworow.kel`)では案内が的外れのまま残る。
推奨案は、代案 1 で走らせた既存の cram と `ex/` の 16 本の出力を変えずに、`rowarg.kel` と `rowarg2.kel` の案内を戻す(実測。`doc/log/261017-3-spike/V102/results.final.txt`)。
推奨案で確定する。

判断事項 P[V102-3]: 効果でない行の失敗(`arity.kel` の `_item`、`recmiss.kel` の欠けたフィールド)を、欠けたラベルがエフェクトかどうかで除くか。
推奨案: V102 では除かず、残りとして cram で見張る。
代案: 失敗の文面から欠けたラベルを取り出し、エフェクトの名前でなければ添えない。
推奨の根拠: ラベルは文面の中に表示名(`display_of`)でしか無く、エフェクトの表(`Decls.find_effect`)は識別子で引くので、文面からの照合は修飾名やモジュールの別名で外れうる(ソースを読んで導いた性質。試していない)。
確実に絞るには `Unify` の失敗に欠けたラベルを持たせる変更が要り、`row_failure` を共用するほかの言い換え(§11.12、§11.28、§11.29、§11.38)にも及ぶ。
`_item` の形は V127 と X-perform が `row_failure` の側で扱う問題の現れで、そこで直せば §11.18 の `arity.kel` も直る。
推奨案で確定する。

確定しない残り(直さない):
判定はフィールドの型だけを見て、単一化がどこで落ちたかも、欠けたラベルが何かも見ない。
次の 3 形では的外れの案内が残る(HEAD と同じ文面。実測)。

- `ctormixed`: 行の閉じた矢印と型パラメータを両方含むフィールド(`newtype Q[A] = Q(List[(A) => Int32], List[(A) => Int32])`)で、型パラメータの側が落ちる形。
- `ctorarity`(`arity.kel`): `newtype Box = Box((Int32) => Int32)` に 0 引数の関数を渡し、`ラベル _item がありません` で落ちる形。
- `ctorrecmiss`(`recmiss.kel`): `newtype R = R({f: () => Int32, g: Int32})` に `R({f = fn() => 1})` を渡し、`ラベル g がありません` で落ちる形。

落ちた位置を見分けるには単一化の失敗の位置を返す仕組みが要り、費用が効果に見合わない。
3 形を cram で見張る。

診断の位置(コンストラクタの式を指し、落ちた実引数を指さない)と、案内の末尾の `§9`(sample.kel の 9 章を指す。ほかの言い換えと共通)は変えない。

- 案内が消えて困る形: フィールドに書いた閉じた行が原因なのに、判定が偽になる形。スキーマは宣言の時点で `generalize` 済みで、`@` の省略は `TRowEmpty` になる(ctorbox、ctoralias で実測)。`@ {}` を明示した形(`explicit.kel`)、レコード型のフィールドの中の矢印(`recfield.kel`、`rectail.kel`)、タプルの要素の矢印(`tuplefield.kel`)、行カインドのエイリアス `Pure` を `@` に書いた形(`rowalias.kel`)、型引数に書いた閉じた行(`rowarg.kel`、`rowarg2.kel`)も、試作で添える(実測)。
