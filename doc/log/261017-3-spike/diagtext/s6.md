#### (3) 判断と確定

D[X-premise-1]: 出どころは、前提をたどり始めた型とクラスの 1 組だけを、元の文言の後ろに別の文として添える。
形は `<元の文言>。<型> が <クラス> であるための前提として要求されました` である。
段ごとに包まないので、入れ子でも括弧は増えない。
途中の型(`List[List[Opaque]]` の中の `List[Opaque]`)は書かない。
出どころの位置は書かない。

D[X-premise-2]: 前提が未定変数に届いた場合も出どころを残す。
`add_class` の `Unbound` の分岐で、前提経由で新しく付いたクラスについて `(変数の識別子, クラス)` を鍵に出どころを表に控え、`bind` がその表を引いて `add_class` に渡す。
控えた型は束縛する変数をまだ含むので、表示用に変数を代入先に置き換えた型を作って渡す。
一時的に `Link` を張って表示する方法は、`repr` の経路の圧縮がほかのセルを書き換えるので使わない。

D[X-premise-3]: 元の文言に現れる型と出どころの型は、1 回の `show_all` で同じ名前の表に載せて印字する。
別々に印字すると、名前の振り直しが 2 回起き、同じ `ς1` が文の前半と後半で別の型パラメータを指す(検証の d1。(8) を参照)。
`show2` は 2 つの型を `と` でつないだ 1 つの文字列を返すので使えず、2 つの文字列を返す `show_pair` を足す。
`ctx`(制約の前置き)は `show2` と同じく捨てる。

判断事項 P[X-premise-1]: 出どころの表し方。
- 推奨案: たどり始めた 1 組だけを、別の文として後ろに添える(D[X-premise-1])。位置は書かない。
- 代案 A: 台帳の文脈つき版(段ごとに外側を括弧で包む)。入れ子で括弧が段になる。
- 代案 B: 経路を全部並べる(`List[List[Opaque]] から List[Opaque] を経て`)。入れ子の深さに応じて文が伸びる。
- 代案 C: 直さない(据置)。
- 代案 D: 表に出どころの位置も控え、未定変数を経た場合だけ `4:13 の比較で List[Opaque] が Eq であるための…` のように位置を書く。
  診断の位置と出どころの式が食い違う形(pr26)が読めるようになる。
  ただし `add_class`、`unify`、`bind` は位置を受け取らず、位置は第11章の `at_node` が後から貼る(`aux.ml:89` 以降の記事)。
  位置を控えるには、現在のノードの位置を大域に置くか、`unify` の呼び出しすべてに位置を通す必要があり、変更の範囲が `elab.ml` に広がる。

  既存の文言が括弧を含む形(`p15`)や、外側の包み(`インスタンスメソッド eq がクラス宣言の型を満たしません(…)`)と組み合わせても、括弧の段が増えない。
  位置が食い違う形は cram(pr26)で振る舞いを固定し、代案 D は必要になったときの拡張として残す。

判断事項 P[X-premise-2]: 型パラメータ(剛定数)に届いた場合の文の順序。
- 推奨案: 出どころを案内の前に置く(`… のインスタンスではありません。List[ς1] が Eq であるための前提として要求されました。[A: Eq] のように制約を書いてください`)。
- 代案: 案内の後ろに置く。
- 推奨の根拠: 案内は直し方なので末尾に置き、事実(何が、どこから)を先に並べる。
  剛定数が `ς1` と表示されるのは既存の挙動(`diktor/doc/log/260912-1-plan.md:4961-4963` のリスク 5)で、本項目では変えない。
  型パラメータが 2 個以上の形では、D[X-premise-3] によって前半と後半の名前が一致する(pr25)。

判断事項 P[X-premise-3]: 構造的導出(レコードとヴァリアント)を出どころの起点にするか。
- 推奨案: 起点にしない。構造的導出の分岐は受け取った出どころをそのまま渡すだけにする。
- 代案: レコードの比較も起点にし、`{xs: List[Opaque]} が Eq であるための…` と出す。
- 推奨の根拠: 本項目はインスタンスの前提の経由を示すもので、構造的導出の経由はフィールドの型が見えていれば読める。
  起点にすると `{x: Opaque} == …` のように前提を持たない比較にも文が付き、変更の範囲が広がる。

#### (6) リスク

- 位置と出どころのずれ: 出どころは表に控えた時点の要求で、診断の位置は束縛が起きた式を指す。
  実測(pr26、検証の d2): `fn(x) => { let a = Cons(x, Nil) == Nil; x == o }` で、診断の位置は 5:5 の `x == o`(`Opaque` どうしの直接の比較)なのに、`List[Opaque] が Eq であるための前提として要求されました` と出る。
  文は事実として正しい(4 行目の比較が `x` に `Eq` を付けた)が、位置の式は前提を経ていない。
  `p18` も位置と別の式を指す形だが、位置の式も `List[List[Opaque]]` の比較なので pr26 ほど紛らわしくない。
  読めるようにするには P[X-premise-1] の代案 D が要る。
- 出どころが付くかどうかが let の一般化で変わる: let で一般化された変数を経ると表の鍵(変数の識別子)が使用点の具体化で切れ、出どころは付かない。
  実測(pr27、検証の d8): `let k = fn(x) => Cons(x, Nil) == Nil` の後の `k(o)` では、HEAD も試作も `Opaque は Eq のインスタンスではありません` だけを出す。
  検証の d6(`show`)も同じである。
  同じ比較を一般化を経ずに `x` と `Opaque` に結ぶ形(pr26)では付く。
- 投機の取り消し: 型検査の中の投機(`elab.ml:2189` など)は `trail` を使わずに `Type_error` を捕まえるので、捕まえた後も表に項目が残る。
  `vcls` の書き換えも同じく残るので、表と `vcls` の食い違いは生じないと見込む(ソースを読んだ推測。反例は試していない)。

- 出どころの表示が内部の形になる: pr19 の部分適用の頭(`P2[Opaque]`)、剛定数の `ς1`、束縛しない未定変数の `_A`。

  型パラメータが 2 個以上のときは、元の文言に出ない型パラメータにも名前が振られ、`P2[ς2, ς1]` のように番号が宣言順と逆になることがある(pr25)。
  案内の `[A: Eq]` の `A` は固定の文字で、パラメータの名前ではない(HEAD から同じ)。

  出どころの型にも矢印やリージョンの型が現れる(`p9`: `List[(Int32) => Int32]`)ので、どちらかが先に入ると本項目の新しい期待値も動きうる。
