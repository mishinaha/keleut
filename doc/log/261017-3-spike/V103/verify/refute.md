## 2. 退行の探索

HEAD が受理して正しく実行する形を、担当の例とは別に 25 本ほど両方で走らせた。
受理が狭まる形は見つからなかった。
見たのは、エイリアスの注釈(r12_alias)、module の中の pub(r5_module)、import(imp/main.kel)、REPL(repl.in)、--no-prelude(np.kel)、--prelude による差し替え(myprelude.kel と usep.kel)、行変数を型パラメータに取る高階関数(r3_rigid、r7_hof、r14_effvar)、ガードと入れ子のハンドラ(r6_handler)、if と match の節(r13_ifmatch)、コンストラクタ、レコード、タプルの中の一般化しない関数(r1、r2、r11、r15〜r18)、組み込みのクラスのインスタンスと演算子(r8_instance、i3、i4)、9 クラスと Ref、MutableArray、Array.get の全操作(m3_matrix_top)である。
m3_matrix_top は変更前に 13:15 で拒否、試作で受理する。
タプルの要素に入れた形(m1_matrix)は試作でも拒否するが、利用者の `pub let` を入れた m2_tuple_user も変更前から同じく拒否するので、仕様の制限 2 の形である。

出力が変わる形は次のとおりである。

1. 演算子を本体に持つ無名関数を一般化しない束縛に置くと、表示に ` @ {}` が付く(r4_display)。
   `let w = idf2(fn(x: Int32) => x + 1)` は、変更前 `w : (Int32) => Int32`、試作 `w : (Int32) => Int32 @ {}` である。
   REPL では、`let w = id(fn(x: Int32) => x + 1)` の応答が `w : (Int32) => Int32 = <fn>` から `w : (Int32) => Int32 @ {} = <fn>` に変わる。
   その後 `println` と `echo` の文脈で使ってからの `:type w` は、変更前 `(Int32) => Int32 @ {Console, Blocking, Print extends R1}`、試作 `(Int32) => Int32` である。
   下書きのリスクの節は表示の変化を ml9e だけとし、この形を挙げていない。
2. 組み込みのメソッドや操作を一般化しない束縛に置いた形の表示にも ` @ {}` が付く(np.kel の `s`、imp/main.kel の `g`)。
   ml9e と同じ類である。
3. 組み込みのクラスのインスタンスのメソッドを、エフェクトを起こす初期化式の値束縛で書く形が、拒否から受理に変わる。
   i7_valeff_console.kel(`type instance Show[N] { let show = { echoln("init"); idf(fn(x: N) => "n") } }`)は、変更前は「…元の報告: スコープ付きの型 ς1 がスコープの外に漏れています」で終了状態 1、試作は `init` と `n` を出して終了状態 0 である。
   i5_valeff.kel(初期化式が `println`)は、試作で型検査を通り、実行すると「未処理のエフェクト操作: Print.print」で終了状態 3 になる。
   型検査を通ったプログラムが未処理のエフェクトで止まるので、健全性の穴が組み込みのクラスに広がる。
   利用者のクラスでは同じ穴が変更前からある(i6_valeff_user.kel は変更前も試作も終了状態 3、i8_user_console.kel は両方で受理して実行する)。
   V97 の下書きの D[V97-4](インスタンスの本体を `TRowEmpty` の下で検査する)がこの穴を塞ぐ。
4. 組み込みの `Show` のインスタンスの実装を、行変数を持つ一般化しない束縛で書く形が受理に変わる(i1_weakimpl、i2_weakimplval。変更前は ς1 の漏れで終了状態 1、試作は `n`)。
   仕様どおりの受理であるが、下書きは挙げていない。
