#### (3) 判断と確定

判断事項 P[V25-1]: 対象確定後の 2 検査のどちらを先に報告するか。

- 推奨案: 所属を先に調べ、所属違反を報告する。文面は既存の 2 つのまま。
- 代案 A: 現状(網羅が先)のまま。
- 代案 B: 両方を 1 つの診断にまとめる(「操作 flush はエフェクト File に属しません。File の write も漏れています」の形)。
- 代案 C: 所属違反を先に報告し、対象で漏れている操作があればその文面に添える(「操作 wirte はエフェクト File に属しません(File の write が漏れています)」の形)。報告は 1 件のまま。B の文面を所属違反の側に寄せたものである。
- 推奨の根拠: qual5 の形(書いた節が別のエフェクトのもの)では、所属違反は書かれた節を名指しし、どの節を直すか(修飾を変える、消す)が入力から読める。網羅漏れは書かれていない操作を名指しし、原因が別の節にあるときに読み手を取り違えさせる。所属違反を直した後に網羅漏れが残れば、それが次に出る(実測、`doc/log/261017-3-spike/V25/ex/qual5w.kel`)。
- 推奨案の弱点(実測、`doc/log/261017-3-spike/V25/verify/typo.out`): 操作名の書き誤り(r9_typo)では、試作は「操作 wirte はエフェクト File に属しません」と書かれた名前だけを示し、HEAD が示していた正しい名前 `write` は節を消すか直した後の 2 段目で出る。どちらの順でも、片方の情報が 1 段目では隠れる。推奨案の利点は、1 段目の診断が書き手の書いた節を指すことに限られる。
- 代案 B と C を退ける根拠: どちらも報告の件数は 1 件のままにできる。退ける理由は、文面を新設し、網羅漏れの列(漏れが複数あるときの並べ方)を所属違反の文面に組み込む設計が要り、cram の期待値の文面も増えることである。C は書き誤りの形で両方の名前が読めるので、診断の改善としては推奨案より情報が多い。本計画は順序の入れ替えにとどめ、C は文面の設計を伴う別の改善として台帳に残す(V[V25-1])。
- 代案 A は台帳の問題(qual5 の形で書いた節が名指しされない)を残す。

推奨案で確定する。
