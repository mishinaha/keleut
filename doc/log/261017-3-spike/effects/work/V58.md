#### (3) 判断と確定

判断事項 P[V58-1]: 直す範囲を、台帳の引数の個数とラベルに限るか、1 つの節だけで決まる誤りのすべてに広げるか。
推奨案: すべてに広げる(上の表の 5 群)。
代案: 引数の個数とラベルだけを直す。期待値の変わる既存のブロックは 0 になる。
推奨の根拠: 原因が同じ(節のノードに `at_node` が掛かっていない)で、直し方も同じ 1 行の包みである。
代案では、同じ handle の中で引数の個数は節を、所属は handle 式を指すという不揃いが残る。

判断事項 P[V58-2]: 節の誤りの位置を、節(`case` のキーワード)、節のパターン(`case` の直後)、のどちらにするか。
推奨案: 節のパターン(`cl_pat` のノード)。ガードの誤りだけはガードの式のノード。
代案 1: 節のノード(`case` の位置)にそろえる。
代案 2: ラベルの誤りだけは、ラベルを書いた引数のパターン(`a.T.cap_pat`)を指す。
ただし `cap_pat` の位置はラベルの後ろのパターン(`x = a` の `a`)で、ラベルそのものではない。
推奨案のほうが、引数の個数の誤りと位置がそろう。
推奨の根拠: コンストラクタパターンの引数の個数の誤り(e15)は、`elab_pat` がパターンのノードを指す(計画 260926-1 の 898 行の 4:12)。

ガードの誤りは、取り除くべきものがガードの式なので、その位置を指す。

判断事項 P[V58-3]: 対象エフェクトの決定(§11.23)の誤りを節に寄せるか。
推奨案: 寄せない。handle 式の位置のままにする。

D[V58-1]: handle の 1 つの節だけで決まる誤りは、その節のパターンの位置で報告し、return 節と cancel 節のガードの誤りはガードの式の位置で報告する。
