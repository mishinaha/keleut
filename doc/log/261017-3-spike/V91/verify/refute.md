## 退行の探索

受理されるプログラム 8 本(ガード、型パラメータ、エイリアス、module、pub、入れ子のハンドラ、import、`--prelude` の差し替え)と、`test/sample` の `stubs.kel` と `sample.kel` の型検査を両方で走らせ、出力と終了状態はすべて同じだった。
成功の経路は、`default_to` が `Int32` か `Float64` に制約を付けてから `bind` がもう一度付けるだけで、型引数が無いので結果は変わらない(ソースから導いた)。

拒否されるプログラムでは、位置が HEAD より悪くなる形を 1 つ見つけた。

```
let ident[T](x: T): T = x
let g = ident(fn(y) => y % y)
let a = 0
let k = g(1.5)
```

HEAD は `w1_weak.kel:4:1`、試作は `w1_weak.kel:2:24` で、文面はどちらも「Float64 は Rem のインスタンスではありません」である。
試作は、すでに受理して `g : [_A: Rem] (_A) => _A` を表示した前の宣言の `y % y` を指す。
`g` は一般化しない束縛なので、`Rem` の穴は 2 行目の宣言で作られたまま解けずに残り、4 行目の宣言の既定化で `same h.h_ty` に当たる。
穴の番号 `hole_seq` は解けない穴を積み直すたびに新しくなるので、番号では宣言を区別できない(試作に計測を入れて、穴 23 が床 22 を超えるのを確かめた)。
穴の `h_id`(作った時点の `new_oid`)を宣言ごとの床と比べる版を試作し(`verify/floor.patch`、`verify/diktor4`)、この形は 4:11(`1.5`)になり、`dune runtest` の出力は担当の試作と同一で、担当の例の位置も変わらなかった。

経路 3(既定を選んだ述語のリテラル)は、`dune runtest` と担当の例のどれでも通らなかった(各経路に印字を入れた写し `verify/diktor3` で数えた。経路 1 が 11 回、経路 2 が 2 回)。
経路 3 を通るのは、一般化しない束縛を通って前提から伝わった制約の形である(`verify/ex/p4_path3.kel`、HEAD 7:1、試作 7:15)。
経路 4 を通る形は見つからなかった。
`default_to` のコメントは経路 3 の例を「インスタンスの前提から伝わった制約のように」と書くが、同じ差分の premlit(前提から伝わった制約)は経路 1 で参照の位置(5:9)に出る。コメントの例は実測と合わない。

## 範囲の外に残る形

注釈で型が決まる形は既定化を通らないので、試作でも変わらない。
`let b: Float64 = 1.5 % 2.0` は HEAD も試作も 2:5(束縛の名前)に「注釈された型を満たしません(Float64 は Rem のインスタンスではありません)」と出る。
`let f(): Float64 = 1.5 % 2.0` も 2:5 である。
台帳 V91 の題(リテラルの型エラーが演算子の位置に出ない)にこの形も当たるので、下書きは範囲の外であることを書き、台帳の候補に挙げるのがよい。

## 判断事項への意見
