## 6. 判断事項の推奨案

P[V121-3] の推奨(現在位置)には同意するが、根拠の一部が実測と食い違う。
下書きは代案の cur_pos について、文字列リテラルやコメントの中では開始の二重引用符や /* を指すと書く。
cur_pos を使う変種を作って測ると(verify/curpos)、次のとおりだった。

- 文字列の中 `let s = "abcdefghij\377"`: cur_pos も現在位置も 1:20
- ブロックコメントの中 `/* abcdefghij \377 */`: どちらも 1:15
- 行コメントの中 `let x = 1 // abcdefghij \377`: cur_pos は 1:11(// の位置)、現在位置は 1:25
- 識別子の途中 `let ab\377c`: cur_pos は 1:5、現在位置は 1:7

cur_pos は直前の照合の開始位置で、文字列とブロックコメントは 1 文字ずつ照合するので、不正なバイトそのものを指す。
食い違うのは、1 つの正規表現で長く読む形(識別子、行コメント、数値など)だけである。
根拠の文は「識別子や行コメントのように 1 回の照合で長く読む形では、照合の開始位置が不正なバイトから離れる」と直すべきである。

P[V121-1] には見落とした代案がある。
from_filename、parse_string、try_parse の 3 つの入口で原文を String.is_valid_utf_8 などで先に検査し、位置を自前で数える案である。
sedlex の refill の内部の振る舞いに依らない利点があるが、入口が 3 つに分かれ、行と桁を sedlex と同じ数え方で再現する手間がかかる。
推奨案を覆す理由にはならないが、リスクの節の sedlex の版の依存への対策の代案として挙げてよい。

P[V121-2] と P[V121-4] には異論は無い。
