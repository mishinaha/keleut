## 下書きに無い形の実測

試作は、下書きの表に無い次の形にも専用の診断を出す(verify/ex/e1〜e20)。
f { x = 1 => 2 } と f { x, => 1 } は「末尾ブロックの引数は小文字の識別子 1 個です(2 個以上の引数を取る関数は…)」になる。
LBRACE_RECORD field_list EQ_GREATER が、名前の並び以外のフィールドの並びも受けるからである(ソース)。
f { x: Int32 }(=> の無いレコード型の形)と f { Foo: Int32 => 1 } は型注釈の診断になる。
f { _: Int32 => 1 } と perform E.op { k } は、HEAD と同じ一般のパースエラーのままである。
どれも HEAD では一般のパースエラーなので退行ではない。

## 仕様の文面の案

§5.5 に足す「文の列は空でもよく」は、410 行の直後に置くと { 文の列 } の形にもかかる。
421〜422 行は「空の {} もレコードなので、末尾ブロックとしては書けない」と定めるので、2 つの文が食い違って読める。
「{ x => 文の列 } の文の列は空でもよく」のように形を限る必要がある。

§2.3 に足す段落は、付録 A.3(case は始端トークンに無く、{ は始端トークン)と合い、armnl、armnl2、armnl3、armsemi、armparen の実測とも合う。
§15.5 の終了状態 2 とも、新しい診断の終了状態 2(実測)が合う。
§18.5 の REPL の性質は、受理する入力が変わらないので保たれる。
