#### (2) 現状(根拠つき)

仕様: `doc/LangSpec.md:641`(§6.4)は「型の宣言群の中では、後ろで宣言する型名も参照できる。」と書く。参照できることを書く文面で、受理が宣言順に依存しないとまでは書いていない。§18.4 の 6 つ目の除外(`:1869`)は後ろのエイリアスへ渡す `{}` の話で、V124 の範囲である。

実装(行番号は diktor 39d4091):

- `lib/elab.ml` §11.39 `process_decls` の 1a の後始末(`:4788-4795`)が、newtype の本体を宣言順に 1 周だけ投機する(`speculate_newtype`、`:3713-3728`)。投機はフィールドごとに例外を握り潰す。
- 投機の時点では、利用者の effect は宣言表 `Decls.effects` に無い(V30 で解消)。
- タプルとレコードの要素は右から読む(§11.31 の記事 `:3607-3611`)ので、`(() => Unit @ E, () => Unit @ {Log})` は `{Log}` で落ちて `E` に届かず、`E` のカインドは KVar のまま 1b に入る。
- 1b で、前に置いた宣言の `B[{}]` を `elab_con_args`(§11.5、`:854-880`)が読むと、`{}` を空レコードとして読めてしまい、照合の `same_kind` が `E` を Type に張る。投機の中の飛ばす読み(`:865-867`)は 1b では効かない。
- 相手のフィールドがさらに後ろの newtype にラベルつきの行を渡す形(`MkB((() => Unit @ E, C[{Log}]))` の後ろに `C`)は、ラベルが読めても、`B` の投機の時点で `C` のパラメータが KVar なので `{Log}` を型として読んで落ちる。1 周では届かない。

#### (3) 判断と確定

D[V22-2]: 1a の後始末の投機(newtype と、D[V124-2] が足すエイリアス)を、決まったパラメータのカインドの数が増えなくなるまで繰り返す。
根拠: V30 でラベルが読めても `ex/residual.kel` が残る(V30 の試作で `4:34: …: E`。V22 の変種 `verify/v1` でも同じ)。`B` の投機が `C[{Log}]` を読む時点で `C` のパラメータが KVar なので `{Log}` を型として読んで落ちる。2 周目には `C` のパラメータが 1 周目に決めた Row なので読める。
合成の写しで繰り返しを外した変種では、specfix、specalias、fwdalias3、fwdalias4 の 4 本だけが落ちる(実測)。

D[V22-3]: D[V22-2] の数には、newtype のパラメータに加えてエイリアスのパラメータ(`al_kinds`)を数える。
根拠: `ex2/gap.kel`(`newtype A = MkA(B[{}])`、`newtype B[E] = MkB((() => Unit @ E, Al1[{Log}]))`、`type Al1[F] = Al2[F]`、`type Al2[G] = () => Unit @ G` の順)は、newtype だけを数える版では 1 周目に `Al1` のカインドだけが決まって数が増えず、止まる。結果は `4:34: 行カインドではない型パラメータです: E` で、宣言を並べ替えた `ex2/gap2.kel` は通る(V22 の担当の実測)。エイリアスも数えると両方が通る(合成の写しで実測、specalias)。

繰り返しを入れるかは、§18.4 の除外とあわせて P[V124-1] で決める(推奨は入れる)。
代案は、入れずに `ex/residual.kel` と `ex2/gap.kel` の形を台帳に残すことである。

確定後に残る形: 見つかっていない。構造上残りうるのは、投機の中のフィールドの読みが 1b でも落ちる理由で落ちる形である(ソースから導いた性質。網羅の証明ではない)。

#### (6) リスク

- 繰り返しの終了: 数はパラメータの総数を超えず、増えなければ止まる。
- REPL: V22 の最終稿の推奨案で懸念した、1b で effect の登録が失敗した後に名前が主張だけ残る経路は、判定を入れないので無くなる。V30 の 1a の登録は入力の失敗で戻る(effrepl で実測)。
