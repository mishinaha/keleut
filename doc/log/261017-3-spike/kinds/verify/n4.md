### N.4 V56：非 pub の Type エイリアスのコンパニオンをエフェクト位置に書いたときの、効かない pub の案内

#### (1) 判定、規模、依存、出典

判定: fix(診断の文面だけが変わる。受理と拒否と終了コードは変わらない)。

規模: S。
コードは `lib/elab.ml` の 1 行と記事の 5 行、cram は `test/visibility.t` に 2 ブロック(コマンド 12 行、プログラム 6 本、visrow16〜visrow21)。

依存: 無い。
V57 と同じ cram の位置(visrow15 の直後)に足すので、V56 を先に当て、V57 のブロックをその後ろに置く(N.5)。
V30 の後でも当たる(合成で実測)。

出典: diktor の `doc/log/260926-2-m34.md:343`(台帳の行)と `:176`(M36 の検証の指摘 4、台帳 V56 と V57 とする)。

#### (2) 現状(根拠つき)

仕様: LangSpec §15.1(`doc/LangSpec.md:1447-1481`)は、コンパニオン型を「モジュールと同じ名前の公開型」と定め(:1467)、エフェクト位置で module の宣言が名前を覆うのは `EffectRow` の別名のときだけと書く(:1478-1481)。
診断の文面は仕様に書かれていない。

実装: `lib/elab.ml` §11.5 の `find_alias`(:912-927)。
`find_row_alias` で EffectRow エイリアスが見つからず、effect の宣言表にも無いとき、行にならないエイリアスを `Decls.resolve_con` と `Decls.resolve_con_global` で引き、見つけたものに種類を問わず `Decls.check_con_visible`(:925)を掛ける。
`resolve_con_global` は同じファイルの module 名と同名の型を pub でなくても引き当てるので、module の外から書いた非 pub の Type エイリアスのコンパニオンは、ここで可視性の誤りになる。
`find_alias` の呼び出しは §11.6 の `elab_eff` の 2 か所(名前 1 個の分岐 :1172、波括弧の要素 :1218)だけで、可視性を通った行にならないエイリアスを「エフェクト位置に Type エイリアス P は使えません」(:1175)と「エフェクト行に Type エイリアス P は置けません」(:1221)で落とす。
波括弧の要素は修飾名(`M.T`)も `find_alias` で引く(:1213-1217 のコメントと :1218)。
波括弧の外の修飾名(`@ M.T`)は `find_alias` を通らず、`elab_eff` の最後の分岐から `elab_type` の一般の可視性の検査に進む。

HEAD での実測(`doc/log/261017-3-spike/V56/ex/` と `verify/ex/`。HEAD と試作の対照は `results.final.txt`):

| 例 | 形 | HEAD の診断 |
|---|---|---|
| a1 | `module P { type P = Int32 }` と `@ P` | 型 P.P は module P の外からは参照できません(pub を付けてください) |
| a2 | a1 に pub | エフェクト位置に Type エイリアス P は使えません(: EffectRow を付けてください) |
| a3 | a1 で `@ {P}` | a1 と同じ可視性の誤り |
| a12 | `type P[A] = A` と `@ {P[Int32]}` | a1 と同じ可視性の誤り |
| q1 | `module M { type T = Int32 }` と `@ {M.T}` | 型 M.T は module M の外からは参照できません(pub を付けてください) |
| q2 | q1 に pub | エフェクト行に Type エイリアス M.T は置けません(: EffectRow を付けてください) |
| q4 | `type T[A] = A` と `@ {M.T[Int32], Console}` | q1 と同じ可視性の誤り |
| a14 | q1 で `@ M.T`(a7 の `@ P.P`、q5 の `@ M.T[Int32]` も同じ) | 型 M.T は module M の外からは参照できません(pub を付けてください) |
| a13 | `@ P.P` で pub | エフェクト位置の型のカインドが Row ではありません: Int32 :: Type |
| a8 | `type P: EffectRow = {Print}`(非 pub)と `@ P` | 型 P.P は module P の外からは参照できません(pub を付けてください) |
| imp2/a | 別ファイルの `pub module P { type P = Int32 }` を import して `@ P` | 未知のエフェクト: P(`@ {P}` も同じ) |

a1 の案内どおりに pub を付けると a2 になり、別の理由で落ちる。
pub を付けても使えるようにはならないので、a1 の案内は誤りへの道筋を示さない。
q1 と q2 の組も同じである。

#### (3) 判断と確定

D[V56-1]: `find_alias` の可視性の検査は、返すエイリアスが EffectRow エイリアスのときだけ掛ける。
行にならないエイリアスは、可視性によらず呼び出し側の Type エイリアスの誤りへ渡す。
変わるのは、同じファイルの module の外から、非 pub の行にならないエイリアスを `find_alias` の経路で書いた形である。
module 名だけの `@ P`、`@ {P}`、`@ {P[Int32]}`(a1、a3、a12)と、波括弧の中の修飾名 `@ {M.T}`、`@ {M.T[Int32]}`(q1、q4)が、pub の場合(a2、q2)と同じ「: EffectRow を付けてください」の案内になる。
案内どおり `: EffectRow` を付けて pub が無ければ a8(既存の visrow15)と q3 の可視性の誤りになり、どの段の案内も実行できる。
変わらないのは、波括弧の外の修飾名(a7、a14、q5。可視性の誤りのまま)、別ファイルから import した module(imp2。未知のエフェクトのまま)、非 pub の EffectRow エイリアス(a8、q3)である。

判断事項 P[V56-1]: module の外から非 pub の Type エイリアスの存在を、可視性の誤りでなく「Type エイリアス P」と名指して報告してよいか。
推奨案: よい。
代案: 非 pub で見えないエイリアスは見つからなかったことにし、`unknown_effect` に回す。
推奨の根拠: 同じファイルの中では、HEAD でも非 pub の名前を型の位置で「型 P.P は module P の外からは参照できません」と名指して報告しており(a11)、名前の存在はすでに分かる。
別ファイルからは、型の位置でも「未知の型: P」(imp2/c)、エフェクト位置でも「未知のエフェクト: P」(imp2/a、imp2/b)で、この項目はこれを変えない。
代案は `unknown_effect` が `con_kinds` を見て「型 P はエフェクトではありません」を出すか「未知のエフェクト」を出すかが resolve の経路次第で、文面の予測が立ちにくい(未試作)。

判断事項 P[V56-2]: 波括弧の外の修飾名(`@ M.T`、a14)の案内も揃えるか。
推奨案: 扱わない。台帳 V[V56-2] として残す。
代案: `elab_eff` の最後の分岐の手前で、2 段以上の修飾名を `find_alias` で引き、行にならないエイリアスなら「エフェクト位置に Type エイリアス M.T は使えません」で落とす(反証者の試作 `doc/log/261017-3-spike/V56/verify/alt-P2.patch`、8 行)。
a7、a13、a14 が Type エイリアスの誤りに揃い、既存の期待値は `test/kinds.t` の effkind3 の 1 か所だけが変わる(反証者の実測)。
判断の材料: この項目の後は、非 pub の `@ M.T`(可視性の誤り)と `@ {M.T}`(Type エイリアスの誤り)の文面が分かれる。
HEAD では非 pub の 2 形は同じ可視性の誤りだった。
ただし pub の場合は HEAD ですでに分かれている(a13 はカインドの誤り、q2 は Type エイリアスの誤り)。
推奨の根拠: `@ M.T` の可視性の誤りは `find_alias` の外の `elab_type` の一般の検査から出る。
代案は effkind3 の期待値に加えて、その前書き(`test/kinds.t:741-742`)と、`elab_eff` の最後の分岐のコメント(:1240-1247)を改める必要がある。
`@ M.T` の pub の案内も、付けた後にカインドの誤りという、事実に合う次の案内に進むので、行き止まりの度合いは a1 より小さい。

台帳の要約の後半「pub の場合も未知のエフェクトから Type エイリアスの誤りに文面が変わる」(a2、a4)は、文面が事実に合っているので変えない。

#### (6) リスク

- 可視性の検査が抜けるのは、`find_alias` が行にならないエイリアスを返す場合だけで、その場合の呼び出し側は 2 か所とも型エラーで止まる(:1175、:1221)。行にならないエイリアスの中身が展開されて受理される経路は無い(ソースを読んで導いた性質)。反証者は HEAD が受理する 7 本と REPL で退行を探し、見つけていない。
- EffectRow エイリアスの可視性の検査は残る(a8、q3、visrow15 が HEAD と同じ)。`@ W[E]` の適用の分岐(:1186)は `find_alias` を通らないので変わらない。
- 非 pub の名前の存在が、同じファイルの中ではエフェクト位置からも読める。型の位置ではすでに同じである(P[V56-1])。
- 非 pub の `@ M.T` と `@ {M.T}` の文面が分かれる(P[V56-2])。
- b1(`module E { type E = Int32 }` と `let f[E](...) @ {E, Console}`)は、この項目だけでは Type エイリアスの誤りに変わるが、V57 の後は「行変数 E は extends の位置にのみ書けます」になる(合成の写しで実測、`ex/b1.kel` と `verify/ex/b1.kel`)。これは V57 の最終稿の予告どおりである。同じ宣言で `@ E` と書くと型パラメータを指し、`@ {E}` は module のエイリアスを指しうる非対称は HEAD からあり、台帳 V[V56-1] に載せて V57 と突き合わせる。
- V28 は `find_row_alias` と `find_alias`(:895-927)と同じ記事を触る見込みがあり、`test/visibility.t` の visrow 系にブロックを足しうる。番号は visrow27 からにする。
