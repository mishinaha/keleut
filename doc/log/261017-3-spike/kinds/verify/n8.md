#### (2) 現状(根拠つき)

仕様: LangSpec §15.2(1483〜1490 行)は「注釈の中の入れ子の矢印には、`@` を省略せずに書く」と定める。
§13.2(1123 行〜)は「型エイリアスを展開して現れる矢印は、最外の矢印に含めない」とする。
§18.4 の 2 つ目の除外(1862〜1863 行)は、§15.2 の要求が注釈に直接書いた矢印だけに働くことを、性質の除外として書いている。

規範: doc/sample.kel 487 行は「注釈の先頭が型エイリアスのときは最外の矢印がなく、エイリアスを展開した矢印は入れ子として読む」とする。
498〜500 行は、入れ子の矢印を「最外以外のすべての矢印」とし、その例に「型エイリアスを展開した矢印」を挙げる。
825 行は「pub を付けるには、型注釈が完全でなければならない。入れ子の矢印の `@` も省略できない」とし、理由を「純粋を意図したのか書き忘れたのかを、読み手が区別できる必要がある」とする(826〜827 行)。
規範の字句では、エイリアスの本体の矢印にも、値束縛の注釈の先頭のエイリアスを展開した矢印にも `@` が要る。

実装: `lib/elab.ml` の `fully_effected`(343〜353 行)は表層の型式だけをたどり、`EIdent` を `true` とする。
エイリアスの名前を引かないので、本体の矢印は調べない。
呼ぶ側は `check_pub_annots`(383〜399 行)と、§11.31 の `register_newtype` の中(3749〜3750 行)である。
`check_pub_annots` は §11.28 の `elab_binding`(3079 行)、§11.29 の `let rec`(3377 行)、extern(5028 行)から呼ばれる。
値束縛の頭は `fully_effected_value_head`(378〜381 行)が扱い、頭が矢印リテラルのときだけ頭の `@` を問わない。

#### (3) 判断と確定

判断事項 P[V117-1]: §15.2 の要求をエイリアスの本体に広げるか。

- 推奨案: 使う位置で広げる。pub の注釈に書いたエイリアスを展開した型の矢印を、入れ子の矢印として数える。
- 代案 1: §15.2 に「注釈に直接書いた矢印に限る」と書き、§18.4 の除外を残す(処理系は変えない)。
- 代案 2: 規則を外す。
- 推奨の根拠: 規範の 487 行と 500 行は展開した矢印を入れ子の矢印に数え、825 行はその `@` を省略させない。推奨案は規範の字句どおりである。代案 1 は矢印を名前に包むだけで要求を逃れられ、826〜827 行の理由が成り立たないうえ、規範を変えずに採れば実装が規範を緩めたままになる。代案 2 も規範の改訂が要る。

判断事項 P[V117-2]: pub の値束縛の注釈で、先頭がエイリアスのとき、展開して先頭に現れた矢印に `@` を求めるか。

- 推奨案: 求める。規範 487 行のとおり、注釈の先頭がエイリアスなら最外の矢印は無く、展開した矢印は入れ子の矢印である。型引数に書いた矢印(a9 の `Id[...]`)も同じである。a6 は拒否に変わり、a9 は HEAD のまま拒否する。
- 代案: 求めない。展開した型の先頭の矢印は、エイリアスの本体から現れても型引数から現れても、要求から除く。採るなら doc/sample.kel 487 行を「pub の値束縛では、展開して先頭に現れた矢印の `@` も省略してよい」に改め、test/sample/sample.kel を test/sample/README.md の手順で同期し、§13.2 の最外の矢印の定義に pub の値束縛の例外を足す。
- 推奨の根拠: 推奨案は規範を変えずに済み、§13.2 の「展開して現れる矢印は最外の矢印に含めない」とも、pub のない値束縛の扱い(§18.4 の 3 つ目の除外、V119)とも一致する。代案の利点は、どちらの省略も `@ {}` と読むので型が変わらず、a6 と a7、a7 と a9 の置き換えで受理が変わらない点である。推奨案ではこの 2 組の受理が変わるので、§18.4 の 2 つ目の箇条を、この位置の除外に書き換える((4))。

判断事項 P[V117-3]: `pub type` の宣言の本体そのものにも `@` を求めるか。

- 推奨案: 求めない。要求は pub の注釈と pub newtype のフィールドで、使う位置で働かせる。
- 代案: `pub type F = (Int32) => Int32` を宣言の位置で拒否する。
- 推奨の根拠: sample.kel は `pub type` に要求を課していない。代案は規範に無い拒否を足す。

判断事項 P[V117-4]: 本体で使わないパラメータに渡した型引数の矢印(r2、r15)を調べるか。

- 推奨案: 調べる。型引数は、本体で使うかどうかに関わらず、使う位置で、注釈に直接書いた型として調べる。HEAD の拒否を保つ。
- 代案: 展開で消える型引数は調べない。採るなら §15.2 と cram にその緩和を書き、sample.kel 825 行の「入れ子の矢印」から除く文を規範に足す。
- 推奨の根拠: 型引数の矢印は利用者が注釈に書いた矢印で、825 行の要求の対象である。代案は HEAD の拒否を緩め、規範の改訂が要る。

D[V117-1](読む位置): エイリアスの本体の名前は、エイリアスを宣言した単位と module で解決する(§11.5 の `expand_alias` と同じ)。
エイリアスのパラメータ、束縛の型パラメータ、外側で束縛した型パラメータ(インスタンスの型パラメータを含む)は、同じ名前のエイリアスを隠す(§11.3 の優先順位)。

D[V117-2](打ち切り): EffectRow エイリアスの本体、再帰したエイリアス、引数の個数が合わない使用、使う位置から見えないエイリアスは、本体を見ずに打ち切る。
型引数は打ち切りの後も調べる(P[V117-4])。
打ち切った形の診断は、続く注釈の精緻化が出す(c1_invisible、c2_arity、b8 で実測)。
エフェクト行の中は、直接書いた場合も HEAD が調べないので、それに合わせる。

D[V117-3](診断の文面): `@` の無い矢印がエイリアスの本体にあるときは「(型エイリアス F の本体の矢印に @ がありません)」とし、その矢印を本体に書いたエイリアスを名指す(a16_chain は G でなく F)。
型引数に書いた矢印は従来の「(注釈の中の矢印に @ がありません)」とする。
型引数と本体の両方に誤りがあれば、型引数を先に報告する。

#### (4) 仕様側の改訂案

LangSpec §15.2(1485〜1490 行)を次に置き換える。

```markdown
`pub let` と `pub extern` には、各引数と返り値の型注釈が必要である。
値束縛の場合は、束縛全体の型を注釈する。
注釈の中の入れ子の矢印には、`@` を省略せずに書く。
注釈に書いた型エイリアスを展開して現れる矢印も、入れ子の矢印として数える（§13.2）。
エイリアスの本体の名前は、エイリアスを宣言した位置で解決する（§15.1）。
エイリアスの型引数に書いた矢印は、本体でその引数を使うかどうかに関わらず、注釈に直接書いた矢印として数える。
この要求は、`pub newtype` のフィールドに書く矢印にも適用する。
`pub type` の本体には、宣言の位置ではこの要求を課さない。

最外の矢印の `@` だけは省略でき、その意味は §13.2 の省略の表に従う。
値束縛の注釈の先頭が型エイリアスのときは最外の矢印がない（§13.2）ので、展開して先頭に現れる矢印にも `@` が要る。
```

LangSpec §18.4 の 2 つ目の箇条(1862〜1863 行)を、次の箇条に置き換える(箇条の数と順序は変えない)。

```markdown
- `pub` の値束縛の注釈の先頭の矢印で、`@` を省略したもの。
  先頭に直接書いた矢印は最外の矢印なので `@` を省略できるが、先頭の型エイリアスを展開して現れる矢印は入れ子の矢印なので `@` が要る（§13.2、§15.2）。
  どちらの省略も `@ {}` と読むので型は変わらないが、先頭の矢印をエイリアスの使用に置き換えると、受理していた宣言を拒否する。
```

V124 の推奨案は同じ §18.4 の 6 つ目の箇条(1869 行)を削る。
2 つの編集は別の行で、箇条の序数(2 つ目と 3 つ目)は変わらない(N.z)。

doc/sample.kel は変えない。
推奨案は 487、500、825 行の字句どおりだからである。
test/sample/sample.kel の同期も要らない。
P[V117-2] または P[V117-4] で代案を採る場合は、(3) に書いた sample.kel の改訂と同期が要る。
