#### (2) 現状(根拠つき)

仕様の文面は次のとおりである。

- `doc/LangSpec.md:179-182`(§3.3): 「注釈を省略すると `Type` になる」「`EffectRow` の別名を書けるのは、`@` の後ろ、エフェクト行の要素、`EffectRow` の別名の右辺、行を取る型引数の位置に限る」。

したがって、規範は `type Q = P`(`P` は EffectRow エイリアス)を許していない。

#### (3) 判断と確定

D[V31-1]: `EffectRow` の注記が無いエイリアス(`: Type` と書いたものを含む)の本体は、カインドが行であってはならない。
パス 2 の `DType` が本体を精緻化した直後にカインドを照会し、行なら本体の位置で型エラーにする。
照会は `kind_repr` で行い、`same_kind` を使わないので、未確定のカインド変数を張らない。

判断事項 P[V31-1]: 引数つきの `type Q[E] = P[E]` も宣言で落とすか。
- 推奨案: 落とす。
- 代案: パラメータの無い形だけを落とし、引数つきは今の振る舞い(`@ Q[E]` で使える)を残す。
- 推奨の根拠: §3.3 と `sample.kel:71-74` は Type エイリアスの右辺を行の位置に数えていない。
  残すと `@ Q` は落ちて `@ Q[E]` は通るという非対称が残る。
  既存の cram とプレリュードと `test/sample` に、この形に頼るものは無い(合成の runtest で差分 0)。
  利用者の直し方は `: EffectRow` を付けることで、同じ型になる。

判断事項 P[V31-2]: 照合をどの時点で走らせるか。
- 推奨案: パス 2 の `DType`(宣言順)。
- 代案: 1b の後始末のカインドの既定化の直後に、診断を出す周回を 1 つ足す。宣言順によらず宣言の位置で落ちる。
- 推奨の根拠: 未知の型、再帰、部分適用というほかの本体の誤りもパス 2 で宣言順に出ており、時点をそろえられる。
  推奨案でも、使用がエイリアスより前にあるときは使用点の既存の診断(`: EffectRow を付けてください` を含む)が出るので、利用者への案内は失われない(実測 d4、cram の aliasrow5)。
  V124 でエイリアスのカインドの推論が 1b の前にも走るようになったが、パス 2 の照会は 1b の後始末で既定化済みの `al_kinds` を見るので、前提は変わらない(ソースから導いた性質。合成で V31 の例 45 本が単独の試作と一致)。

判断事項 P[V31-3]: 高階カインドの本体(`type Q[F[_]] = F`)を落とすか。
- 推奨案: 落とさない。照合は行(`KRow`)だけにする。
- 代案: `Type` 以外の本体をすべて落とし、§3.3 に「本体のカインドは Type」と書く。
- 推奨の根拠: この形は HEAD で `App[Q[F]]` の形で使え、正しく実行する(h6、h7)。
  §3.2 は `F[_]` のパラメータを認め、§3.3 に高階の本体を禁じる文は無く、落とす規範上の根拠が見当たらない。

判断事項 P[V31-4](合成で立てた): 本体が型パラメータそのもののエイリアス(`type Id[A] = A`)を照合から除くか。
- 問い: V27 の hktrowok(`type Id[A] = A` と `newtype N[X] = MkN(Callback[Id[X]])`)は HEAD で通り、V27 はこれを「行変数のカインドの推論」として通す形に固定する。V31 の照合はこの `Id` の本体のカインドが `Row` に決まるので、`1:14: Type エイリアス Id の本体のカインドが Type ではありません: ς1 :: Row` で落とす(合成で実測。V31 の単独の試作でも、`Id` を先に置いても後に置いても同じく落ちる)。
- 推奨案: 除く。本体が `EIdent` でエイリアスのパラメータの名前そのものなら照合しない(D[V31-2])。
- 代案: 除かない。hktrowok と V27 の c1 は拒否に変わり、V27 の D[V27-1] の「裸の型変数は `Row` に張ってよい」の例を改める。
- 推奨の根拠: 恒等のエイリアスは本体のカインドがパラメータのカインドで、使う位置が決めたものである。HEAD の受理を変えず、V27 の記述とも揃う。本体が行になるのは、利用者が行を渡したときだけで、`type Q = P` のように行に名前を付ける宣言ではない。

D[V31-2]: P[V31-4] の推奨案のとおり、本体が型パラメータそのもののエイリアスは照合しない。

文面は、推奨案 P[V31-3] により 1 通りになる。
`Type エイリアス Q の本体のカインドが Type ではありません: {Log} :: Row(行に名前を付けるには : EffectRow を付けてください)`。
エイリアスの名前は `Type.display` を通した表示名で出す(import したファイルでも `Q`、module の中では `M.Q`)。

`{Log extends ς1}` の `ς1` は剛変数の表示で、パラメータ名 `E` が出ない。
これは既存の `check_value_kind` の文面(実測 c5)と同じ性質で、X-regionshow と同じく表示の規約の問題として、この項目では扱わない。

#### (4) 仕様側の改訂案

`doc/LangSpec.md` §3.3 の `:181-182` の後(「関数の引数型、…には使えない。」の次の行)に、次の文を足す。

