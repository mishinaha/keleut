## 5. 軽い指摘

- spec.patch、V83.patch、V32.patch の --- 行と diff 行に一時領域の絶対パスが入っている。統括者が doc/log/261017-3-spike/ に写すとリポジトリに一時領域のパスが残る。写す前に見出しを a/ b/ などに置き換えるのがよい(節の本文には一時領域のパスは無い)。
- N.2 (5) の「V32.patch(63 行)」は足す行の数で、N.z の「spec.patch(138 行)」はファイルの行数である。V32.patch のファイルは 73 行。単位をそろえる。
- N.2 (1) と (3) は「閉じた行の束縛から行変数を取る束縛を呼ぶ形は『…(注釈を extends 付きの形にしてください)』」と書くが、q07(後ろが裸の @ F)の文言は「ラベル Console を足せません(注釈側に Console を…書き足してください)」で別である(実測)。表は「…」で省いているので矛盾しないが、(1) の文は q01 型に限ると書くほうが正確。
- V34 の後の recrowclosed の新しい文言「空の行と一致させられません」は、呼ぶ側の行が {Console} の形でも「空の行」と言う(残りの行の話)。N.2 (3) の「V34 の推奨案は本項目の実測と合う」は助言を外す点については正しいが、文言が読者に伝わるかは diagtext の分野で見る価値がある。
- 合成の順序の要望(M[spec] を V37 と V34 のマイルストーンより前に置く)は、統括者の既定の並び(分野の列で spec は最後)と逆になる。節は逆順の場合の手当て(折り返しのコミットの作り直し、V34 の文言で cram を書く)も書いているので矛盾ではないが、統括者が明示的に決める必要がある。
