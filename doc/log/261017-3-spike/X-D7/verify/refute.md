## 試作の差分

`X-D7.patch` は `diff -ruN` の旧パスが絶対パスなので `patch -p0` では当たらない。
`patch -p1 test/std_names.t < X-D7.patch` で当て、`dune build` と `dune runtest` は差分無し、exit 0 だった。
足した内容は前書き 1 つの後に `$` の行が 7 本(mkdir、printf 3 本、diktor 2 本、`(cd sc && diktor …)` を含む)である。
下書きの「5 コマンド」は数え方の定義(`$` で始まる 1 行)では 7 コマンドである。
前書きが 1 つなので、定義(前書きとコマンドの組)では 1 ブロックである。
16 行は正しい。

変異試験として、写しの `add_class_decl` の第 1 の分岐を `()` に置き換えて `dune runtest` を走らせた。
差分は足したブロック 1 の 1 か所だけで、`! lib/s.kel:1:1: …` と `[1]` が `_ : {}` に変わった。
したがって、足したブロック 1 が第 1 の分岐を固定する唯一の cram であり、HEAD の既存の cram はこの分岐を外しても通る。
これは推奨案の根拠(「退行しても気付けない」)を実測で裏付ける。

## 退行の探索

コードの変更が無いので、HEAD と試作のビルドの出力は全件一致した(`probes.out`、`probes2.out`)。
試したプログラムは次のとおりで、どれも両方のビルドで同じ出力だった。
- import 先で利用者のクラス `Pretty` を宣言し、起点で使う(`<3>`、exit 0)。
- 型パラメータの前提つきインスタンス `[A: Show] Describe[List[_]]` とガード(`head 1`、`head true`、exit 0)。
- `--prelude` で差し替えたプレリュードが利用者のクラスを宣言し、起点が使う(`s : String`、exit 0)。
- module の中の `pub type Show = Int32`(`4`、exit 0)と、トップレベルの `type Show = Int32`(`1`、exit 0)。
- REPL での利用者のクラスの二重宣言、`Eq` の再宣言、その後の `1 == 1`(診断 2 行の後に `true`、exit 0)。
- 推移的な import、`Integral` と `Fractional`、後置の `Show` 宣言、`pub type class Show`(どれも拒否で、両ビルド一致)。

## 判断事項への意見

推奨案に異論は無い。
付記として、`lib/elab.ml:4024-4025` のコメント「組み込みと同名のクラスの宣言は同じ oid なので素通しになり」は、起点の宣言にだけ当てはまる。
import 先の宣言は綴りに印が付いて oid が違い、素通しになる理由は 4033 行の `Type.display_of` どうしの比較である(ソースを読んで導いた性質)。
振る舞いは正しい(import 先の `Show` は「再宣言できません」で落ちることを実測)が、下書きの「ソースコメントは変えない」を保つなら、この不正確さは別項目として残すか、同じコミットで「綴りの表示が同じなので」と直すかを決めるとよい。
