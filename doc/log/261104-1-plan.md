## 0. 要約

1. 付録 B の 1836 行「`<値>` は、Diktor の値の表示(第12章の `show`)で書いた値である」を、ラベルの違うフィールドどうしの順だけを読み手に任せる文に改める(D555)。
   同じ緩めを、`cancel` 節の打ち切りの記録(付録 B の後ろの表、1872 行)の中の `<値>` にも当てる。
2. KIR の版は 1.0 のままにする(D556)。
   付録 B の文面はバイナリに現れず、KIR の節、命令、符号の意味を変えないからである。
   IRSpec 14 節に、版を変えない本文の改訂の扱いを 1 文足し、版の履歴に改訂の行を足す。
3. IRSpec 1 節の「同じ出力」の除外の一覧に、レコードのフィールドの順の項目を足す(D557)。
   付録 B だけを直すと、1 節の「次のものを除いて、同じ出力と同じ終了状態を出す」と食い違う。
4. `keleut repl` の表示の順(V221)も処理系が決めるものとし、いまの「型の行の順」を保つ(D558)。
   LangSpec は REPL の表示の書式を定めていないので、LangSpec は変えない。
5. `keleut repl` が型の配置の上限を超えた型の値を正準の配置の順で書くとき、受理しなかった入力が振ったラベルの番号で表示が変わりうる(V231、【推論】)。
   M104 で測り、変わればラベルの綴りの順で書くように直す(D559)。
6. 試験の道具に、`<値>` の中のレコードのフィールドをラベルの綴りの順に並べ替える関数を 1 つ作り、Diktor の出力とバイト列で比べる 4 か所で使う(D560、D561)。
   4 か所は、kconform の正規化(`cancel` 節の打ち切りの記録の行)、`kconform kir-roundtrip`、`run_cmd.rs` のコーパスの比較、`repl_cmd.rs` のコーパスの比較である。
   `repl_cmd.rs` の「` with ` を含むファイルは標準出力を比べない」という広すぎる除外は、これで置き換える(V233)。
7. `conformance/recshow/` を新設し、レコードを含む `<値>` を書く実行時エラーと `cancel` 節の打ち切りの記録を置く(D562)。
   後段どうしの完全一致の比較で、Rust の `Rt::show` と host の JavaScript の `show` が同じ綴りを書くことを見張る。
8. 記録が「緩めないなら」として挙げていた作業(既知の差の登録、形に印字の順を持たせる改修)は行わない(本計画 2.3 節)。
9. マイルストーンは M102(仕様と文書)、M103(比較の道具と試験)、M104(REPL の表示と V231)、M105(実施記録)の 4 つである(本計画 7 節)。

## 1. 現状

### 1.1 仕様の文

- 付録 B(`doc/IRSpec.md:1831-1874`)は、実行時エラーに Diktor の日本語の文面を使うと定める。
  `<値>` を使う文面は 3 番、4 番、9 番(`<操作><値>`)、12 番である(1842、1843、1848、1851 行)。
  12 番の `<値>` は `Float64` の値なので、レコードは現れない。
- 1836 行は `<値>` を「Diktor の値の表示(第12章の `show`)で書いた値」とする。
  「第12章」は Diktor の `lib/value.ml` である(`diktor/README.md:47`)。
  Diktor の `show` はレコードのフィールドを値のリストの順に書く(`diktor/lib/value.ml:483-488`)。
  拡張は先頭に足し(`value.ml:334`)、更新はその場で差し替える(`value.ml:353-358`)ので、リストの順は作った順で、同じラベルは外側から並ぶ。
- 付録 B の後ろの表(1872 行)は、`cancel` 節の打ち切りの記録を「`cancel 節で例外が抑制されました: …`」とだけ書く。
  記録の「…」は付録 B の文面から `実行時エラー: ` を除いたもので、`<値>` をそのまま含む(`rustkeleut/crates/keleut-rt/src/effect.rs:159-175`、`rustkeleut/host/keleut-host.mjs:687`、`diktor/lib/driver.ml:1110`)。
- IRSpec 1 節(33-45 行)は「本書に従う読み手は、次のものを除いて、同じ KIR のプログラムに対して同じ出力と同じ終了状態を出す」とし、除外を 5 項目挙げる。
  レコードのフィールドの順の項目は無い。
  「出力」が標準エラーを含むかどうかは書いていない。
- IRSpec 6.6 節(567 行)は「レコードの配置は読み手が決め、結果に効かない(§18.3)」と書く。
- IRSpec 14 節(1689-1708 行)は、副版で足してよいものを「読み飛ばせる節と、機能のビットで守る新しい命令だけ」とし、「意味や符号を変えるときは、主版を上げる」とする。
  付録 B の番号は「バイナリには現れない」(1834 行)。
  1.0 の凍結(2026-10-28、f54da8a)の後に IRSpec を変えたコミットは無い。
  草稿 0.3 の間は、版を上げずに本文を直し、履歴の 0.3 の行に追記した(spec.md 2 節)。
- LangSpec §18(1958-1961 行)は、評価の結果を「標準出力に書いたバイト列と終わり方の組」とし、「処理系が表示する型、診断、警告の文面は、評価の結果に含めない」とする。
  §15.5(1792 行)は、実行時エラーと `cancel` 節の打ち切りの記録を診断に含める。
  §15.5(1802-1803 行)は、対話的な実行での診断の出力先を処理系に任せる。
- LangSpec に、レコードの値の表示の順と REPL の表示の書式を定める文は無い(spec.md 1 節)。
  §18.5(2054 行)は「受理した各入力の受理、表示、評価の結果」が、受理しなかった入力を挟んでも変わらないと定める。
  `doc/sample.kel:179-187` が定めるのはタプルの記法と空の行の表記だけである。
- レコード型は `Show` のインスタンスを持たない(§16.2 の表、`diktor/lib/interp.ml:526-531`)。
  プログラムがレコードのフィールドの順を標準出力に書く道は無い。
  順が見えるのは、実行時エラーの文面、`cancel` 節の打ち切りの記録、REPL の表示の 3 つである。

### 1.2 RustKeleut の綴り

- `keleut run` の 3 つの後段は、レコードのフィールドを正準の配置の順(ラベルの番号の昇順、同じラベルは外側から)に書く。
  インタプリタと JIT は `Rt::show`(`rustkeleut/crates/keleut-rt/src/ctx.rs:846-852`、レコードは 922-938 行)を使う。
  WasmGC は host の `show`(`rustkeleut/host/keleut-host.mjs:481-559`)を使い、ラベルの列を rtcore の形の表から取る(475-479 行)。
  印字の実装は Rust と JavaScript の 2 つである(critic.md 2 節)。
- ラベルの番号は、KIR を LIR に下ろすときに初めて出会った順に振る(`rustkeleut/crates/keleut-lir/src/lower.rs:162-171`)。
  そのため、同じ値の綴りが、プログラムのほかの場所に書いたレコードによって変わる。
- 【実測】Diktor と RustKeleut の綴り(`probe/t*.kel`、rk-runtime.md「実測した結果」)。
  終了状態はどれも 3 で、interp、jit、wasm は全件で同じ綴りだった。

  | プログラム | Diktor | keleut run |
  | --- | --- | --- |
  | t1: 型 `{b, a}` の照合の失敗に `{a = 1, b = 2}` | `{a = 1, b = 2}` | `{b = 2, a = 1}` |
  | t2: `{c = 3 extends base}` | `{c = 3, a = 1, b = 2}` | `{a = 1, b = 2, c = 3}` |
  | t3: 前に `let q = {a = 7, b = 8, c = 9}` があり `{b = 1, a = 2, c = 3}` | `{b = 1, a = 2, c = 3}` | `{a = 2, b = 1, c = 3}` |
  | t3b: t3 から `q` を除く | `{b = 1, a = 2, c = 3}` | `{b = 1, a = 2, c = 3}` |
  | t5: ヴァリアントの中 `#P({a = 2, b = 1})` | `#P({a = 2, b = 1})` | `#P({b = 1, a = 2})` |
  | t7: 同じラベル `{x = 1 extends {x = 2, y = 3}}` | `{x = 1, x = 2, y = 3}` | 同じ |
  | t10: タプルの中 | `({a = 1, b = 2}, 3)` | `({b = 2, a = 1}, 3)` |
  | t11: `{z = 3 extends (1, 2)}` | `{z = 3, _item = 1, _item = 2}` | `{_item = 1, _item = 2, z = 3}` |

- 【実測】`cancel` 節の中で t2 の照合を失敗させるプログラム(`probe/gaps/cx.kel`)では、Diktor は `cancel 節で例外が抑制されました: match のどの節にも一致しません: {c = 3, a = 1, b = 2}`、3 つの後段は `{a = 1, b = 2, c = 3}` と書き、どれも 0 で終わった(critic.md 1 節)。
- `keleut repl` は値を `show_value`(`rustkeleut/crates/keleut-cli/src/repl_cmd.rs:936-1047`)で書く。
  フロントエンドが作る型の配置 `Layouts`(`rustkeleut/crates/keleut-front/src/types/session.rs:88-118`)が分かれば型の行の順に並べ替え(`repl_cmd.rs:1013-1039`)、分からなければ正準の配置のまま書く。
  配置の表は項目の数 4096(`LAYOUT_BUDGET`)と型の鍵の長さ 4096(`LAYOUT_KEY_MAX`)で打ち切り、超えた型は分からない値(`Layout::Any`)になる(`session.rs:110-117`)。
- 【実測】`keleut repl` の表示が Diktor と違う形は、注釈の型とリテラルの順が違う束縛、レコードの更新、`if` の 2 つの枝で違う順に作ったレコードである(`probe/r1.txt`、rk-runtime.md「keleut repl の表示」)。
  Diktor の表示は型を行の順、値を作った順で書くので、Diktor の中でも型と値の順がそろわない(`k : {m: Int32, n: Int32} = {n = 1, m = 2}`)。
- 【実測】REPL の実行時エラーの行と `cancel` 節の打ち切りの記録は、Diktor でも keleut でも標準出力に出る。
  keleut ではその `<値>` を `Rt::show` で書くので、前の入力(受理しなかった入力を含む)が振ったラベルの番号で綴りが変わる(`probe/r2.txt`〜`r4.txt`、`probe/gaps/s1.txt`、`s2.txt`)。
  これらの行は §15.5 の診断なので、§18.5 の「表示」には当たらないと読む。

### 1.4 差分試験

### 3.1 付録 B の `<値>`(D555)

### 4.2 型の配置の上限を超えた型の表示(D559、V231)

【推論】型の鍵が 4096 文字を超える型や、配置の表が 4096 項目を超える型の値は `Layout::Any` になり、`show_value` は正準の配置の順で書く(本計画 1.2 節)。
正準の配置はセッションのラベルの番号で決まり、実行時エラーで受理しなかった入力の単位のコードとラベルの番号はセッションに残る(rk-runtime.md「keleut repl の表示」)。
そのため、受理した入力の表示が、前に受理しなかった入力の有無で変わりうる。
これは §18.5 に反し、診断の除外では許されない。

**D559**: M104 で次のとおりに測り、変われば直す。

1. ラベルの違うフィールドを多く持ち、型の鍵が 4096 文字を超えるレコードの型を作る(例: `field_long_name_000` から始まる 200 個のラベル)。
2. セッション A では、そのレコードを受理する入力だけを与える。
   セッション B では、その前に、同じラベルを逆の順で初めて使い、実行時エラーで止まる入力を与える。
3. 2 つのセッションの、受理した入力の表示を比べる。
   型の鍵の上限と配置の表の項目の上限の両方の道で試す。

表示が変われば、`Layout::Any` のレコードのフィールドを、ラベルの綴りのバイト列の順(同じラベルは外側から)で書くように直す。
この順はセッションの履歴に依らない。
直した場合は、2 つのセッションの表示が同じになることを `repl_cmd.rs` の試験にする。
変わらなければ、変わらない理由を実施記録に書き、V231 を閉じる。

代案: 上限を上げる。
上限は正則でない再帰型で表が限りなく伸びるのを止めるためにあり(`session.rs:110-113`)、上げても超える型は残るので採らない。

## 5. 比較の道具と試験

### 5.1 フィールドの順を並べ替える関数と kconform の正規化(D560、V232)

**D560**: kconform に lib の標的を足し、`<値>` の中のレコードのフィールドを並べ替える関数を置く(モジュール名は `fieldsort` を案とする)。
kconform の正規化は、`cancel` 節の打ち切りの記録の行にこの関数を当てる。

関数の仕様:

- 入力は 1 行で、出力は同じ行のレコードのフィールドを並べ替えたものである。
- 当てる範囲は、行の中で次の接頭辞の直後から行末までである。
  - 付録 B の 3 番、4 番、9 番の文面の `<値>` の前まで(`パターンに値が一致しません: `、`match のどの節にも一致しません: `、`handle のどの節にも一致しません: `)。
  - 接頭辞の前に `実行時エラー: ` か `cancel 節で例外が抑制されました: ` があるときだけ当てる。
  14 番の `panic: <文字列>` のように、利用者の文字列をそのまま書く文面には当てない。
- 値の字句は、文字列(`"` で囲み、`\` で次の 1 文字を逃がす)、括弧(`(` `)` `[` `]` `{` `}`)、`,`、` = `、それ以外の文字の並びとする。
  文字列の中の括弧は数えない。
- `{` で始まり、ラベル、` = `、値の組を `, ` で並べて `}` で閉じる部分をレコードとし、内側から順に、フィールドをラベルのバイト列の順に安定に並べ替える。
  安定なので、同じラベルのフィールドは元の順(外側から)のまま残る。
- 字句が読めないときは、行を変えずに返す。

kconform の正規化(`normalize::line`)の変更:

- 行に `cancel 節で例外が抑制されました: ` が含まれ、上の接頭辞が続くときは、行を `fieldsort` で並べ替える。
- 種別の語で切る既存の規則は変えない。
  実行時エラーの行はいまも種別の語の後ろで切られるので、`fieldsort` を当てる必要が無い。

理由:

- 打ち切りの記録の行を種別の語に加えて切る代案(critic.md 1 節の (a))は、記録の中身の比較をすべて失う。
  並べ替えなら、レコードを含まない記録の行はいまと同じく完全に比べられ、既存の試験の結果は変わらない。
- 当てる範囲を接頭辞で限るので、プログラムの標準出力の行や利用者の文字列は並べ替えない。
- 関数を kconform の lib に置くのは、keleut-cli の試験(本計画 5.2 節)からも使うためである。
  kconform はほかの crate に依らないので、keleut-cli の `[dev-dependencies]` に足しても依存は輪にならない。

`conformance/README.md:197-198` の正規化の説明に、打ち切りの記録の並べ替えと、その根拠(D555)を書き足す。

## 12. 進め方の原則

- マイルストーンごとに、実装の後で敵対的な検証を行う。
  観点は、仕様の文(付録 B、1 節、14 節が互いに、また LangSpec §15.5、§18、§18.5 と食い違わないか)、道具の正しさ(`fieldsort` が並べ替えてはいけないものを並べ替えないか、隠す範囲が D555 を超えないか)、試験の網羅(後段どうしの一致が見張られているか)、記録の整合(番号、行番号、台帳)の 4 つを基本とする。
  検証者の指摘ごとに反証者を立て、反証されなかった指摘を直し、直したものを 1 回検証し直す。
- 振る舞いの分類を文書に書くときは、区別する最小の変種を並べて同じ条件で測ってから書く。
- 検証者と担当の書き込み先は scratchpad に限り、報告を受けたら親と diktor の `git status --short` を確かめる。
  本計画の作成中に、調査の担当が親の作業木に `rustkeleut/-o`(KIR のバイナリ)を残し、統括者が消した。
- 本文に逆引用符を含むテキストをシェルで書くときは、ヒアドキュメントを `<<'EOF'` と引用する。
- 既存の `doc/log` の記録は書き換えない。
