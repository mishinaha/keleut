### 1. 見落とし: `cancel` 節の打ち切りの記録は正規化されない(実測で確認)

- **記録の作り方**
  - 記録の文面は「`cancel 節で例外が抑制されました: `」に、付録 B の文面を `実行時エラー: ` 抜きで続けたものです。その中に `<値>` がそのまま入ります。
    - Rust 側: `rustkeleut/crates/keleut-rt/src/effect.rs:159-175` の `suppressed_text`(`Pending::Error(Stop::Runtime(m)) => m.clone()`)と `rustkeleut/crates/keleut-interp/src/interp.rs:1326`。
    - wasm 側: `rustkeleut/host/keleut-host.mjs:687`。
    - Diktor: `diktor/lib/driver.ml:1110` は標準エラーに書き、REPL の `driver.ml:1518` は `printf` で標準出力に書きます。
  - 付録 B の外の表 `doc/IRSpec.md:1872` は、この文面を「`cancel 節で例外が抑制されました: …`」としか書いていません。
- **実測**: `p253/gaps/cx.kel` は、`cancel` 節の中で `{c = 3 extends base}` の照合を失敗させるプログラムです。
  - Diktor の出力は `cancel 節で例外が抑制されました: match のどの節にも一致しません: {c = 3, a = 1, b = 2}`、終了状態は 0 です。
  - interp、jit、wasm の 3 つは `{a = 1, b = 2, c = 3}` と書き、終了状態は 0 です。
- **kconform の結果**
  - Diktor の出力を記録した `p253/gaps/cx.t` を、`kconform --pairs dk,ki,kw,kr-ki` で走らせました。
  - 結果は「差 6 件、既知の差 0 件」です。
  - `normalize.rs:14-21` の種別の語は `型エラー`、`構文エラー`、`字句エラー`、`実行時エラー`、`import エラー`、`未実装` の 6 つで、この記録の行はどれにも当たらないため切られません。
- **LangSpec との関係**: LangSpec:1792 は、`cancel` 節の打ち切りの記録を「診断」に含めています。§18(1960 行)により、評価の結果の外です。仕様の上では差ではありませんが、kconform の正規化がそれに追いついていません。
- **REPL での実測**(`p253/gaps/s1.txt` と `s2.txt`)
  - `keleut repl` では、この記録が受理した入力の標準出力に出ます(`2>/dev/null` でも残ります)。
  - 前に実行時エラーで受理しなかった入力が `b` を先に使っていると、綴りは `{b = 2, a = 1}` になります。その入力が無いと `{a = 1, b = 2}` です。Diktor はどちらも `{a = 1, b = 2}` と書きます。
  - LangSpec:1792 によりこの行は診断なので、§18.5(2054 行)には反しないと読みます。計画にはこの読み方を書いておく必要があります。
- **計画の候補**(どちらかを決める)
  - (a) kconform の正規化に「`cancel 節で例外が抑制されました`」を加える。合わせて計画 261024-1 の 8.1 節の規則の扱い、`normalize.rs` の試験、`conformance/README.md:197-198` を直します。
  - (b) 付録 B の緩めが、`cancel` 節の打ち切りの記録の中の `<値>` にも及ぶと IRSpec:1872 に書くだけにして、正規化は変えない。
  - どちらの場合も、付録 B を緩める文の範囲に IRSpec:1872 の記録を入れる必要があります。
- **既存の試験への影響**: `diktor/test` と `conformance` にある `抑制されました` の行に、レコードを含むものはありません(eval.t、never_ops.t、tail_calls.t、ir_depth.t、depth/retry.t、bytes/sinkfail.t、depth/handlers.t を見た範囲)。conform のコーパス全件の比較が差 0 件だったこととも合います。いまの試験は落ちません。
- **試験を足すときの使い道**: 正規化されない経路なので、`conformance/` に `.t` を置けば正準の配置の綴りを記録との比較で固定できます。ただし (a) を選ぶと、この使い道はなくなります。
