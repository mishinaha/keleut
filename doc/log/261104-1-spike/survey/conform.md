## 1. kconform の比べ方

**標準出力と標準エラーは 1 本にして比べる**
- `runner.rs:191` は `. {} > {} 2>&1` で、cram と同じく 2 つの出力を 1 本にして読みます。

**正規化は「実行時エラー: 」の後ろを丸ごと捨てる**
- `crates/kconform/src/normalize.rs:13-21` と `line()` は、種別の語(`実行時エラー` など)に `: ` が続く行を、その語の直後で切ります。
- そのため、付録 B の `<値>` を含む文面は Diktor と比べる対象に入りません。
- この正規化は、標準出力の行にも標準エラーの行にも同じように当たります。
- 記録との比較(`main.rs:529`)と、基準の組との比較(`main.rs:567`)の両方が、正規化した行で比べます。
- 正規化の前だけ違うものは `--verbose` のときに「正規化の前の不一致」として印字されるだけで、失敗にはなりません(`main.rs:530`、`main.rs:568`、`main.rs:643-652`)。
- 根拠は計画 261024-1 の 8.1 節の末尾「標準エラーは、種別の語の後ろを切り…」と、LangSpec §18 の冒頭です(`doc/LangSpec.md:1959-1960`。「処理系が表示する…診断…の文面は、評価の結果に含めない」)。

**後段どうしは完全一致を求め、既知の差では許さない**
- 書き手ごとの群(`ki kj kt ka km kw` と `kr-*`)の中では、正規化をせずに比べます(`main.rs:372-436`、`backend_group_diffs`)。
- この比較の種類は `Comparison::Backend` です。`known_diffs.rs:89-104` の `Against::allows` は、どの値もこの比較を許しません(D499)。
- 書き手の違う群どうし(`ki` と `kr-ki`)は比べません(`main.rs:378`)。

**既知の差の鍵は粗い**
- 項目の鍵は file、`$` の行、pairs、ledger、`when`、`against` です(`known_diffs.rs:1-35`)。
- `when` は `"unimplemented"` だけで、`keleut: 未実装` の行より前が一致するときだけ当たります。
- `against` は `record`、`pair`、省略(両方)のどれかです。
- 当たる単位はコマンドの出力全体で、行やパターンの単位では書けません。V228 や V221 を登録すると、同じコマンドのほかの差まで隠すことになります。

**`known-diffs.toml` にレコードの順に関わる項目は無い**
- いまある一覧は `conformance/known-diffs.toml` の 1 つだけです。
- 74 項目の台帳の番号は V213 が 37 件、V217 が 31 件、V215 が 4 件、V218 が 2 件で、V221 と V228 は 0 件です。
- `known-diffs-*.toml` は 1 つもありません。過去の `known-diffs-unimplemented.toml`(V219)と `known-diffs-wasm-g.toml`(V220)は M89 と M95 で消えています(README:187-194、コミット 2352519 と 86e956c)。

## 3. 小さな例で確かめた振る舞い(scratchpad の `p253/kc/`)

**V228 は再現し、後段どうしは一致する**
- 例は `b.kel` です。`base = {a = 1, b = 2}` を `{c = 3 extends base}` で広げ、照合に失敗させます。

  - interp、jit、wasm の 3 つはどれも `{a = 1, b = 2, c = 3}` と書きます。
  - `KELEUT_DIKTOR` を与えた `--frontend diktor` でも同じです。
- 例 `c.kel` は `{c=7,b=8,a=9}` をあらかじめ書いておくもので、keleut の綴りは `{c = 3, b = 1, a = 2}` になりました。ラベルの番号に依って綴りが変わる性質は、記録 2100 行の記述どおりです。

## 5. 計画の作業の候補

**(a) 既知の差の登録:要らない**
- 理由 1:いまの試験群に該当するコマンドが 0 件で、`kconform` の「使われなかった既知の差」になるだけです(M101 の締めで残した V213 の 22 件と同じ扱いになります)。
- 理由 2:鍵がコマンド単位で粗く、関係の無い差まで隠します。
- 理由 3:実行時エラーの文面はもともと正規化で比べない対象です。
- 記録 2107 行の「緩めないなら…既知の差を登録する」は、緩める方針では不要になります。

**(b) 比較の正規化を足す:kconform には要らない**
- `<値>` はすでに捨てています。
- REPL の束縛の表示(V221)だけは正規化の外です。直すなら「`name : 型 = 値` のレコードのフィールドを並べ替える」正規化が必要で、値を構文として読まなければなりません(推測:入れ子、文字列の中の `{`、`<fn>` があって脆い)。
- 該当する試験が 0 件なので、正規化は作らないのが妥当だと考えます(推測)。
- ただし、V221 が P253 の答えに含まれるかは計画で明記すべきです。記録 5684 行に「REPL の表示の順(V221)も同じ答えに従う」とあります。

**(c) Diktor と比べる Rust の試験の扱い:計画で決める**
- `repl_cmd.rs` の ` with ` による除外を、次のどれかに改める候補があります。
  - `ir_emit/0004-rec.kel` に限った除外にする。
  - P253 に基づく旨と台帳の番号(V221)をコメントに書く。
  - そのまま残す。
- `run_cmd.rs:282` と `roundtrip.rs:291` の生の比較について、将来レコードの `<値>` が入ったときにどうするかを決めておく。
  - 候補 1:`実行時エラー: ` の行を kconform と同じ規則で正規化してから比べる。
  - 候補 2:何もせず、該当が出た時点で直す。
- いま必要なのは方針を書くことだけで、コードの変更はいまは要りません。

**(d) 後段どうしの一致の試験を足す:任意**
- いまは、後段の間の完全一致(D499)が、レコードを含む `<値>` で一度も試されていません。
- `conformance/`(たとえば `prim/` に足すか、新しい cram)にレコードの `<値>` を持つ実行時エラーを置く候補があります。
  - `kconform` の後段の群の比較で、interp、jit、wasm の正準の配置の一致を固定できます(`keleut-wasm/src/meta.rs` と `keleut-interp/src/interp.rs` は印字を別々に実装しています)。
  - 組 `dk` との比較は正規化で通るので、既知の差は要りません(`rec.t` で確かめました)。
