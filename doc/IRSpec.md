# KIR 仕様

版 0.2(草稿)。

本書は、Keleut の中間言語 KIR(Keleut Intermediate Representation)を定める。
0.2 は草稿であり、1.0 までは版ごとに中身を変えうる。
書き手と読み手は、同じ `0.y` の版の本書に字句どおり従わなければならない。
0.2 では、バイナリ(13 節)の節の中身と命令の番号がまだ決まっていない。
1.0 までの版の扱いは 14 節に書く。

本書が「言語仕様」と書くときは `doc/LangSpec.md` を指し、その節を「§13.6」のように書く。
本書の節は「本書 9 節」のように書く。

## 1. 適用範囲

KIR は、型検査と精緻化を済ませた Keleut のプログラムを表す中間言語である。
ファイルの形は 2 つある。

| 拡張子 | 形 |
| --- | --- |
| `.kir` | バイナリ(本書 13 節) |
| `.kirt` | 正準のテキスト(本書 12 節)。バイナリと 1 対 1 に往復する |

**書き手**:Keleut のソースから KIR を作る処理系。
Diktor(`diktor --emit-ir`)と RustKeleut のフロントエンド(`keleut emit-kir`)がこれにあたる。
**読み手**:KIR を読み込み、検証し、実行する処理系。
Diktor(`diktor --run-ir`)と RustKeleut(`keleut run`)がこれにあたる。

KIR のプログラムの意味は、それを書き出した元の Keleut のプログラムの、言語仕様が定める意味である。
言語仕様が処理系に任せている点のうち、実行の結果に効くもの(論理的な深さの限度と、1 回の確保の要素の数の上限)は、本書 11 節が値と数え方を定める。
深さの限度を検査する読み手は、どれも同じ深さを数え、同じ位置で `depth_limit` にする(本書 11.2 節〜11.5 節)。
`N_alloc_max` の検査は RustKeleut のすべての後段が同じ値で行い、Diktor(`--run-ir`)は行わない(本書 11.6 節)。

本書に従う読み手は、次のものを除いて、同じ KIR のプログラムに対して同じ出力と同じ終了状態を出す。

- `sin`、`cos`、`exp`、`log` の結果の 1 ulp の違い(正しい値に最も近い 2 つの `Float64` のどちらを返すか)。
  言語仕様 §17 が処理系に任せている。
- 1 回の確保の要素の数が `N_alloc_max` を超える場合。
  RustKeleut の後段はメモリの不足(3)で終わり、Diktor(`--run-ir`)は検査しないので確保が成功しうる(本書 11.6 節)。
- `N_alloc_max` の検査によらないメモリの不足。
  RustKeleut の WasmGC の後段が V8 のヒープを使い尽くした場合(3 でなく 70 で終わる)と、Diktor での確保がこれにあたる(本書 11.1 節、11.6 節)。

KIR を作る段で、書き手は次のものを済ませる。

- 構文の脱糖(`if`、タプル、`with`、末尾ブロック)。
- 名前の解決(大域は記号、局所はスロットの番号)。
- クロージャ変換(関数ごとの捕獲の列。辞書の引数も捕獲する)。
- 辞書渡しの明示(証拠の平坦化、インスタンスの頭の解決、メソッドの辞書の位置)。
- 数値リテラルの確定と module の平坦化。
- 末尾の印と操作節の分類(本書 5.3 節、9.2 節)。
- `run` の消去と、二項演算子と前置の `-` のメソッド呼び出しへの書き換え。

KIR は木であり、子は符号化に現れる順に評価する(本書 5 節)。
ANF にはしない。

RustKeleut の内部の形(LIR とバイトコード)は本書の対象ではない。
それらはファイルに書かず、互換性も約束しない。

読み手の検証(本書 13.3 節)は、型の健全性を保証しない。
型の健全性は、型検査を済ませた書き手が保証する。

## 2. プログラムと単位

### 2.1 プログラム

`.kir` の 1 ファイルは、自己完結のプログラムである。
組み込みとプレリュードを含むすべての単位を、次の順に並べて持つ。

1. 組み込みの単位 `builtin`。
2. プレリュードの単位 `prelude`。
3. 起点が import する単位を、初期化の順(§15.4。import を書いた順に深さ優先でたどった帰りがけ順)に並べたもの。
4. 起点の単位 `main`。

**単位**:鍵、元のファイルの綴りの列、初期化の手順(本書 10 節)の列を持つ、プログラムの部分。
`builtin` の単位は初期化の手順を持たない。
`--no-prelude` で走らせた書き手も、手順の無い `prelude` の単位を書く。

単位ごとの `.kir` と、その結合(分割コンパイル)は 0.y では定めない。

### 2.2 単位の鍵

単位の鍵は次の規則で決める。
鍵は、処理系のプロセスや作業ディレクトリによらず、コマンド行と import の文で決まる。
例外は、下の起点のディレクトリを綴りから決められないときで、そのときだけファイルシステムを引く。

| 単位 | 鍵 |
| --- | --- |
| 組み込み | `builtin` |
| プレリュード | `prelude` |
| コマンド行の起点(複数のファイルを連結した 1 単位) | `main` |
| import した単位 | 下の規則で決めた、`.kel` で終わる綴り |

import した単位の鍵は、その単位に初めて到達した import の文から決める。
初めて到達した文とは、起点のファイルを書いた順にたどり、各ファイルの import を書いた順に深さ優先でたどったとき、最初に現れたその単位への import の文である。

- **正規化**:綴りを `/` で成分に分け、空の成分と `.` を除き、`..` を直前の成分と相殺する。
  次の 3 つの `..` は相殺せずに残す。
  直前の成分が無い `..`、直前の成分が `..` である `..`、直前の成分が先頭の成分で `@` と 1 個以上の数字だけからなる(下の検索パスの印)`..` である。
  先頭の `/` も空の成分として除くので、正規化した綴りは `/` で始まらない。
- **基準のディレクトリ** `B`:コマンド行の最初のファイルの `dirname`(POSIX の `dirname` で、`/` を含まない名前では `.`)。
- **ディレクトリ** `dir(K)`:鍵 `K` の最後の `/` より前の部分で、`/` を含まない鍵では空の綴りである。
- **起点のディレクトリ**:起点の j 番目のファイルの `dirname` を `D` とする。
  `B` と `D` を正規化した成分の列から、共通の先頭の成分を除く。
  `B` の残りの成分の数だけ `..` を並べ、`D` の残りの成分を続けて `/` でつないだ綴りを、そのファイルの `dir(K)` とする(`B` と `D` が同じなら空)。
  `B` と `D` の一方だけが `/` で始まるときと、`B` の残りの成分に `..` があるときは、綴りから相対パスを決められない。
  そのときは、`B` と `D` の `realpath` を同じ規則にかけた綴りを使う。
- **相対パスの import**(`./p` と `../p`):import を書いたファイルの鍵を `K` とする。
  `dir(K)`、import のパスの綴り、`.kel` を連結し(`dir(K)` が空でなければ間に `/` を置く)、正規化した綴りを鍵とする。
- **検索パスの import**:`--import-path` の i 番目(1 から数える)のディレクトリで見つけたファイルの鍵は、`@i/`、import のパスの綴り、`.kel` を連結したものである。
  複数の i で同じファイルが見つかったときは、最小の i を使う。

鍵は `.kel` で終わるので、`builtin`、`prelude`、`main` と重ならない。
例を示す。
`diktor a/m.kel` が `./lib/x` を import し、`a/lib/x.kel` が `../y` を import すると、鍵は `lib/x.kel` と `y.kel` になる。
`--import-path vendor` の下の `util` は `@1/util.kel` になる。
`diktor a/m.kel c.kel` で、`a/m.kel` と `c.kel` がどちらも `./w` を import すると、鍵は `w.kel`(`a/w.kel`)と `../w.kel`(`w.kel`)になる。
起点を絶対パスで書いても、鍵は変わらない。

この規則は綴りだけで鍵を決めるので、別のファイルが同じ鍵になることがある。
たとえば、シンボリックリンクのディレクトリの下の `..` は、綴りの相殺と OS の解決で別のディレクトリを指す。
書き手は、別のファイル(`realpath` が違うファイル)の単位が同じ鍵になったら、KIR を書かずに使い方の誤り(終了状態 64)で終える。

### 2.3 元のファイルの綴り

単位の `paths` は、診断のための綴りの列であり、実行の意味に使わない。

| 単位 | `paths` |
| --- | --- |
| `builtin` | 空 |
| `prelude` | 埋め込みのプレリュードなら `<prelude>`、`--prelude PATH` なら `PATH`、`--no-prelude` なら空 |
| `main` | コマンド行に書いたファイルの綴りの列(書いた順) |
| import した単位 | 下の規則で決めた表示の綴り 1 個 |

import した単位の表示の綴りは、Diktor が診断の位置に書くファイル名でもある。
次の手順で決める。
ここでの正規化は、本書 2.2 節の正規化と次の 2 点で違う。
先頭の `/` を残すことと、`@` で始まる成分を特別に扱わないことである。

1. **相対パスの import**:import を書いたファイルの表示の綴りの `dirname` を `P` とする。
   起点のファイルの表示の綴りは、コマンド行に書いた綴りそのものである。
   `P`、`/`、import のパスの綴り、`.kel` を連結して正規化した綴りを `S` とする。
2. **検索パスの import**:そのファイルを見つけた `--import-path` のディレクトリのうち、番号が最小のものの綴り(書いたまま。空なら `.`)を `P` とする。
   `P`、`/`、import のパスの綴り、`.kel` を連結して正規化した綴りを `S` とする。
3. **開くパス**:相対パスの import では、import を書いたファイルの開くパスの `dirname` と、import のパスの綴りに `.kel` を付けたものを、`/` でつないだ綴りである。
   起点のファイルの開くパスは、コマンド行に書いた綴りである。
   検索パスの import では、ディレクトリの綴りと、パスの綴りに `.kel` を付けたものを、`/` でつないだ綴りである(ディレクトリが空ならつながない)。
4. `S` の `realpath` が開くパスの `realpath` と同じなら、`S` を表示の綴りにする。
   違うとき(シンボリックリンクの下の `..`)と `S` を解決できないときは、開くパスから空の成分と `.` の成分だけを除いた綴り(先頭の `/` は残す)を表示の綴りにする。

表示の綴りは作業ディレクトリによって変わる。
テキストを比べるときは、同じ作業ディレクトリと同じ引数で書いたもの同士を比べる。

## 3. 名前

### 3.1 記号

Diktor のオブジェクトの番号やハンドラの起動の番号のように、1 つのプロセスの中でしか通用しない番号は、KIR に書かない。
KIR は表の項目を記号で名指す。

**記号**:`単位の鍵/名前` の形の文字列。
名前の部分は `/` を含まない。
そのため、記号の単位の鍵は、記号の最後の `/` より前の部分である。

**修飾名**:module の平坦化の後の名前(`M.f`、`M.N.T` など)。
Diktor が起点でない単位の宣言に付ける `%N.` の印は、修飾名に含めない。
Keleut の識別子は `$`、`#`、`:`、`[`、`]`、`/` を含まないので、本書 3.2 節〜3.4 節が名前に付ける接尾辞と印(`#n`、`instance:`、`$init<k>`、`$n`、`$h<n>`)は、利用者の名前と重ならない。

記号はリンクと診断にだけ使い、実行時の意味には使わない(§18.1)。
記号の文字列は表ごとに一意である。
大域の記号と関数の記号は別の表に属するので、同じ文字列でもよい(本書 3.4 節)。

### 3.2 大域

大域の記号は `単位の鍵/修飾名` である。
同じ単位で同じ修飾名を再び束縛したときは、2 つ目に `#1`、3 つ目に `#2` を付ける(`main/x`、`main/x#1`、`main/x#2`)。
再束縛した名前は別の実体である(§6.1)。
数えるのは、単位の初期化の手順(本書 10 節)が定義する大域で、手順の順、手順の中の並びの順に数える。
`extern` の宣言も数える。

組み込みの値の記号は `builtin/Ref.new` などである(付録 A)。

### 3.3 型、エフェクト、クラス、インスタンス

| 対象 | 記号か名前 |
| --- | --- |
| 名目的な型 | `単位の鍵/修飾名`。組み込みの型は `builtin/Int32` など(付録 A) |
| コンストラクタ | 宣言に書いた名前(`Some`)。module の中の型のコンストラクタも module の名前を付けない(`main/M.Tree` の `Leaf`)。型の記号と組で名指す |
| エフェクト | `単位の鍵/修飾名` |
| 操作 | エフェクトの中の短い名前(`write`)。エフェクトの記号と組で名指す |
| クラス | `単位の鍵/修飾名`。組み込みのクラスは `builtin/Eq` など(付録 A) |
| メソッド | クラスの中の短い名前(`eq`)。クラスの記号と組で名指す |
| インスタンス | `単位の鍵/instance:C[H]`。`C` と `H` はクラスと頭の型構成子の記号の名前の部分 |

インスタンスの単位は、インスタンスを宣言した単位である。
同じ単位で同じ `C[H]` の綴りが 2 回現れたとき(別の単位の同名の型に対するインスタンス)は、大域と同じく 2 つ目から `#1`、`#2` を付ける。
例は `prelude/instance:Show[List]` である。

### 3.4 関数

**根の関数**:トップレベルの実体ごとに 1 個ある関数。
次の表の記号を持つ。

| 実体 | 根の関数の記号 |
| --- | --- |
| 種類が `fn` か `dictabs` の大域 `g` | `g` と同じ文字列 |
| `def_value g` の初期化式 | `g` と同じ文字列 |
| `def_pattern` の初期化式と `run_exp` の式 | `単位の鍵/$init<k>`。`k` は、その手順の単位の中での番号(0 から数える)。手順を作らない宣言(型の宣言、辞書を受け取る式文など)は数えない |
| インスタンス `I` のメソッド `m` の実装 | `I` の記号に `.m` を付けたもの(`prelude/instance:Show[List].show`) |

**持ち上げた関数**:根の関数の本体の中で作る関数。
持ち上げた関数を作る式は、`closure`、`dictabs`、`handle` の 3 種である。
この 3 種の式を**場所**と呼ぶ。

場所の番号は次のとおりに振る。
根の関数を、正準のテキスト(本書 12 節)に現れる順にたどる。
場所に着いたら、その場所に次の番号(0 から数える)を振り、続けてその場所が作る関数の中身をたどってから、場所の後ろへ進む。
`handle` の場所では、本体、操作節(書いた順)、`return` 節、`cancel` 節の関数をこの順にたどる。
関数の中身は、操作節のパターンとガード、本体の順にたどる。
番号は、根の関数ごとに 0 から振り直す。
入れ子の場所も、根の関数の通し番号を受け取る。

持ち上げた関数の記号は、根の関数の記号 `R` と場所の番号 `n` から作る。

| 場所 | 関数の記号 |
| --- | --- |
| `closure`、`dictabs` | `R$n` |
| `handle` の本体 | `R$h<n>.body` |
| `handle` の操作 `op` の操作節 | `R$h<n>.op.<op>`。同じ操作の 2 つ目の節から `#1`、`#2` を付ける |
| `handle` の `return` 節 | `R$h<n>.return` |
| `handle` の `cancel` 節 | `R$h<n>.cancel` |

たとえば、`main/f` の本体の最初のラムダの中にハンドラ式があれば、ラムダは `main/f$0`、ハンドラの本体は `main/f$h1.body` である。
同じ操作 `ask` に 2 つの節を書いたハンドラの節は、`$h1.op.ask` と `$h1.op.ask#1` である。

### 3.5 短い名前と局所

レコードとヴァリアントのラベル、コンストラクタ、操作、メソッドの名前は、記号ではなく短い名前で書く。
バイナリはこれらを文字列の表(本書 13 節)の添字で表す。
局所は、関数の中のスロットの番号で表す(本書 6.4 節)。

### 3.6 決定性

書き出しは決定的でなければならない。
書き手は、同じ入力(同じコマンド行、同じファイルの中身)からは、プロセスが違っても同じバイト列を出す。
表の並び(本書 12.4 節)はどれも宣言の順か本書が定める固定の順であり、ハッシュ表の走査の順を使ってはならない。

## 4. Rep

**Rep**:値の機械の上の表現の種類。
`bool`、`i32`、`i64`、`f64`、`str`、`any` の 6 種がある。

型 `τ` の Rep `rep(τ)` は、`τ` の束縛の鎖をたどった結果が引数の無い型構成子 `Boolean`、`Int32`、`Int64`、`Float64`、`String` ならそれぞれ `bool`、`i32`、`i64`、`f64`、`str` であり、ほか(型変数、関数、レコードを含む)は `any` である。

Rep は次の場所に付ける。

| 場所 | Rep |
| --- | --- |
| 引数のスロット | 仮引数のパターンのノードの型の Rep |
| 局所のスロット | そのスロットを束縛する変数のパターンのノードの型の Rep。`let` の名前の変数では、束縛の型の Rep。`closure` と `dictabs` を束縛するスロットは `any` |
| 捕獲 | 捕獲した元の変数の Rep。辞書の引数を捕獲したものは `any` |
| 関数の結果 | 本書 6.2 節 |
| 種類が `value` の大域 | 束縛する変数のパターンのノードの型の Rep。`let` の名前の変数では、束縛の型の Rep |

Rep は検証と最適化のためのものであり、プログラムの意味を変えない。
読み手は、関数の境目でどの Rep の値をどう渡すかを、自分で決めてよい。
末尾の印(本書 5.3 節)は Rep に依らない。

**`yield` の印**:関数と `call` に付ける 1 ビット。
`noyield` は、継続の取り出しがその関数やその呼び出しの外へ及ばないことを表す。
`yield` と `noyield` は次の規則で決め、書き手はこの規則のとおりに書く。

- 型 `τ` が `noyield` であるとは、`τ` の束縛の鎖をたどった結果が関数の型で、そのエフェクト行が閉じていて、行のラベルがすべてプレリュードの `Console`、組み込みの `Heap`、組み込みの `Blocking` のどれかであることをいう。
- 種類が `lambda` の関数は、そのラムダか関数の定義の型が `noyield` なら `noyield`、ほかは `yield` である。
- ほかの種類の関数は `yield` である。
- `call` は、呼び出し先の式の型が `noyield` なら `noyield`、ほかは `yield` である。

この印は最適化にだけ効く。

完全な型は、読み飛ばせる節 types-debug(本書 13 節)に文面で置く。
読み手の検証は、完全な型を使わない。

## 5. 式と評価順序

### 5.1 式

式の子は、正準のテキスト(本書 12 節)に現れる順に評価する。
レコードの拡張と更新のように評価の順が構文の順と違う式は、テキストに子を評価の順に書く。
次の表の「テキスト」の列は本書 12.5 節の文法の形で、`e` は式、`d` は辞書の式、`p` はパターン、`N` は非負の整数を表す。

| 式 | テキスト | 評価の順と意味 |
| --- | --- | --- |
| 定数 | `(lit bool true)`、`(lit i32 N)`、`(lit i64 N)`、`(lit f64 0xHHHHHHHHHHHHHHHH)`、`(lit str "…")` | 定数。`f64` は IEEE 754 のビット列である |
| 範囲外のリテラル | `(lit_error lit_range "字面")` | 評価したら実行時エラーになる(本書 10.4 節) |
| 局所 | `(local N)` | スロット `N` を読む |
| 捕獲 | `(env N)` | 捕獲の `N` 番目を読む |
| 大域 | `(global "記号")` | 大域を読む。初期化の前なら実行時エラーになる(本書 10.3 節) |
| 構築 | `(construct "型" C (field N e)…)` | `e` を書いた順に評価し、それぞれをフィールドの位置 `N` に格納する。項目はソースに書いた順に並べる |
| ヴァリアント | `(variant L e)` | `e` を評価し、ラベル `L` を付ける。積載値の無いヴァリアントは `e` が `(rec_empty)` である |
| 呼び出し | `(call tail\|ntail yield\|noyield f a…)` | `f` を先に、次に引数を左から評価して呼ぶ(§5.1) |
| メソッドの値 | `(method "クラス" m d o…)` | `d` と `o` を評価し、メソッドの値を作る(本書 5.4 節) |
| 演算子の呼び出し | `(opcall "クラス" m d a…)` | `d`、引数の順に評価し、メソッドを選んで呼ぶ。末尾の呼び出しにならない |
| 否定 | `(not e)` | |
| 論理積、論理和 | `(and e1 e2)`、`(or e1 e2)` | 短絡する |
| クロージャ | `(closure "関数" c…)` | 捕獲 `c` を左から読み、関数と組にする |
| 辞書の抽象 | `(dictabs "関数" c…)` | 捕獲を左から読み、種類 `dictabs` の関数と組にする。本体は評価しない |
| 辞書の適用 | `(dictapp e d…)` | `e` を評価し、次に `d` を左から評価し、`e` の値に辞書を渡す(本書 7.5 節) |
| 束縛 | `(let N e1 e2)` | `e1` の値をスロット `N` に置いて `e2` を評価する |
| パターンの束縛 | `(letpat p e1 e2)` | `e1` の値を `p` と照合する。一致しなければ実行時エラーになる |
| 再帰の束縛 | `(letrec (rec N e)… e0)` | 各 `e`(`closure` か `dictabs`)の値をすべて作ってスロット `N` に置いてから、捕獲を埋める。そのため捕獲は群のどのスロットも読める。その後で `e0` を評価する |
| 列 | `(seq e1 … en)` | 左から評価し、最後の値を返す。`n` は 2 以上である |
| 照合 | `(match e (clause p e1)…)`、ガード付きは `(clause p (guard g) e1)` | `e` を 1 回評価し、節を上から試す(本書 8 節) |
| 空のレコード | `(rec_empty)` | Unit でもある |
| レコードの拡張 | `(rec_extend L v r)` | `v` を先に、`r` を後に評価し、`r` の最も外側にラベル `L` を足す |
| 選択 | `(rec_select L e)` | 最も外側の `L` のフィールドを読む |
| 制限 | `(rec_restrict L e)` | 最も外側の `L` のフィールドを 1 つ除く |
| 更新 | `(rec_update L r v)` | `r` を先に、`v` を後に評価し、最も外側の `L` のフィールドを置き換える。フィールドの位置は変えない |
| `perform` | `(perform "エフェクト" op a…)` | 引数を左から評価し、最も内側のハンドラへ送る(本書 9 節) |
| ハンドラ式 | `(handle tail\|ntail "エフェクト" (body "関数" c…) (op op N\|T\|G "関数" c…)… [(return "関数" c…)] [(cancel "関数" c…)])` | 各部分の捕獲を書いた順に読んでから、本体の関数を呼ぶ(本書 9 節) |
| `resume` | `(resume tail\|ntail e)` | `e` を評価してから、継続が再開済みかを調べて再開する(本書 9.5 節) |
| 穴 | `(hole)` | `???`。評価したら実行時エラーになる |

ラベル `L`、コンストラクタ `C`、メソッド `m`、操作 `op` は短い名前である(本書 12.2 節)。
`!=` は `(not (opcall "builtin/Eq" eq d l r))` にする。

### 5.2 辞書の式

辞書の式は次の 5 種である(本書 7 節)。
辞書の式の評価はエフェクトを起こさず、実行時エラーにもならない。

| 式 | テキスト | 意味 |
| --- | --- | --- |
| インスタンス | `(dinst "インスタンス" d…)` | 利用者が宣言したインスタンスに、前提の辞書を渡したもの |
| 辞書の引数 | `(dparam N)` | 関数の辞書の引数の `N` 番目 |
| 捕獲 | `(env N)` | 捕獲した辞書 |
| レコード | `(drecord (field L d)…)` | 閉じたレコード型の構造的な `Eq` の辞書 |
| ヴァリアント | `(dvariant (field L d)…)` | 閉じたヴァリアント型の構造的な `Eq` の辞書 |
| 組み込み | `(dbuiltin "クラス" "型")` | 組み込みのインスタンス(付録 A) |

### 5.3 末尾の印

`call`、`handle`、`resume` は、`tail` か `ntail` の印を必ず持つ。
印は、本節の規則で計算した末尾位置にその式があるとき `tail` で、ほかは `ntail` である。
読み手の検証は末尾位置を計算し直し、印と違えば拒否する。

末尾位置は、関数ごとに本体を根としてたどって決める。
根が末尾位置かどうかは、関数の種類で決まる。

| 関数の種類 | 本体の根 |
| --- | --- |
| `lambda` | 末尾位置 |
| 分類 N の `opclause`、`retclause` | その関数を持つ `handle` の印が `tail` なら末尾位置 |
| ほか(`thunk`、`dictabs`、`handlebody`、分類 T と G の `opclause`、`cancelclause`) | 末尾位置でない |

末尾位置にある式の子のうち、次のものだけが末尾位置にある。
ほかの子は末尾位置にない。

- `let`、`letpat`、`letrec` の続きの式(最後の子)。
- `seq` の最後の子。
- `match` の各節の本体(ガードと照合対象は末尾位置にない)。
- `and` と `or` の右辺。

`opcall`、`perform`、`dictapp` は、末尾位置にあっても末尾の呼び出しにならない。

**`resume` の背骨**:分類 T と G の `opclause` の本体を根とし、上の 4 つの規則でたどった末尾位置。
`resume` の印は、背骨の上にあるとき `tail`、ほかは `ntail` である。
背骨は `handle`、`closure`、`dictabs` の作る関数には入らない。
これらは別の関数だからである。
そのため、T と G の節の中のハンドラ式の本体(`handlebody` の関数)に書いた `resume` は、背骨の上になく `ntail` である(本書 9.2 節)。

本節の規則は §5.7 を関数ごとに書き直したものである。
§5.7 が末尾位置とするハンドラ式の `return` 節と再開しない操作の節の本体は、そのハンドラ式が末尾位置にあるときに限って、上の表で根を末尾位置にする。
同じハンドラの末尾位置にない `resume` で再開した計算の中でそれらの節を評価するときは、末尾の呼び出しが返す先がその `resume` になる。
読み手は、それでも節の関数の領域を一定に保つ。

### 5.4 メソッドの値

`(method "C" m d o…)` は、`d` と `o…` を評価して**メソッドの値**を作る。
メソッドの値を作る時点では、インスタンスを選ばない。
メソッドの値を引数とともに呼ぶと、引数をすべて評価した後で、`d` の辞書から次の手順でメソッドを選んで呼ぶ。

1. `d` が `dinst(I, ps)` の値なら、インスタンス `I` が初期化済みかを調べる。
   初期化の前なら実行時エラー(付録 B の「インスタンスは宣言より前の位置では使えません」)になる。
   初期化済みなら、`I` のメソッド `m` の実装の関数に、辞書の列 `ps ++ o…` を渡して値を得る(本書 7.4 節)。
   その値を引数とともに呼ぶ。
2. `d` が `dbuiltin(C, T)` の値なら、付録 A の組み込みのメソッドを呼ぶ。
3. `d` が `drecord` か `dvariant` の値なら、`C` は `builtin/Eq` で、構造的な等値比較を行う(§12.5)。

`(opcall "C" m d a…)` は、`(call ntail noyield (method "C" m d) a…)` と同じ時点で同じメソッドを選ぶ。
`opcall` は自分の辞書を `o` に持たない。
演算子のメソッドの型は自分の制約を持たないからである。

メソッドの値を 1 回呼ぶことは、論理的な深さ(本書 11 節)では、選んだ実装を 1 回呼ぶことと数える。
選んだメソッドの値を覚えておき、次の呼び出しで使い回すことは観測できないので、読み手に許す。
インスタンスは、一度初期化されたら初期化の前に戻らないからである。

### 5.5 書き手の写し方

書き手は、精緻化を済ませた木の各構文を次のとおりに写す。
2 つの書き手が同じバイト列を出すために、この写し方は規範である。

| 構文 | KIR |
| --- | --- |
| 真偽値、文字列 | `lit` |
| 数値 | 型の Rep の `lit`。範囲外の整数なら `lit_error`(本書 10.4 節) |
| 局所の変数 | `local` か `env`。辞書を受け取る局所の束縛なら、それを `dictapp` で包む |
| トップレベルの値 | `global`。辞書を渡す使用なら `dictapp` で包む |
| 組み込みの値 | `global "builtin/…"` |
| クラスのメソッド | `method`。使用の辞書の列(メソッドのスキーマの正準順。本書 7.1 節)のうち、クラスの引数の型変数とそのクラスの組の位置にある辞書を `d` に、残りをその列の順に `o` に置く。たとえば `[B: Show + Eq]` の `o` は `Eq`、`Show` の順である |
| 引数の無いコンストラクタの参照 | フィールドの無い `construct` |
| `???` | `hole` |
| 適用 `f(a…)` | `call`。引数のレコード(`_item` の行)を、外側の要素から順に引数の列にする |
| コンストラクタの適用 | `construct` |
| ヴァリアント | `variant` |
| `&&`、`\|\|` | `and`、`or` |
| ほかの二項演算子 | 組み込みのクラスの `opcall`(`!=` は `not` で包む) |
| `!e` | `not` |
| 前置の `-` | `(opcall "builtin/Neg" neg d e)` |
| ラムダ | `closure` |
| 関数の定義の `let` | `let` で `closure` を束縛する。辞書を受け取るなら `dictabs` を束縛する(本書 7.5 節) |
| 値の `let` | 名前が変数なら `let`。辞書を受け取るなら `dictabs` を束縛する。名前がほかのパターンなら `letpat` |
| `let rec` | `letrec`。各項目は `closure`、辞書を受け取るものは `dictabs` |
| 文の列 | 要素が 0 個なら `rec_empty`、1 個ならその式、2 個以上なら `seq` |
| `match` | `match` |
| レコードの 5 つの操作 | `rec_empty`、`rec_extend`、`rec_select`、`rec_restrict`、`rec_update` |
| `perform` | `perform`。引数のレコードを引数の列にする |
| ハンドラ式 | `handle` |
| `resume()`、`resume(e)` | `(resume … (rec_empty))`、`(resume … e)` |
| `run h { e }` | `e`(`run` は消す) |

`if`、タプル、`with`、末尾ブロックは構文解析の段で脱糖されている。
型注釈のパターンは外す。

## 6. 関数と捕獲

### 6.1 関数の種類

関数の表の各項目は、次の 7 種のどれかである。

| 種類 | 作る場所 | 引数 | 辞書の引数 | 捕獲 |
| --- | --- | --- | --- | --- |
| `lambda` | ラムダ、関数の定義、種類 `fn` の大域 | 仮引数の数 | 0 | 外側の変数 |
| `opclause` | `handle` の操作節 | 操作の引数の数 | 0 | 外側の変数 |
| `retclause` | `handle` の `return` 節 | 1 | 0 | 外側の変数 |
| `cancelclause` | `handle` の `cancel` 節 | 0 | 0 | 外側の変数 |
| `handlebody` | `handle` の本体 | 0 | 0 | 外側の変数 |
| `thunk` | `def_value`、`def_pattern`、`run_exp` の式 | 0 | 0 | 0 |
| `dictabs` | 辞書を受け取る束縛、インスタンスのメソッドの実装 | 0 | 受け取る辞書の数 | 外側の変数 |

根の関数(本書 3.4 節)は捕獲を持たない。
トップレベルの名前は `global` で読むからである。

### 6.2 欄

関数の項目は次の欄を持つ。

- 記号(本書 3.4 節)と種類。
- `yield` の印(本書 4 節)。
- `params`:引数のスロットの Rep の列。
- `locals`:引数でないスロットの Rep の列。
  スロットの番号は、引数が `0` から、続けて局所が並ぶ。
- `dicts`:辞書の引数の数。
- `caps`:捕獲の Rep の列。
- `result`:結果の Rep。
- `opclause` だけが持つ `pats`(引数ごとのパターン)と、省略できる `guard`(ガードの式)。
- 本体の式。

結果の Rep は、本体にあたるソースの式の型の Rep である。

| 種類 | 結果の Rep を決める式 |
| --- | --- |
| `lambda` | ラムダか関数の定義の本体 |
| `opclause`、`retclause`、`cancelclause` | 節の本体 |
| `handlebody` | ハンドラ式の本体 |
| `thunk` | 初期化式か式文。辞書を受け取る値束縛を名前でないパターンに束縛する `def_pattern` では `any`(本体は初期化式を本体とする `dictabs` の場所で、その関数の結果の Rep が初期化式の Rep である) |
| `dictabs` | 値の束縛の初期化式。関数の定義とインスタンスのメソッドの実装では `any` |

本体の中では、捕獲を `env(i)` で、辞書の引数を `dparam(i)` で、スロットを `local(i)` で読む。

### 6.3 仮引数のパターン

`lambda` と `retclause` の仮引数は、次のとおりに写す。
`j` 番目の仮引数のパターン(型注釈を外したもの)を `p` とする。

- `p` が変数なら、その変数はスロット `j` そのものである。
- `p` が `_` なら、何もしない。
- ほかのパターンなら、本体を `(letpat p' (local j) …)` で包む。
  `p'` は `p` を写したパターンである。
  包みは仮引数の順に、最初の仮引数を最も外側にする。

照合が失敗したときは、`letpat` と同じ実行時エラーになる。

`opclause` の仮引数は、`pats` の欄に書く。
`j` 番目のパターンを `local j` と照合する。
変数のパターンはスロット `j` そのものとし、`(wild)` と書く。
ほかのパターンは写したものを書く。
どれかが一致しない節は飛ばして、次の節を試す(本書 9.4 節)。

### 6.4 スロットの番号

スロットの番号は、関数ごとに次の規則で振る。

1. 引数に `0` から `n−1` を振る。
2. 続けて、関数を正準のテキストに現れる順にたどり、スロットを束縛する箇所に着くたびに次の番号を振る。
   束縛する箇所は、`let` の `N`、`letrec` の `rec` の `N`、パターンの `bind`(`letpat`、`match` の節、`opclause` の `pats` のもの)である。
   たどる順は、`pats`、`guard`、本体である。
   持ち上げた関数の中には入らない。

そのため、テキストを先頭から読むと、束縛の番号は `n`、`n+1`、`n+2` と 1 ずつ増える。
1 つのスロットを束縛する箇所はちょうど 1 つで、スロットを使い回さない。
たとえば `(let 2 (let 3 e1 e2) e3)` の `3` は、外側の `let` の `2` より後に現れるので `3` である。

`def_pattern` のパターン(本書 10.1 節)の `bind` は、スロットではなく、手順が定義する大域の列の番号を指す。
この番号も現れる順に `0` から振る。

### 6.5 捕獲

持ち上げた関数 `F` の捕獲は、`F` の本体(`F` の中で持ち上げた関数の捕獲の列を含む)が読む、外側の関数の変数の集まりである。
使わない変数は捕獲しない。

捕獲の列は、外側の関数での読み方の順に並べる。
`dparam` を番号の昇順に、続けて `env` を番号の昇順に、続けて `local` を番号の昇順に並べる。
`F` の中の `env(i)` は、この列の `i` 番目である。
場所の式(`closure`、`dictabs`、`handle` の各部分)は、この列を外側の関数での読み方(`(dparam N)`、`(env N)`、`(local N)`)で書く。

`letrec` の項目は、群のスロット(自分を含む)を捕獲してよい。
`letrec` は、すべての値を作ってから捕獲を埋めるからである。

### 6.6 データ

名目的な型の値は、型の記号、コンストラクタ、フィールドの値の列からなる。
フィールドは宣言の順に置く。
コンストラクタは第一級の値ではない。

レコードは、ラベルで操作する式(本書 5.1 節の `rec_*`)のまま表す。
レコードの配置は読み手が決め、結果に効かない(§18.3)。
ヴァリアントは、ラベルと積載値 1 個からなる。

## 7. 辞書

### 7.1 辞書の引数の順

辞書を受け取る束縛の辞書の引数の順(**正準順**)は、束縛の一般化した型 `τ` から次のとおりに決める。

1. `τ` を左から深さ優先にたどる。
   型構成子の適用は引数を左から、関数の型は引数のレコード、結果、エフェクト行の順にたどる。
   レコードとヴァリアントの行は、各フィールドの型を、ラベルの綴りのバイト列の昇順にたどり、最後に行の尾部をたどる。
   同じラベルのフィールドが 2 つ以上あるときは、外側のものを先にたどる。
2. 一般化した型変数に初めて着いたら、その変数に付いた制約のクラスを、クラスの表(本書 12.4 節)での位置の昇順に列に足す。
   予約述語(`Integral`、`Fractional`)は足さない。
   同じ変数に再び着いても何も足さない。

列の `i` 番目の制約の辞書が `dparam(i)` である。
使う側も、同じ正準順で辞書を渡す。

型の行の中のフィールドの並びと、型変数に制約が付く順は、型検査がソースのどの部分を先に処理したかで変わる。
正準順はどちらも使わないので、型だけから決まる。
たとえば `show(r.b) + show(r.a)` と `show(r.a) + show(r.b)` の `r` の型は、どちらも `a` のフィールドの制約を先にする。
`[A: Show + Eq]` と `[A: Eq + Show]` は、どちらも `Eq` を先にする。
Diktor では、この順を第8章(unify.ml)の `constraints_of` が決める。

### 7.2 インスタンス

インスタンスの項目は、記号、クラス、頭の型構成子、前提の数、メソッドの実装の列を持つ。
前提の辞書の順は、インスタンスの宣言の型パラメータを左から、各パラメータの制約を書いた順に並べたものである。
`dinst(I, [前提…])` の前提もこの順である。

メソッドの実装の項目は、`(method m k "関数")` である。
`m` はメソッドの名前、`k` はメソッド自身の辞書の数(クラスの宣言のメソッドの型の制約のうち、クラスの引数のクラスの制約を除いたものの数)、`"関数"` は実装の関数である。
項目はインスタンスの本体に書いた順に並べる。

### 7.3 メソッドの実装の関数

実装の関数は種類 `dictabs` で、辞書の引数の数は `前提の数 + k` である。
辞書の引数は `前提の辞書 ++ メソッド自身の辞書` の順に受け取る。
本体は、メソッドの束縛の値 `V` である。

| メソッドの束縛 | `V` |
| --- | --- |
| 関数の定義 | `closure` |
| 値の束縛 | 初期化式 |
| `let rec` の群の 1 つ | 群全体の `letrec` で、続きの式がそのメソッドのスロットを読むもの |

実装の型が自分の制約を持つとき(インスタンスの宣言の型よりも一般的な実装)は、`V` の代わりに `(dictapp (dictabs "F" c…) d…)` を本体にする。
`F` は辞書の引数を実装の型の正準順に受け取り、本体が `V` の `dictabs` の関数である。
`d…` は、インスタンスの文脈でその制約を満たす辞書である。
`let rec` の群の 1 つのメソッドでは、自分の制約を持つ項目が群の `letrec` の中ですでに `dictabs` なので、本体は `(dictapp V d…)` である。

### 7.4 メソッドの選択

`(method "C" m d o…)` のメソッドの値は、本書 5.4 節のとおりにメソッドを選ぶ。
`dinst(I, ps)` の辞書では、`I` の `m` の実装の関数に `ps ++ o…` を渡す。
実装の関数の辞書の数が 0 のものは、`def_instance` が 1 回だけ評価した値(本書 10.1 節)を使う。

使う側の辞書の列は、メソッドのスキーマの正準順(本書 7.1 節)である。
書き手は、そのうちクラスの引数の型変数とそのクラスの組の位置にある辞書を `d` にし、残りを順に `o…` にする。

### 7.5 辞書の適用と使うたびの評価

`(dictapp e d…)` は、`e` の値に辞書の列を渡す。

| `e` の値 | 結果 |
| --- | --- |
| `dictabs` の値(局所の束縛か、種類 `dictabs` の大域) | 関数の本体を、辞書の引数を `d…` にして評価した値 |
| 辞書を受け取る `extern` の大域 | その `extern` の値。辞書は捨てる |

**使うたびの評価**:辞書を受け取る値束縛は、使うたびに初期化式を評価する(§6.4、§12.2)。
読み手が結果を保存して再び使ってよいのは、`dictabs` の関数の本体が構文上 `closure` のときだけである。
同じ辞書の列で前の結果を返す覚え込みは、ほかの本体でも観測できないので許す。
初期化式はエフェクトを起こせず、1 回目が実行時エラーになるか停止しないなら 2 回目の評価に届かないからである。

### 7.6 構造的な辞書と組み込みの辞書

`drecord` と `dvariant` は `builtin/Eq` の辞書であり、閉じた行の型にだけ現れる。
項目は、ラベルと、そのフィールドの型の `Eq` の辞書である。
項目は、ラベルの綴りのバイト列の昇順に並べる。
同じラベルが行に 2 回現れたときは 2 つの項目を書き、外側のフィールドの項目を先にする。
`drecord` の比較は、項目を書いた順に、両辺の最も外側の同名のフィールドを取り出して比べ、取り出した残りで次の項目へ進む。
比べた項目が偽なら、その時点で結果を偽とし、残りの項目の辞書を呼ばない。
結果が真になるのは、すべての項目が等しく、両辺の残りが空になったときだけである。
利用者のインスタンスが実行時エラーになるか停止しないとき、比べるのをどこでやめるかは観測できる。
`dvariant` の比較は、ラベルが等しく、そのラベルの項目の辞書で積載値が等しいときに真である。

`dbuiltin(C, T)` は組み込みのインスタンスである。
書き手は、型検査がインスタンスとして選んだ組 `(C, T)` が組み込みのインスタンス(付録 A)なら `dbuiltin` を、利用者の宣言したインスタンスなら `dinst` を書く。

## 8. パターン

パターンは次の 6 種である。

| パターン | テキスト | 意味 |
| --- | --- | --- |
| ワイルドカード | `(wild)` | 値を受け取り、束縛しない |
| 変数 | `(bind N)` | 値をスロット `N` に束縛する |
| リテラル | `(lit …)` | 値がリテラルと等しいかを調べる |
| レコード | `(record closed\|open (field L p)…)`、`(record rest (field L p)… p0)` | 書いた順に、各ラベルの最も外側のフィールドを取り出して `p` と照合し、取り出した残りで次へ進む。`rest` は最後の残りを `p0` と照合する |
| コンストラクタ | `(ctor "型" C (field N p)…)` | コンストラクタが `C` で、各フィールドの位置 `N` の値が `p` に一致するかを調べる |
| ヴァリアント | `(variant L p)` | ラベルが `L` で、積載値が `p` に一致するかを調べる |

積載値を書かないヴァリアントのパターン `#L` は、`(variant L (record closed))` と書く。
積載値の位置は、空のタプルのパターンである。
積載値の無いヴァリアントの式が `(variant L (rec_empty))` であることに対応する。

照合は、項目を書いた順に進め、一致しない項目に着いたらそこで失敗する。
ラベルの無いレコードとの照合は、実行時エラーではなく照合の失敗である。

レコードのパターンの `closed`(タプルのパターン)と `open`(既定のレコードのパターン)は、照合では同じに働く。
残りのフィールドが無いことは型検査が保証しているからである。

コンストラクタのパターンの項目は、ソースに書いたフィールドだけを、フィールドの位置の昇順に並べる。
書かなかったフィールドには触れない。

数値の `lit` は、照合する値の型で読んだ値として書く(`case 0xFFFFFFFF` は `Int32` の `-1` である)。
パターンの数値は型検査が範囲を確かめるので、パターンに `lit_error` は現れない。
`f64` の `lit` は、IEEE 754 の `==` で照合する(§11.1)。
そのため `0.0` の `lit` は `-0.0` にも一致し、NaN にはどの `lit` も一致しない。
`str` の `lit` は、バイト列が等しいときに一致する。

`match` は、節の順とガードを保つ。
ガードは、パターンが一致した節だけで評価する。
ガードが偽なら次の節へ進む。
どの節にも一致しなければ実行時エラーになる(§11.2)。
決定木は読み手が作ってよいが、ガードを評価する順と回数を変えてはならない。

## 9. エフェクトと抽象機械

本節は、エフェクトの意味を抽象機械の言葉で定める。
本節の規則は、読み手がハンドラと継続をどう実装するかに依らない。
本節の文は §13 を KIR の水準で書き直したものであり、§13 と食い違うときは §13 に合わせて本書を直す。

### 9.1 ハンドラと操作節

`handle` は、エフェクト、本体の関数、操作節の列、`return` 節(省略できる)、`cancel` 節(省略できる)を持つ。
操作節は、引数のパターン、ガード(省略できる)、本体を 1 つの `opclause` の関数にまとめたものである。
操作の名前と分類は、`handle` の操作節の項目 `(op op N|T|G "関数" c…)` に書く(本書 5.1 節)。
1 つの `handle` は 1 つのエフェクトを処理する(§13.4)。

### 9.2 操作節の分類

各操作節は、N、T、G のどれか 1 つに分類する。

| 分類 | 条件 |
| --- | --- |
| N | 操作の返り値の型が `Never` である |
| T | N でなく、本体の中の `resume` がすべて末尾の `resume` である(`resume` の無い枝を含んでよい) |
| G | それ以外 |

書き手は分類を書く。
読み手の検証は、操作の `never` の印と、`resume` の `tail` の印から分類を計算し直し、書いた分類と違えば拒否する。

`resume` を書けるのは、T と G の節の本体の中と、その本体の中のハンドラ式の本体(`handlebody` の関数。入れ子のハンドラ式の本体を含む)の中だけである。
操作節のガード(種類 `opclause` の関数の `(guard …)` の欄)、`return` 節、`cancel` 節、N の節、ラムダの本体には書けない。
T か G の節の本体の中、またはその下の `handlebody` の関数の中にある `match` のガードは、その本体の一部である。
そこには `resume` を書ける。
ガードは背骨の上にないので(本書 5.3 節)、その `resume` は `ntail` であり、囲む操作節は G になる。
読み手の検証は、ほかの位置の `resume` を拒否する。

`handlebody` の関数の中の `resume` は、その関数を作ったハンドラ式を囲む操作節の継続を再開する。
間の `handlebody` の関数は、囲む関数の継続をそのまま受け継ぐ。
この `resume` は背骨の上にないので `ntail` であり(本書 5.3 節)、囲む操作節は G になる。
Diktor の型検査は、操作節の本体の中のハンドラ式の本体に書いた外側の節の `resume` を受理する。

### 9.3 抽象機械の状態

抽象機械は、評価の文脈ごとに次のものを持つ。

- **ハンドラの連鎖**:有効なハンドラの起動の列。
  最も内側の起動が先頭にある。
- **ハンドラの起動**:`handle` を 1 回評価するたびに作るもの。
  エフェクト、節、`return` 節、`cancel` 節、親の起動、深さ `h`(本書 11 節)を持つ。
- **継続**:G の節が受け取る、中断した計算。
  1 回だけ再開できる。
  節の外へは持ち出せない。

ハンドラの起動の同一性は、64 ビットの単調に増える番号で表す。
巻き戻しの宛先は、この番号で名指す。
同じ `handle` の式を入れ子に起動したとき(再帰や、同じ関数の 2 回の呼び出し)、内側の起動が外側の起動宛ての巻き戻しを受け取ってはならない。

### 9.4 `perform`

`perform(E, op, [a…])` は、引数を左から評価した後、次の順に進む。

1. ハンドラの連鎖から、エフェクトが `E` である最も内側の起動を探す。
2. 操作節を上から試す。
   パターンが一致した節だけでガードを評価する。
   パターンが一致しない節とガードが偽の節は飛ばして、次の節へ進む。
3. 選んだ節の分類で分ける。
   - T:節の本体を評価する。
     末尾の `resume(v)` は、`perform` の値を `v` にする。
     `resume` しないで節が値 `r` になったときは、`perform` の位置から宛先の起動までの計算を破棄し、`r` をハンドラ式の値にする。
   - N:`perform` の位置から宛先の起動までの計算を破棄し、その後でハンドラの外で節の本体を評価する(9.6 節の 2)。
     ガードは破棄の前に評価してある。
   - G:`perform` の位置から宛先の起動までの計算を継続として取り出し、宛先の起動を連鎖から外して、節の本体を継続とともに評価する。

どの節にも一致しない操作を外側のハンドラへ送り直すことはない。

`runtime` の印の付いた操作(プレリュードの `Console` の `write`。本書 12.5 節)の `perform` は、KIR ではほかの操作と同じに書く。
プレリュードの `Console` は利用者が処理できず、最も外側の実行時が処理する。
読み手は、`runtime` の印の付いた操作の `perform` を実行時の直接の呼び出しにしてよい。
そのときも、標準出力への書き込みの順と失敗の扱い(9.7 節)は変えない。
`user` の操作の `perform` は、名前が `Console` のエフェクトのものでも、この扱いにしてはならない。

### 9.5 `resume`

`resume(e, tail)` は、まず `e` を評価する。
その後で、継続がすでに再開されていれば実行時エラーにする。
再開されていなければ、再開済みの印を立ててから再開する。
`e` の評価の中で同じ継続を再開したときも、この検査で外側の `resume` が実行時エラーになる(§13.5)。

再開した計算の中では、継続を取り出したハンドラの起動が再び連鎖に入る。
再開した計算の中で決まった `return` 節の値と、`resume` しない節の値は、ハンドラ式の値ではなく、この `resume` の値になる(§13.6)。

末尾の `resume` で再開するとき、読み手は節の評価のために持っていた情報を捨てる。
T の節と N の節の本体と `return` 節は、繰り返し起動しても一定の領域で評価できなければならない(§5.7)。
G の節の末尾でない `resume` の領域は保証しない。

### 9.6 規範の文

次の文は、上の各節の規則の中で、取り違えやすい点を定める。

1. 本体の側から届いた巻き戻しの宛先がこのハンドラの起動でないときは、このハンドラの `cancel` 節を 1 回走らせてから巻き戻しを続ける。
   宛先がこの起動なら、`cancel` 節を走らせない。
   `return` 節も走らせない。
2. `return` 節は、ハンドラを連鎖から外した後で評価する。
   そのため、`return` 節の中の誤りでは、自分の `cancel` 節を走らせない。
   N の節の本体も、継続を破棄してハンドラを外した後で評価する。
   G の節の中で `resume` が戻った後のコードも、そのハンドラが連鎖にいない文脈で走る(§13.6)。
3. 節の選択(パターンとガード)と、T の節の本体では、ハンドラの連鎖を、そのハンドラの親に付け替える。
   そのため、節の中で起こした操作は外側のハンドラへ届く(§13.4)。
   節を抜けたら、連鎖を `perform` の時点のものに戻す。
4. `cancel` 節は、自分のハンドラの外で走る。
   `cancel` 節の中で起きた脱出(実行時エラー、破棄、論理的な深さの限度)は、すべて打ち切る。
   打ち切ったら、標準出力を flush してから標準エラーに記録し、元の巻き戻しを続ける。
   標準出力への書き込みがすでに失敗しているときは、この flush は何もしない(9.7 節)。
5. ハンドラの起動の同一性は、64 ビットの単調に増える番号で表す(9.3 節)。

### 9.7 巻き戻しと `cancel` の順序

巻き戻しは、破棄する計算の中のハンドラを、内側から外側の順にたどる。
宛先でない起動に着くたびに、9.6 節の 1 のとおり `cancel` 節を走らせる。

T と G の節が `resume` の前に脱出したとき(`resume` の引数の評価中を含む)は、節の評価の中で起動したハンドラの `cancel` 節、継続の中の `cancel` 節(内側から外側の順)、宛先の起動の `cancel` 節、さらに外側の順に走らせる(§13.6)。
宛先の起動の継続はまだ生きているからである。
G の節が `resume` の後に脱出したときは、宛先の起動はもう連鎖にいないので、その `cancel` 節は走らせない。

N の節では、ガードの評価が破棄より先にある。
ガードの中の脱出では継続がまだ生きているので、宛先の起動の `cancel` 節を走らせる。
本体の中の脱出は、ハンドラ式の後ろで起きたものとして扱い、宛先の起動の `return` 節と `cancel` 節を走らせない。

`cancel` 節の中から、まだ連鎖にいるハンドラの G の操作を起こしてよい。
そのハンドラが継続を再開すると、`cancel` 節の続きと、中断していた巻き戻しの続きが走る。

実行時エラーは操作ではなく、ハンドラで捕まえられない。
実行時エラーが起きると、有効なハンドラを内側から外側の順に巻き戻し、各起動の `cancel` 節を走らせる(§15.5)。
最上位に届いたら、標準出力を flush し、文面(付録 B)を標準エラーに書いて、終了状態 3 で終わる。

`runtime` の印の付いた操作(プレリュードの `Console` の `write`)の書き込みが失敗したら、その失敗を実行時エラーと同じに巻き戻し、`cancel` 節を走らせてから終了状態 74 で終わる。
最初の失敗で未出力のバッファを捨て、その後の flush は何もせず、誤りも起こさない。

## 10. 初期化

### 10.1 手順

各単位の初期化は、次の 6 種の手順の列である。
読み手は、単位を本書 2.1 節の順に、各単位の手順を書いた順に実行する。

| 手順 | テキスト | 意味 |
| --- | --- | --- |
| `def_value` | `(def_value "大域" "関数")` | `thunk` の関数を評価して大域に置き、初期化済みにする |
| `def_pattern` | `(def_pattern "関数" (globals "大域"…) p)` | `thunk` の関数を評価し、結果をパターン `p` と照合する。一致しなければ実行時エラーにする(文面は `letpat` と同じ)。一致すれば、束縛した各大域に置き、列の順に初期化済みにする |
| `def_fns` | `(def_fns "大域"…)` | 種類が `fn`、`dictabs`、`extern` の大域を、評価せずに初期化済みにする |
| `def_dictabs` | `(def_dictabs "大域")` | 辞書を受け取る値束縛の大域を、評価せずに初期化済みにする(本書 7.5 節) |
| `def_instance` | `(def_instance "インスタンス")` | 辞書の引数の数が 0 の実装の関数を、メソッドを書いた順に 1 回だけ評価し、すべて評価し終えてからインスタンスを初期化済みにする |
| `run_exp` | `(run_exp "関数")` | `thunk` の関数を評価し、値を捨てる |

`def_pattern` の `p` の `bind k` は、大域の列の `k` 番目に束縛することを表す(本書 6.4 節)。
`def_instance` で評価した値は、メソッドを選ぶたびに使い回す。
実装の関数を評価している間、インスタンスは初期化の前である。
その間にそのインスタンスからメソッドを選ぶと、実行時エラー(付録 B の 6 番)になる(本書 5.4 節)。
したがって、まだ評価していない実装の値を選ぶことは起こらない。
たとえば `let k = { let n = sz(B(1)); fn(b) => n }` を実装に持つ `Sz[B]` のインスタンスは、`k` を評価する中で `Sz[B]` の `sz` を選ぶので、`def_instance` の中で実行時エラーになる。

### 10.2 宣言の写し方

書き手は、各単位のトップレベルの宣言を、書いた順(module の平坦化の後の順)に次のとおりに写す。

| 宣言 | 手順と大域 |
| --- | --- |
| 関数の定義の `let`(仮引数を持つ) | `def_fns`。辞書を受け取らなければ種類 `fn`、受け取れば種類 `dictabs` で、`dictabs` の関数の本体は `closure` |
| 値の `let` で、名前が変数で辞書を受け取らないもの | `def_value`。種類 `value` |
| 値の `let` で、名前が変数で辞書を受け取るもの | `def_dictabs`。種類 `dictabs` で、関数の本体は初期化式 |
| 値の `let` で、名前が変数でないもの | `def_pattern`。束縛する変数ごとに種類 `value` の大域。`_` だけなら大域の列は空 |
| `let rec` の群 | 群全体で 1 つの `def_fns`。各項目は辞書を受け取らなければ `fn`、受け取れば `dictabs` |
| `extern` | `def_fns`。種類 `extern` |
| `type instance` | `def_instance` |
| 式文 | 辞書を受け取らなければ `run_exp`。受け取るものは何も書かない |
| `newtype`、`effect`、`type class` | 手順を書かない(型、エフェクト、クラスの表に書く) |
| `type`(型エイリアス) | 何も書かない。型の表にも項目を作らない |

`let rec` の項目の右辺がラムダ(`let rec f = fn(x) => …`)のときは、そのラムダを関数の定義と同じに扱う。
種類 `fn` の大域の関数は、そのラムダか関数の定義の `lambda` の関数で、記号は大域と同じである。

### 10.3 初期化済みの印

大域とインスタンスは、初期化済みの印を持つ。
種類が `builtin` の大域は、プログラムの開始の時点で初期化済みである。
初期化の前の大域を読むと実行時エラー(付録 B の「未束縛の変数」)になる。
初期化の前のインスタンスからメソッドを選ぶと実行時エラー(付録 B)になる(本書 5.4 節)。

**検査を省いてよい条件**:読み手が大域 `g` の初期化の検査を省いてよいのは、`g` の参照を含む最も外側のトップレベルの実体の手順が `g` の手順より後にあるときと、両者が同じ `def_fns` の手順にあるときだけである。
たとえば `let p = {f = fn(x) => h(x)}` で `h` が後に宣言されているときは、ここで作った無名関数を `h` の初期化の前に呼べるので、検査を省いてはならない。

### 10.4 範囲外のリテラル

範囲外の数値リテラルは `(lit_error lit_range "字面")` とする。
これは評価したときに初めて実行時エラー(付録 B の「数値リテラルが範囲外です」)になる。
読み手は、これを畳み込んだり、前へ動かしたり、消したりしてはならない(§4.2)。

字面は次の 3 つを空白を挟まずに連結した綴りである。

1. リテラルに `-` を畳み込んだとき(§4.2)だけ `-`。
   `-` とリテラルの間の空白とコメントは字面に入れない。
2. ソースに書いた数字の綴り。
   `0x`、`0o`、`0b` の前置と区切りの `_` を残す。
3. ソースに書いた接尾辞(`i32` など)。書いていなければ何も書かない。

たとえば `- 2147483649` の字面は `-2147483649`、`0x1_0000_0000i32` の字面は `0x1_0000_0000i32` である。
Diktor では、この綴りを `Lexer.show_number` が作る。

数値リテラルの値は、書き手が型の頭の Rep で確定させる。
`i32` と `i64` は言語仕様 §4.2 の範囲と綴りの規則で読む。
`f64` は次の規則で読む。

1. 接尾辞(`f64` など)を除いた数字の綴りから、区切りの `_` をすべて除く。
   `1_f64` や `1.0_` のような末尾の `_` も除く。
2. 残りを 10 進の数として読み、IEEE 754 の binary64 に正しく丸めた値にする(最も近い値へ丸め、等距離なら偶数へ丸める)。
   `99999999999999999999f64` のような整数の綴りに接尾辞 `f64` を付けたものも、同じに読む。
3. 絶対値が binary64 の範囲を超えるものは +inf にし、`-` を畳み込んだ(§4.2)ときは -inf にする。
   小さすぎるものは非正規化数か ±0 になる。

`f64` のリテラルは `lit_error` にならない。
`Float64` のリテラルが `0x`、`0o`、`0b` の前置を持つことはない。
字句解析が `0b101f64` のような綴りを拒むか、`0x10f64` のように整数のリテラルとして読むからであり、`Float64` は `Integral` のインスタンスでない。
たとえば `1e400` は `0x7ff0000000000000`、`- 1e400` は `0xfff0000000000000`、`1_000.5` は `0x408f440000000000`、`2.5e-324` は `0x0000000000000001` である。
言語仕様 §4.2 は無限大を直接書くリテラルは無いとしているが、`1e400` は無限大に評価される。
この食い違いは言語仕様の側で決める問いとして残す。
`-` を畳み込んだ `0x`、`0o`、`0b` のリテラルは、`-` を除いた数字を型のビット幅のビット列として読み(§4.2)、その値を型のビット幅で桁あふれさせて符号を反転する。
ビット幅に収まるかの検査は、`-` を除いた数字に対して行う。
`Int32` の例を示す。

| リテラル | 値 |
| --- | --- |
| `-0x80000000` | `-2147483648` |
| `-0xffffffff` | `1` |
| `-0x1ffffffff` | `lit_error`(字面は `-0x1ffffffff`) |

## 11. 実行時エラーと論理的な深さ

### 11.1 実行時エラーの種類

KIR の評価が止まる誤りは、次の 4 種である。

| 種類 | 起きる場面 | 終了状態 |
| --- | --- | --- |
| 実行時エラー | 言語仕様が「実行時エラーになる」と書く場面(付録 B) | 3 |
| `depth_limit` | 論理的な深さが限度を超えた(11.2 節〜11.5 節) | 3 |
| メモリの不足 | 確保の要素の数が `N_alloc_max` を超えた(11.6 節)か、読み手がヒープを広げられない | 3(注) |
| 出力の失敗 | 標準出力に書けない(本書 9.7 節) | 74 |

どれも、有効なハンドラを内側から巻き戻して `cancel` 節を走らせる(本書 9.7 節)。
文面は付録 B に定める。

注:RustKeleut の WasmGC の後段では、V8 のヒープそのものを使い尽くすと Node のプロセスが落ち、`cancel` 節を走らせずに 70 で終わる。
これは §15.5 からの既知の逸脱で、本書 1 節が同じ結果の保証から除くものである。

### 11.2 論理的な深さ

§15.5 は、評価に要する領域の限度の大きさを処理系に任せている。
一方で、限度を超えたときの振る舞い(`cancel` 節を走らせて終了状態 3)は結果に効く。
そこで本書は、評価の各文脈に整数の深さ `d` を定め、すべての読み手が同じ値を数えるようにする。
深さは、読み手のスタックの使い方とは無関係に、次の表の境目で決まる。

| 場面 | 深さ |
| --- | --- |
| 最上位の初期化の手順 | 0 |
| 深さ `d` の文脈での末尾でない `call`、`opcall`、`dictapp` と、組み込みが利用者の関数を呼ぶ呼び出し(組み込みの中で末尾の位置にあっても、この行で数える) | 呼ばれた側は `d+1` |
| 末尾の呼び出し、末尾の `resume` | 呼び出し元の深さを引き継ぐ(増えない) |
| 深さ `h` の `handle` の本体 | `h+1` |
| 深さ `p` の `perform` の、節の選択(パターンとガード)と T の節の本体 | `p+1` |
| G の節の本体(宛先のハンドラの起動の深さを `h` とする) | `h+1` |
| G の節の中の、深さ `c` での末尾でない `resume`(継続の深さの差を `Δ = p − h` とする) | 再開した `perform` は深さ `c+Δ` で値を返す |
| N の節の本体、`return` 節 | `h`(ハンドラ式の位置の深さを引き継ぐ) |
| `cancel` 節 | 巻き戻されるハンドラの起動の `h` |

ここで、ハンドラの起動の深さ `h` は、その `handle` の式を評価した文脈の深さである。

`runtime` の印の付いた操作(プレリュードの `Console` の `write`。本書 12.5 節)の `perform` は、深さを変えず、限度の検査もしない。
`user` の操作の `perform` は、名前が `Console` のエフェクトのものでも、上の表の行に従う。

読み手が内部で使う呼び出し(ハンドラの本体への呼び出しや、インライン展開など)は、上の表のとおりに数え、読み手の中の呼び出しの数では数えない。

### 11.3 限度の検査

読み手は、表で深さが増えるすべての境目で、新しい深さを限度 `L` と比べる。
対象は、末尾でない呼び出し、`handle` の本体に入るとき、節の選択、T の節の本体、G の節の本体、末尾でない `resume` である。
新しい深さが `L` を超えるときは、その境目に入る前に `depth_limit` にする。

末尾でない `resume` では、再開した `perform` の深さ `c+Δ` を、継続を再開する前に `L` と比べる。

### 11.4 再開での深さのずれ

深さ `c` で継続 `K` を再開するとき(`K` を取り出したハンドラの起動の深さを `h` とする)、`K` の中の各文脈の深さと、`K` の中で始まったすべてのハンドラの起動の `h` を、`c − h` だけずらす。
`K` を取り出したハンドラの起動自身の `h` は `c` になる。
そのため、再開した計算の中で走るそのハンドラの `return` 節と、`resume` しない節は、深さ `c` で走る。
これは、それらの値がこの `resume` の値になること(本書 9.5 節)と合う。

`K` の中で始まったハンドラの起動は、`K` が持つ連鎖の切り取りの中のものだけではない。
T の節(またはガード)を評価している間は、そのハンドラの起動と、`perform` の位置からそのハンドラまでの起動が、連鎖から外れている(本書 9.6 節の 3)。
その節の中から外側のハンドラの G の操作を起こすと、これらの起動は連鎖の切り取りには入らず、`K` の中の文脈からだけ届く。
これらの起動の `h` もずらす。

### 11.5 予備と既定の限度

**予備**:`depth_limit` の巻き戻しが伝播している間は、限度を `L + R` とする。
`R = max(1024, L / 64)` で、`/` は切り捨ての整数除算である。
巻き戻しが最上位に届いたら、限度を `L` に戻す(対話的な実行では、その入力の終わりで戻す)。
予備の中でさらに限度を超えたら、その `cancel` 節からの脱出として打ち切り、記録する(本書 9.6 節の 4)。

既定の限度は `L = 2^20 = 1,048,576` である。
読み手は、限度を変える手段(`keleut --max-depth N`、`diktor --run-ir --max-depth N`)を持つ。

この値で、WasmGC の後段が `L + R` 段の非末尾の再帰に要るスタックを確保できることを、測定で確かめた(`doc/log/261024-2-m79.md` の 1.5 節)。

Diktor の木の評価器(`--run-ir` を付けない実行)は、本節の限度に従わない。
その限度は OCaml のスタックで決まる。
深さが `L` を超えるが木の評価器では最後まで走るプログラムは、限度を処理系に任せた §15.5 の範囲の差であり、不具合として扱わない。

### 11.6 1 回の確保の上限

**`N_alloc_max`**:1 回の確保で作れる要素の数の上限。
長さを取る確保(`MutableArray.new` と、文字列を作るプリミティブ)は、確保の前に長さを `N_alloc_max` と比べ、超えたらメモリの不足にする。
`N_alloc_max` の値は、RustKeleut のすべての後段で同じにする。

`N_alloc_max = 2^26 = 67,108,864`(要素の数)である。
V8 の WasmGC の配列の長さの上限は、中身がおよそ 1 GiB になる長さで、8 バイトの要素の配列の `2^27 − 8` がもっとも小さい。
`N_alloc_max` は、それ以下の最大の 2 の冪である(`doc/log/261024-2-m79.md` の 2 節)。

Diktor には 1 回の確保の上限が無い。
Diktor でのメモリの不足は機械の空きに依り、限度を処理系に任せた §15.5 の範囲の差として扱う(本書 1 節が、上限を超える確保と、機械の空きによるメモリの不足の両方を、同じ結果の保証から除く)。

## 12. テキスト

### 12.1 正準の形

`.kirt` は S 式で書く。
`.kirt` とバイナリは 1 対 1 に往復する。
往復の対象は、本書 13 節の必須の節(id が 0x01 から 0x0B のもの)の中身である。
読み飛ばせる節(0x80 以上)はテキストに書かない。

書き手は、本節の正準の形だけを出す。
比較はバイト単位で行う。
`diktor --emit-ir-text` と `keleut kir dis` は、どちらもこの形を出す。
テキストを読む `keleut kir asm` は、正準の形を必ず受け付ける。
正準でない空白の並びを受け付けるかどうかは、読み手が決めてよい。

文字列の表(strings)と blobs の表は、テキストに書かない。
名前とリテラルはテキストの中にじかに書き、バイナリの表とその添字は符号化のときに作る。
表の並びは、テキストの中身だけから決まる規則で定める(本書 13 節)。
prims の表も同じで、`extern` の大域から作る。

### 12.2 字句

テキストはバイトの列で、次の字句からなる。

| 字句 | 綴り |
| --- | --- |
| 括弧 | `(` と `)` |
| 整数 | `0`、または `-` を任意に前に置き、`1`〜`9` で始まる 10 進の数字の列 |
| ビット列 | `0x` に続く 16 桁の 16 進の数字(小文字の `0`〜`9`、`a`〜`f`) |
| 文字列 | `"` で囲んだバイトの列(下の規則) |
| 名前 | 正規表現 `[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)*` に一致する綴り |

**文字列の綴り**:文字列の各バイト `b` を次のとおりに書く。

- `b` が `"`(0x22)なら `\"`、`\`(0x5C)なら `\\`。
- `b` が 0x20 から 0x7E のほかのバイトなら、そのまま。
- ほか(0x00〜0x1F、0x7F、0x80〜0xFF)は `\x` と 2 桁の小文字の 16 進(`\x0a`、`\xe3`)。

UTF-8 の多バイト文字も、バイトごとに `\xHH` で書く。
そのため、正準のテキストは ASCII だけからなる。

**短い名前の綴り**:ラベル、コンストラクタ、操作、メソッドの名前は、名前の字句に一致すれば名前として書き、一致しなければ文字列として書く。
記号(本書 3 節)とファイルの綴りは、常に文字列として書く。
キーワード(`lit`、`tail`、`i32` など)は名前の字句と同じ綴りで、置かれた位置で区別する。

**数の綴り**:`i32` と `i64` の値と、個数や番号は整数で書く。
`f64` の値はビット列で書く。
NaN の積載と負のゼロもビット列に残る。

### 12.3 字下げと改行

テキストの各要素を**ノード**と呼ぶ。
ノードは括弧で囲んだ列で、先頭のキーワード、続く原子(整数、ビット列、文字列、名前)、続く子のノードの順に並ぶ。
原子と子が混ざる形はなく、原子はすべて子より前にある。

**葉**:子を持たないノード。
ノードは次の規則で印字する。
ノードの開き括弧の桁を `c` とする。

1. ノードの子がすべて葉なら、ノード全体を 1 行に書く。
   キーワード、原子、子を 1 個の空白で区切る。
2. ほかの場合は、1 行目にキーワードと原子を空白で区切って書く。
   続けて、各子を改行して桁 `c+2` から書き、子の印字にも同じ規則を当てはめる。
   閉じ括弧は最後の子の閉じ括弧のすぐ後ろに置く。

行の幅では折り返さない。
行末に空白を置かない。
改行は LF(0x0A)で、ファイルの最後の行も LF で終える。
最上位のノードは桁 0 から書き、最上位のノードの間に空行を置かない。

### 12.4 ファイルの構成と表の並び

ファイルは次の最上位のノードを、この順に並べたものである。

1. 見出し `(kir 0 2 0)`。主版、副版、必要な機能のビットである。
2. 単位 `(unit …)` を、本書 2.1 節の順に。
3. 型 `(type …)` を、付録 A の組み込みの型の順に続けて、単位の順、各単位の宣言の順に。
4. エフェクト `(effect …)` を、単位の順、各単位の宣言の順に。
   組み込みの `Heap` と `Blocking` は操作を持たないので書かない。
5. クラス `(class …)` を、付録 A の組み込みのクラスの順に続けて、単位の順、各単位の宣言の順に。
6. インスタンス `(instance …)` を、単位の順、各単位の宣言の順に。
7. 大域 `(global …)` を、付録 A の組み込みの値の順に続けて、単位の順、各単位の手順の順、手順の中の並びの順に。
8. 関数 `(fn …)` を、下の順に。
9. 初期化 `(init …)` を、単位ごとに本書 2.1 節の順に(`builtin` も書く)。

関数の並びは次のとおりである。
単位の順、各単位の手順の順に、手順が持つ根の関数を並べる。
手順が持つ根の関数は、`def_value`、`def_pattern`、`run_exp` では `thunk` の関数、`def_fns` では種類が `fn` と `dictabs` の大域の関数(列の順。`extern` は関数を持たない)、`def_dictabs` では大域の関数、`def_instance` では実装の関数(メソッドを書いた順)である。
各根の関数のすぐ後に、その根の関数から持ち上げた関数を、場所の番号の順に並べる。
`handle` の場所の関数は、本体、操作節(書いた順)、`return` 節、`cancel` 節の順である。

### 12.5 文法

次の文法の終端記号は、空白を除いた字句の並びを表す。
空白と改行は本書 12.3 節の規則で入れる。
`INT` は整数、`BITS` はビット列、`STR` は文字列(`unit` と `init` では単位の鍵)、`NAME` は短い名前の綴り(名前か文字列)、`SYM` は記号の文字列である。
`X*` は 0 個以上、`X+` は 1 個以上、`[X]` は省略できることを表す。

```
file      ::= header unit* type* effect* class* instance* global* fn* init*
header    ::= (kir INT INT INT)
unit      ::= (unit STR (paths STR*))
type      ::= (type SYM (ctor NAME INT)*)
effect    ::= (effect SYM (op NAME INT never|resume runtime|user)*)
class     ::= (class SYM (method NAME INT)*)
instance  ::= (instance SYM SYM SYM (premises INT) (method NAME INT SYM)*)
global    ::= (global SYM builtin)
            | (global SYM extern prim|C STR INT)
            | (global SYM fn SYM)
            | (global SYM dictabs SYM)
            | (global SYM value rep)
fn        ::= (fn SYM kind yield|noyield (params rep*) (locals rep*) (dicts INT) (caps rep*) (result rep)
                 [(pats pat*)] [(guard exp)] exp)
kind      ::= lambda | opclause | retclause | cancelclause | handlebody | thunk | dictabs
rep       ::= bool | i32 | i64 | f64 | str | any
init      ::= (init STR step*)
step      ::= (def_value SYM SYM) | (def_pattern SYM (globals SYM*) pat) | (def_fns SYM+)
            | (def_dictabs SYM) | (def_instance SYM) | (run_exp SYM)

lit       ::= (lit bool true|false) | (lit i32 INT) | (lit i64 INT) | (lit f64 BITS) | (lit str STR)
cap       ::= (local INT) | (env INT) | (dparam INT)
exp       ::= lit | (lit_error lit_range STR) | (local INT) | (env INT) | (global SYM)
            | (construct SYM NAME (field INT exp)*) | (variant NAME exp)
            | (call tail|ntail yield|noyield exp exp*)
            | (method SYM NAME dict dict*) | (opcall SYM NAME dict exp*)
            | (not exp) | (and exp exp) | (or exp exp)
            | (closure SYM cap*) | (dictabs SYM cap*) | (dictapp exp dict*)
            | (let INT exp exp) | (letpat pat exp exp) | (letrec (rec INT exp)+ exp)
            | (seq exp exp exp*) | (match exp clause*)
            | (rec_empty) | (rec_extend NAME exp exp) | (rec_select NAME exp)
            | (rec_restrict NAME exp) | (rec_update NAME exp exp)
            | (perform SYM NAME exp*)
            | (handle tail|ntail SYM (body SYM cap*) (op NAME N|T|G SYM cap*)+
                 [(return SYM cap*)] [(cancel SYM cap*)])
            | (resume tail|ntail exp) | (hole)
clause    ::= (clause pat exp) | (clause pat (guard exp) exp)
dict      ::= (dinst SYM dict*) | (dparam INT) | (env INT) | (drecord (field NAME dict)*)
            | (dvariant (field NAME dict)*) | (dbuiltin SYM SYM)
pat       ::= (wild) | (bind INT) | lit
            | (record closed|open (field NAME pat)*) | (record rest (field NAME pat)* pat)
            | (ctor SYM NAME (field INT pat)*) | (variant NAME pat)
```

各ノードの欄の意味は次のとおりである。

- `type` の `(ctor NAME INT)` は、コンストラクタの名前とフィールドの数である。
  組み込みの型は `ctor` を持たない。
  利用者の型で `ctor` を持たないのは、右辺を省いた `newtype X` だけである。
  型エイリアスは型の表に現れない。
- `effect` の `(op NAME INT …)` は、操作の名前、引数の数、返り値の型が `Never` か(`never`)否か(`resume`)、実行時が処理するか(`runtime`)否か(`user`)である。
  `runtime` は、プレリュードの単位の `Console`(記号 `prelude/Console`)の `write` にだけ付く。
  ほかの単位が宣言した `Console` は、`--no-prelude` のときの起点の単位のものも含めて、どの操作も `user` である。
  そうした `Console` の操作はトップレベルの行に入らないので、型検査を通ったプログラムでは利用者の `handle` が処理する。
  本書 4 節の `noyield` の規則も、同じくプレリュードの `Console` だけを数える。
- `class` の `(method NAME INT)` は、メソッドの名前と、メソッド自身の辞書の数である(本書 7.2 節)。
  メソッドはクラスの宣言の順に並べる。
- `instance` の 3 つの `SYM` は、インスタンス、クラス、頭の型構成子の記号である。
- `global` の `extern` は、ABI、実装名(修飾しない元の名前)、受け取って捨てる辞書の数である。
  `fn` と `dictabs` の `SYM` は大域の関数である。
- `fn` の `(pats …)` と `(guard …)` は種類 `opclause` の関数だけが持ち、`(pats …)` は `opclause` では必ず書く。
- `def_pattern` の `(globals …)` は、パターンが束縛する大域の列である。
- `handle` の `(op …)` は操作節の書いた順に並べる。

`(let INT exp exp)` は Rep を持たない。
スロットの Rep は関数の `params` と `locals` が持つからである。

### 12.6 例

例を `doc/ir/examples/` に置く。
各 `.kirt` は、`doc/ir/examples/` を作業ディレクトリにして、同じ名前の `.kel` をファイル名だけで `diktor --no-prelude --emit-ir-text` に渡して書き出したものである。
次は `loop.kel` の関数 `main/loop` である。
`loop` のエフェクト行は一般化した行変数なので、関数も再帰の呼び出しも `yield` である。

```
(fn "main/loop" lambda yield
  (params i32 i64)
  (locals)
  (dicts 0)
  (caps)
  (result i64)
  (match
    (opcall "builtin/Eq" eq (dbuiltin "builtin/Eq" "builtin/Int32") (local 0) (lit i32 0))
    (clause (lit bool true) (local 1))
    (clause
      (lit bool false)
      (call tail yield
        (global "main/loop")
        (opcall "builtin/Sub" sub (dbuiltin "builtin/Sub" "builtin/Int32") (local 0) (lit i32 1))
        (opcall "builtin/Add" add (dbuiltin "builtin/Add" "builtin/Int64") (local 1) (lit i64 1))))))
```

## 13. バイナリ

### 13.1 見出し

バイナリの先頭 16 バイトは次のとおりである。
多バイトの整数はリトルエンディアンで書く。

| 位置 | 大きさ | 中身 |
| --- | --- | --- |
| 0 | 4 | マジック `00 4B 49 52`(`\0KIR`) |
| 4 | 2 | 主版(u16) |
| 6 | 2 | 副版(u16) |
| 8 | 4 | 必要な機能のビット(u32) |
| 12 | 4 | 節の数(u32) |

見出しの後に、節 `id: u8, size: uLEB128, payload` が id の昇順に並ぶ。
節の中の整数は uLEB128 と sLEB128 で書く。
Wasm と同じく、最長の符号化を超えた LEB128 は誤りである。
`f64` は 8 バイトで書き、NaN の積載も保つ。

### 13.2 節

| id | 節 | 中身 |
| --- | --- | --- |
| 0x01 | strings | 名前。UTF-8 でなければならない |
| 0x02 | blobs | `String` のリテラル。任意のバイト列で、NUL と不正な UTF-8 も許す(§4.4) |
| 0x03 | units | 単位の鍵、元のパス、初期化の順 |
| 0x04 | types | 名目的な型、コンストラクタ、フィールド |
| 0x05 | effects | エフェクト、操作、引数の数、`never` の印、実行時が処理する印 |
| 0x06 | classes | クラス、メソッド、メソッドの辞書の数 |
| 0x07 | instances | 本書 7 節 |
| 0x08 | prims | このファイルが使うプリミティブの名前。付録 A に無い名前も許す |
| 0x09 | globals | 記号、種類(`fn`、`value`、`dictabs`、`extern`、`builtin`)、単位、辞書の数、Rep |
| 0x0A | functions | 関数の表(本書 6 節)。本体は前順の木で、各ノードは 1 バイトの命令とその欄 |
| 0x0B | init | 単位ごとの初期化の手順(本書 10 節) |
| 0x80 | producer | 書き手の名前と版、元のファイルのハッシュ |
| 0x81 | locations | ノードの前順の番号から(ファイル、行、桁)への表 |
| 0x82 | types-debug | 完全な型の文面 |

0x80 以上の節は、読み飛ばしてよい。
各節の payload の並びと、命令の番号は M82 で定める。
テキスト(本書 12 節)は strings、blobs、prims の表を持たないので、これらの表の並びは、テキストの中身だけから決まる規則で定める。

prims の節にあって付録 A に無い名前の呼び出しは、読み込みでは拒否せず、呼んだときに実行時エラー(付録 B の未実装のプリミティブ)にする(§17)。

### 13.3 読み手の検査

読み手は、読み込んだ KIR を次の点で検査し、どれかに通らなければ実行せずに拒否する。

1. マジック、版(本書 14 節)、機能のビット、節の順と大きさが正しいこと。
2. 添字が範囲にあること。
3. Rep が合うこと(プリミティブ、`let`、初期化)。
4. 末尾の印と背骨が、計算し直した結果と一致すること(本書 5.3 節)。
5. N、T、G の分類が、計算し直した結果と一致すること(本書 9.2 節)。
6. `resume` が許された位置にだけあること(本書 9.2 節)。
7. 初期化の手順が、各大域をちょうど 1 回定義すること。
8. prims の節の各名前が正しい UTF-8 で、`extern(abi, 名前)` の大域から参照されていること。

RustKeleut と Diktor は、拒否したときに終了状態 65 で終わる。
読み込みと検証の再帰も限度を持ち、限度を超えたら 65 で終わる。

## 14. 版

1.0 までの版は `0.y` とする。
読み手は、書き手と同じ `0.y` だけを受け付ける。

1.0 に凍結する条件は、Diktor と RustKeleut の両方の書き手と読み手が、試験のコーパスの全件で往復と差分試験に通ることである。
1.0 の後は、次のとおりにする。

- 副版で足してよいのは、読み飛ばせる節と、機能のビットで守る新しい命令だけである。
- 意味や符号化を変えるときは、主版を上げる。
- 各副版の見本を `rustkeleut/conformance/kir-fixtures/` に置き続ける。

| 版 | 日付 | 内容 |
| --- | --- | --- |
| 0.1(草稿) | 2026-10-24 | 節の骨格と、エフェクトの抽象機械(9 節)と論理的な深さ(11 節)の規範の文。実施計画 `doc/log/261024-1-plan.md` の 4 節から作った |
| 0.2(草稿) | 2026-10-24 | 単位の鍵、名前、Rep、式、関数と捕獲、辞書、パターン、初期化、正準のテキスト(2〜8 節、10 節、12 節)と付録 A、B を定めた。インスタンスは、メソッドの値を呼んだときに選ぶ(5.4 節)。Diktor の書き手(`--emit-ir-text`)に合わせて、コンストラクタの名前、`$init<k>` の番号、`let` の名前の Rep、`handlebody` の中の `resume`、`runtime` の印、`let rec` のメソッドの実装を補った |

2 番の `<名前>` は、読んだ大域の記号から `単位の鍵/` を除き、末尾の `#n` も除いた修飾名である。
module の中から修飾せずに読んだときも、書いた綴りではなく修飾名を書く(`main/M.h` なら `M.h`)。
Diktor の木の評価器も同じ名前を書く。

17 番と 18 番の `<表示名>` は、その `extern` の大域の記号から `単位の鍵/` を除き、末尾の `#n` も除いた修飾名である(`main/__no_such#1` なら `__no_such`、`main/M.__no_such` なら `M.__no_such`)。
どちらの文面にするかは、この表示名と `extern` の実装名を比べて決める。
等しければ 17 番、違えば 18 番である。
