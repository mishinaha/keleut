# KIR 仕様

版 0.1(草稿)。

本書は、Keleut の中間言語 KIR(Keleut Intermediate Representation)を定める。
0.1 は草稿であり、まだ書き手も読み手も無い段で書いた。
9 節と 11 節は規範の文を揃えた。
ほかの節は骨格で、「M81 で定める」などと書いた箇所は、その段で書き手と読み手を作るときに決めて書き足す。
1.0 までの版の扱いは 14 節に書く。

本書が「言語仕様」と書くときは `doc/LangSpec.md` を指し、その節を「§13.6」のように書く。
本書の節は「本書 9 節」のように書く。

## 1. 適用範囲

KIR は、型検査と精緻化を済ませた Keleut のプログラムを表す中間言語である。
ファイルの形は 2 つある。

| 拡張子 | 形 |
| --- | --- |
| `.kir` | バイナリ(本書 13 節) |
| `.kirt` | 正準のテキスト(本書 12 節)。バイナリと 1 対 1 に往復する |

**書き手**:Keleut のソースから KIR を作る処理系。
Diktor(`diktor --emit-ir`)と RustKeleut のフロントエンド(`keleut emit-kir`)がこれにあたる。
**読み手**:KIR を読み込み、検証し、実行する処理系。
Diktor(`diktor --run-ir`)と RustKeleut(`keleut run`)がこれにあたる。

KIR のプログラムの意味は、それを書き出した元の Keleut のプログラムの、言語仕様が定める意味である。
言語仕様が処理系に任せている点のうち、実行の結果に効くもの(論理的な深さの限度と、1 回の確保の要素の数の上限)は、本書 11 節が値と数え方を定める。
深さの限度を検査する読み手は、どれも同じ深さを数え、同じ位置で `depth_limit` にする(本書 11.2 節〜11.5 節)。
`N_alloc_max` の検査は RustKeleut のすべての後段が同じ値で行い、Diktor(`--run-ir`)は行わない(本書 11.6 節)。

本書に従う読み手は、次のものを除いて、同じ KIR のプログラムに対して同じ出力と同じ終了状態を出す。

- `sin`、`cos`、`exp`、`log` の結果の 1 ulp の違い(正しい値に最も近い 2 つの `Float64` のどちらを返すか)。
  言語仕様 §17 が処理系に任せている。
- 1 回の確保の要素の数が `N_alloc_max` を超える場合。
  RustKeleut の後段はメモリの不足(3)で終わり、Diktor(`--run-ir`)は検査しないので確保が成功しうる(本書 11.6 節)。
- `N_alloc_max` の検査によらないメモリの不足。
  RustKeleut の WasmGC の後段が V8 のヒープを使い尽くした場合(3 でなく 70 で終わる)と、Diktor での確保がこれにあたる(本書 11.1 節、11.6 節)。

KIR を作る段で、書き手は次のものを済ませる。

- 構文の脱糖(`if`、タプル、`with`、末尾ブロック)。
- 名前の解決(大域は記号、局所はスロットの番号)。
- クロージャ変換(関数ごとの捕獲の列。辞書の引数も捕獲する)。
- 辞書渡しの明示(証拠の平坦化、インスタンスの頭の解決、メソッドの辞書の位置)。
- 数値リテラルの確定と module の平坦化。
- 末尾の印と操作節の分類(本書 5.3 節、9.2 節)。
- `run` の消去と、二項演算子と前置の `-` のメソッド呼び出しへの書き換え。

KIR は木であり、子は符号化に現れる順に評価する(本書 5 節)。
ANF にはしない。

RustKeleut の内部の形(LIR とバイトコード)は本書の対象ではない。
それらはファイルに書かず、互換性も約束しない。

読み手の検証(本書 13.3 節)は、型の健全性を保証しない。
型の健全性は、型検査を済ませた書き手が保証する。

## 2. プログラムと単位

`.kir` の 1 ファイルは、自己完結のプログラムである。
プレリュードを含むすべての単位を、初期化の順(§15.4。起点が最後)に並べて持つ。
単位ごとに節を分けて持つ。

**単位**:初期化の手順(本書 10 節)の列を持つ、プログラムの部分。
単位は鍵で名指す。

| 単位 | 鍵 |
| --- | --- |
| プレリュード | `prelude` |
| 組み込み | `builtin` |
| コマンド行の起点(複数のファイルを連結した 1 単位) | `main` |
| 起点のディレクトリの下のファイル | 起点のディレクトリからの相対パス(区切りは `/`) |
| `--import-path` の i 番目の下のファイル | `@i/相対パス` |

単位ごとの `.kir` と、その結合(分割コンパイル)は 0.y では定めない。

## 3. 名前

Diktor のオブジェクトの番号やハンドラの起動の番号のように、1 つのプロセスの中でしか通用しない番号は、KIR に書かない。

大域の記号は `単位の鍵/修飾名` である。
同じ単位で同じ名前を再び束縛したときは、2 つ目から `#1`、`#2` を付ける。
再束縛した名前は別の実体である(§6.1)。

型、コンストラクタ、エフェクト、操作、クラス、インスタンスにも記号を付ける。
インスタンスの記号は `単位の鍵/instance:クラス[頭]#n` である。

持ち上げた関数は、持ち主の記号に `$` と、持ち主の本体の前順の番号を付けて名指す(例 `main/loop$3`)。
ハンドラの本体と節は、`$h<n>.body`、`$h<n>.op.<名前>`、`$h<n>.return`、`$h<n>.cancel` と名指す。

ラベルと操作の短い名前は、文字列の表(本書 13 節の strings)の添字で表す。
局所は、関数の中の番号で表す。

書き出しは決定的でなければならない。
書き手は、同じ入力からは、プロセスが違っても同じバイト列を出す。
記号はリンクと診断にだけ使い、実行時の意味には使わない(§18.1)。

## 4. Rep

**Rep**:値の機械の上の表現の種類。
`bool`、`i32`、`i64`、`f64`、`str`、`any` の 6 種がある。

Rep は、局所の束縛(`let`、引数、パターンの変数)、関数の結果、大域に付ける。
書き手は、束縛の型の頭が `Int32`、`Int64`、`Float64`、`Boolean`、`String` ならその Rep を、ほか(型変数を含む)なら `any` を書く。

Rep は検証と最適化のためのものであり、プログラムの意味を変えない。
読み手は、関数の境目でどの Rep の値をどう渡すかを、自分で決めてよい。
末尾の印(本書 5.3 節)は Rep に依らない。

関数と呼び出しには `may_yield` の 1 ビットを付ける。
値が 0 になるのは、エフェクト行が閉じていて、要素が `Console`、`Heap`、`Blocking` だけのときである。
この印は最適化にだけ効く。

完全な型は、読み飛ばせる節 types-debug(本書 13 節)に文面で置く。
読み手の検証は、完全な型を使わない。

## 5. 式と評価順序

### 5.1 式

式の子は、次の表の順に評価する。
表に順を書いていない式の子は、符号化に現れる順に評価する。

| 式 | 子の評価の順と意味 | 末尾の位置の子 |
| --- | --- | --- |
| `lit(bool\|i32\|i64\|f64\|str)` | 定数。`f64` はビット列、`str` は blobs の添字 | |
| `lit_error(kind, text)` | 評価したら実行時エラーになる(本書 10 節) | |
| `local(i)`、`env(i)`、`dparam(i)`、`global(g)` | 読む。`global` は初期化の検査を伴う(本書 10 節) | |
| `ctor0(T, c)`、`construct(T, c, [(field, e)…])` | `e` を書いた順に評価し、`field` の位置(宣言の順)に格納する | |
| `variant(l, e)` | 引数が無ければ Unit を積む | |
| `call(f, [a…])` | `f` を先に、次に引数を左から評価して呼ぶ(§5.1) | 自身(`tail` の印) |
| `method(C, m, d, [own…])` | `d` と `own` を評価し、この時点でインスタンスの初期化を検査してメソッドを選ぶ | |
| `opcall(C, m, d, [a…])` | `d` と引数を左から評価し、その後でメソッドを選んで呼ぶ。末尾の呼び出しにはならない | |
| `not`、`and`、`or` | `and` と `or` は短絡する | `and` と `or` の右辺 |
| `closure(fn, [cap…])`、`dictabs(fn, [cap…])`、`dictapp(e, [d…])` | 捕獲と辞書を左から評価する | |
| `let(i, rep, e1, e2)`、`letpat(p, e1, e2)`、`letrec([(i, fn, [cap…])…], e)`、`seq` | 照合が失敗したら実行時エラーになる。`letrec` はクロージャをすべて作ってから捕獲を埋める | `e2`、`e`、`seq` の最後 |
| `match(e, [clause…])` | `e` を 1 回評価し、節を上から試す(本書 8 節) | 節の本体 |
| `rec_empty`、`rec_extend(l, v, r)`、`rec_select`、`rec_restrict`、`rec_update(l, r, v)` | 拡張は `v` を先に、`r` を後に評価する。更新は `r` を先に、`v` を後に評価する。対象は最も外側の同名のラベルである | |
| `perform(E, op, [a…])` | 引数を左から評価し、最も内側の `E` のハンドラへ送る(本書 9 節) | |
| `handle(E, body, [opclause…], ret?, cancel?)` | 本書 9 節 | 自身(`tail` の印) |
| `resume(e, tail)` | `e` を評価してから、継続が再開済みかを調べて再開する(本書 9.3 節) | 自身(`tail` の印) |
| `hole` | `???`。評価したら実行時エラーになる | |

`opcall` と、`call` の呼び出し先に置いた `method` は、メソッドを選ぶ時点が違う。
書き手は、演算子の形で書いたメソッドを `opcall` に、関数の形で書いたメソッド(`show(x)` など)を `call(method(…), …)` にする。
インスタンスの宣言の前にメソッドを選ぶと実行時エラーになるので、この時点は結果に効く。

`!=` は `not(opcall(Eq, eq, …))` にする。

### 5.2 辞書の式

辞書の式は次の 5 種である(本書 7 節)。

| 式 | 意味 |
| --- | --- |
| `dinst(I, [前提…])` | インスタンス `I` に前提の辞書を渡したもの |
| `dparam(i)`、`env(i)` | 辞書の引数か、捕獲した辞書 |
| `drecord([(l, d)…])` | レコードの構造的な等値比較などの辞書 |
| `dvariant(…)` | 構造的ヴァリアントの辞書 |
| `dbuiltin(C, 頭)` | 組み込みのインスタンス(付録 A) |

`drecord` と `dvariant` の欄は M81 で定める。

### 5.3 末尾の印

`call`、`handle`、`resume` は `tail` の印を持つ。
印は、その式が §5.7 の規則で末尾位置にあるときに限り立つ。
読み手の検証は末尾位置を計算し直し、印と違えば拒否する。

`resume` の背骨は操作節の本体から始まり、`handle` と `lambda` の中には入らない。

## 6. 関数と捕獲

関数の表の各項目は、次の欄を持つ。

- `kind`:`lambda`、`opclause`、`retclause`、`cancelclause`、`handlebody`、`thunk`、`dictabs` のどれか。
- 引数の Rep の列。
- 辞書の引数の数。
- 捕獲の数。
- スロットの数と、各スロットの Rep。
- 本体の式。

ハンドラの本体と各節も関数にする。
読み手が継続を取り出すとき、フレームの境目で切れるようにするためである。

`closure(fn, [cap…])` は、関数 `fn` と捕獲の値の列からクロージャを作る。
本体の中では、捕獲を `env(i)` で、辞書の引数を `dparam(i)` で、引数と局所を `local(i)` で読む。

名目的な型は、記号とコンストラクタの番号で表す。
フィールドは宣言の順に置く。
コンストラクタは第一級の値ではない。

レコードは、ラベルで操作する式(本書 5.1 節の `rec_*`)のまま表す。
レコードの配置は読み手が決め、結果に効かない(§18.3)。
ヴァリアントは、ラベルと積載値 1 個からなる。

## 7. 辞書

インスタンスは、クラス、頭、前提の数と、`(メソッドの番号, メソッド自身の辞書の数, 関数)` の列を持つ。
メソッドを実装する関数は、`前提の辞書 ++ メソッド自身の辞書` の順に辞書の引数を受け取る。

**使うたびの評価**:辞書を受け取る値束縛(`def_dictabs`。本書 10 節)は、使うたびに初期化式を評価する(§6.4、§12.2)。
読み手が結果を保存して再び使ってよいのは、初期化式が構文上 `closure` のときだけである。
同じ辞書の列で前の結果を返す覚え込みは、ほかの初期化式でも観測できないので許す。
初期化式はエフェクトを起こせず、1 回目が実行時エラーになるか停止しないなら 2 回目の評価に届かないからである。

組み込みのクラスとインスタンスは付録 A に挙げる。

## 8. パターン

パターンは次の 6 種である。

| パターン | 意味 |
| --- | --- |
| `wild` | 値を受け取り、束縛しない |
| `bind(i)` | 値を局所 `i` に束縛する |
| `lit` | リテラルと等しいかを調べる |
| `record([(l, p)…], closed\|open\|rest(p))` | フィールドを取り出す。`rest(p)` は残りのレコードを `p` と照合する |
| `ctor(T, c, [(field, p)…])` | 名目的なコンストラクタを分解する |
| `variant(l, p)` | 構造的ヴァリアントを分解する |

数値の `lit` は、照合する値の型で読んだ値として書く(`case 0xFFFFFFFF` は `Int32` の `-1` である)。
`f64` の `lit` は、IEEE 754 の `==` で照合する(§11.1)。
そのため `0.0` の `lit` は `-0.0` にも一致し、NaN にはどの `lit` も一致しない。

`match` は、節の順とガードを保つ。
ガードは、パターンが一致した節だけで評価する。
どの節にも一致しなければ実行時エラーになる(§11.2)。

## 9. エフェクトと抽象機械

本節は、エフェクトの意味を抽象機械の言葉で定める。
本節の規則は、読み手がハンドラと継続をどう実装するかに依らない。
本節の文は §13 を KIR の水準で書き直したものであり、§13 と食い違うときは §13 に合わせて本書を直す。

### 9.1 ハンドラと操作節

`handle` は、エフェクト、本体の関数、操作節の列、`return` 節(省略できる)、`cancel` 節(省略できる)を持つ。
操作節は、操作、引数のパターン、ガード(省略できる)、本体、分類を、1 つの `opclause` の関数にまとめたものである。
1 つの `handle` は 1 つのエフェクトを処理する(§13.4)。

### 9.2 操作節の分類

各操作節は、N、T、G のどれか 1 つに分類する。

| 分類 | 条件 |
| --- | --- |
| N | 操作の返り値の型が `Never` である |
| T | N でなく、本体の中の `resume` がすべて末尾の `resume` である(`resume` の無い枝を含んでよい) |
| G | それ以外 |

書き手は分類を書く。
読み手の検証は、操作の `never` の印と、`resume` の `tail` の印から分類を計算し直し、書いた分類と違えば拒否する。

`resume` を書けるのは、T と G の節の本体の中だけである。
ガード、`return` 節、`cancel` 節、N の節、ラムダの本体には書けない。
読み手の検証は、ほかの位置の `resume` を拒否する。

### 9.3 抽象機械の状態

抽象機械は、評価の文脈ごとに次のものを持つ。

- **ハンドラの連鎖**:有効なハンドラの起動の列。
  最も内側の起動が先頭にある。
- **ハンドラの起動**:`handle` を 1 回評価するたびに作るもの。
  エフェクト、節、`return` 節、`cancel` 節、親の起動、深さ `h`(本書 11 節)を持つ。
- **継続**:G の節が受け取る、中断した計算。
  1 回だけ再開できる。
  節の外へは持ち出せない。

ハンドラの起動の同一性は、64 ビットの単調に増える番号で表す。
巻き戻しの宛先は、この番号で名指す。
同じ `handle` の式を入れ子に起動したとき(再帰や、同じ関数の 2 回の呼び出し)、内側の起動が外側の起動宛ての巻き戻しを受け取ってはならない。

### 9.4 `perform`

`perform(E, op, [a…])` は、引数を左から評価した後、次の順に進む。

1. ハンドラの連鎖から、エフェクトが `E` である最も内側の起動を探す。
2. 操作節を上から試す。
   パターンが一致した節だけでガードを評価する。
   パターンが一致しない節とガードが偽の節は飛ばして、次の節へ進む。
3. 選んだ節の分類で分ける。
   - T:節の本体を評価する。
     末尾の `resume(v)` は、`perform` の値を `v` にする。
     `resume` しないで節が値 `r` になったときは、`perform` の位置から宛先の起動までの計算を破棄し、`r` をハンドラ式の値にする。
   - N:`perform` の位置から宛先の起動までの計算を破棄し、その後でハンドラの外で節の本体を評価する(9.6 節の 2)。
     ガードは破棄の前に評価してある。
   - G:`perform` の位置から宛先の起動までの計算を継続として取り出し、宛先の起動を連鎖から外して、節の本体を継続とともに評価する。

どの節にも一致しない操作を外側のハンドラへ送り直すことはない。

`Console.write` の `perform` は、KIR ではほかの操作と同じに書く。
`Console` は利用者が処理できず、最も外側の実行時が処理する。
読み手は、これを実行時の直接の呼び出しにしてよい。
そのときも、標準出力への書き込みの順と失敗の扱い(9.7 節)は変えない。

### 9.5 `resume`

`resume(e, tail)` は、まず `e` を評価する。
その後で、継続がすでに再開されていれば実行時エラーにする。
再開されていなければ、再開済みの印を立ててから再開する。
`e` の評価の中で同じ継続を再開したときも、この検査で外側の `resume` が実行時エラーになる(§13.5)。

再開した計算の中では、継続を取り出したハンドラの起動が再び連鎖に入る。
再開した計算の中で決まった `return` 節の値と、`resume` しない節の値は、ハンドラ式の値ではなく、この `resume` の値になる(§13.6)。

末尾の `resume` で再開するとき、読み手は節の評価のために持っていた情報を捨てる。
T の節と N の節の本体と `return` 節は、繰り返し起動しても一定の領域で評価できなければならない(§5.7)。
G の節の末尾でない `resume` の領域は保証しない。

### 9.6 規範の文

次の文は、上の各節の規則の中で、取り違えやすい点を定める。

1. 本体の側から届いた巻き戻しの宛先がこのハンドラの起動でないときは、このハンドラの `cancel` 節を 1 回走らせてから巻き戻しを続ける。
   宛先がこの起動なら、`cancel` 節を走らせない。
   `return` 節も走らせない。
2. `return` 節は、ハンドラを連鎖から外した後で評価する。
   そのため、`return` 節の中の誤りでは、自分の `cancel` 節を走らせない。
   N の節の本体も、継続を破棄してハンドラを外した後で評価する。
   G の節の中で `resume` が戻った後のコードも、そのハンドラが連鎖にいない文脈で走る(§13.6)。
3. 節の選択(パターンとガード)と、T の節の本体では、ハンドラの連鎖を、そのハンドラの親に付け替える。
   そのため、節の中で起こした操作は外側のハンドラへ届く(§13.4)。
   節を抜けたら、連鎖を `perform` の時点のものに戻す。
4. `cancel` 節は、自分のハンドラの外で走る。
   `cancel` 節の中で起きた脱出(実行時エラー、破棄、論理的な深さの限度)は、すべて打ち切る。
   打ち切ったら、標準出力を flush してから標準エラーに記録し、元の巻き戻しを続ける。
   標準出力への書き込みがすでに失敗しているときは、この flush は何もしない(9.7 節)。
5. ハンドラの起動の同一性は、64 ビットの単調に増える番号で表す(9.3 節)。

### 9.7 巻き戻しと `cancel` の順序

巻き戻しは、破棄する計算の中のハンドラを、内側から外側の順にたどる。
宛先でない起動に着くたびに、9.6 節の 1 のとおり `cancel` 節を走らせる。

T と G の節が `resume` の前に脱出したとき(`resume` の引数の評価中を含む)は、節の評価の中で起動したハンドラの `cancel` 節、継続の中の `cancel` 節(内側から外側の順)、宛先の起動の `cancel` 節、さらに外側の順に走らせる(§13.6)。
宛先の起動の継続はまだ生きているからである。
G の節が `resume` の後に脱出したときは、宛先の起動はもう連鎖にいないので、その `cancel` 節は走らせない。

N の節では、ガードの評価が破棄より先にある。
ガードの中の脱出では継続がまだ生きているので、宛先の起動の `cancel` 節を走らせる。
本体の中の脱出は、ハンドラ式の後ろで起きたものとして扱い、宛先の起動の `return` 節と `cancel` 節を走らせない。

`cancel` 節の中から、まだ連鎖にいるハンドラの G の操作を起こしてよい。
そのハンドラが継続を再開すると、`cancel` 節の続きと、中断していた巻き戻しの続きが走る。

実行時エラーは操作ではなく、ハンドラで捕まえられない。
実行時エラーが起きると、有効なハンドラを内側から外側の順に巻き戻し、各起動の `cancel` 節を走らせる(§15.5)。
最上位に届いたら、標準出力を flush し、文面(付録 B)を標準エラーに書いて、終了状態 3 で終わる。

`Console.write` の書き込みが失敗したら、その失敗を実行時エラーと同じに巻き戻し、`cancel` 節を走らせてから終了状態 74 で終わる。
最初の失敗で未出力のバッファを捨て、その後の flush は何もせず、誤りも起こさない。

## 10. 初期化

各単位の初期化は、次の 6 種の手順の列である。

| 手順 | 意味 |
| --- | --- |
| `def_value g f` | 0 引数の関数 `f` を評価して `g` に置き、初期化済みにする |
| `def_pattern [g…] p f` | 0 引数の関数 `f` を評価し、結果をパターン `p` と照合する。一致しなければ実行時エラーにする(文面は `letpat` と同じ)。一致すれば、束縛した各大域に順に置き、初期化済みにする |
| `def_fns [g…]` | 関数の大域(`let rec` の群を含む)を初期化済みにする |
| `def_dictabs g` | 辞書を受け取る値束縛を初期化済みにする。評価はしない(本書 7 節) |
| `def_instance i` | インスタンスを使える状態にし、前提も自分の制約も持たない値束縛のメソッドを、宣言の順に 1 回だけ評価する |
| `run_exp f` | 式文を評価する。書き手は、辞書を受け取る式文を書き出さない |

大域とインスタンスは、初期化済みの印を持つ。
初期化の前に読むと実行時エラーになる。

**検査を省いてよい条件**:読み手が大域 `g` の初期化の検査を省いてよいのは、`g` の参照を含む最も外側のトップレベルの実体の手順が `g` の手順より後にあるときと、両者が同じ `def_fns` の群にあるときだけである。
たとえば `let p = {f = fn(x) => h(x)}` で `h` が後に宣言されているときは、ここで作った無名関数を `h` の初期化の前に呼べるので、検査を省いてはならない。

範囲外の数値リテラルは `lit_error(lit_range, 字面)` とする。
これは評価したときに初めて実行時エラーになる。
読み手は、これを畳み込んだり、前へ動かしたり、消したりしてはならない(§4.2)。

## 11. 実行時エラーと論理的な深さ

### 11.1 実行時エラーの種類

KIR の評価が止まる誤りは、次の 4 種である。

| 種類 | 起きる場面 | 終了状態 |
| --- | --- | --- |
| 実行時エラー | 言語仕様が「実行時エラーになる」と書く場面(付録 B) | 3 |
| `depth_limit` | 論理的な深さが限度を超えた(11.2 節〜11.5 節) | 3 |
| メモリの不足 | 確保の要素の数が `N_alloc_max` を超えた(11.6 節)か、読み手がヒープを広げられない | 3(注) |
| 出力の失敗 | 標準出力に書けない(本書 9.7 節) | 74 |

どれも、有効なハンドラを内側から巻き戻して `cancel` 節を走らせる(本書 9.7 節)。
文面は付録 B に定める。

注:RustKeleut の WasmGC の後段では、V8 のヒープそのものを使い尽くすと Node のプロセスが落ち、`cancel` 節を走らせずに 70 で終わる。
これは §15.5 からの既知の逸脱で、本書 1 節が同じ結果の保証から除くものである。

### 11.2 論理的な深さ

§15.5 は、評価に要する領域の限度の大きさを処理系に任せている。
一方で、限度を超えたときの振る舞い(`cancel` 節を走らせて終了状態 3)は結果に効く。
そこで本書は、評価の各文脈に整数の深さ `d` を定め、すべての読み手が同じ値を数えるようにする。
深さは、読み手のスタックの使い方とは無関係に、次の表の境目で決まる。

| 場面 | 深さ |
| --- | --- |
| 最上位の初期化の手順 | 0 |
| 深さ `d` の文脈での末尾でない `call`、`opcall`、`dictapp` と、組み込みが利用者の関数を呼ぶ呼び出し(組み込みの中で末尾の位置にあっても、この行で数える) | 呼ばれた側は `d+1` |
| 末尾の呼び出し、末尾の `resume` | 呼び出し元の深さを引き継ぐ(増えない) |
| 深さ `h` の `handle` の本体 | `h+1` |
| 深さ `p` の `perform` の、節の選択(パターンとガード)と T の節の本体 | `p+1` |
| G の節の本体(宛先のハンドラの起動の深さを `h` とする) | `h+1` |
| G の節の中の、深さ `c` での末尾でない `resume`(継続の深さの差を `Δ = p − h` とする) | 再開した `perform` は深さ `c+Δ` で値を返す |
| N の節の本体、`return` 節 | `h`(ハンドラ式の位置の深さを引き継ぐ) |
| `cancel` 節 | 巻き戻されるハンドラの起動の `h` |

ここで、ハンドラの起動の深さ `h` は、その `handle` の式を評価した文脈の深さである。

`Console.write` の `perform` は、深さを変えず、限度の検査もしない。

読み手が内部で使う呼び出し(ハンドラの本体への呼び出しや、インライン展開など)は、上の表のとおりに数え、読み手の中の呼び出しの数では数えない。

### 11.3 限度の検査

読み手は、表で深さが増えるすべての境目で、新しい深さを限度 `L` と比べる。
対象は、末尾でない呼び出し、`handle` の本体に入るとき、節の選択、T の節の本体、G の節の本体、末尾でない `resume` である。
新しい深さが `L` を超えるときは、その境目に入る前に `depth_limit` にする。

末尾でない `resume` では、再開した `perform` の深さ `c+Δ` を、継続を再開する前に `L` と比べる。

### 11.4 再開での深さのずれ

深さ `c` で継続 `K` を再開するとき(`K` を取り出したハンドラの起動の深さを `h` とする)、`K` の中の各文脈の深さと、`K` の中で始まったすべてのハンドラの起動の `h` を、`c − h` だけずらす。
`K` を取り出したハンドラの起動自身の `h` は `c` になる。
そのため、再開した計算の中で走るそのハンドラの `return` 節と、`resume` しない節は、深さ `c` で走る。
これは、それらの値がこの `resume` の値になること(本書 9.5 節)と合う。

`K` の中で始まったハンドラの起動は、`K` が持つ連鎖の切り取りの中のものだけではない。
T の節(またはガード)を評価している間は、そのハンドラの起動と、`perform` の位置からそのハンドラまでの起動が、連鎖から外れている(本書 9.6 節の 3)。
その節の中から外側のハンドラの G の操作を起こすと、これらの起動は連鎖の切り取りには入らず、`K` の中の文脈からだけ届く。
これらの起動の `h` もずらす。

### 11.5 予備と既定の限度

**予備**:`depth_limit` の巻き戻しが伝播している間は、限度を `L + R` とする。
`R = max(1024, L / 64)` で、`/` は切り捨ての整数除算である。
巻き戻しが最上位に届いたら、限度を `L` に戻す(対話的な実行では、その入力の終わりで戻す)。
予備の中でさらに限度を超えたら、その `cancel` 節からの脱出として打ち切り、記録する(本書 9.6 節の 4)。

既定の限度は `L = 2^20 = 1,048,576` である。
読み手は、限度を変える手段(`keleut --max-depth N`、`diktor --run-ir --max-depth N`)を持つ。

この値で、WasmGC の後段が `L + R` 段の非末尾の再帰に要るスタックを確保できることを、測定で確かめた(`doc/log/261024-2-m79.md` の 1.5 節)。

Diktor の木の評価器(`--run-ir` を付けない実行)は、本節の限度に従わない。
その限度は OCaml のスタックで決まる。
深さが `L` を超えるが木の評価器では最後まで走るプログラムは、限度を処理系に任せた §15.5 の範囲の差であり、不具合として扱わない。

### 11.6 1 回の確保の上限

**`N_alloc_max`**:1 回の確保で作れる要素の数の上限。
長さを取る確保(`MutableArray.new` と、文字列を作るプリミティブ)は、確保の前に長さを `N_alloc_max` と比べ、超えたらメモリの不足にする。
`N_alloc_max` の値は、RustKeleut のすべての後段で同じにする。

`N_alloc_max = 2^26 = 67,108,864`(要素の数)である。
V8 の WasmGC の配列の長さの上限は、中身がおよそ 1 GiB になる長さで、8 バイトの要素の配列の `2^27 − 8` がもっとも小さい。
`N_alloc_max` は、それ以下の最大の 2 の冪である(`doc/log/261024-2-m79.md` の 2 節)。

Diktor には 1 回の確保の上限が無い。
Diktor でのメモリの不足は機械の空きに依り、限度を処理系に任せた §15.5 の範囲の差として扱う(本書 1 節が、上限を超える確保と、機械の空きによるメモリの不足の両方を、同じ結果の保証から除く)。

## 12. テキスト

`.kirt` は S 式で書く。
`.kirt` とバイナリは 1 対 1 に往復する。
書き手は正準の形だけを出し、比較はバイト単位で行う。

```
(fn "main/loop" lambda (params (n i32) (acc i64)) (result i64) (dicts 0) (caps 0) (yield 0)
  (match (opcall Eq eq (dbuiltin Eq Int32) (local 0) (lit i32 0))
    (clause (lit bool true) (local 1))
    (clause (lit bool false)
      (call tail (global "main/loop")
        ((opcall Sub sub (dbuiltin Sub Int32) (local 0) (lit i32 1))
         (opcall Add add (dbuiltin Add Int64) (local 1) (lit i64 1)))))))
```

バイト列は `\xHH` で書く。

正準の印字の規則(字下げ、表の並び、数の綴り)は M81 で定める。
例は `doc/ir/examples/*.kirt` に置く。

## 13. バイナリ

### 13.1 見出し

バイナリの先頭 16 バイトは次のとおりである。
多バイトの整数はリトルエンディアンで書く。

| 位置 | 大きさ | 中身 |
| --- | --- | --- |
| 0 | 4 | マジック `00 4B 49 52`(`\0KIR`) |
| 4 | 2 | 主版(u16) |
| 6 | 2 | 副版(u16) |
| 8 | 4 | 必要な機能のビット(u32) |
| 12 | 4 | 節の数(u32) |

見出しの後に、節 `id: u8, size: uLEB128, payload` が id の昇順に並ぶ。
節の中の整数は uLEB128 と sLEB128 で書く。
Wasm と同じく、最長の符号化を超えた LEB128 は誤りである。
`f64` は 8 バイトで書き、NaN の積載も保つ。

### 13.2 節

| id | 節 | 中身 |
| --- | --- | --- |
| 0x01 | strings | 名前。UTF-8 でなければならない |
| 0x02 | blobs | `String` のリテラル。任意のバイト列で、NUL と不正な UTF-8 も許す(§4.4) |
| 0x03 | units | 単位の鍵、元のパス、初期化の順 |
| 0x04 | types | 名目的な型、コンストラクタ、フィールド |
| 0x05 | effects | エフェクト、操作、引数の数、`never` の印、実行時が処理する印 |
| 0x06 | classes | クラス、メソッド、メソッドの辞書の数 |
| 0x07 | instances | 本書 7 節 |
| 0x08 | prims | このファイルが使うプリミティブの名前。付録 A に無い名前も許す |
| 0x09 | globals | 記号、種類(`fn`、`value`、`dictabs`、`extern`、`builtin`)、単位、辞書の数、Rep |
| 0x0A | functions | 関数の表(本書 6 節)。本体は前順の木で、各ノードは 1 バイトの命令とその欄 |
| 0x0B | init | 単位ごとの初期化の手順(本書 10 節) |
| 0x80 | producer | 書き手の名前と版、元のファイルのハッシュ |
| 0x81 | locations | ノードの前順の番号から(ファイル、行、桁)への表 |
| 0x82 | types-debug | 完全な型の文面 |

0x80 以上の節は、読み飛ばしてよい。
各節の payload の並びと、命令の番号は M81 で定める。

prims の節にあって付録 A に無い名前の呼び出しは、読み込みでは拒否せず、呼んだときに実行時エラー(付録 B の未実装のプリミティブ)にする(§17)。

### 13.3 読み手の検査

読み手は、読み込んだ KIR を次の点で検査し、どれかに通らなければ実行せずに拒否する。

1. マジック、版(本書 14 節)、機能のビット、節の順と大きさが正しいこと。
2. 添字が範囲にあること。
3. Rep が合うこと(プリミティブ、`let`、初期化)。
4. 末尾の印と背骨が、計算し直した結果と一致すること(本書 5.3 節)。
5. N、T、G の分類が、計算し直した結果と一致すること(本書 9.2 節)。
6. `resume` が許された位置にだけあること(本書 9.2 節)。
7. 初期化の手順が、各大域をちょうど 1 回定義すること。
8. prims の節の各名前が正しい UTF-8 で、`extern(abi, 名前)` の大域から参照されていること。

RustKeleut と Diktor は、拒否したときに終了状態 65 で終わる。
読み込みと検証の再帰も限度を持ち、限度を超えたら 65 で終わる。

## 14. 版
