# LIR の命令

本書は、RustKeleut の内部の中間言語 **LIR** の各命令の意味を定める。
LIR は crate `keleut-lir` が KIR から作り、インタプリタ(M87)、LLVM の後段(M91)、WasmGC の後段(M94)が同じ LIR から自分の形を作る。
LIR はファイルに書かず、互換性も約束しない(計画 261024-1 の 4.1 節)。

本書が扱うのは、計画 6.4 節のパス 1〜12 が出す命令である。
エフェクトの下ろし(パス 8)の命令、ハンドラのフレームの関数 `$rt_handle`(計画 6.6 節の `rt_handle` と `rt_resume`)と防壁は 16 節に、yield の刈り込み(パス 11)は 17 節に書く。

本書は、言語仕様 `doc/LangSpec.md` の節を「LangSpec §5.7」、KIR の仕様 `doc/IRSpec.md` の節を「IRSpec 8 節」のように書く。

## 1. 全体の形

### 1.1 プログラム

LIR のプログラムは、関数の表と、次の表からなる。

| 表 | 中身 |
| --- | --- |
| 関数 | 先頭の部分は KIR の関数と同じ添字に置く。その後ろに、組み込みの値、`extern`、組み込みのインスタンスのメソッドの本体と、単位の初期化の関数を置く |
| 大域 | KIR と同じ添字。種類ごとの値は 1.6 節 |
| インスタンス | KIR と同じ添字。クラスのメソッドの順に、実装の関数とそれが受け取る辞書の数(前提の数 + メソッド自身の辞書の数)を持つ |
| 型、クラス | KIR と同じ添字。コンストラクタの名前と引数の数、メソッドの名前 |
| 組み込みのメソッド | `(クラス, 型, メソッド)` ごとの本体の関数(IRSpec 付録 A.3 の 44 個) |
| ラベル | レコードとヴァリアントのラベルの文字列 |
| 形 | レコードの形(1.5 節)。0 番は空の形である |
| 文字列 | 文字列の定数(任意のバイト列) |
| 初期化 | 単位ごとの初期化の関数(初期化の順) |

実行は、初期化の関数を順に、文脈の深さ 0 で呼ぶことである。

### 1.2 関数、ブロック、レジスタ

関数は基本ブロックの列である。
先頭のブロックが入口で、どの枝も番号の大きいブロックへ向かう。
そのため、どの関数の制御も非巡回である。
Keleut には反復の構文が無く(LangSpec §5.7)、繰り返しは末尾呼び出しで書く。

**レジスタ**は関数ごとの仮想の場所で、それぞれがちょうど 1 つの Rep を持つ。
Rep は KIR と同じく `bool`、`i32`、`i64`、`f64`、`str`、`any` の 6 種である。
`any` は**一様な語**(後段が値の種類を問わずに同じ形で持つ値)である。
`str` は文字列の参照で、一様な語に入れるときに形を変えない。
レジスタは SSA ではない。
`match` や `and` の合流では、各枝が同じレジスタに書いてから合流のブロックへ移る。
検証器は、どのレジスタも、読むどの経路でも先に書かれていることを確かめる。

関数の**引数**はどれも `any` のレジスタで、入口で値を持つ。
KIR の引数の Rep が生の Rep なら、入口の `unbox` が生の値を取り出す。
戻り値も `any` である(D503)。
種類 `dictabs` の関数の引数は、辞書の引数である。

**環境**は、クロージャが持つ捕獲の列である。
関数は、入口の `depth_enter` の直後に、自分を呼んだクロージャの環境の捕獲を `env_get` でレジスタに読む。
以後は捕獲もほかの値と同じくレジスタで扱うので、フレームはクロージャを持ち続けない(1.8 節)。
捕獲を持たない関数は、`call_direct` で環境なしに呼べる。

### 1.3 trap しないこと

LIR の命令は trap せず、未定義の動作を持たない(D524)。
具体的には次のように定める。

- 誤りになりうる演算(ゼロ除算、範囲外の添字、`Float64` から整数への変換)は、命令の前に下ろしが明示の検査と `error` への枝を置く(パス 7)。
  命令そのものはすべての入力に結果を定める(**全域**)。
  たとえば `i32.div` は除数が 0 なら 0 を返す。
  検査の後でしか命令に届かないので、この値はプログラムからは見えない。
- 実行時エラーになりうる命令は、1.7 節の「失敗しうる命令」だけである。

ただし、命令の意味は KIR の型の健全性を前提にする箇所がある。
`unbox` の元が同じ Rep の値を箱に入れたものであること、`ctor_tag` の対象が名目的な型の値であることなどである。
KIR の検証器は型の健全性を確かめない(計画 6.3 節)。
信頼の根は型検査を済ませたフロントエンドである。
この前提が破られたときの振る舞いは処理系の内部の誤りで、後段は終了状態 70 で止まってよい。
各命令の節の「前提」の項がこの前提を挙げる。

型検査を済ませたプログラムでもこの前提が破られる場合が 1 つある。
`console_write`(13 節)は、宣言された返り値の型によらず `r` を Unit にする。
KIR の操作の表は操作の名前、引数の数、`never`、`runtime` の印だけを持ち、返り値の型を持たない。
そのため下ろしは、プレリュードが `Console.write` を `(String) => Unit` と宣言したことを確かめられない。
`--prelude` で差し替えたプレリュードが別の返り値の型を宣言すると、そのプログラムは LIR の前提の外にある。
たとえば `write: (String) => Int32` と宣言して `perform write("a") + 1` を書くと、下ろしは Unit を `i32` に `unbox` する。
Diktor はこのプログラムで `a` を書き、値を調べた所で実行時エラー(`Int32 ではありません: ()`)になって 3 で終わる。

### 1.4 論理的な深さ

深さは IRSpec 11.2 節の規則で数える。
実行時は文脈の深さ `ctx.depth` と限度 `L` を持ち、各フレームは自分の深さを持つ。
LIR の深さの命令は次の 4 つである(パス 10)。

| 命令 | 置く場所 |
| --- | --- |
| `depth_enter` | 関数の入口の先頭 |
| `depth_push` | 利用者のコードに届く末尾でない呼び出しの直前 |
| `depth_restore` | その呼び出しの直後 |
| `depth_check` | プリミティブ、組み込みのメソッド、組み込みの値のように、利用者のコードに届かない末尾でない呼び出しの位置 |

末尾の呼び出しは深さを変えない。
呼ばれた側が正常に戻ったとき、`ctx.depth` は呼ばれた側の入口の深さに等しい。
末尾でない呼び出しは、`depth_push` と `depth_restore` で囲むか、`ctx.depth` を変えずに呼び出し側のいまの深さで呼ばれた側を走らせるかのどちらかだからである。
後者は、初期化の関数の呼び出しと、メソッドの呼び出しの中の実装の関数の評価である(13 節)。
`depth_enter` はフレームの深さを `ctx.depth` から取るので、帰納法により、どの呼ばれた側も入口の深さで戻る。
メソッドの値の呼び出し(`dict.rs`)は、この性質を使って、実装の関数の評価と得た関数の呼び出しを同じ深さで行う。

### 1.5 値の種類

LIR の値は次のどれかである。
後段は一様な語の符号化を自分で決める(ネイティブは計画 6.5 節、WasmGC は 6.10 節)。

| 値 | 中身 |
| --- | --- |
| Unit | 空のレコード |
| 真偽値、`Int32`、`Int64`、`Float64` | 生の値か、それを箱に入れた一様な語 |
| 文字列 | 長さとバイト列 |
| データ | 型、コンストラクタの番号、フィールドの列(宣言の順)。引数の無いコンストラクタは型と番号だけ |
| ヴァリアント | ラベルの番号と積載値 |
| レコード | 形とフィールドの列 |
| クロージャ | 関数と捕獲の列 |
| メソッドの値 | クラス、メソッド、辞書、メソッド自身の辞書の列 |
| 辞書 | 組み込みのインスタンス `(クラス, 型)`、利用者のインスタンスと前提の辞書の列、構造的な `Eq` のレコードかヴァリアントの辞書(ラベルと辞書の列) |
| `Ref`、配列、可変の配列 | 1 つの値の入れ物、値の列 |

**形**は、ラベルの番号の昇順に並べたラベルの列である。
同じラベルが 2 つ以上あるときは、外側(後で足したもの)を先に置く。
レコードのフィールドは形の順に並ぶ。
この配置は正準で、同じラベルの多重集合を持つレコードはどの経路で作っても同じ形になる。
LangSpec §18.3 によりラベルの順は結果に効かない。
プログラムの形の表の番号は、実行時が作る形の番号と一致させる(実行時は表の形を先に登録する)。

### 1.6 大域の値

`global_get` が読む値は、大域の種類で決まる。

| 種類 | 値 |
| --- | --- |
| `fn` | その関数の、捕獲を持たないクロージャ |
| `dictabs` | その関数の、捕獲を持たないクロージャ(辞書の抽象) |
| `extern` | 本体の関数のクロージャ。実装名が付録 A.5 に無いときは、呼ぶと実行時エラー 17 か 18 になる値 |
| `builtin` | 本体の関数のクロージャ |
| `value` | 初期化の手順が `global_set` で置いた一様な語 |

### 1.7 実行時エラーと失敗しうる命令

**失敗しうる命令**は、次の命令である。

- 呼び出し(`call_direct`、`call_value`、`call_method`、`dict_app`)。呼ばれた側で起きた実行時エラーがここへ伝わる。
- 確保する命令。回収してもヒープを広げられないときにメモリの不足(付録 B の 19 番)になる。
  長さを取る確保(`marray_new`、文字列を作る命令)は、長さが `N_alloc_max = 2^26` を超えるときもメモリの不足になる(IRSpec 11.6 節)。
- `depth_check` と `depth_push`。限度を超えると `depth_limit` になる。
- `console_write`。書き込みの失敗は出力の失敗(終了状態 74)になる。
- エフェクトの命令のうち、`handler_find`(どのハンドラも処理しない操作)、`perform`(`p + 1` が限度を超えたときの `depth_limit` と、候補が無いときの実行時エラー 9)、`cont_check`(16.5 節)、`cont_resume`(値スタックを広げられないときのメモリの不足。16.4 節)。
  `call_clause` は、深さ `h + 1` が限度を超えたら節を呼ばずに `ERROR` を立て、番兵を結果に書く。
  エフェクトのブロックの終わり `tail_call_clause` も、候補が無ければ実行時エラー 9 になる。
- `pending_suppress`。記録の前の標準出力の flush が失敗したら(前の失敗の後にバッファに残したものや書き足したものを書き出せなかった場合を含む)、巻き戻さずに出力の失敗(74)で止まる(16.4 節の防壁)。

失敗した命令の後の命令は実行されない。
後段は誤りを状態語 `ctx.pending` の `ERROR` にして、そのフレームを番兵で戻す(16.1 節)。
誤りは、番兵を受け取るハンドラのフレームを通るたびに `cancel` 節を走らせながら、呼び出し元へ伝わる。
最上位に届いたら、実行時は標準出力を flush し、文面(付録 B)を標準エラーに書いて終了状態 3(出力の失敗は 74)で終わる。

### 1.8 フレーム(パス 12)

パス 12 は、各関数に次のものを付ける。

- **スロット**:各レジスタの置き場。
  スロットは `any` の区画と生の区画に分ける。
  `any` と `str` のレジスタは `any` の区画(GC が走査する)に、`bool`、`i32`、`i64`、`f64` のレジスタは生の区画に置く。
  引数は `any` の区画の 0 番から順に置く(呼ぶ側が値を書く位置である)。
  2 つのレジスタが同じスロットを使うのは、区間(1.9 節)が重ならないときだけである。
- **再開点**:末尾でない呼び出しの命令。
  関数の中で位置の順に 0 から番号を振り、その呼び出しの後で生きているレジスタの集合を付ける。
  呼び出しが書くレジスタは除く。
  呼び出しの引数は呼ばれた側のフレームの `any` の区画に写るので、呼び出し側の集合には入れない。
  メソッドを実行時に選ぶ呼び出しは、引数を写す前に GC が起きうるので、この節の後のほうに書く規則で引数を根に残す。
- **安全点**:確保する命令。
  確保をまたいで生きているレジスタの集合を付ける。
  これは、その命令の後で生きているレジスタから命令が書くレジスタを除き、命令の被演算子を足したものである。
  被演算子を入れるのは、確保が GC を起こしても、新しい値に写す前のフィールドや文字列が根に残るようにするためである。
  命令が書くレジスタは、確保を終えてから書く。
  区間(1.9 節)の上では被演算子と書くレジスタが同じ位置で重なるので、両者が同じスロットを使うことはない。

生きているレジスタの集合は、正確な生存解析で求める。
GC は、安全点と再開点で、この集合の `any` の区画のスロットだけを根として走査する。
集合に入らないスロットには、すでに死んだ値か、まだ書いていない値が残りうるからである。

メソッドを実行時に選ぶ呼び出しは、引数を呼ばれた側のフレームに写す前に、確保する関数を呼びうる。
この呼び出しは、`call_method`、`tail_call_method`、メソッドの値(`method_new` の値)を呼ぶ `call_value` と `tail_call_value` である。
辞書が前提を持つ利用者のインスタンスのとき、これらの命令は、引数 `a…` を渡す前に実装の関数を辞書 `p… ++ o…` で評価する(13 節)。
実装の関数の本体はクロージャを作る `closure_new` で、確保するので GC を起こしうる。
この間、辞書 `d`、メソッド自身の辞書 `o…`、引数 `a…`(`call_value` では呼ぶ値 `f` も)は呼び出し元のフレームのスロットにだけあり、再開点の集合には入らない。

インタプリタ(M87)は、これらの値を呼び出し元のフレームのスロットに残したまま、実装の関数をふつうのフレームとして上に積む。
呼び出し元の見出しの再開点には印 `PHASE` を付ける。
実装の関数が戻ったら、呼び出しの命令を読み直し、得た関数を同じスロットの引数で呼ぶ。
末尾の形(`tail_call_method` と `tail_call_value`)も、実装の関数が戻るまで呼び出し元のフレームを残し、戻った後にフレームを再利用する。
そのため、印の付いたフレームでは、GC は再開点の集合に加えて、その呼び出しの命令の被演算子(`d`、`o…`、`a…`、`call_value` では `f`)のスロットも根として走査する。

見出しの再開点の番号は後段の再開点の表の番号である。
表は、LIR の再開点の行(番号は LIR の再開点の番号と同じ)の後ろに、末尾の形の呼び出しごとの行を足す。
0 から数えて `k` 番目の末尾の形の行(番号は LIR の再開点の数 + `k`)は、関数のブロックの順で 0 から数えて `k` 番目の、終わりが `tail_call_value` か `tail_call_method` のブロックのものである。
末尾の形の行は LIR の生存の集合を持たないので、印の無いときの根の集合は空である。
印の付いたフレームの呼び出しの命令は、表の行が持つ命令の位置(`call_pc`)から引く。
LLVM の後段(M91)も同じフレームの形を使い、同じ規則に従う。
WasmGC の後段(M94)では、ホストの GC が Wasm の局所変数と値のスタックにある参照を根として扱うので、この規則による義務は無い。

辞書が利用者のインスタンスでも前提を持たないもの、組み込みのインスタンス、構造的な辞書のときは、実装の関数の評価が無い。
構造的な `Eq` の比べ方(13 節の `call_method`)は実行時の関数が行い、項目の辞書の `eq` を呼ぶ間、比べる両辺と辞書を `Root` で持つ。
比べ方を始める前に、呼び出し元の見出しの再開点をこの呼び出しのものにする。
末尾の形では、その行は上の末尾の形の行で、呼び出し元のフレームの根の集合は空である。

GC(crate `keleut-rt` の `gc`)は、確保の中でだけ起こる。
GC は、実行時の文脈の `gc.top`(今の最上段のフレームの論理的な位置)から呼び出し元の鎖をたどり、各フレームが止まっている**点**で根の集合を決める。
点は、最上段のフレームが確保する命令で止まっているときは `gc.top_point`(印 `SAFEPOINT` と安全点の番号)、そのほかは見出しの 0 番の語の上位 32 ビットである。

| 点 | 根のスロット |
| --- | --- |
| 印 `SAFEPOINT`(`1 << 29`)と安全点の番号(`gc.top_point` だけ) | その安全点の集合 |
| LIR の再開点の数より小さい行の番号 | その再開点の集合。`perform` の行なら被演算子も |
| それ以上の行の番号 | 末尾の形の行で、集合は空 |

印 `PHASE`(`1 << 31`)が付いていれば、行の呼び出しの命令(末尾の形の行ならブロックの終わり)の被演算子も根にする。
印 `YIELDED`(`1 << 30`)は取り除いて読む。
`$rt_handle` のフレームは、どの点でも `any` の区画の 0 番のスロットを根にする。

後段は、確保する前に次を守る。

- 確保する命令の前に、`gc.top` を今のフレームの位置にし、`gc.top_point` をその命令の安全点にする(`GcState::at_safepoint`)。
  インタプリタは、確保する命令の前に置いた 1 語の命令 `safepoint` でこれを行う。
  安全点は見出しに書かない。
  見出しの点は、確保に失敗して巻き戻すときに呼び出し元の行として読まれうるからである(`cont_make` が継続を作れずに区間の最上段へ移ると、ハンドラのフレームは本体の呼び出しの行で誤りを受け取る)。
- 命令の外で実行時が確保するとき(`perform` の引数の配列)は、フレームが `perform` の再開点で止まっているので、`gc.top` を置いて見出しの点を使わせる(`GcState::at_frame`)。
- 実行時の関数がインタプリタを入れ子に呼ぶとき(構造的な `Eq`)は、見出しの点を呼び出しの再開点にし、`GcState::at_frame` で位置を置いてから呼ぶ。
- Rust(ccc)から管理されたフレームの鎖に入る入口は、どの後段でも `GcState::enter_native` で外側の最上段の位置を `gc.outer` に積み、戻るときに `GcState::leave_native` で外して `gc.top` と `gc.top_point` を元に戻す。
  入口の最下段の見出しの 3 番の語は「ネイティブの呼び出し元」の印なので、GC はそこに着いたら `gc.outer` に積んだ位置から続ける。
  積まない入口があると、GC はその入口より下のフレームをたどらない。
  この義務は、入れ子のインタプリタの起動(`Interp::run`。初期化の駆動と構造的な `Eq` の入れ子)に課される。
  管理されたフレームどうしのふつうの呼び出し(見出しの 3 番の語に呼び出し元の位置を書く)は使わない。
  LLVM の後段(M91)の JIT とインタプリタの境目(インタプリタから `enter_tailcc` で JIT の関数を呼ぶ入口と、JIT から `interp_stub` で入るインタプリタの起動)は、ネイティブのスタックの上では入れ子になるが、ふつうの呼び出しに当たる。
  呼ばれた側のフレームの 3 番の語には本当の呼び出し元のフレームの位置を書き、`enter_native` を使わない。
  回収と継続は、この境目をまたいで呼び出し元の鎖をたどる。
  インタプリタは、起動の最下段のフレームの位置を覚え、そのフレームが戻るか番兵で戻ったときにネイティブの呼び出し元へ返る(`keleut-interp` の `native.rs`)。
- JIT の関数は、末尾でない呼び出しの前に、再開点で生きているレジスタをスロットに書き、見出しの 0 番の語に再開点を書く。
  yield を受け取らない再開点(17 節)では `any` の区画のレジスタだけを書き、受け取る再開点では生の区画のレジスタも書く(継続に写したフレームはインタプリタが続けるので、続きに要る値がすべてスロットに要る)。
  確保する命令の前には、安全点で生きている `any` の区画のレジスタを書き、実行時の関数が `GcState::at_safepoint` を行う。
  実行時に相手を決める呼び出しが実装の関数を評価する間(印 `PHASE`)は、呼び出しの命令の被演算子もスロットに書く。
  WasmGC の後段(M94)は、上に書いたとおりホストの GC が根を扱うので、この義務を負わない。
- 状態語が `YIELD` の間、`perform` のフレームから今のフレームの上までのフレームは、まだ継続に写さずに値スタックに残る。
  GC は、状態語の `YIELD` が持つ `perform` のフレームの位置から、今の最上段の手前までもたどる。
- GC は値スタックのフレームを、使っている塊を変えずに読む(`ValueStack::ptr_at_ro`)。
  使っている塊は次のフレームの置き場所に効くからである。
- 実行時の関数が 1 回の呼び出しの中で 2 回以上確保するときは、先に作った箱を `Root` か実行時の表に置いてから次を確保する。
  引数で受け取った語は、呼び出し元のフレームの集合が根として持つ(安全点の集合は命令の被演算子を含む)。

GC は根の集合のスロットの語だけを読むので、生の区画と、集合に入らない `any` のスロットは何を持っていてもよい。
論理的な位置は値スタックの塊の境目の場所を含む。
そのため、継続が区間を写し戻すときは、位置を一様にずらさず、フレームを 1 つずつ置き直して 3 番の語を書き直す(16.4 節の `cont_resume`)。

捕獲は入口でレジスタに読む(1.2 節)ので、関数がまだ使う捕獲はこの集合に入る。
そのため、フレームの頭部(計画 6.5 節)は環境の欄を持たなくてよい。
再開点から実行を続ける後段(継続の再開、インタプリタでの再開)も、スロットだけから続きを再現できる。

エフェクトの命令(16 節)は、根について次の規則を足す。

- `perform` の再開点で待っているフレームは、再開点の集合に加えて、その `perform` の被演算子(`hr`、`saved`、引数)のスロットも根として走査する。
  節の選択が戻った後に、これらを読み直すからである(16.5 節の `perform`)。
  メソッドの印の付いたフレームの規則と同じである。
- `$rt_handle` のフレームは、`any` の区画の 0 番のスロットにハンドラ記録を持つ(0 番の引数は再利用されない)。
  `cont_resume` は、写し戻したフレームのうち `$rt_handle` のものから、このスロットを読む。
- ハンドラ記録、継続、退避した状態語の中の語(本体と節の関数の値、親や `res` のハンドラ記録と継続、継続の中のフレームの写し、`perform` の引数の配列)は、実行時の表にある。
  表は根ではない。
  GC は、項目の添字を持つ箱(種類 16、17、18)に印を付けたときに、その項目の語を走査する。
  印付けを終えたら、箱に印の付かなかった項目を表から外す。
  表の語をすべて根にすると、項目どうしの参照の輪(`cont_resume` が付け替えたハンドラ記録の親、`handler_new` の `res` の継続、その継続のハンドラ記録)がいつまでも外れないからである。
  実行時は、項目を表に入れてから、その添字を持つ箱を確保する。
  表に入れたがまだ箱の無い項目は、箱ができるまで根である。
  外した項目の添字は、次に表に入れる項目に使い回す。
  使い終えた継続の語(ハンドラ記録、連鎖の切り取りの先頭、引数)は消さない。
  継続の箱は、継続を受け取った節のフレームが終われば届かなくなり、項目ごと外れるからである。
- 状態語 `ctx.pending` の積載値(`DISCARD` の値、`YIELD` と `DISCARD(NeverBody)` の引数の配列、`ERROR` は語を持たない)と、ハンドラの連鎖 `ctx.handlers` も根である(計画 6.5 節)。
- 継続の中のフレームの写しは、値スタックの生きたフレームと同じ規則で走査する。
  見出しの 0 番の語の再開点(印 `PHASE` と取り出された印を除いた番号)の集合を使う。
  取り出された印があれば `perform` の被演算子を、印 `PHASE` があれば呼び出しの命令の被演算子を足す。
  `$rt_handle` のフレームの写しは、0 番のスロットも根にする。
  写しの `any` の区画を全体として走査してはならない。
  フレームを置くときにスロットを消さず、`cont_make` もフレームをそのまま写すので、集合に入らないスロットには死んだ値やまだ書いていない値が残りうる。

`keleut-lir` の生存解析は、ブロックを位相の逆の順にたどり、1 つの集合を書き換えながら進む。
集合を変えるたびに変えたレジスタを日誌に積み、ブロックの入口の集合は日誌の長さとして取っておく。
入口の集合を使うときは、その後の日誌をたどって今の集合との違いを求める。
したがって、近くで使う入口の集合では、手間は変わったレジスタの数に比例する。
日誌が長く伸びてから使う入口の集合(長い節の後に置いた節の入口など)は、途中で写しを作って持つ。
そうしたブロックでは、手間が集合の幅(レジスタの数の 64 分の 1 の語の数)に比例する。
移る先の無い小さなブロック(誤りで終わるブロックなど)は、この集合を使わずに処理する。
検証器の定義の検査(前向きの解析)も、同じ仕組みで出口の集合を持つ。

集合は、値を持ち続けたまま確保や呼び出しを重ねる関数(長いリストのリテラルなど)で大きくなる。
点ごとに丸ごと持つと、大きさの合計が点の数と生きている値の数の積になる。
そこで `keleut-lir` は、各点の集合を位置の順で次の点の集合からの差分で持ち、差分を積み重ねた量がその点の集合の大きさを超えた点では集合を丸ごと持つ(型 `Points`)。
持つ量の合計は差分の量の合計の 2 倍を超えず、1 つの点の集合を作り直す手間はその集合の大きさに比例する。
`keleut dump lir` の印字は各点の集合を丸ごと書くので、そうした関数では印字が長くなる。

### 1.9 区間

関数の命令に通し番号を振る。
引数は 0、ブロックを位相の順に並べ、各ブロックの命令とブロックの終わりに 1 から順に振る。
レジスタの**区間**は、最初に書く位置から最後に読む位置までである。
ブロックは位相の順に並ぶので、ある経路でレジスタが生きている位置は必ずこの区間に入る。
したがって、区間の重ならない 2 つのレジスタが同時に生きることはない。

## 3. 定数と移動

### `const`

`r = const c` は、定数 `c` をレジスタ `r` に置く。

- 被演算子:定数は `unit`、`bool b`、`i32 n`、`i64 n`、`f64 0xHHHHHHHHHHHHHHHH`(ビット列)、`str "…"`(文字列の表の添字)、`ctor0 T C`(引数の無いコンストラクタ)、`dict_builtin C T`(組み込みのインスタンスの辞書)、`dict_inst0 I`(前提を持たない利用者のインスタンスの辞書)である。
- Rep:`r` の Rep は定数の Rep(`unit`、`ctor0`、`dict_builtin`、`dict_inst0` は `any`)である。
- 前提:`dict_builtin C T` の組 `(C, T)` は組み込みのメソッドの表にある(検証器が確かめる)。
- 出すパス:3(リテラル)、2(リテラルのパターン)、5(辞書)、7(検査の定数)。
- trap しない条件:常に成り立つ。
  `str` の定数は確保しない。

### `move`

`r = move s` は、`s` の値を `r` に写す。
`r` と `s` は同じ Rep である。
出すパスは 3(合流のブロックへ移る前に、各枝が合流のレジスタに書く)と 5(`Show[String]` は文字列そのものを返す)である。
trap しない。

## 4. 箱と環境

### `box`

`r = box s` は、生の値 `s`(Rep は `any` 以外)を一様な語 `r` にする。

- 出すパス:4。
  関数の引数、戻り値、データとレコードのフィールド、捕獲、大域に置く値は一様な語なので、生の値をそこへ渡すときに置く。
- trap しない条件:`i64` と `f64` の箱は確保する(ネイティブの表現。計画 6.5 節)。
  確保の失敗はメモリの不足である(1.7 節)。
  `bool`、`i32`、`str` は確保しない。

### `unbox`

`r = unbox s` は、一様な語 `s` から Rep が `r` の Rep の値を取り出す。

- 出すパス:4。
  関数の入口の引数、`env_get` の結果、大域の値、フィールドの値を生の Rep のスロットに置くときと、プリミティブに渡すときに置く。
- 前提:`s` は、`r` の Rep の値を `box` したものである(`str` なら文字列)。
- trap しない条件:前提の下で常に成り立つ。

### `env_get`

`r = env_get i` は、いまの関数を呼んだクロージャの捕獲の `i` 番目を、一様な語で読む。

- 被演算子:`i` は関数の捕獲の数より小さい。
- 置く場所:入口のブロックの先頭の `depth_enter` の直後に、使う捕獲ごとに 1 つずつ置く(検証器が確かめる)。
  この位置より前に呼び出しも確保も無いので、フレームは `env_get` のためにクロージャを持ち続けなくてよい(1.8 節)。
- 出すパス:1。
  KIR の `env`、辞書の `env`、捕獲の列の `env` は、入口で読んだレジスタを使う。
  捕獲は一様な語で持つので、KIR の捕獲の Rep が生の Rep なら、使う箇所で `unbox` を置く。
- trap しない条件:常に成り立つ(添字は検証器が確かめる)。

## 5. 深さ

### `depth_enter`

関数の入口の先頭に 1 つだけ置き、`ctx.depth` をこのフレームの深さとして書く。
出すパスは 10 である。
trap しない。

### `depth_check`

呼ばれた側の深さ `ctx.depth + 1` を限度と比べ、超えれば `depth_limit` の誤りにする。
`ctx.depth` は変えない。

- 出すパス:10。
  利用者のコードを呼ばずに終わる末尾でない呼び出しの位置に置く。
  `dbuiltin` の辞書の `opcall` とメソッドの呼び出し(パス 5 がプリミティブにしたもの)、`extern` のプリミティブの直の呼び出し、組み込みの値(`Ref.new` など)の直の呼び出し、`extern` の大域への `dictapp` である。
  IRSpec 11.2 節は、これらも末尾でない呼び出しとして数える。
  実装の無いプリミティブの末尾でない呼び出しでは、`error` の前に置く(Diktor と同じく、深さの検査が先である)。
- trap しない条件:失敗は `depth_limit` の実行時エラーで、trap ではない。

### `depth_push`

`depth_check` と同じ検査を行い、通れば `ctx.depth` を 1 増やす。
出すパスは 10 で、利用者のコードに届く末尾でない呼び出し(`call_direct`、`call_value`、`call_method`、`dict_app`)の直前に置く。

### `depth_restore`

`ctx.depth` をこのフレームの深さ(`depth_enter` が書いた値)に書き戻す。
出すパスは 10 で、`depth_push` に対応する呼び出しの直後に置く。
番兵で戻ったときも、後段が呼び出し元に戻る時点で `ctx.depth` をそのフレームの深さに書き戻す(計画 4.10 節の実装の不変条件。16.1 節)。
trap しない。

## 6. 整数、浮動小数点数、真偽値

### `iN.add`、`iN.sub`、`iN.mul`、`iN.div`、`iN.rem`

`r = i32.add a b` などは、`a` と `b`(Rep は `i32` か `i64`)の二項演算である。
`N` は 32 か 64 である。

- 意味:`add`、`sub`、`mul` は 2 の補数で折り返す。
  `div` は 0 へ切り捨てる商、`rem` はその剰余(符号は被除数と同じ)である。
  `div` と `rem` は全域で、除数が 0 なら 0、`MIN / -1` は `MIN`、`MIN % -1` は 0 である。
- 出すパス:5(`Add`、`Sub`、`Mul`、`Div`、`Rem` の組み込みのメソッドと、同名のプリミティブ)。
  パス 7 が、`div` と `rem` の前に除数の検査(`iN.eq` と `branch`、`error 10`)を置き、`__string_sub` の範囲の検査で `i32.sub`(長さ - `len`)を使う。
  `Array.each` の内側のループの関数(12 節)は、添字を進める `i32.add` を使う。
- trap しない条件:どの入力にも結果を定めている。
  LLVM の後段は `nsw` を付けず、`sdiv` と `srem` の前に除数と `MIN / -1` の分岐を置く。
  WasmGC の後段は、`div_s` と `rem_s` を許可した補助関数の中に置く(D543)。

### `iN.neg`

`r = i32.neg a` は、折り返す符号反転である(`-MIN` は `MIN`)。
出すパスは 5 である。
trap しない。

### `iN.eq`、`iN.lt`、`iN.le`、`iN.gt`、`iN.ge`

`r = i32.lt a b` などは、符号付きの比較で、結果は `bool` である。
出すパスは 5(`Eq`、`Ord` のメソッド)、2(リテラルのパターン、コンストラクタとヴァリアントの番号)、7(検査)である。
trap しない。

### `f64.add`、`f64.sub`、`f64.mul`、`f64.div`

`r = f64.add a b` などは、IEEE 754 の binary64 の演算(最も近い値へ丸める)である。
0 による除算は無限大か NaN になる。
出すパスは 5 である。
trap しない。
後段は浮動小数点数の縮約(fma への融合)をしない。

### `f64.neg`

`r = f64.neg a` は、符号のビットを反転する。
出すパスは 5 である。
trap しない。

### `f64.eq`、`f64.lt`、`f64.le`、`f64.gt`、`f64.ge`

`r = f64.lt a b` などは、IEEE 754 の比較で、どちらかが NaN なら結果は偽である。
`f64.eq` では `0.0` と `-0.0` は等しい。
出すパスは 5、2(`Float64` のリテラルのパターン。D515)、7 である。
trap しない。

### `f64.sin`、`f64.cos`、`f64.sqrt`、`f64.exp`、`f64.log`

`r = f64.sin a` などは、`extern "C"` の数学の関数である。
`sin`、`cos`、`exp`、`log` は rtcore の `krt_sin` などの結果、`sqrt` は IEEE 754 の平方根である(D529)。
出すパスは 5(`extern "C"` の直の呼び出しと、その本体の関数)である。
trap しない。
後段はこれらを組み込み関数に置き換えず、畳み込まない。

### `f64.trunc`

`r = f64.trunc a` は、0 へ切り捨てた値である(NaN は NaN、無限大は無限大)。
出すパスは 7(整数への変換の範囲の検査)である。
trap しない。

### `f64.is_nan`

`r = f64.is_nan a` は、`a` が NaN なら真である。
出すパスは 7 である。
trap しない。

### `conv.i32_to_i64`、`conv.i32_to_f64`、`conv.i64_to_i32`、`conv.i64_to_f64`、`conv.f64_to_i32`、`conv.f64_to_i64`

`r = conv.OP a` は、数の変換である。

| 命令 | 意味 |
| --- | --- |
| `i32_to_i64` | 符号を拡張する |
| `i32_to_f64` | 正確に変換する |
| `i64_to_i32` | 下位 32 ビットを取る(折り返し) |
| `i64_to_f64` | 最も近い値へ丸める(等距離なら偶数) |
| `f64_to_i32`、`f64_to_i64` | 0 へ切り捨てる。全域で、NaN は 0、範囲の外は最小値か最大値に飽和する |

- 出すパス:5(同名のプリミティブ)。
  パス 7 が、`f64_to_i32` と `f64_to_i64` の前に、`f64.is_nan` で NaN を(`error 11`)、`f64.trunc` と `f64.ge`、`f64.lt` で範囲 `-2^31 ≦ trunc(a) < 2^31`(`i64` は `-2^63 ≦ trunc(a) < 2^63`。上端は開区間)を(`error 12`)確かめる。
- trap しない条件:どの入力にも結果を定めている。
  LLVM の `fptosi` は範囲の外で poison になるので、後段は検査の後でだけ使うか、飽和する変換を使う。

### `bool.not`

`r = bool.not a` は否定である。
出すパスは 3(KIR の `not`。`!=` は `not` と `Eq.eq` である)、5(`inst_is_init` の検査)、7(`f64_to_i32` と `f64_to_i64` の範囲の検査)、9(初期化の検査)である。
trap しない。

### `bool.eq`

`r = bool.eq a b` は、2 つの真偽値が等しいとき真である。
出すパスは 5(`Eq[Boolean]`)、2(`bool` のリテラルのパターン)、7 である。
trap しない。

## 7. 文字列

### `str.concat`

`r = str.concat a b` は、2 つのバイト列を連結した新しい文字列である。
出すパスは 5(`Add[String]`、`__string_concat`)である。
確保するので、失敗しうる(長さが `N_alloc_max` を超えるときと、ヒープを広げられないときにメモリの不足)。
ほかに trap はしない。

### `str.eq`、`str.lt`、`str.le`、`str.gt`、`str.ge`

`r = str.lt a b` などは、符号なしバイトの辞書順の比較である(rtcore の `bytes.c`)。
出すパスは 5、2(`String` のリテラルのパターン)である。
trap しない。

### `str.len`

`r = str.len a` は、バイトの数(`i32`)である。
出すパスは 5(`__string_length`)と 7(`__string_sub` の検査)である。
trap しない。

### `str.sub`

`r = str.sub s pos len` は、`s` の `pos` バイト目から `len` バイトの部分の文字列である。

- 意味:全域で、範囲の外の部分は切り詰める(`pos` と `len` を `[0, 長さ]` に収めてから取る)。
- 出すパス:5(`__string_sub`)。
  パス 7 が、前に `pos < 0`、`len < 0`、`pos > 長さ - len` の検査(どれかが真なら `error 13`)を置く。
  `0 ≦ len ≦ 長さ < 2^31` なので、`長さ - len` は桁あふれしない。
- trap しない条件:確保の失敗のほかは常に成り立つ。

### `show.i32`、`show.i64`、`show.f64`、`show.bool`

`r = show.i32 a` などは、値を文字列にする。
`i32` と `i64` は 10 進、`bool` は `true` か `false`、`f64` は LangSpec §16.2 の綴り(rtcore の `f64show.c`。NaN は符号と積載に依らず `nan`)である。
出すパスは 5(`Show` の組み込みのメソッドと `__show_int32`)である。
確保するので失敗しうる。
`Show[String]` は文字列そのものなので、命令でなく `move` になる。

## 8. データとヴァリアント

### `ctor_new`

`r = ctor_new T C (f…)` は、型 `T` のコンストラクタ `C` の値を作る。
`f…` はフィールドの位置(宣言)の順の一様な語で、数はコンストラクタの引数の数に等しく、1 以上である。
引数の無いコンストラクタは `const ctor0` にする。

- 出すパス:3(KIR の `construct`)。
  下ろしは、フィールドの式をソースに書いた順に評価してから、位置の順に並べる。
  書かなかったフィールドは Unit にする(Diktor と同じ)。
- trap しない条件:確保の失敗のほかは常に成り立つ。

### `ctor_tag`

`r = ctor_tag v` は、データ `v` のコンストラクタの番号(`i32`)である。

- 出すパス:2。
  型のコンストラクタが 2 つ以上あるときだけ、照合の前に置く。
- 前提:`v` は名目的な型の値である。

### `ctor_field`

`r = ctor_field v i` は、データ `v` のフィールドの `i` 番目である。
全域で、`i` がフィールドの数以上なら Unit を返す。
出すパスは 2 である。
前提は `ctor_tag` と同じである。

### `variant_new`

`r = variant_new L p` は、ラベル `L` と積載値 `p` のヴァリアントを作る。
積載値の無いヴァリアントの `p` は Unit である。
出すパスは 3 である。
確保するので失敗しうる。

### `variant_tag`

`r = variant_tag v` は、ヴァリアント `v` のラベルの番号(ラベルの表の添字。`i32`)である。
出すパスは 2 で、`i32.eq` で照合するラベルの番号と比べる。
前提は、`v` がヴァリアントであることである。

### `variant_payload`

`r = variant_payload v` は、ヴァリアント `v` の積載値である。
出すパスは 2 である。
前提は `variant_tag` と同じである。

## 9. レコード

KIR 0.3 は型を持たないので、下ろしが形を知るのは、同じ関数の中で `rec_empty` と `rec_extend` の鎖から作ったレコードと、`closed` のレコードのパターン(タプルのパターン)の対象だけである(パス 6)。
`open` のレコードのパターン(既定のレコードのパターン)は、パターンに書かないフィールドを持つレコードにも一致する(IRSpec 8 節)ので、形を決めない。
ほかのレコードには、実行時に形を調べる命令を使う。

下ろしが形を覚えておくのは、フィールドが `KNOWN_RECORD_FIELDS` 個(64 個)以下のレコードだけである。
形の分かるレコードの制限、更新、拡張は、配置を写した `rec_new` にするので、1 つの箇所の命令の大きさがフィールドの数に比例する。
形を限りなく覚えると、同じレコードを更新し続ける鎖や、`let` で束ねたレコードを拡張し続ける鎖で、LIR の大きさと下ろしの手間が鎖の長さの 2 乗になる。
上限を超えるレコードは形の分からないレコードと同じに扱い、`rec_extend`、`rec_field`、`rec_restrict`、`rec_update` を使う。
そのため、1 つの箇所が形の分かるレコードから写す既存のフィールドは 64 個以下である。
`rec_extend` の鎖の値は写しでなく、その数は KIR の大きさに比例する。
`rec_empty` から作る鎖は、上限を超えても 1 回の `rec_new` にする。

### `rec_new`

`r = rec_new S (f…)` は、形 `S` のレコードを作る。
`f…` は形の順のフィールドの値で、数は形の長さに等しく、1 以上である。
空のレコードは `const unit` にする。

- 出すパス:6。
  `rec_extend` の鎖の元が `rec_empty` か形の分かるレコードなら、鎖の値をすべて評価した後で 1 回の `rec_new` にする。
  形の分かるレコードの `rec_restrict` と `rec_update` も、新しい配置の `rec_new` にする。
  形を覚えるのは、フィールドが 64 個以下の `rec_new` だけである(この節の初め)。
- trap しない条件:確保の失敗のほかは常に成り立つ。

### `rec_get`

`r = rec_get v i` は、レコード `v` のフィールドの `i` 番目(形の順)である。
全域で、`i` がフィールドの数以上なら Unit を返す。

- 出すパス:2、6。
  `closed` のレコードのパターン(タプルのパターン)は、残りのフィールドが無いことを型検査が保証するので、パターンのラベルの列から形を決め、各ラベルを位置で読む。
  同じラベルの `j` 番目の項目は、外側から `j` 番目のフィールドである。
  `open` のパターンには使わない(`rec_field` の節)。
- 前提:`v` の形は、下ろしが決めた形である。

### `rec_extend`

`r = rec_extend v L x` は、レコード `v` の最も外側にラベル `L` のフィールド `x` を足した新しいレコードである。
`v` が Unit なら、フィールドが 1 つのレコードになる。
出すパスは 6(形の分からない元への `rec_extend` の鎖。内側から順に足す)である。
確保するので失敗しうる。
実行時は rtcore の `shape.c` で新しい形を引く。

### `rec_field`

`r = rec_field v L n` は、レコード `v` の、外側から `n` 番目(0 から数える)のラベル `L` のフィールドである。
全域で、そのフィールドが無ければ Unit を返す。
出すパスは 6(形の分からないレコードの `rec_select`。`n` は 0)と 2(`open` と `rest` のレコードのパターン)である。
`open` のパターンでは、書いたラベルがあることを型検査が保証するので、前に `rec_has` を置かない。
パターンの対象が形の分かるレコードなら、どちらのパターンでもこの命令を使わず、フィールドの値のレジスタをそのまま使う。
前提は、`v` がレコードか Unit であることである。

### `rec_has`

`r = rec_has v L n` は、レコード `v` が外側から `n` 番目のラベル `L` のフィールドを持てば真である。
出すパスは 2(`rest` のレコードのパターン)である。
IRSpec 8 節のとおり、ラベルの無いレコードとの照合は照合の失敗になる。
trap しない。

### `rec_restrict`

`r = rec_restrict v L` は、レコード `v` から最も外側のラベル `L` のフィールドを 1 つ除いた新しいレコードである。
全域で、`L` が無ければ `v` と同じフィールドのレコードを返す。
出すパスは 6(形の分からないレコードと、フィールドが 64 個を超えるレコードの `rec_restrict`)と 2(`rest` のパターンの残り。パターンの各ラベルを順に除く)である。
確保するので失敗しうる。

### `rec_update`

`r = rec_update v L x` は、レコード `v` の最も外側のラベル `L` のフィールドを `x` に置き換えた新しいレコードである。
フィールドの位置は変えない。
全域で、`L` が無ければ `v` と同じフィールドのレコードを返す。
出すパスは 6(形の分からないレコードと、フィールドが 64 個を超えるレコードの `rec_update`)である。
KIR の `rec_update` は、レコードを先に、値を後に評価する。
確保するので失敗しうる。

## 10. 関数の値と辞書

### `closure_new`

`r = closure_new F (c…)` は、関数 `F`(種類 `lambda` か `dictabs`)と捕獲 `c…`(一様な語)のクロージャを作る。
捕獲の数は `F` の捕獲の数に等しい。
出すパスは 1(KIR の `closure` と `dictabs`)である。
確保するので失敗しうる。

### `closure_set_cap`

`closure_set_cap c i x` は、クロージャ `c` の捕獲の `i` 番目を `x` にする。

- 出すパス:1。
  KIR の `letrec` だけが使う。
  `letrec` は、群のクロージャをすべて Unit の捕獲で作ってスロットに置いた後、各クロージャの捕獲をこの命令で埋める。
  そのため、捕獲は群のどのスロットも読める。
- 前提:`c` は同じ `letrec` で作ったばかりのクロージャで、まだほかへ渡していない。
  `i` は `c` を作った関数の捕獲の数より小さい。
  検証器は、同じブロックの中で `c` を最後に書いた命令が `closure_new` であることと、`i` がその関数の捕獲の数より小さいことを確かめる(下ろしは 1 つの `letrec` の命令を 1 つのブロックに置く)。
- trap しない条件:前提の下で常に成り立つ。

### `method_new`

`r = method_new C m d (o…)` は、クラス `C` のメソッド `m` の値を、辞書 `d` とメソッド自身の辞書 `o…` から作る。
作る時点ではインスタンスを選ばない(IRSpec 5.4 節)。
出すパスは 5(呼び出し先でない位置の KIR の `method`)である。
確保するので失敗しうる。

### `dict_inst`

`r = dict_inst I (p…)` は、利用者のインスタンス `I` に前提の辞書 `p…` を渡した辞書である。
前提の数は `I` の前提の数に等しく、1 以上である(検証器が確かめる)。
前提を持たないインスタンスの辞書は `const dict_inst0 I` にする。
出すパスは 5 である。
確保するので失敗しうる。

### `dict_record`、`dict_variant`

`r = dict_record (L d…)` と `r = dict_variant (L d…)` は、閉じた行の型の構造的な `Eq` の辞書である。
項目はラベルと、そのフィールドの型の `Eq` の辞書で、KIR の順(ラベルの綴りのバイト列の昇順、同名は外側から)に並ぶ。
比べ方は `call_method` の節にある。
出すパスは 5 である。
確保するので失敗しうる。

## 11. 大域とインスタンス

### `global_get`

`r = global_get g` は、大域 `g` の値(1.6 節)を一様な語で読む。
初期化の検査はしない。
KIR の大域の Rep が生の Rep なら、続けて `unbox` を置く。
出すパスは 3 である。
trap しない。

### `global_is_init`

`r = global_is_init g` は、大域 `g` が初期化済みなら真である。
種類 `builtin` の大域は、プログラムの開始の時点で初期化済みである。

- 出すパス:9。
  大域を読む前に `bool.not` と `branch` と `error 2` とともに置く。
  パス 9 は、読む箇所を含む最も外側のトップレベルの実体の手順が大域の手順より後にあるとき、または両者が同じ `def_fns` の手順にあるときだけ、この検査を省く(D506、IRSpec 10.3 節)。
  最も外側のトップレベルの実体は、関数を作った場所の鎖をたどって着く根の関数で決める。
  根が決まらない関数(作る場所が 2 つ以上あるものなど)では省かない。
- trap しない。

### `global_set`

`global_set g x` は、大域 `g` に一様な語 `x` を置く。
初期化の関数だけが使う(`def_value` の値、`def_pattern` の照合が束縛した値)。
trap しない。

### `global_mark_init`

`global_mark_init g` は、大域 `g` を初期化済みにする。
初期化の関数だけが使う。
`def_pattern` では、照合が成功した後で、大域の列の順に置く。
trap しない。

### `inst_is_init`

`r = inst_is_init I` は、インスタンス `I` が初期化済みなら真である。
出すパスは 5 で、`dinst` の辞書のメソッドの呼び出しで、引数をすべて評価した後(と `depth_push` の後)に `error 6` への枝とともに置く。
trap しない。

### `inst_mark_init`

`inst_mark_init I` は、インスタンス `I` を初期化済みにする。
初期化の関数が、`def_instance` の実装をすべて評価した後に置く。
trap しない。

### `inst_set_value`

`inst_set_value I m x` は、インスタンス `I` のメソッド `m`(クラスの中の位置)の値として `x` を覚える。
初期化の関数が、辞書の引数の数が 0 の実装の関数をメソッドを書いた順に評価した直後に置く(IRSpec 10.1 節)。
trap しない。

### `inst_get_value`

`r = inst_get_value I m` は、`inst_set_value` が覚えた値である。
出すパスは 5 で、実装の関数が受け取る辞書の数が 0 のメソッドの呼び出しに使う。
前提は、`I` が初期化済みであることである(`inst_is_init` の検査の後でだけ使う)。
検証器は、`inst_get_value` と `inst_set_value` のメソッド `m` の実装の関数が辞書を受け取らないことを確かめる。

## 12. 組み込みの値

これらの命令は、組み込みの値の本体の関数と、組み込みの値の大域を直に呼ぶ箇所(`call` の呼び出し先が `global "builtin/…"` であるもの)で使う。
直に呼ぶ箇所が末尾でなければ、前に `depth_check` を置く(組み込みの値は呼ばれた側の深さで走る。IRSpec 付録 A.4)。
添字と長さは一様な語で受け取り、`unbox` で `i32` にする。

### `ref_new`、`ref_get`、`ref_set`

`r = ref_new x` は値 `x` を持つ新しい `Ref` を作る(確保する)。
`r = ref_get c` は `Ref` の `c` の値を読み、`ref_set c x` は `c` の値を `x` にする。
`Ref.set` の結果の Unit は `const unit` で作る。
前提は、`c` が `Ref` であることである。

### `array_len`、`marray_len`

`r = array_len a` と `r = marray_len a` は、配列の長さ(`i32`)である。
前提は、`a` がそれぞれ `Array` と `MutableArray` であることである。

### `array_get`、`marray_get`

`r = array_get a i` と `r = marray_get a i` は、配列の `i` 番目の要素である。
全域で、範囲の外なら Unit を返す。
下ろしは前に `i < 0` と `i ≧ 長さ` の検査(どちらかが真なら `error 15`)を置く。

### `marray_set`

`marray_set a i x` は、可変の配列の `i` 番目を `x` にする。
全域で、範囲の外なら何もしない。
下ろしは `marray_get` と同じ検査を前に置く。

### `marray_new`

`r = marray_new n x` は、長さ `n` のすべての要素が `x` の可変の配列を作る。
全域で、負の長さは 0 とみなす。
下ろしは前に `n < 0` の検査(`error 16`)を置く。
長さが `N_alloc_max` を超えるときと、ヒープを広げられないときはメモリの不足(19 番)になる。

### `marray_freeze`

`r = marray_freeze a` は、可変の配列の写しの `Array` を作る。
確保するので失敗しうる。

`Array.each` と `pinned` は利用者の関数を呼ぶので、命令にせず、LIR の関数として本体を書く。
`pinned(f)` の本体は `depth_push`、`call_value f ()`、`depth_restore`、`return` である。
`Array.each(a, f)` の本体は、内側のループの関数 `(a, f, i)` を末尾で呼ぶ。
ループは、`i ≧ 長さ` なら Unit を返し、そうでなければ要素を `call_value` で `f` に渡し(`depth_push` と `depth_restore` で囲む)、`i + 1` で自分を末尾で呼ぶ。
こうすると、利用者の関数は組み込みの深さ + 1 で走る(IRSpec 付録 A.4)。

## 13. 呼び出し

呼び出しの引数と結果は、どれも一様な語である。
`yield` か `noyield` の印は KIR の印を写したもので、パス 11 が再開点の印を決めるときに使う(17 節)。
呼ばれた側が番兵で戻ったら、呼び出しの命令は呼び出し元のフレームも番兵で戻す(16.1 節の伝播)。
`opcall` から作るメソッドの呼び出しは、KIR に印が無いので `yield` にする。

### `call_direct`

`r = call_direct y F (a…)` は、捕獲を持たない関数 `F` を環境なしに、末尾でなく呼ぶ。
引数の数は `F` の引数の数に等しい。

- 出すパス:3(呼び出し先が種類 `fn` の大域の `call`、組み込みの値 `Array.each` と `pinned` の直の呼び出し)、5(`dictapp` の相手が種類 `dictabs` の大域のもの。辞書を引数に渡す)、初期化の関数(`thunk` と実装の関数の評価)。
- 深さ:命令は深さを変えない。
  KIR の末尾でない呼び出しから作ったものは `depth_push` と `depth_restore` で囲む。
  初期化の関数の呼び出しと、メソッドの呼び出しの中の実装の関数の評価は囲まない(呼ばれた側の深さで評価する)。
  ハンドラ式と末尾でない `resume` から `$rt_handle` を呼ぶもの(16.3 節)も囲まない。
  ハンドラのフレームは、ハンドラ式の位置の深さ `h`、または `resume` の位置の深さ `c` で走るからである。
- 失敗しうる命令である。

### `call_value`

`r = call_value y f (a…)` は、値 `f` を引数とともに末尾でなく呼ぶ。

| `f` の値 | 働き |
| --- | --- |
| 種類 `lambda` の関数のクロージャ | 関数を、クロージャを環境として呼ぶ |
| 本体の関数を持つ大域の値(1.6 節) | 本体の関数を呼ぶ |
| 実装名の無い `extern` の値 | 実行時エラー 17 か 18 |
| メソッドの値 | `call_method` と同じにメソッドを選んで呼ぶ |

- 出すパス:3(ほかの `call`)、5(`dinst` の辞書のメソッドの呼び出しで、選んだ値を呼ぶもの)。
- 前提:`f` は上の表のどれかで、引数の数が関数の引数の数に等しい。
- 根:`f` がメソッドの値で、実装の関数を評価する間は、呼び出し元のフレームの再開点に印が付き、`f` と `a…` のスロットが根になる(1.8 節)。
- 失敗しうる命令である。

### `call_method`

`r = call_method y C m d (o…) (a…)` は、辞書 `d` からクラス `C` のメソッド `m` を選び、引数 `a…` で末尾でなく呼ぶ。
選ぶのは引数をすべて評価した後である(IRSpec 5.4 節)。

| `d` の値 | 働き |
| --- | --- |
| 利用者のインスタンス `I`(前提 `p…`) | `I` が初期化の前なら実行時エラー 6。実装の関数が受け取る辞書の数が 0 なら `inst_get_value` の値を、そうでなければ実装の関数を辞書 `p… ++ o…` で評価した値を、`a…` で呼ぶ。評価も呼び出しも、この呼び出しの呼ばれた側の深さで行う |
| 組み込みのインスタンス `(C', T)` | 組み込みのメソッドの表の `(C', T, m)` の本体の関数を呼ぶ |
| `dict_record` | `C` は `Eq` である。項目を順に、両辺の最も外側の同名のフィールドを取り出し、項目の辞書の `eq` を末尾でなく呼んで比べる(深さ + 1。`depth_push` と同じ検査と、戻った後の書き戻しを行う)。偽ならその時点で偽を返し、残りの辞書を呼ばない。すべて真で、両辺の残りが空なら真 |
| `dict_variant` | `C` は `Eq` である。ラベルが等しく、そのラベルの項目の辞書の `eq` で積載値が等しいとき真(比べ方の深さは `dict_record` と同じ) |

- 出すパス:5。
  辞書が辞書の引数、捕獲、構造的な辞書のときに使う。
  `dbuiltin` の辞書はプリミティブの命令に、`dinst` の辞書は `inst_is_init`、`inst_get_value`(または実装の関数の `call_direct`)、`call_value` にする。
- 深さ:`depth_push` と `depth_restore` で囲む。
- 根:再開点の集合は `d`、`o…`、`a…` を含まない。
  利用者のインスタンスの実装の関数を評価する間は、呼び出し元のフレームの再開点に印が付き、これらのスロットが根になる。
  構造的な `Eq` の比べ方の間は、実行時の関数が両辺と辞書を `Root` で持つ(1.8 節)。
- 失敗しうる命令である。
  構造的な `Eq` の比べ方は実行時が行う。
  比べ方は、利用者のインスタンスの `eq` を入れ子のインタプリタで呼ぶ実行時の関数のままにする(LIR の関数にしない)。
  `Eq` のメソッドの型はエフェクトの行を持たないので、`eq` の中で起こした操作はその中のハンドラが処理する。
  入れ子の境目は `DISCARD` と `ERROR` を外へ通し、境目の外へ `YIELD` が届いたら内部の誤り(70)にする。

### `dict_app`

`r = dict_app f (d…)` は、値 `f` に辞書の列を渡す(IRSpec 7.5 節)。

| `f` の値 | 結果 |
| --- | --- |
| 種類 `dictabs` の関数のクロージャ | 関数を、辞書を引数に、クロージャを環境として呼んだ値 |
| `extern` の値 | `f` そのもの(辞書は捨てる) |

- 出すパス:3(相手が大域でない `dictapp`)。
  相手が種類 `dictabs` の大域なら `call_direct` に、`extern` の大域なら `depth_check` と `global_get` にする。
- 深さ:`dictapp` は末尾の呼び出しにならないので、常に `depth_push` と `depth_restore` で囲む。
- 失敗しうる命令である。

### `console_write`

`r = console_write s` は、文字列 `s` を標準出力のバッファに足し、`r` を Unit にする。
バッファの大きさ、flush の時点、書き込みの失敗の扱いは計画 6.5 節の出力の規約(D530)に従い、失敗は出力の失敗(終了状態 74)である。

- 前提:プレリュードが `Console.write` の返り値の型を Unit と宣言している。
  KIR はこの型を持たないので、下ろしも検証器も確かめない。
  `--prelude` で別の型を宣言したプログラムでは、`r` を読む命令の前提が破られうる(1.3 節)。
- 出すパス:3。
  エフェクトの表で `runtime` の印の付いた操作(プレリュードの `Console.write`)の `perform` を、この命令にする。
  エフェクトの名前では判断しない(`--no-prelude` のプログラムは自分の `Console` を宣言できる)。
- 深さ:深さを変えず、限度の検査もしない(IRSpec 11.2 節)。
- 失敗しうる命令である。

## 14. ブロックの終わり

### `jump`

`jump b` は、ブロック `b`(番号は自分より大きい)へ移る。
trap しない。

### `branch`

`branch c b1 b2` は、`c`(`bool`)が真なら `b1` へ、偽なら `b2` へ移る。
どちらも番号は自分より大きい。
trap しない。

### `return`

`return x` は、一様な語 `x` を関数の値として返す。
trap しない。

### `tail_call_direct`

`tail_call_direct y F (a…)` は、`call_direct` と同じ相手を末尾で呼ぶ。
フレームを再利用し、深さを変えない。
LLVM の後段は `musttail` に、WasmGC の後段は `return_call` に、インタプリタはフレームの再利用にする(計画 6.12 節)。
出すパスは 3(末尾の印の付いた `call`)と、`Array.each` の本体とループである。

### `tail_call_value`

`tail_call_value y f (a…)` は、`call_value` と同じ相手を末尾で呼ぶ。
`f` がメソッドの値なら、実装の関数を評価する間は呼び出し元のフレームを残して `f` と `a…` のスロットを根にし、評価が戻ってからフレームを再利用する(1.8 節)。
出すパスは 3 と 5(`dinst` の辞書の末尾のメソッドの呼び出し)である。

### `tail_call_method`

`tail_call_method y C m d (o…) (a…)` は、`call_method` と同じ選び方で末尾で呼ぶ。
利用者のインスタンスの実装の関数の評価は、末尾の呼び出しの呼ばれた側の深さ(呼び出し元と同じ深さ)で行う。
この評価の間は呼び出し元のフレームを残して `d`、`o…`、`a…` のスロットを根にし、評価が戻ってからフレームを再利用する(1.8 節)。
出すパスは 5 である。

### `error`

`error N [operand]` は、付録 B の `N` 番の実行時エラーを起こす。
文面に要る情報は、命令が持つか被演算子で渡す。

| 番号 | 起こす場面 | 命令が持つもの、被演算子 | 出すパス |
| --- | --- | --- | --- |
| 1 | `hole` | | 3 |
| 2 | 初期化の前の大域を読んだ | 大域(表示名は大域の表の `display`) | 9 |
| 3 | `letpat` と `def_pattern` の照合の失敗 | 照合した値(`any`) | 2 |
| 4 | `match` のどの節にも一致しない | 照合した値(`any`) | 2 |
| 5 | 範囲外の数値リテラル | 字面 | 3 |
| 6 | 初期化の前のインスタンスからメソッドを選んだ | インスタンス(`<C>[<T>]` はインスタンスの表の `display`) | 5 |
| 10 | 整数のゼロ除算 | | 7 |
| 11 | NaN を整数に変換しようとした | 変換(実装名) | 7 |
| 12 | 変換の結果が範囲外 | 変換(実装名)、元の値(`f64`) | 7 |
| 13 | `__string_sub` の範囲外 | | 7 |
| 14 | `__panic` | 文面(`str`) | 5 |
| 15 | 配列の範囲外 | | 7 |
| 16 | `MutableArray.new` の負の長さ | | 7 |
| 17、18 | 実装の無いプリミティブを呼んだ | `extern` の大域(表示名と実装名が等しければ 17、違えば 18) | 3 |
| 19 | メモリの不足 | | (確保する命令が起こす。`error` には使わず、検証器が拒否する) |

17 と 18 は、LIR では同じ `error` の種類で表し、大域の表の `display` と実装名から番号を決める(`Program::error_number`。印字もこの番号を書く)。

範囲外の数値リテラル(5 番)の `error` は、評価の順の位置にそのまま置き、畳み込んだり前へ動かしたり消したりしない(IRSpec 10.4 節)。
実行時エラーを起こした後の扱いは 1.7 節のとおりである。
trap ではない。

### `unimplemented`

`unimplemented "…"` は、未実装の機能に届いたことを表す。
実行時は標準出力を flush し、標準エラーに `keleut: 未実装: …` を書いて終了状態 4 で終わる。

- 出すパス:下ろし。
  本体の関数を作れない組み込みの値(`"組み込みの値 …"`)と、下ろしの内部の誤り(`"内部の誤り: …"`)に置く。
  M86 は操作節の選択の失敗の枝にも置いたが、パス 8 がこれを `tail_call_clause`(16.6 節)に置き換えた。
- trap しない。

## 15. 未実装の機能

### `unimplemented_value`

`r = unimplemented_value "…"` は、未実装の機能に届いたことを表す命令である。
実行時の振る舞いは `unimplemented` と同じで、標準出力を flush し、標準エラーに `keleut: 未実装: …` を書いて終了状態 4 で終わる。
`r`(`any`)は続きの下ろしのための値で、実行時に書かれることはない。

- 出すパス:いまの下ろしは出さない。
  M86 は、`handle`、利用者の操作の `perform`、`resume` をこの命令に下ろし、後に続く KIR も下ろして検証した。
  パス 8 がこれらをエフェクトの命令(16 節)に置き換えた。
  後段は、まだ下ろしの無い機能の置き場としてこの命令を残す。
- 呼び出しでも確保でもないので、再開点にも安全点にもならない。
- trap しない。

## 16. エフェクト(パス 8)

本節は、`handle`、利用者の操作の `perform`、`resume` の下ろしと、それが出す命令の意味を定める。
規約は計画 6.6 節のもので、IRSpec 9 節と 11 節の振る舞いを実装する。
`rt_handle`、`rt_resume`、防壁は、すべての後段が共有する 1 つの LIR の関数 `$rt_handle` の文面である(16.3 節)。
後段が違うのは、番兵で戻ったフレームの扱い(16.1 節)と、継続のフレームの持ち方(16.4 節)だけである。

### 16.1 状態語、番兵、伝播

実行時は次のものを持つ。

| 名前 | 中身 |
| --- | --- |
| ハンドラ記録 `hr` | 起動ごとの 64 ビットの番号、エフェクト、操作節の表(書いた順の操作、分類、節の関数の値)、本体の関数の値、本体に渡す継続、`return` 節と `cancel` 節(省略できる)、親、深さ `h` |
| 連鎖 `ctx.handlers` | 有効なハンドラ記録の単方向の連鎖(最も内側が先頭) |
| 状態語 `ctx.pending` | `NONE`、`YIELD(hr, 節, 引数, 切り取りの先頭)`、`DISCARD(hr, Value v)`、`DISCARD(hr, NeverBody(節, 引数))`、`ERROR(種類, 文面)` |
| 継続 `k` | フレームの写しの列、取り出したハンドラ記録、連鎖の切り取りの先頭、選んだ G の節と引数、`Δ`、`used`、`alive` |

`ERROR` の種類は、実行時エラー、`depth_limit`、メモリの不足、出力の失敗、どのハンドラも処理しない操作である。
状態語は、ほかに 3 つの**印**を持つ。
`clause_matched`、`clause_value`、`tail_resume` の印で、操作節の関数とその呼び手(`perform` のフレームか `$rt_handle` のフレーム)の間だけで使う(16.6 節)。

**番兵**は戻り値の位置に置く語で、状態語が立っていることを表す(ネイティブの表現では `0x2`。計画 6.5 節)。
番兵は値ではない。
レジスタに番兵が入るのは、`$rt_handle` の中の番兵を受け取る呼び出しの結果だけである。

**伝播**:末尾でない呼び出しの呼ばれた側が番兵で戻ったら、呼び出し元は呼び出しの種類で次のようにする。

| 呼び出し | 振る舞い |
| --- | --- |
| ふつうの呼び出し(`call_direct`、`call_value`、`call_method`、`dict_app`) | 自分も番兵で戻る。`YIELD` なら自分のフレームを値スタックに残して継続に含め(再開点は呼び出しの前に見出しに書いてある)、ほかならフレームを捨てる |
| 番兵を受け取る呼び出し(`call_body`、`cont_resume`、`call_clause`、`call_cancel`) | 結果のレジスタに番兵を書いて、次の命令へ進む |
| `perform` | 節の選択の結果を状態語にする(16.5 節) |

どの場合も、呼び出し元に戻るときに `ctx.depth` を呼び出し元のフレームの深さに書き戻す。
失敗しうる命令(1.7 節)が失敗したときは、誤りを `ERROR` にして、そのフレームを番兵で戻す。
`propagate`(16.6 節)も、状態語を変えずにフレームを番兵で戻す。

`YIELD` が、yield を受け取らないとした再開点(17 節)で待っているフレームに届いたら、`may_yield` の印の誤りである。
後段は内部の誤り(70)で止まる。

構造的な `Eq` の比べ方(13 節の `call_method`)は、実行時の関数が入れ子に後段を呼ぶ。
この境目は、`DISCARD` と `ERROR` を呼び出し元のフレームへ通す。
境目の外へ `YIELD` が届いたら、内部の誤り(70)にする。
`Eq` のメソッドの型はエフェクトの行を持たないので、型検査を済ませたプログラムでは起きない。

### 16.2 ハンドラ式、`perform`、`resume` の下ろし

**ハンドラ式**:`(handle tail|ntail E body ops… ret cancel)` は、本体、各操作節、`return` 節、`cancel` 節の関数の値を作り(`closure_new`)、次の命令にする。

```
hr = handler_new E [(op class)…] [ret] [cancel] (body res clause… [ret] [cancel])
r  = call_direct yield $rt_handle (hr unit unit)        ; 末尾の handle なら tail_call_direct
```

`res` は、本体に渡す継続である。
ハンドラ式を書いた関数が G の節の関数かハンドラ式の本体の関数なら、その関数の継続のレジスタ、そうでなければ Unit である。
`$rt_handle` を呼ぶ `call_direct` は `depth_push` で囲まない(13 節)。

**`perform`**:利用者の操作の `(perform E op a…)` は、引数を評価した後、次の命令にする。

```
hr    = handler_find E op
saved = handlers_get
r     = perform E op (hr saved a…)
```

`runtime` の印の付いた操作は `console_write` にする(13 節)。

**`resume`**:`(resume tail|ntail e)` は、`e` を評価して一様な語 `v` にした後、次の命令にする。

| 場所 | 命令 |
| --- | --- |
| T の節の背骨の上の末尾の `resume` | `return v` |
| G の節の背骨の上の末尾の `resume` | `tail_resume (v)` |
| 末尾でない `resume`(G の節の本体と、その中のハンドラ式の本体) | `cont_check ntail (k)`、`h = cont_hr (k)`、`r = call_direct yield $rt_handle (h k v)` |

`k` は関数の継続のレジスタである。
末尾でない `resume` の `call_direct` も `depth_push` で囲まない。
再開した計算のハンドラのフレームは、`resume` の位置の深さ `c` で走るからである(IRSpec 11.4 節)。

**操作節の関数**:種類 `opclause` の関数は、KIR の引数の後ろに隠れた引数 `x` と `sel`(どちらも `any`)を持つ。

- `sel` が 0 以上なら**選択の段**である。
  `x` はハンドラ記録、`sel` はこの節の候補の番号(ハンドラ記録の操作節の表の位置)である。
  関数は引数のパターンを照合し、一致したらガードを評価する。
  一致しないかガードが偽なら、`tail_call_clause` で次の候補を末尾で呼ぶ。
  一致して分類が T なら、そのまま本体を走らせる。
  分類が N か G なら、`clause_matched (sel)` で戻る。
- `sel` が負なら**本体の段**で、N と G の節だけが使う。
  `x` は、G の節では継続、N の節では Unit である。
  関数は引数のパターンをもう一度照合し(照合は副作用を持たないので、選択の段と同じに束縛する)、ガードを飛ばして本体を走らせる。

本体の末尾の値と末尾の `resume` は、分類で次のように下ろす。

| 分類 | 末尾の値 `r` | 末尾の `resume(v)` |
| --- | --- | --- |
| T | `clause_value (r)` | `return v` |
| G | `return r` | `tail_resume (v)` |
| N | `return r`(`handle` が末尾なら末尾の呼び出しも使う) | (書けない) |

T と G の節の本体の根は末尾位置でない(IRSpec 5.3 節)ので、これらの節の本体の呼び出しは末尾の呼び出しにならない。

**ハンドラ式の本体の関数**:種類 `handlebody` の関数は、隠れた引数として、受け継ぐ継続 `res` を持つ(Unit でもよい)。
本体の中の末尾でない `resume` は、この継続を再開する(IRSpec 9.2 節)。

### 16.3 `$rt_handle`

`$rt_handle(hr, k, v)` は、ハンドラのフレームの関数である(種類 `handler`)。
ハンドラ式から呼ぶと(`k` が Unit)、計画 6.6 節の `rt_handle` の手順 1 を行う。
継続を再開するときに呼ぶと(`k` が継続、`hr` は `k` のハンドラ記録)、`rt_resume` として `k` のフレームを自分の上に写し戻す。
どちらも、その後は下の同じ手順 3〜4(計画 6.6 節の手順 2〜7)で終わる。
写し戻した計算は、新しいハンドラのフレームの上で走る(計画 6.6 節の「写し戻した計算は rt_handle の手順 2〜7 で終わる」)。

文面は次のとおりである(`keleut-lir` の `effect::rt_handle_body`)。
この節の手順の番号は、この下の列の番号である。
`r` は本体か写し戻した計算の結果、`c` は `pending_class` の値である。

1. `is_cont (k)` が偽なら(ハンドラ式から)、`depth_check` で本体の深さ `h + 1` を限度と比べ、`handler_install (hr)`、`depth_push`、`r = call_body (hr)`、`depth_restore` とする。
   限度を超えたら、ハンドラを連鎖に入れる前の誤りなので、`cancel` 節を走らせずに伝播する。
2. 真なら(`rt_resume`)、`cont_check tail (k)`(再開済みなら実行時エラー 7)、`r = cont_resume (k v)`、`depth_restore` とする。
3. `r` が番兵でなければ、`handler_uninstall (hr)` の後、`return` 節があればそれを `tail_call_value` で `r` に呼び、無ければ `return r` とする。
4. 番兵なら、`c = pending_class (hr)` で分ける。
   - 自分宛ての `DISCARD(Value v)`(1):`handler_uninstall`、`pending_take`、`pending_value` の値を返す。
     `return` 節も `cancel` 節も走らせない。
   - 自分宛ての `DISCARD(NeverBody)`(2):`handler_uninstall`、`pending_take` の後、`tail_call_never` で N の節の本体を末尾で呼ぶ(深さ `h`)。
   - 自分宛ての `YIELD`(3):`handler_uninstall`、`kk = cont_make (hr)`、`g = call_clause (kk)`(G の節の本体を深さ `h + 1` で)、`depth_restore` とし、`g` で分ける。
     `cont_make` の前に連鎖から外すので、継続を作れずにメモリの不足になっても(16.4 節)、連鎖に死んだハンドラが残らない。
     - 値なら、`cont_kill (kk)` の後、`cont_used (kk)` が真なら `return g`、偽なら `pending_discard (hr g)` を注入する値として `tail_call_direct $rt_handle (hr kk p)` とする。
       継続の中の `cancel` 節が内側から走り、付け直したハンドラの手順 4 の 1 が `g` を返す(§13.6 の「値が決まった後で破棄」)。
     - `tail_resume` の印なら、`cont_kill` の後、その値で `tail_call_direct $rt_handle (hr kk v)` とする(G の節の末尾の `resume`。一定の領域)。
     - ほかの宛ての `YIELD` なら、`propagate` で自分のフレームも継続に含めて戻る。
       再開されたら、`call_clause` の結果を受け取って続ける。
     - `DISCARD` か `ERROR` なら、`cont_kill` の後、`cont_used (kk)` が真なら `propagate`(`resume` の後の脱出)、偽なら `pending_take` の値を注入して `tail_call_direct $rt_handle (hr kk p)` とする(`resume` の前の脱出。継続の中の `cancel` 節、`hr` の `cancel` 節、外側の順に走る)。
   - ほかの宛ての `YIELD`(4):`propagate`。
   - ほかの宛ての `DISCARD` と `ERROR`(5):`handler_uninstall` の後、`cancel` 節があれば防壁(16.4 節)の中で走らせ、`propagate` で伝播を続ける。

`cont_resume` の結果と `call_body` の結果は同じ手順 3〜4 で扱う。
そのため、再開した計算の中で決まった `return` 節の値と、`resume` しない節の値は、ハンドラ式の値ではなく、この `resume` の値になる(§13.6)。

### 16.4 継続と防壁

**`cont_make (hr)`**:状態語が自分宛ての `YIELD` のとき、`perform` のフレーム(継続の最上段)から、呼び出し元の鎖をたどって、今のフレームの 1 つ上までのフレームを写す。
写す順は最下段から最上段で、各フレームの深さの語は `hr` の深さ `h` からの差にする。
`Δ = p − h`(`p` は `perform` のフレームの深さ)、切り取りの先頭、選んだ節、引数を継続に置き、状態語を消す。
写しの領域と表の項目は、状態語を消す前に、確保の失敗を返す形で取る。
取れなければ、まだ値スタックに残る区間の最上段(`perform` のフレーム)へ移り、メモリの不足の `ERROR` をそこから伝播する。
区間の中のハンドラの `cancel` 節は内側から走り、`hr` のフレームには本体の呼び出しの再開点からほかの宛ての `ERROR` として戻る。

**`cont_resume (k v)`**:今のフレーム(深さ `c`)の上に `k` のフレームを最下段から順に置き直し、すべて置けたら `k` の `used` を立てる。
値スタックを広げられずに途中で失敗したら、`k` を変えずにメモリの不足にする。
`k` は使われていないので、外側の `$rt_handle` は注入の道で `k` の中の `cancel` 節を走らせようとする。
各フレームの深さの語は `c` に差を足したものにし、3 番の語(呼び出し元の位置)を置いた位置に書き直す。
置いたフレームのうち `$rt_handle` のフレームは、そのハンドラ記録の `h` を新しい深さにする(1.8 節)。
次に `k.hr.parent = ctx.handlers`、`k.hr.h = c`、`ctx.handlers = 切り取りの先頭` とする。
最後に、最上段の `perform` のフレームへ移る。
`v` が退避した状態語なら、それを状態語にして最上段から伝播する(注入)。
そうでなければ、`v` を `perform` の結果に書いて続ける。

深さを `h` からの差で持つので、IRSpec 11.4 節のずれは写し戻すだけで済む。
`k` の中の、まだ再開していない継続 `k2` のフレームは、`k2` を取り出したハンドラ記録の `h` からの差で持つ。
そのハンドラ記録は `k` の中で始まったので、`k` を写し戻すとその `h` がずれ、`k2` を再開しても捨てても(注入して写し戻しても)、`k2` のフレームはずれた後の `h` の上に置かれる。
写し戻す前の深さの検査(`c + Δ` と限度)は、末尾でない `resume` の `cont_check ntail` が行う(IRSpec 11.3 節)。

ネイティブの後段とインタプリタは、値スタックの区間の写しをこの形で持つ。
WasmGC の後段(M95)は、フレームの構造体の列で同じ手順を行う。

**防壁**:手順 4 の 5 で、`cancel` 節を次のように走らせる。

1. `p = pending_take` で状態語を退避して消し、`l = limit_get` で今の限度を覚える。
2. `c = call_cancel (f)` で `cancel` 節を深さ `h` で呼び、`depth_restore` とする。
3. `c` が番兵なら、`pending_class` がほかの宛ての `YIELD` のとき `propagate` で戻る。
   `p` と `l` はフレームのスロットに残るので、再開されたら 3 から続ける。
   ほかなら `pending_suppress` で打ち切って記録する。
4. `limit_set (l)`、`pending_restore (p)` の後、`propagate` で元の伝播を続ける。

`cancel` 節が限度を超えて打ち切られても、限度は節の前の値に戻る(IRSpec 11.5 節)。

### 16.5 エフェクトの命令

被演算子はどれも `any` で、結果の Rep は表のとおりである。
`hr` はハンドラ記録、`k` は継続、`p` は退避した状態語の値である。
これらは値として利用者のコードに渡らない。

| 命令 | 結果 | 意味 |
| --- | --- | --- |
| `handler_new E [(op class)…] [ret] [cancel] (body res clause… ret? cancel?)` | `any` | 新しい起動の番号を振ったハンドラ記録を作る。確保する |
| `handler_find E op` | `any` | 連鎖の中でエフェクトが `E` である最も内側のハンドラ記録。無ければ `ERROR`(文面は `未処理のエフェクト操作: E.op`、終了状態 3) |
| `handlers_get` | `any` | 連鎖の先頭(空なら Unit) |
| `perform E op (hr saved a…)` | `any` | 下の説明。再開点を持つ |
| `cont_check ntail\|tail (k)` | なし | `ntail` なら、`k` が節の外なら実行時エラー 8、再開済みなら 7、`c + Δ` が限度を超えれば `depth_limit`。`tail` なら再開済みかだけを調べる |
| `is_cont (x)` | `bool` | `x` が継続か |
| `cont_hr (k)` | `any` | `k` のハンドラ記録 |
| `handler_install (hr)` | なし | `hr.parent = ctx.handlers`、`hr.h = このフレームの深さ`、`ctx.handlers = hr` |
| `handler_uninstall (hr)` | なし | `ctx.handlers = hr.parent` |
| `call_body (hr)` | `any` | 本体の関数の値を、受け継ぐ継続を引数に呼ぶ。番兵を受け取る。再開点を持つ |
| `cont_resume (k v)` | `any` | 16.4 節。番兵を受け取る。再開点を持つ |
| `is_pending (r)` | `bool` | `r` が番兵か |
| `pending_class (hr)` | `i32` | 状態語を `hr` から見て分ける。1 は自分宛ての `DISCARD(Value)`、2 は自分宛ての `DISCARD(NeverBody)`、3 は自分宛ての `YIELD`、4 はほかの宛ての `YIELD`、5 はほかの宛ての `DISCARD` と `ERROR`、6 は `tail_resume` の印 |
| `pending_take` | `any` | 状態語を値にして消す。確保する |
| `pending_restore (p)` | なし | 状態語を `p` にする |
| `pending_value (p)` | `any` | `DISCARD(Value v)` か `tail_resume` の印の `v` |
| `pending_discard (hr v)` | `any` | `DISCARD(hr, Value v)` の値を作る(注入する値)。確保する |
| `pending_suppress` | なし | 標準出力を flush し、標準エラーに `cancel 節で例外が抑制されました: …` を書いて状態語を消す。flush が失敗したら(前の失敗の後にバッファに残したものや書き足したものを書き出せなかった場合を含む。どの誤りでバッファを残すかは IRSpec 9.7 節)、記録を書かずに巻き戻さずに 74 で止まる |
| `cont_make (hr)` | `any` | 16.4 節。確保する |
| `call_clause (k)` | `any` | `k` の G の節を本体の段で呼ぶ。深さ `h + 1` を限度と比べ、超えれば呼ばずに `ERROR` を立てて番兵を結果に書く(継続をまだ使っていないので注入の道に入る)。番兵を受け取る。再開点を持つ |
| `cont_kill (k)` | なし | `k` を節の外にする |
| `cont_used (k)` | `bool` | `k` が再開済みか |
| `handler_has (hr) ret\|cancel` | `bool` | 節を持つか |
| `handler_get (hr) ret\|cancel` | `any` | 節の関数の値 |
| `call_cancel (f)` | `any` | `f` を引数なしに、深さを変えずに呼ぶ。番兵を受け取る。再開点を持つ |
| `limit_get` | `i64` | 今の限度(`depth_limit` の伝播中は `L + R`) |
| `limit_set (l)` | なし | 限度を `l` にする |

`cont_check` の文面は付録 B の 7 番と 8 番である。
`handler_find`、`perform`、`cont_check`、`cont_resume`、`pending_suppress` と確保する命令は、失敗しうる命令である(1.7 節)。
`call_clause` は限度を超えても失敗せず、`ERROR` を立てて番兵を結果に書く。

**`perform E op (hr saved a…)`**:深さ `p` のフレームで次の順に進む。

1. `p + 1` が限度を超えれば `depth_limit` にする(連鎖は変えていない)。
2. `hr` の操作節の表で、操作が `op` の最初の候補を探す。
   無ければ実行時エラー 9(`handle のどの節にも一致しません: E.op(a…)`)にする。
3. `ctx.handlers = hr.parent`、`ctx.depth = p + 1` とし、その候補の関数を選択の段で末尾でなく呼ぶ(引数は `a…`、`hr`、候補の番号)。
4. 戻ったら、`ctx.depth = p` とし、結果で分ける。
   - 値 `v`(T の節の末尾の `resume`):`ctx.handlers = saved` とし、`v` を結果にする。
   - `clause_matched (j)` の印:`ctx.handlers = saved` とする。
     節 `j` が N なら、`DISCARD(hr, NeverBody(j, a…))` を立ててフレームを捨てて伝播する(ガードは評価済み)。
     G なら、`YIELD(hr, j, a…, saved)` を立て、自分のフレームを取り出された印を付けて残し、伝播する。
     このフレームが継続の最上段になり、`cont_resume` の値がこの `perform` の結果になる。
   - `clause_value (r)` の印:`ctx.handlers = saved` とし、`DISCARD(hr, Value r)` を立てて伝播する。
   - ほかの宛ての `YIELD`(節の中から外側の G の操作を起こした):連鎖を変えず、フレームを残して伝播する。
   - `DISCARD` か `ERROR`:`ctx.handlers = saved` とし、伝播する。

節の選択とガードと T の節の本体は、連鎖をハンドラの親に付け替えた深さ `p + 1` の文脈で走る(IRSpec 9.6 節の 3)。
引数を `Array` の値にした `DISCARD` と `YIELD` の積載は、計画 6.6 節の「束縛」の代わりである。
本体の段でパターンを照合し直すので、束縛でなく引数を持てば足りる。

### 16.6 エフェクトのブロックの終わり

| 終わり | 意味 |
| --- | --- |
| `propagate` | 状態語を変えずに番兵で戻る(16.1 節) |
| `tail_call_never (p)` | `p` は退避した `DISCARD(hr, NeverBody(j, a…))` である。節 `j` の関数を本体の段で末尾で呼ぶ(引数は `a…`、Unit、-1) |
| `clause_value (r)` | `clause_value` の印を立てて番兵で戻る |
| `clause_matched (sel)` | `clause_matched` の印を立てて番兵で戻る |
| `tail_resume (v)` | `tail_resume` の印を立てて番兵で戻る |
| `tail_call_clause op (hr sel a…)` | `hr` の操作節の表で、番号が `sel` より大きく操作が `op` の最初の候補を、選択の段で末尾で呼ぶ。無ければ実行時エラー 9 |

印は、操作節の関数を呼んだフレームだけが受け取る。
ほかのフレームに届いたら内部の誤り(70)である。

## 17. yield の刈り込み(パス 11)

パス 11 は、各再開点に、`YIELD` を受け取りうるかの印を付ける(`Frame::yield_points`。D534)。
末尾でない呼び出しの印が `noyield` なら受け取らないとし、`yield` の呼び出しとエフェクトの呼び出しの一種(`perform`、番兵を受け取る呼び出し)は受け取るとする。
`dict_app` は KIR に印が無いので受け取るとする。
`keleut run --no-yield-prune` はパス 11 を行わず、すべての再開点を受け取るとする。

ネイティブの後段は、受け取らない再開点で生きている生の値をスロットに書かなくてよい。
WasmGC の後段(M94)は、その呼び出しの後の `yield_save` を出さなくてよい。
インタプリタはすべての再開点からフレームを続けられるので、この印でコードを変えない。
代わりに、受け取らない再開点で待っているフレームに `YIELD` が届いたら、内部の誤り(70)で止まる(16.1 節)。
これは `may_yield` の印の誤りを見つける検査で、`--no-yield-prune` と比べると結果が分かれる(計画 11 節のリスクの表)。

検証器は、受け取らないとした再開点の呼び出しの印が `noyield` であることを確かめる。
