# kir-bad

このディレクトリには、不正な KIR の入力ファイルと、それを使うテストを置く。
テストは、`keleut kir verify` が、どの入力でも異常終了せず、終了コード 65 で拒否することを確かめる。
`rustkeleut/` で次のように実行する。

```sh
cargo build --release
target/release/kconform expect conformance/kir-bad/*.t
```

各 `.t` には、`keleut kir verify` が標準エラーに出力する診断メッセージと `[65]` を、期待出力として書いてある。
Diktor が読めるバイナリの入力では、メッセージは `diktor --run-ir` と同じで、違うのは先頭の `keleut:` だけである。
Diktor が読めるバイナリの入力とは、`binary.t` の b の入力ファイル、`verify.t` の v の入力ファイルを `keleut kir asm --no-verify` でバイナリに変換したもの、`deep.t` のバイナリの入力である。
`text.t` の t の入力ファイルと `deep.t` のテキストの入力は、RustKeleut だけで確かめる(理由は「テキストの読み込み」の節に書く)。
kconform は、比較の前に行を正規化する。
診断の種別名(型エラーなど)に `: ` が続けばその後ろを切り捨て、先頭が `⚠ ` の行は `⚠` だけにする。
KIR の診断メッセージはどちらにも該当しないので、正規化してもメッセージの全体を比較でき、各入力ファイルがどの検査で拒否されたかまで固定できる。
kconform は、正規化の前の不一致の件数も要約に出力する。

## 作り方

入力ファイルは、`crates/kir/tests/fixtures/` にある正しいプログラム(Diktor が書き出した KIR)を 1 か所ずつ壊して作った。
ヘッダのバージョンは、バージョンを変える入力ファイルを除いて 1.0 である(バイナリでは位置 4〜7 のバイトが `01 00 00 00`、テキストでは先頭が `(kir 1 0 0)`)。
b02 は、この 1.0 のヘッダの位置 4 のビット 0 を反転したものである。

- `bNN-*.kir`: `ex_loop.kir` の 1 ビットを反転したもの、途中で切り詰めたもの、ヘッダやセクションを書き換えたもの。
- `tNN-*.kirt`: `ex_loop.kirt` のテキストを書き換えたもの。
- `vNN-*.kirt`: `ex_handle.kirt` か `ex_dict.kirt` のテキストを書き換えたもの。
  書き換えは、`crates/kir/tests/verify.rs` の `MUTATIONS` から、IRSpec 13.8 節の各規則につき 1 つ以上を選んだ。
  どれも読み込みの検査に通り、検証で拒否される。
- `deep-base.kirt`: `ex_loop.kirt` と同じ内容の、正しいプログラム。
  `deep.t` が、これをもとに深い入力をその場で作る。

## 入力ファイルと検査

### バイナリの読み込み(IRSpec 13.7 節。`binary.t`)

「作り方」の列の「位置 n のビット k」は、ファイルの先頭から n バイト目(0 始まり)のビット k を反転したことを表す。
「診断」の列は、メッセージのうち位置(b23 では関数名)の後ろの部分である(末尾の括弧の補足は省いてある)。

| 入力ファイル | 13.7 節の項目 | 作り方 | 診断 |
| --- | --- | --- | --- |
| b01-header-short | 1 ヘッダ | 先頭の 10 バイトだけ | `見出しの 16 バイトがありません` |
| b02-version | 1 ヘッダ | 位置 4 のビット 0 | `版 0.0 は読めません` |
| b03-feature-bit | 1 ヘッダ | 位置 8 のビット 0 | `必要な機能のビット 0x00000001 を処理できません` |
| b04-section-count | 2 セクションの並び | 位置 12 のビット 0 | `節の数が見出し(10)と違います(11)` |
| b05-section-undefined | 2 セクションの並び | 位置 16 のビット 0 | `節 0x00 は定義されていません` |
| b06-section-order | 2 セクションの並び | 位置 16 のビット 1 | `節 0x02 が id の昇順に並んでいません` |
| b07-section-missing | 2 セクションの並び | 位置 815 のビット 7 | `必須の節 0x0b がありません` |
| b08-section-size | 2 セクションの並び | 位置 18 のビット 1 | `節 0x01 の大きさがファイルの残りを超えます` |
| b09-section-trailing | 3 エンコーディング | 位置 19 のビット 0 | `節 0x01 の中身の後ろにバイトが残っています` |
| b10-read-past-end | 3 エンコーディング | 位置 19 のビット 4 | `節の終わりを越えて読もうとしました` |
| b11-leb128-overlong | 3 エンコーディング | 最初のセクションのサイズを 6 バイトの LEB128 にした | `uLEB128 が u32 の範囲を超えます` |
| b12-count-overflow | 3 エンコーディング | 位置 604 のビット 4 | `個数が節の残りのバイト数を超えます` |
| b13-bad-tag | 3 エンコーディング | 位置 746 のビット 5 | `式の番号 0x34 は定義されていません` |
| b14-bool-value | 3 エンコーディング | 位置 734 のビット 0 | `yield の印の値が 0 でも 1 でもありません` |
| b15-flag-bits | 3 エンコーディング | 位置 769 のビット 2 | `呼び出しの印に定義されていないビットがあります` |
| b16-strings-order | 4 表 | 位置 21 のビット 1 | `stringsの表が厳密な昇順に並んでいません` |
| b17-strings-unused | 4 表 | 位置 617 のビット 0 | `strings の項目 1 がどこからも使われていません` |
| b18-strings-utf8 | 4 表 | 位置 22 のビット 7 | `strings の表に UTF-8 でない名前があります` |
| b19-index-range | 5 添字 | 位置 772 のビット 1 | `大域の添字 14 が範囲外です` |
| b20-count-lower-bound | 6 個数の下限 | 位置 822 のビット 0 | `def_fns の大域がありません` |
| b21-truncated | 2 セクションの並び | 先頭の 400 バイトだけ | `節 0x01 の大きさがファイルの残りを超えます` |
| b22-bad-magic | 1 ヘッダ | マジックナンバーを `00 4B 49 53` にした | `マジックが KIR のものではありません` |
| b23-verify-tail-mark | (13.8 節の 8) | 位置 805 のビット 0 | `call の末尾の印が、再計算した結果と違います` |
| b24-strings-order-trailing | 4 表 | b16 の strings の個数(位置 19)を 1 減らした | `stringsの表が厳密な昇順に並んでいません` |
| b25-version-major | 1 ヘッダ | 位置 4 を 2 にした | `版 2.0 は読めません` |
| b26-version-draft | 1 ヘッダ | 位置 4〜7 を `00 00 03 00` にした(草稿のバージョン 0.3) | `版 0.3 は読めません` |

b23 は、ビットを反転しても読み込みの検査に通り、検証で拒否される例である。
b24 は、strings のセクションに、順序の誤りと余分なバイトの両方がある例である。
Diktor と同じく、順序の誤りを先に報告する。
b02、b25、b26 は、メジャーバージョンがリーダのメジャーバージョン 1 と違う例である(IRSpec 14 節)。
マイナーバージョンだけを変えたファイルはリーダが受理するので、ここには置かない。
その例は `../kir-fixtures/1.0/fixtures.t` にある。
b22 は、拡張子が `.kir` なのでバイナリとして読まれる。
`keleut kir` がマジックナンバーで形式を判別するのは、拡張子が `.kir` でも `.kirt` でもないファイルだけである。

### テキストの読み込み(IRSpec 12 節。`text.t`)

| 入力ファイル | 書き換え | 診断 |
| --- | --- | --- |
| t01-syntax | 閉じ括弧を 1 つ消した | `) がありません` |
| t02-unknown-name | 表にないグローバルを参照した | `大域が表にありません: main/nosuch` |
| t03-count-lower-bound | `seq` の要素を 1 つにした | `seq の要素が 2 個より少なくなっています` |
| t04-version | ヘッダを `(kir 0 2 0)` にした | `版 0.2 は読めません` |
| t05-version-major | ヘッダを `(kir 2 0 0)` にした | `版 2.0 は読めません` |
| t06-version-minor-range | ヘッダを `(kir 1 65536 0)` にした | `副版 65536 が u16 の範囲にありません` |

Diktor は KIR のテキストを読まないので、この 6 個は RustKeleut だけで確かめる入力ファイルである。
t06 のマイナーバージョンはバイナリのヘッダの `u16le` に収まらないので、メジャーバージョンが同じでも拒否する。

### 検証(IRSpec 13.8 節。`verify.t`)

| 入力ファイル | 13.8 節の規則 | 書き換え |
| --- | --- | --- |
| v01-symbol-form | 1 名前 | グローバルのシンボル `main/r3` を `r3` にした |
| v02-creation-site | 2 関数の生成箇所 | `lambda` の関数を `thunk` にした |
| v03-function-fields | 3 関数のフィールド | `lambda` の `dicts` を 1 にした |
| v04-slot-range | 4 スロット | `local` の番号を範囲外にした |
| v05-capture-count | 5 キャプチャ | `handle` の本体のキャプチャを消した |
| v06-rep | 6 Rep | `def_value` のグローバルの Rep を `any` にした |
| v07-construct-fields | 7 構文 | `construct` のフィールドを消した |
| v08-tail-mark | 8 末尾の印 | 末尾位置の `handle` を `ntail` にした |
| v09-resume-tail-off-spine | 9 resume | `resume` の背骨の外にある `resume` を `tail` にした |
| v09-resume-in-lambda | 9 resume | 種類が `lambda` の関数の本体に `resume` を書いた |
| v09-resume-cyclic-handlebody | 9 resume | 互いを作る 2 つの `handlebody` の関数の一方に `resume` を書いた |
| v10-classification | 10 分類 | 分類 G の操作節を T と書いた |
| v11-instance-methods | 11 インスタンス | クラスにメソッドを追加し、インスタンスがそれを実装しない状態にした |
| v12-init-twice | 12 単位と初期化 | グローバルを 2 回定義した |
| v13-builtin-tables | 13 組み込みの表 | 組み込みの型の名前を変えた |
| v14-runtime-mark | 14 操作の印 | `prelude/Console` でない操作に `runtime` の印を付けた |

v09-resume-cyclic-handlebody は、`resume` の持ち主(その `resume` が再開する継続を受け取る操作節)をたどる経路が循環する入力である。
検証器は、この入力でも処理を終え、`keleut kir verify` も Diktor も同じメッセージを出して終了コード 65 で終了する。
v の入力ファイルはどれも、`keleut kir asm --no-verify` でバイナリに変換して `diktor --run-ir` に渡すと、同じメッセージが出て終了コード 65 になる。

### 入れ子の上限(IRSpec 13.9 節。`deep.t`)

`deep.t` は、`deep-base.kirt` の `main/total` の本体を深さ n の連鎖に置き換えた入力を、awk で作る。

| 入力 | 終了コード | 診断 |
| --- | --- | --- |
| 深さ 100,000 の `not` の連鎖(対照) | 0 | なし |
| 深さ 100,001 の `not` の連鎖、`variant` のパターンの連鎖、`drecord` の辞書の連鎖(テキスト) | 65 | `処理系の限度: KIR の読み込みで入れ子が深すぎます` |
| 同じ `not` と `drecord` の連鎖を `asm --max-nest 100001` でバイナリにしたもの | 65 | 同じ |
| `deep-base.kirt` を `--max-nest 3` で読む | 65 | 同じ |

深さ 100,000 の対照は、上限がちょうど `N_nest` であることを示すために置く。
この入力だけは、終了コード 65 でなく 0 で終了する。
深さ 100,001 のバイナリの診断は、位置まで Diktor の `--run-ir` と同じである。
